# Демо-набор для показа аналитики и психометрики

Синтетические данные для показа аналитики и психометрики. Набор состоит из двух пакетов
тестов `.tbtest` и трёх выгрузок отчёта LMS `.xlsx`. Все люди, ответы и даты вымышлены.
Сущности набора называются с префиксом «Демо-аналитика», и на общем стенде их легко отличить.

| Файл | Что это |
| --- | --- |
| `demo-ib-test.tbtest` | Оцениваемый тест «Демо-аналитика: информационная безопасность». Три раздела и 27 вопросов всех девяти типов |
| `demo-ib-lms-wave1.xlsx` | Первая волна: 190 первых попыток, октябрь 2025 — март 2026, версия публикации 1 |
| `demo-ib-lms-wave2.xlsx` | Вторая волна: 279 прохождений, апрель — сентябрь 2026, версия 2. Это пересдачи (вторые и третьи попытки) и 70 новых участников |
| `demo-style-survey.tbtest` | Опросник «Демо-аналитика: опросник рабочего стиля»: 12 пунктов, 4 шкалы, показатель |
| `demo-style-lms.xlsx` | 160 прохождений опросника, ноябрь 2025 — сентябрь 2026 |

Выгрузка привязывается к тесту по идентификаторам вопросов. Импорт пакета их сохраняет,
поэтому тест выбирать не нужно: сервер определит его сам.

## Как залить

Нужны права на создание тестов, публикацию и импорт в аналитику. Подойдёт, например,
администратор.

1. **Тесты → Импорт пакета.** Загрузите оба файла `.tbtest` с настройками по умолчанию.
2. **Опубликуйте оба теста.** Публикация создаёт версию 1, на которую ссылается первая волна.
3. **Аналитика теста ИБ → «Загрузить выгрузку LMS».** Загрузите `demo-ib-lms-wave1.xlsx`
   в новую группу «Демо · Волна 1».
4. **Аналитика опросника → «Загрузить выгрузку LMS».** Загрузите `demo-style-lms.xlsx`
   в новую группу «Демо · Опрос».
5. **Только для разреза по версиям.** Если он не нужен, переходите к шагу 6.
   1. Откройте тест ИБ как участник и начните прохождение. Завершать его не обязательно.
   2. В вопросе «Какой пароль надёжнее всего?» поменяйте формулировку, например на
      «Какой из этих паролей надёжнее всего?».
   3. Опубликуйте тест ИБ ещё раз. Появится версия 2.

   Начатая попытка удерживает версию 1: при публикации старые версии удаляются, если на них
   не ссылается ни одна веб-попытка, а импортированные строки их не удерживают. Правка
   вопроса даёт ему вторую редакцию содержания.
6. **Аналитика теста ИБ → «Загрузить выгрузку LMS».** Загрузите `demo-ib-lms-wave2.xlsx`
   в новую группу «Демо · Волна 2».

Все шаги можно выполнить одной командой. Скрипт вызывает те же API, что и интерфейс:

```bash
npx tsx scripts/dev/demo-analytics/load-demo.ts --base https://стенд --email ... --password ...
```

Задержки и экспозиция считаются только за последние 12 месяцев. Даты в файлах привязаны
к 30.09.2026. Если набор показывают сильно позже, пересоберите выгрузки со сдвигом
календаря (см. «Как пересобрать»).

## Что где смотреть

### Тест ИБ → «Качество вопросов»

- **Плитки.** Надёжность считается по связям вопросов, потому что выдача неоднородна. Рядом
  показаны альфа по ядру из 14 вопросов, ошибка измерения, число вопросов под подозрением и
  число вопросов с надёжной оценкой (n ≥ 100).
- **Баннеры.** Показываются два баннера:
  - «Показатели дискриминации ослаблены». Причины: варианты, случайная выдача и доля
    импорта больше 20 %.
  - «Проходной балл попадает внутрь интервала ошибки».
- **Флаги вопросов.** Каждый случай заложен в данные нарочно:

  | Вопрос | Что показывает |
  | --- | --- |
  | «Что обязательно проверить в письме…» | Испорченный ключ: сильные ошибаются чаще, r < 0 |
  | «Какой алгоритм используется для хранения паролей…» | Слишком трудный и на уровне угадывания |
  | «Какой порт по умолчанию использует протокол RDP?» | Ответы почти случайные: r около нуля, флаги «на уровне угадывания» и «сильные ошибаются чаще» |
  | «Какой признак чаще всего выдаёт целевой фишинг?» | Слабая дискриминация |
  | «Можно ли сообщать свой пароль коллеге?» | Слишком лёгкий, верных больше 90 % |
  | «Какой принцип требует выдавать только необходимые права?» | Отвечают не читая: 30 % ответов за 0 с |
  | «Сотрудник получил письмо от „ИТ-поддержки“…» и ранжирование | Тормозит прогон: медиана вдвое выше медианы теста |
  | «Что означает аббревиатура MFA?» | Заезжено и трудно; быстро и неверно (вкладка «Вопросы», «Требуют ревизии») |
  | «Опишите своими словами…» | Развёрнутый ответ: не оценивается, наблюдений нет |

- **Разбор вопроса.** Откройте его через меню строки:
  - «Кто согласует выдачу прав администратора?». Таблица дистракторов показывает мёртвый
    вариант «Служба уборки» (его выбирают меньше 5 %). Вариант «Сам сотрудник» перевёрнут:
    его выбирают сильные участники.
  - «Какой из этих паролей надёжнее всего?». Блок «Версии содержания» показывает две
    редакции (шаг 5) и строку «версия неизвестна».
- **«Сравнить срезы».** Используются сохранённые срезы из раздела «Аналитика → Срезы».

### Тест ИБ → «Вопросы», «Выдача»

- **«Вопросы».** Экспозиция, медиана времени и флаги ревизии: «Заезжено и трудно», «Быстро
  и неверно». Колонка «Что отвечали» показывает частоты:
  - у короткого ответа «вишинг» — частоты написаний;
  - у числового ответа (регламент, минуты) — гистограмму;
  - у развёрнутого ответа — объём текста.
- **«Выдача».**
  - Таблица вариантов: «Вариант А» и «Вариант Б», 248 и 221 прохождение.
  - Таблица версий: версия 1, версия 2 и «Версия не указана» (около 12 % строк первой волны).
  - Профиль экспозиции раздела «Основы ИБ».

### Раздел «Аналитика»

- **«Прохождения».** Реестр из 630 прохождений, фильтры по подразделению и должности.
- **«Срезы».** Доступны оси:
  - подразделение: пять отделов, ИТ заметно сильнее, бухгалтерия слабее;
  - должность;
  - период: 12 месяцев;
  - попытка: 1, 2, 3+;
  - группа: волны 1 и 2;
  - версия, вариант, источник.

  У каждого среза видна «Слабейшая тема».

### Опросник → «Качество вопросов» и «Шкалы»

Тест целиком измерительный: вместо трудности показывается разброс ответов.

| Шкала | Что показывает |
| --- | --- |
| Проактивность | Альфа около 0,86, «Хорошо». Обратный пункт «ждать указаний» перевёрнут правильно. Пункт «соблюдаю сроки» — мёртвый: около 93 % одинаковых ответов |
| Командность | Альфа около 0,37, «Ниже приемлемого». Пункт «работать в одиночку» работает против шкалы, прогноз после разворота — альфа 0,88 |
| Ориентация на результат | Шкала на одном пункте, альфа не считается |
| Баланс ценностей | Ипсативная: сумма распределения у всех равна 10. Полос толкования нет |

На вкладке «Шкалы» видны средние по шкалам и доли по полосам толкования. Там же показано
состояние «полосы толкования не заданы».

## Что этими файлами показать нельзя

В интерфейсе есть экраны, которые импортированная выгрузка не заполняет. Причина в продукте,
а не в данных:

- **Процент и вердикт.** У импортированной попытки нет процента и вердикта: импорт не
  заполняет `result_percent` и `max_points`. Колонки «Статус» и «Баллы» из файла в расчёт не
  попадают. Из-за этого пустуют:
  - плитки «Сдали» и «Средний результат»;
  - распределение результатов и динамика сдаваемости;
  - «Прошли тему» (0 %);
  - доля сдавших и средний балл в срезах, вариантах и версиях.

  Кроме того, вкладка называет оцениваемый тест измерительным.
- **Длительность.** В выгрузке нет времени начала и конца, поэтому «Время, медиана»
  показывает 0:00.
- **Только веб-попытки.** Пропуски вопросов, адаптивные уровни, очередь «Требует внимания»
  (просрочено, не сдал, исчерпал, бросил) и ось «внешний участник» строятся только по
  веб-попыткам, назначениям и связанным учётным записям.
- **Организация.** При обезличивании по умолчанию организация не сохраняется, поэтому ось
  «Организация» пуста.

## Как пересобрать

Генераторы лежат в `scripts/dev/demo-analytics/`:

1. `build-tests.ts` собирает оба теста на работающем стенде через REST API и выгружает пакеты.
2. `generate-lms-exports.ts` строит выгрузки по пакетам без базы и сервера. Флаг `--today`
   сдвигает календарь.

Генератор детерминирован: повторный запуск на тех же пакетах даёт те же числа.

```bash
npx tsx scripts/dev/demo-analytics/build-tests.ts --base http://localhost:5000 \
  --email admin@test.com --password admin123 --out docs/demo/analytics
npx tsx scripts/dev/demo-analytics/generate-lms-exports.ts --dir docs/demo/analytics --today 2026-09-30
```

Пакеты и выгрузки пересобираются только вместе: у нового пакета другие идентификаторы
вопросов.
