## 1. Обзор

### 1.1 Контекст

В референсном Storyline-проекте есть не только линейное прохождение разделов, но и сценарий,
где обучающийся возвращается на общую страницу выбора после прохождения каждого раздела.
Эта страница показывает доступные разделы, факт прохождения и результаты по разделам. После
завершения всех обязательных разделов становится доступен переход к итоговому результату.

В распакованном референсе видны признаки такого сценария:

- переменная `Blocks_Done` для подсчёта завершённых блоков;
- переменные времени и вопросов по блокам: `Time_Min_1..6`, `Question_Number_1..6`,
  `Answered_1..6`;
- отдельные quiz/result slides по разделам: `Company_v1..v3`, `Finances_v1..v3`,
  `Pravo_v1..v3`, `Tech_v1..v3`, `Comp*_v*`;
- агрегирующий quiz/result `Result`, который собирает результаты отдельных блоков.

Этот сценарий отличается от `section_linear`: следующий раздел не открывается автоматически.
Он также отличается от `section_graph`: автору не нужен произвольный граф правил, достаточно
понятного router-паттерна.

### 1.2 Цель

Добавить режим `section_router`, в котором:

1. Core показывает router-страницу со списком разделов;
2. обучающийся выбирает доступный раздел;
3. после завершения раздела Core рассчитывает результат раздела;
4. обучающийся возвращается на router-страницу;
5. router-страница показывает статусы и результаты разделов;
6. переход к итоговому результату доступен только после выполнения политики завершения.

### 1.3 Не цель

В рамках PRD-8 не требуется:

- реализовывать произвольный graph-editor переходов;
- добавлять кастомный JavaScript автора;
- менять механику расчёта правильности вопросов;
- реализовывать независимые попытки разделов сверх уже согласованных `retakePolicy`;
- переносить экспорт SCORM в Drawer редактора.

## 2. Пользовательский сценарий

```text
SCO loaded
  -> start page / content before test
  -> router page
  -> learner selects section
  -> section intro/content
  -> section questions
  -> section result calculated
  -> optional section summary
  -> router page with updated status/result
  -> repeat until completion policy is satisfied
  -> final result
```

На router-странице обучающийся видит:

- название раздела;
- статус раздела: не начат, в процессе, завершён, пройден, не пройден, заблокирован;
- результат по завершённому разделу, если это разрешено настройками;
- действие открытия доступного раздела;
- действие перехода к итоговому результату, когда оно разблокировано.

## 3. Модель

### 3.1 `flowPolicy`

Целевой runtime-режим:

```json
{
  "mode": "section_router",
  "router": {
    "title": "Выберите раздел",
    "instructions": "Пройдите все обязательные разделы, затем перейдите к итоговому результату.",
    "completionPolicy": "all_required_completed",
    "sectionOrder": "fixed",
    "showSectionResult": true,
    "allowReturnToCompleted": "summary_only",
    "finalResultButton": "enabled_after_completion",
    "sectionUnlockRules": {
      "section-2": {
        "mode": "after_sections_completed",
        "sectionIds": ["section-1"]
      }
    }
  }
}
```

### 3.2 Значения `completionPolicy`

| Значение | Смысл |
| --- | --- |
| `all_required_completed` | Итоговый результат доступен после завершения всех обязательных разделов |
| `all_required_passed` | Итоговый результат доступен только если все обязательные разделы пройдены |

MVP-рекомендация: начать с `all_required_completed`, потому что она покрывает референсный
паттерн без споров о пересдаче отдельных разделов.

### 3.2.1 Условия разблокировки разделов

Условия разблокировки являются логикой router-flow и настраиваются в разделе "Настройки" вместе со
сценарием прохождения. Во вкладке "Структура" они отображаются как read-only индикаторы на
карточках разделов.

MVP scope:

| Значение | Смысл |
| --- | --- |
| `always_available` | Раздел доступен сразу |
| `after_sections_completed` | Раздел доступен после завершения выбранных prerequisite-разделов |
| `after_sections_passed` | Раздел доступен после успешного прохождения выбранных prerequisite-разделов |

Для MVP используется только логика `AND`: все выбранные prerequisite-разделы должны выполнить
условие. Произвольные boolean-выражения и условия по процентам относятся к будущему
`section_graph`.

### 3.3 Повторный вход в завершённый раздел

| Значение | Смысл |
| --- | --- |
| `disabled` | Завершённый раздел нельзя открыть повторно |
| `summary_only` | Можно открыть только страницу результата/summary раздела |
| `retake_if_allowed` | Повторное прохождение доступно только если это разрешено политиками попыток |

MVP-рекомендация: `summary_only`.

### 3.4 Состояние runtime

```json
{
  "flow": {
    "mode": "section_router",
    "currentPage": "router",
    "router": {
      "completedRequired": 2,
      "totalRequired": 4,
      "finalResultUnlocked": false
    },
    "sections": {
      "section-1": {
        "state": "completed",
        "result": {
          "correct": 7,
          "totalQuestions": 10,
          "percent": 70,
          "passed": true
        }
      }
    }
  }
}
```

Состояние хранится в `suspend_data` и восстанавливается при повторном открытии SCO.

## 4. Требования

### 4.1 Авторский UI

| ID | Требование |
| --- | --- |
| FR-01 | В настройках теста доступен сценарий прохождения "Через страницу-маршрутизатор" (`flowMode = router_by_topics`) |
| FR-02 | Вкладка "Структура" для router-режима показывает router-страницу, список разделов и страницы до/после каждого раздела |
| FR-03 | Автор задаёт текст заголовка и инструкции router-страницы как content-настройку router-блока |
| FR-04 | Автор выбирает политику завершения: `all_required_completed` или `all_required_passed` в "Настройках", а не во вкладке "Структура" |
| FR-05 | Автор видит, какие разделы обязательные (`test_sections.required`), и может управлять их порядком |
| FR-05a | Автор может задать условия разблокировки раздела в MVP-объёме: сразу доступен, после завершения выбранных разделов, после прохождения выбранных разделов |
| FR-06 | Wireframes router-состояния вкладки "Структура" должны быть согласованы до frontend-реализации |
| FR-06a | Вкладка "Структура" визуализирует router-режим как сценарную карту `Router -> Раздел -> Возврат на Router -> Итог`, а не как обычный линейный список страниц |
| FR-06b | Router-страница является центральным блоком визуализации; разделы отображаются как карточки/переходы из router-страницы |
| FR-06c | Итоговый результат отображается отдельным конечным блоком и находится в disabled/locked-состоянии до выполнения `completionPolicy` |

### 4.1.1 Wireframe вкладки "Структура"

Целевая схема для `flowMode = router_by_topics`:

```text
[Перед тестом]
   ↓
[Страница-маршрутизатор]
   ├─ Раздел 1 -> возврат на маршрутизатор
   ├─ Раздел 2 -> возврат на маршрутизатор
   └─ Раздел N -> возврат на маршрутизатор
   ↓
[Итоговый результат]
```

Router-блок показывает заголовок, инструкцию, настройку отображения результатов разделов и
состояние перехода к итоговому результату. Completion policy и условия разблокировки показываются
как read-only индикаторы, потому что это логика сценария, а не контентная структура.

Карточка раздела показывает название, обязательность, количество вопросов, проходной порог,
страницы перед разделом, блок вопросов, страницы после раздела/результат раздела и preview
состояния на router-странице.

Поддерживаемые preview-состояния карточки раздела:

- `Не начат`;
- `В процессе`;
- `Завершён`;
- `Пройден`;
- `Не пройден`;
- `Заблокирован`.

### 4.2 Runtime

| ID | Требование |
| --- | --- |
| FR-07 | Core строит router-страницу как системную страницу flow, а не как вопрос или обычную content page |
| FR-08 | Router-страница получает от Core список разделов, их статусы, результаты и доступные действия |
| FR-09 | При выборе раздела Core переводит обучающегося в начало выбранного раздела |
| FR-10 | После завершения раздела Core рассчитывает `sectionResult` и возвращает обучающегося на router-страницу |
| FR-11 | Router-страница обновляет статусы и результаты без потери уже завершённых разделов |
| FR-12 | Переход к итоговому результату заблокирован, пока не выполнена `completionPolicy` |
| FR-13 | При восстановлении сессии Core открывает последнюю активную страницу: router или текущий раздел |
| FR-14 | Завершение SCO и запись стандартного SCORM score выполняются только на итоговом результате, а не после отдельного раздела |

### 4.3 Шаблоны

| ID | Требование |
| --- | --- |
| FR-15 | Шаблон может объявить layout/system page для router-страницы |
| FR-16 | Если шаблон не содержит router-layout, Core использует встроенный fallback-layout |
| FR-17 | Шаблон получает read-only контекст router-страницы и не рассчитывает статусы разделов самостоятельно |

### 4.4 Диагностика

| ID | Требование |
| --- | --- |
| FR-18 | Core пишет события `router:shown`, `router:sectionSelected`, `router:finalResultUnlocked`, `router:finalResultOpened` |
| FR-19 | Ошибка расчёта результата раздела не должна открывать итоговый результат; router показывает диагностируемую ошибку |

## 6. Экспорт SCORM

Экспорт должен добавить в пакет:

- `flowPolicy.mode = section_router`;
- конфигурацию `flowPolicy.router`;
- условия разблокировки разделов `flowPolicy.router.sectionUnlockRules`;
- данные разделов и их порядок;
- router-layout или fallback-layout;
- runtime-код восстановления router-состояния из `suspend_data`.

Старые тесты без `flowPolicy` продолжают экспортироваться как плоский режим.

## 7. Acceptance Criteria

- [ ] Автор может выбрать `router_by_topics` в сценарии прохождения.
- [ ] Вкладка "Структура" показывает router-страницу и разделы как переходы.
- [ ] Router-режим во вкладке "Структура" показан как сценарная карта, а не как линейный список страниц.
- [ ] Итоговый результат в preview заблокирован до выполнения `completionPolicy`.
- [ ] SCORM runtime открывает router-страницу до выбора раздела.
- [ ] Обучающийся может перейти в доступный раздел с router-страницы.
- [ ] Разделы на router-странице блокируются/разблокируются по `sectionUnlockRules` в MVP-объёме.
- [ ] После завершения раздела обучающийся возвращается на router-страницу.
- [ ] Router-страница показывает завершённые разделы и их результаты.
- [ ] Итоговый результат заблокирован до выполнения `completionPolicy`.
- [ ] После выполнения `completionPolicy` итоговый результат доступен.
- [ ] Состояние router-flow восстанавливается после перезагрузки SCO.
- [ ] Стандартный SCORM score записывается на итоговом результате.
- [ ] Wireframes router-режима согласованы до frontend-реализации.

## 8. Открытые вопросы

| Вопрос | Рекомендация |
| --- | --- |
| Разрешать ли повторное прохождение завершённого раздела? | Для MVP открыть только summary, повторное прохождение вынести в связку с `retakePolicy` |
| Должен ли раздел быть обязательным по умолчанию? | Да, все выбранные темы обязательные по умолчанию; автор может снять обязательность, если политика завершения и итогового решения это допускают |
| Показывать ли процент по разделу на router-странице? | Да, если `showSectionResult = true`; иначе показывать только статус |
| Нужно ли поддерживать произвольные условия доступности разделов? | Не в MVP; поддерживаем только `always_available`, `after_sections_completed`, `after_sections_passed` с AND-логикой по выбранным prerequisite-разделам. Более сложные условия относятся к `section_graph` |
