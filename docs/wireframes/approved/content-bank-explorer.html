Конструктор вариантов по типамТип задаёт конструктор: ОДИНОЧНЫЙ — radio (ровно один правильный); МНОЖЕСТВЕННЫЙ — чекбоксы (≥1 правильный); СООТВЕТСТВИЕ — пары левое↔правое; РАНЖИРОВАНИЕ — список с ручкой переноса и эталонным порядком. У одиночного/множественного/соответствия порядок задаётся вручную перетаскиванием (ручка слева) + переключатель «Случайный порядок вариантов». У Ранжирования ручки тоже есть, но порядок = эталон ответа, а перемешивание при выдаче обязательно — тоггла нет. Состояния s-q-multiple / s-q-matching / s-q-ranking показывают только конструктор (остальные поля — как в основном Drawer вопроса)edge case: разные типы вариантов
Валидация перед сохранениемРаньше валидировались только тема+текст — можно было сохранить вопрос без правильного ответа. Теперь гарды: тема выбрана; текст непустой; ≥2 непустых варианта; задан правильный ответ (single — выбран; multiple — отмечен ≥1; matching — все пары заполнены; ranking — ≥2 элемента). Ошибки показываются БАННЕРОМ вверху формы (ou-banner--error), «Сохранить» заблокирована (см. s-q-multiple: нет отмеченного правильного → баннер «Отметьте хотя бы один правильный вариант»)edge case: «не задан корректный вариант ответа»
Смена типа вопросаСмена типа в seg СОХРАНЯЕТ введённые варианты: тексты переносятся между типами без подтверждения (для Соответствия — в левую колонку), пересобирается только структура ответа (один правильный / несколько / пары / порядок). Состояние каждого типа в форме сохраняется — возврат восстанавливает спецификурешение 2026-06-16: без потери данных
Порядок вариантов и перемешиваниеДля ВСЕХ типов, кроме Ранжирования (одиночный/множественный/соответствие): автор задаёт базовый порядок вручную — перетаскиванием за ручку слева; переключатель «Случайный порядок вариантов» (рядом с вариантами, по умолчанию вкл) рандомизирует показ ученику, выключен — показ в заданном порядке (для «Все/Ничего из перечисленного» и т. п.). Ранжирование — исключение: заданный порядок и есть эталон ответа, перемешивание при выдаче обязательно и без тогглауточнение: ручной порядок + «Случайный порядок» для всех типов, кроме ранжирования

Групповые операции — два режима выделенияВыделение работает в двух взаимоисключающих режимах: «Папки и темы» (чекбоксы на строках папок и тем — s-select-ft) и «Вопросы» (чекбоксы на вопросах — s-select). Отметка узла одного режима снимает выделение другого. Каждый режим показывает свой тулбар с применимыми действиямиР-1; ответ «выделение вопроса снимает выделение папок/тем»
Единица операции — тема; папка захватывает свои темыВ режиме «Папки и темы» операции действуют на ТЕМЫ. Выбранная папка = все её темы (транзитивно, включая вложенные папки). Итог = напрямую выбранные темы + темы выбранных папок; счётчик показывает «выбрано … → N тем». Темы, попавшие через папку, помечены (disabled-чекбокс)Р-4; ответ «права на темы в папках при выделении папок»
Групповой доступ (s-bulk-access)Одна модалка, сегмент «Операция»: Выдать доступ (пользователь + уровень Использование/Управление) · Отозвать (пользователь + мягкий/жёсткий отзыв) · Видимость (Приватная/Общая) · Владелец (админ). Полоса охвата показывает, к скольким темам применится (в т.ч. из папок). У ПАПОК собственного доступа нет — правило всегда действует на темы. Жёсткий отзыв проверяет зависимые опубликованные тесты (partial-skip)Р-4; зеркало prd15-topic-access, но пакетно
Перенос группы (s-move-ft)«Переместить…» из тулбара «Папки и темы» открывает выбор папки-получателя (вкл. «в корень»). Папки переносятся как КОНТЕЙНЕР (reparent, со вложенными темами), отдельные темы меняют папку. Защита от цикла: папку нельзя перенести внутрь себя/потомка. Перенос организационный — на выдачу не влияет, content-guard не нуженР-3/Р-6; асимметрия «перенос=контейнер, доступ=темы»
Удаление папки — два режима (s-folder-delete)«Удалить папку…» (⋯-меню папки — s-folder-menu, или групповое удаление с папками в наборе) открывает выбор: «Перенести содержимое в другую папку» (пикер получателя, вкл. корень — папка удаляется, содержимое переезжает, выдача не затронута) ИЛИ «Удалить папку со всем содержимым» (каскад тем→вопросов→секций→страниц, подтверждение точным именем папки). Прежнее молчаливое «свалить в корень» заменено явным выбором. Зеркало s-folder-delete-a/b у папок тестов (prd7-tests-list), но с content-guardР-5; ГО-7
Защита при удалении (s-content-impact, content-guard)Удаление темы (одиночное и групповое) и каскад папки проходят сводную проверку выполнимости (dry-run): темы, используемые в опубликованных тестах, показываются в блоке «Пропущено» с указанием теста/причины; незаблокированные — в блоке «Будет удалено». По умолчанию выполняем для незаблокированных (partial-batch), заблокированные пропускаем. Свитч «Администратор: удалить всё равно» = force (сломает перечисленные тесты). Путь выдачи/оценки права на тему не проверяет — инвариант PRD-15Р-2/Р-7; ответ «сводный диалог, выполнить для незаблокированных»
Одиночное удаление темы — тоже через content-guardРаньше в дереве одиночное «Удалить тему» шло прямым запросом и на конфликт показывало лишь тост. Теперь одиночное и групповое удаление тем идут через один и тот же сводный диалог влияния (s-content-impact)Р-7; ГО-6, закрытие пробела в content-tree
Права папок и наследование — НЕ здесьИдея «дать папкам собственные права и наследовать их темам» вынесена в ОТДЕЛЬНЫЙ трек (BRD/PRD/эскизы): это реверс решения PRD-15 «папки косметичны» и несёт риск утечки ключей при переносе. В этом эскизе групповой доступ = перебор грантов ТЕМ, без наследованиярешение 2026-07-01; вне охвата
Ветвление удаления (дерево решений)«Удалить» из тулбара «Папки и темы» разветвляется: (1) если в наборе есть ПАПКА — сперва двухрежимный диалог папки (s-folder-delete: перенести содержимое / каскад), единый путь с ⋯-удалением папки; (2) затем сводная проверка (dry-run): есть конфликты → s-content-impact (partial-batch), конфликтов нет → простой конфирм s-delete-confirm, всё заблокировано → s-impact-blocked (удалять нечего, кнопка выключена, только admin-force). Одиночное «Удалить тему» из ⋯-меню темы идёт по той же ветке (s-delete-confirm / s-content-impact при count=1)Р-2/Р-5/Р-7; закрытие пробелов 2/3/4/5
Жёсткий отзыв — экран зависимостей (s-revoke-impact)Мягкий отзыв применяется сразу. Жёсткий (админ) сначала показывает сводку: «Отозвано» (у пользователя нет тестов на теме) vs «Пропущено — опубликованные тесты пользователя» (там доступ сохраняется, иначе тесты сломаются). Варианты полного отзыва: заменить секции теста / снять с публикации / сменить владельца темы / зафиксировать снапшот. Свитч «Администратор: отозвать всё равно» = force. Симметрично удалению (partial-skip)Р-4; закрытие пробела 1; dependentTestsForGrant
Смешанные права и upsert в набореКнопки тулбара гейтятся правами: если для действия нет прав ни на одну тему — кнопка скрыта. В наборе могут быть темы, которыми пользователь не управляет (админ видит всё): такие строки для действия недоступны и в сводке помечаются как пропущенные. Групповая выдача доступа — это upsert: если у пользователя уже есть грант на теме, уровень перезаписываетсяР-8; закрытие пробела 6
