Acceptance — FR-35, FR-36, FR-43 покрытие

Код Описание
FR-43 Вкладка "Настройки" имеет двухуровневую навигацию: side nav (var(--wf-size-180)) на >=var(--wf-size-960). Пять секций: Основное, Правила прохождения, Ограничения, Интеграция, Адаптивный режим. «Режим и сценарий» сведено в «Основное»; «Обратная связь» — отдельный feedback-block внутри «Основное» и в карточках уровней Адаптивного режима, не отдельный пункт.
FR-43 / §3.1 Основное: Название (обязательное), Описание. Статус (tests.status) показан только тегом в шапке drawer-а (Черновик / Опубликован / В архиве) — отдельного Select-а в форме нет. Смена статуса выполняется через действия на карточке теста, не в редакторе.
FR-43 / §3.2–3.3 Режим и сценарий: segmented control для tests.mode (Стандартный / Адаптивный) и select flowMode с тремя значениями (Линейный / Линейный по темам / Через страницу-маршрутизатор) перенесены в подраздел «Основное». sectionUnlockRules per-topic настраиваются во вкладке Структура. completionPolicy удалён — gate к итоговому результату вычисляется из passDecisionPolicy + sections[].required (см. project_post_mvp_backlog).
FR-43 / §3.4 Правила прохождения: overall pass rule, passDecisionPolicy с четырьмя вариантами и policy-note, таблица тем с topicPassRule.source (inherit_overall / custom / none) и inline-expanded custom rule fields. Toggle «Обязательная» живёт во вкладке «Состав» (строка темы) — здесь не дублируется.
FR-43 / §3.5 Ограничения: лимит времени теста, switch «Индивидуальные лимиты для тем» (topicTimeLimit.perTopic: bool), таблица индивидуальных лимитов (видима только при switch ON), двойной таймер-preview, max_attempts. show_correct_answers живёт в feedback-block внутри «Основное» (это про выдачу обучающемуся, не про ограничение).
FR-35 / §3.6 Обратная связь — это композитный tb-feedback-block (textarea + ссылки + файлы), не отдельный пункт side-nav. На уровне теста: блок «Общая обратная связь теста» (tests.feedback, test_feedback_links, feedback_assets scope=test) + toggle show_correct_answers внутри карточки «Основное». На уровне темы: «Обратная связь при провале темы» + «Обратная связь для уровня» × N + «Обратная связь при провале всех уровней» — все живут внутри «Адаптивный режим».
FR-35 / §3.7 Интеграция: Webhook URL (tests.webhook_url) и toggle telemetry_enabled, независимые друг от друга.
FR-36 / §3.8 Адаптивный режим: подраздел side-nav доступен только при tests.mode = adaptive. Сам факт показа пункта в навигации заменяет read-only chip режима (отдельный indicator не нужен). Содержит: switch show_difficulty_level, гистограмму распределения сложности темы (.ou-histogram), аккордеон тем (adaptive.topics[].enabled + switch «Включено/Выключено», status-dot, subtitle), раскрытую панель уровней с полями levelIndex, levelName, minDifficulty, maxDifficulty, questionsCount, passThreshold + Тип (Процент/Сумма баллов), feedback-block для уровня (tb-feedback-block: текст + ссылки + файлы PDF) и блок «Обратная связь при провале всех уровней». См. также FR-36 / §3.8.1 — автокоррекция границ уровней.
FR-36 / §3.8.1 Адаптивный режим — автокоррекция границ уровней. При любых изменениях состава уровней (adaptive.topics[].levels[]) система автоматически приводит интервалы [minDifficulty, maxDifficulty] к непересекающемуся виду без gap-ов в диапазоне 0..100:
  • Удаление уровня — освободившийся диапазон забирают соседние: левый расширяет maxDifficulty до прежнего maxDifficulty удалённого, правый расширяет minDifficulty до прежнего minDifficulty удалённого. Если удалён внутренний уровень (есть и левый, и правый сосед) — освободившийся диапазон делится поровну между ними. Удаление крайнего уровня (только один сосед) — единственный сосед растягивается на полный отдаваемый диапазон.
  • Добавление уровня — новый уровень получает диапазон, отрезаемый у соседей. По умолчанию отрезается середина совокупного диапазона двух соседних уровней (если добавлен между ними); крайний — отрезается от единственного соседа. Новый minDifficulty / maxDifficulty подставляются автоматически, автор может их скорректировать.
  • Корректировка границ существующего уровня — при изменении minDifficulty у уровня N смежная граница maxDifficulty уровня N−1 устанавливается так, чтобы стыковка сохранилась (значение N−1.max = N.min). Аналогично для maxDifficulty и уровня N+1. Если корректировка делает чей-то диапазон отрицательным (min > max) — сохранение блокируется с inline error.
Инвариант: для любого difficulty ∈ [0..100] существует ровно один уровень темы. Сортировка панели уровней следует из minDifficulty по возрастанию (см. ниже в notes).

NFR-20 Форма не использует role="dialog" — settings tab является частью уже открытого drawer.

Пояснения — Wireframe

Элемент Поле API / условие Примечание
Состояния wireframe showState(btn, stateId) Метанавигация переключает только визуальные состояния и не является частью продуктового UI.
Статус теста (s-basic*) tests.status В редакторе текущий статус показывается только тегом в шапке drawer-а (Черновик / Опубликован / В архиве) — отдельного Select-а в форме нет. Смена статуса (Опубликовать / В архив / Восстановить) выполняется через действия на карточке теста на странице списка.
Уведомление «Настройки сохранены» (s-basic-saved) ou-toast--success в ou-toast-stack Это toast, а не sticky-banner: подтверждение завершённой операции — эфемерное, появляется bottom-right и автоматически скрывается по таймауту (~4 с) или через крестик. Page-level баннеры наверху формы остаются за устойчивыми состояниями (валидация, влияние на назначенных, конфликт режима).
Опубликован + назначен (s-basic-readonly) tests.status = published и есть назначения Редактирование не блокируется. В шапке drawer-а показывается тег «Назначен N польз.», а в области настроек — warning-баннер о том, что изменения применятся к новым попыткам; результаты уже завершённых попыток не меняются.
Тема в стандартном режиме (s-adaptive-topic-disabled) tests.adaptive.byTopic[topicId].enabled = false Когда автор выключает адаптивность для отдельной темы, в её карточке состояние читается из switch «Выключено», subtitle «N вопросов · в стандартном режиме», серого status-dot и disabled-стиля блока «Уровни сложности». Сохранённые уровни остаются в черновике и применяются при повторном включении адаптивности. Отдельного UI-баннера про это не показываем.
Скрытие общего правила (s-pass-required-only) passDecisionPolicy = "all_required_topics_passed" При политике «пройдены все обязательные темы» / «пройдена каждая выбранная тема» поля «Тип общего правила» и «Порог» скрываются — результат теста определяется только по темам. Сохранённые значения остаются в черновике и восстанавливаются при возврате к политике с общим правилом. Отдельного UI-баннера про скрытие не показываем — отсутствие блока достаточно.
Авто-выбор политики (s-pass-autopolicy) passDecisionPolicy при выборе индивидуального правила в теме Если автор задал в теме «Индивидуальное правило», общая политика теста автоматически переключается на «достигнут общий проходной порог и пройдены все обязательные темы». Отдельного UI-баннера про это не показываем — выбор уже отражён в radio выше; пояснение остаётся в этой таблице.
Блок «Лимит времени темы» (s-limits / s-limits-no-topics) tests.flow_mode Раздел полностью скрыт при flow_mode = linear_flat (тест без тем). Отдельного UI-баннера «доступно только в режиме с темами» в редакторе не показываем — отсутствие блока достаточно для автора, режим переключается во вкладке «Состав».
Подраздел «Адаптивный режим» (s-basic-adaptive-on) tests.mode = adaptive При переключении режима на «Адаптивный» в side nav редактора появляется новый пункт «Адаптивный режим» с подсветкой (tb-rail-item--new) — отдельный UI-баннер про это не показываем, разъяснение остаётся в этой таблице.
Режим теста (s-mode) tests.mode Переключение режима сохраняется в черновик немедленно. Несовместимые настройки противоположного режима сохраняются в БД скрытыми и восстанавливаются при возврате к совместимому режиму — пользовательский ввод не теряется.
Сценарий прохождения (s-mode) tests.flow_mode UI: три значения — «Линейный», «Линейный по темам», «Через страницу-маршрутизатор». Backend-маппинг: «Линейный» → linear_flat при отсутствии тем или mixed, если темы заведены (вопросы всех тем перемешиваются в один блок, темы остаются только для feedback). «Линейный по темам» → linear_by_topics. «Через страницу-маршрутизатор» → router_by_topics. Блок «Настройки маршрутизатора» виден только для router_by_topics.
Правило разблокировки тем (router-flow) tests.section_unlock_rules В Настройках не редактируется. Default-значение always_available (все темы открыты сразу на router-странице, обучающийся проходит в любом порядке) — константа MVP. Индивидуальные правила для конкретных тем задаются во вкладке Структура на карточке темы: значения after_sections_completed (доступна после завершения выбранных prerequisite-тем) и after_sections_passed (только если prerequisite пройдены по pass-rule). Логика AND — все prerequisite должны выполнить условие. Терминология: в editor UX везде «тема» (одна сущность для автора). В backend это пара topics ↔ sections (через topicId), в runtime PRD-8 для router-режима использует «раздел» — но это другой контекст.
Индивидуальные лимиты для тем (s-limits) topicTimeLimit.perTopic (bool) Switch ON — у каждой темы свой жёсткий тайм-аут, в runtime действуют оба таймера (общий + тема). OFF — действует только общий «Лимит времени теста» (если задан). Предпросмотр с двойным таймером показывается только при ON.
PDF-документы (s-feedback) feedback_assets, scope=test Загруженные PDF упаковываются в SCORM-пакет и доступны обучающемуся для скачивания после прохождения теста.
Webhook (s-integration) tests.webhook_url POST-запрос с результатом попытки отправляется после её завершения.
Telemetry (s-integration) tests.telemetry_enabled Расширенные данные о взаимодействии отправляются независимо от наличия Webhook URL — включение/выключение не требует задания адреса webhook.
Адаптивный режим (s-adaptive) tests.mode = adaptive Раздел доступен только в адаптивном режиме теста. JSON / advanced settings будет специфицирован в следующей итерации.
Порядок и границы уровней сложности (s-adaptive) adaptive.topics[].levels[] Список уровней сортируется автоматически по minDifficulty по возрастанию. Ручное перетаскивание/перенумерация не предусмотрены — порядок следует из значений диапазонов, не из user input. Интервалы [minDifficulty, maxDifficulty] поддерживаются непересекающимися и без gap-ов автоматически: добавление / удаление / правка границ перераспределяет диапазоны между соседями (см. FR-36 / §3.8.1 в acceptance). Изменение порядка достигается изменением границ.
