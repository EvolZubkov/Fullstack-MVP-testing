Варианты страниц шаблона «Стандартный»

Шаблон содержит набор вариантов страниц. С точки зрения системы все варианты устроены одинаково: имя, schema полей и render. Поведение страницы (автопереход, навигация, показ результата и т. п.) определяется разработчиком шаблона внутри render'а варианта — никакого enum'а типов в системе нет. Имя варианта — это контракт: при смене шаблона страницы автоматически маппятся по совпадению имени; вариант, имени которого нет в новом шаблоне, переходит в fallback или подлежит ручной замене.

Schema может быть пустой — это валидный кейс, когда содержание страницы полностью определено разработчиком шаблона и не зависит от автора курса (фиксированный контент: поздравление, дисклеймер, шаблонное вступление и т. п.). У таких страниц в списке нет chevron'а разворачивания — редактировать в них нечего.

Поиск фильтрует имена и описания вариантов; при большом наборе вариантов это быстрее, чем прокрутка карточек.
Селектор замены варианта страницы (s-mapping) ou-select
BEM: __trigger, __value, __chev, __menu, __opt (+ .is-selected, .is-open)		 Меню скрыто атрибутом hidden, открывается JS-обработчиком toggleWfSelect. Позиционирование меню — через position: fixed с координатами от getBoundingClientRect(), чтобы выйти за overflow drawer-контейнера. В production DS-Select управляет позицией собственным popper-движком — wireframe-обёртка лишь имитирует поведение.
Иконочные действия в строке страницы (редактирование / удаление / предпросмотр) ou-iconbtn + variant --ghost + размер --s Для удаления — inline style="color:var(--ou-error-default)" (destructive-окраска иконки без замены variant'а на destructive, чтобы не получить заливку).
Кнопки в footer drawer ou-btn + variant (--ghost/--secondary/--primary) + единый размер --m Прямые дочерние ou-drawer__foot, без обёрток __foot-meta/__foot-actions (их нет в DS). FR-аннотации (FR-25a — «Сохранить», FR-25c — «Показать изменения») включаются кнопкой «Аннотации» в state-switcher.
Карточки тем / зоны «До теста» и «После теста» wireframe-локальные классы .topic-block, .zone-block с тонкой тенью --ou-shadow-xs и border --ou-border-soft Аналога в DS на момент эскиза нет. Раскрытие меню DS-Select внутри карточки требует временного overflow: visible на родителе — реализовано CSS-правилом .topic-block:has(.ou-select.is-open) { overflow: visible }.
