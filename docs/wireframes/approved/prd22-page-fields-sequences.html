DS Mapping

Строка с «custom» в колонке DS-компонент является блокером: такой элемент либо заменяется компонентом дизайн-системы, либо дизайн-система расширяется до старта разработки.

Элемент wireframe DS-компонент Используемые токены Примечания
Форма страницы (список полей) Существующая реализация — Раскладка не меняется: .page-row-expand и список .ou-formfield, как в PageEditForm.
Поля содержимого и свойств Input, Textarea, NumberInput, Switch, Select --ou-space-* Контрол выбирается по типу поля из перечня (FR-09, FR-10); соответствие «тип — компонент» полное.
Поле «Идентификатор последовательности» Combobox --ou-space-*, --ou-border-* Значения теста — опции; «Создать идентификатор» — footerAction; число подряд идущих страниц — hint.
Предпросмотр в поле image (.image-field) Новый продуктовый класс --ou-radius-s, --ou-border-soft, --ou-bg-surface-3 Единственное изменение раскладки формы: миниатюра 144×96 вместо чипа с именем файла. Кандидат на перенос в ui-kit как вариант FileUploader; до этого — рядом с остальными классами формы в client/src/styles/tb-components.css.
Переключатель режимов ввода SegmentedControl (размер s) --ou-space-*, --ou-bg-elevated Состав пунктов зависит от типа поля: `html` — три режима, `richText` — два, `text`/`textarea` — переключателя нет вовсе.
Панель форматирования IconButton (ghost, размер s) в ряд --ou-space-*, --ou-border-soft Набор фиксирован: полужирный, курсив, зачёркнутый, списки, ссылка, очистка. Видна только в режиме форматированного текста; кнопка активного начертания подсвечена (is-active).
Область форматированного текста (.text-field__rich) Требуется в ui-kit: RichTextEditor --ou-space-*, --ou-accent-container Редактируемая область, показывающая результат, а не разметку: абзацы, списки, начертания, ссылки. В ui-kit компонента нет — разрабатывается до старта Э5 (риск в PRD-22). В эскизе показана габаритами DS-поля (ou-textarea__box), чтобы поля формы не разъезжались.
Диагностика поля и невалидного шаблона Banner, Tag --ou-warning-*, --ou-error-* Тон warning для невалидного шаблона, error для незаполненной обязательной настройки.
Метанавигация состояний Wireframe utility --ou-space-*, --ou-border-* Не мигрируется в продуктовый UI.
Границы эскиза

Дизайн формы не меняется: это тот же список полей в раскрытой строке, что и сегодня. Вкладка «Структура» — список, зоны, порядок, перетаскивание, модалы — как в prd7-structure-linear-by-topics.html. Новое только два: поля свойств варианта в том же списке и предпросмотр изображения.

Аннотации — поведение, не выраженное статикой
Элемент Текст / содержание Поведение и условие видимости
Состав полей формы Поля содержимого, затем поля свойств Порядок — как объявил вариант: сначала placeholders[], затем settings[]. Вариант без настроек («Информация: текст») даёт форму, неотличимую от сегодняшней (FR-04).
Поле «Идентификатор последовательности» Подсказка о числе подряд идущих страниц Показывается только у варианта, объявившего свойство sequence (FR-15). В списке — значения страниц теста, чей текущий вариант объявляет это свойство (FR-16). Пустое значение допустимо: страница вне последовательности. Число в подсказке пересчитывается по текущему положению страниц; при одной странице точки не строятся (FR-19).
Подпись кнопки «Пусто — кнопка подписана „Далее“» Значение по умолчанию из объявления настройки подставляется при создании страницы; очищенное поле возвращает поведение по умолчанию (FR-26). Для ОБЯЗАТЕЛЬНОЙ настройки очистка даёт ошибку и не обходит обязательность (FR-08).
Поле изображения Миниатюра, имя файла, «Заменить» / «Удалить» Предпросмотр показывается для любого поля типа image — и в содержимом, и в свойствах. Пустое поле показывает пустую рамку и кнопку загрузки.
Переключатель режимов ввода «Простой текст» / «Форматированный» / «HTML» Состав определяется ТИПОМ поля как потолком (FR-32): `html` — все три режима, `richText` — первые два, `text` / `textarea` — переключателя нет. Автор может понизить уровень, но не повысить. Выбранный режим запоминается вместе со значением.
Панель форматирования Полужирный, курсив, зачёркнутый, списки, ссылка, очистка Видна только в режиме форматированного текста; набор одинаков во всех полях и шаблонах (FR-33). Вставка из внешнего источника нормализуется на месте — запрещённая разметка вычищается сразу, поэтому ошибка сохранения в этом режиме невозможна (FR-34).
Редактирование форматированного текста Текст с начертаниями, списками и ссылкой Автор работает с РЕЗУЛЬТАТОМ, а не с разметкой: область показывает то, что увидит ученик. Кнопка панели подсвечивается по начертанию под курсором или в выделении (в состоянии s-rich выделен полужирный фрагмент и подсвечена кнопка «Полужирный»). Переключение в «Простой текст» снимает форматирование, переключение в «HTML» (если тип поля это допускает) показывает ту же разметку кодом.
Ошибка в режиме HTML «Страница не сохранена. Уберите: …» Появляется по нажатию «Сохранить», перечисляет найденные запрещённые конструкции с количеством. Значение НЕ изменяется и НЕ сохраняется — автор правит исходный код сам (FR-34). Перечень запрещённого равен санитизации и не расширяется (FR-35).
Ссылки на ресурсы шаблона images/diagram.png Относительный путь означает файл ШАБЛОНА; базовый путь подставляет ядро на каждом хосте (FR-36). Медиа автора — абсолютные `/uploads/media/…`, внешние `http(s)` удаляются санитизацией.
Баннер невалидного шаблона «Шаблон оформления не соответствует контракту полей» Показывается для УЖЕ установленного шаблона, не прошедшего валидацию после обновления системы (FR-13). Новый шаблон с такой ошибкой не принимается при загрузке и не активируется (FR-12), поэтому в редакторе теста это состояние — только унаследованное.
Индикатор навигации на экране ученика Точки последовательности В редакторе не отображается вовсе: рисовать точки или нет, решает макет варианта (FR-23). Форма сообщает только число подряд идущих страниц с тем же идентификатором.
