Состояния drawer — условия и поведение

СтейтУсловие показаFooterКлючевое поведение
s-default Тест открыт, нет pending-изменений Закрыть + Сохранить (disabled) Тег статуса («Опубликован» / «Черновик») в header. Кнопка «Закрыть» не требует подтверждения.
s-dirty Пользователь изменил хотя бы одно поле, изменения ещё не сохранены Показать изменения | Отменить | Сохранить Тег «Изменено» (warning). Status-dot на затронутых вкладках. Закрытие через крестик вызывает confirmation dialog (→ prd7-editor-close-confirm.html).
s-error Форма содержит ошибки валидации после попытки сохранения или при вводе Показать изменения | Отменить | Сохранить (disabled) Тег «Есть ошибки» (error, outline). DS Banner с описанием и ссылкой «Перейти к ошибкам». Status-dot error на вкладках с невалидными полями. Сохранить заблокирован.
s-saving API-запрос сохранения в процессе Сохранение… (spinner, disabled) Overlay поверх drawer-body (opacity 0.88, inert на контенте). Пользователь не может взаимодействовать с формой. Header и footer остаются видимы.
s-changes Dirty + пользователь нажал «Показать изменения» Показать изменения (active) | Отменить | Сохранить Popover с группировкой изменений по вкладкам (Состав, Настройки и др.). Закрывается крестиком внутри или повторным кликом на «Показать изменения».
s-settings Пользователь переключился на вкладку «Настройки» Показать изменения | Отменить | Сохранить Side-nav с подразделами при viewport ≥960px. Полный wireframe настроек — в отдельном файле prd7-editor-settings-tab.html.
s-mobile Viewport <960px [Тег вкладки] + Изменения + Сохранить (column layout) Drawer 100vw. Табы с навигацией < / >. Длинные названия тем: 2-строчный clamp, тап разворачивает. Side-nav настроек заменяется аккордеоном.

Взаимодействия и граничные случаи

СценарийПоведениеСсылка
Закрытие drawer при dirty-состоянии Открывается confirmation dialog с выбором: «Сохранить и закрыть» / «Закрыть без сохранения» / «Отмена» prd7-editor-close-confirm.html
Конфликт версий при сохранении Сервер возвращает 409; drawer переходит в состояние конфликта с merge-выбором prd7-editor-conflict.html
Отменить изменения Кнопка «Отменить» сбрасывает форму до последнего сохранённого состояния без диалога (необратимо) —
Версионирование (v7) Бейдж версии рядом с крестиком — информационный, не кликабельный на этом wireframe. Версия инкрементируется при каждом успешном сохранении. —
Ошибка сети при сохранении Overlay скрывается; DS Banner «Не удалось сохранить — попробуйте снова». Сохранить снова активна. —
Добавление новой темы Кнопка «+ Добавить тему» доступна в s-default, s-dirty, s-error, s-changes. Добавление переводит drawer в s-dirty. —
Длинное название темы (мобильный) 2-строчный CSS clamp. Тап по имени снимает clamp — строка разворачивается до полного текста. Повторный тап сворачивает. s-mobile
Drawer на мобильном 100vw, высота 100dvh. Footer — column layout: тег текущей вкладки слева, «Изменения» и «Сохранить» растянуты на ширину. s-mobile

Пояснения — Wireframe

Элемент Поле API / условие Примечание
Состояния wireframe showState(btn, stateId) Метанавигация переключает только визуальные состояния и не является частью продуктового UI.
Тег статуса в header test.status «Опубликован» (success) / «Черновик» (neutral) / «Изменено» (warning) / «Есть ошибки» (error, outline). Все варианты — ou-tag--outline.
Status-dot на вкладках наличие dirty / error полей во вкладке Жёлтая точка — dirty, красная — error. Рендерится внутри ou-tabs__tab через span.status-dot. Парный aria-label на кнопке вкладки обязателен (NFR-21).
Кнопка «Показать изменения» isDirty === true Видна только при наличии несохранённых изменений. Открывает popover с группировкой по вкладкам. Текст кнопки не меняется при открытом popover.
Popover изменений список pending-изменений из draft-модели Группировка по вкладкам (Состав, Настройки…). Каждое изменение: label + старое значение (зачёркнуто) → новое (зелёный). Popover не является частью продуктового flow — только информационный.
Overlay сохранения isSaving === true Абсолютный слой поверх ou-drawer__body: полупрозрачный фон (opacity 0.88) + spinner + «Сохранение…». Контент body заблокирован атрибутом inert.
Banner ошибок validationErrors.length > 0 DS Banner (error tone) в начале drawer-body. Содержит счётчик полей с ошибками и кнопку «Перейти к ошибкам» (scroll к первому невалидному полю).
Кнопка «Отменить» isDirty === true Сбрасывает форму к последнему сохранённому состоянию без confirmation dialog. Действие необратимо — реализовать через window.confirm на продуктовом уровне или добавить confirmation sheet.
Бейдж версии (v7) test.version Только информационный. Инкрементируется при каждом успешном сохранении. На данном wireframe не кликабелен.
Названия тем — truncation (mobile) viewportWidth < 960 2-строчный CSS clamp (-webkit-line-clamp: 2). Тап по имени темы снимает clamp — строка разворачивается. Тег и счётчик вопросов всегда остаются справа (flex layout).
Mobile footer viewportWidth < 960 Column layout: тег текущей вкладки (нейтральный) / «Изменения» / «Сохранить» растянуты на всю ширину. «Показать изменения» отсутствует (заменён тегом вкладки).
Mobile tabs-nav < / > viewportWidth < 960 Стрелки prev/next по бокам от tab list. Левая стрелка disabled на первой вкладке, правая — на последней. Сами вкладки с overflow: hidden — скролл запрещён.
