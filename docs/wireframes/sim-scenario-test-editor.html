Пояснения — Wireframe

ЭлементПоле API / условиеПримечание
Режим «Сценарий»tests.mode = scenarioТретий сегмент «Режима теста». Тест содержит один пункт-сценарий. План: docs/specs/sim-scenario/plan-tests.md, Э2
Предупреждение при переключениикак FR-25d режима «Адаптивный»Встроенное, без подтверждения: данные не удаляются, темы и их настройки сохраняются и вернутся при возврате к стандартному режиму
Вкладка «Задание»заменяет «Состав и сценарий»Тем, выдачи, вариантов и сценария прохождения у теста «Сценарий» нет. Остальные вкладки — правила прохождения, оценка, итоги, оформление, комментарии — работают как у любого теста
Банк сценариевtest_scenarios.topic_idТема, в которой есть вопросы типа «Сценарий»; темы без сценариев в списке нет. Пул пункта — сценарии темы, прочие её вопросы пункт не видит
Выдача: случайный сценарий темыtest_scenarios.question_id = null; shared/draw/exposure.ts, PRD-55На старте попытки из пула выбирается один сценарий взвешенной выборкой по экспозиции и фиксируется в попытке. Новая попытка — новый выбор. В SCORM-пакет запекается весь пул с весами
Выдача: фиксированный сценарийtest_scenarios.question_id — сценарий этой темыВсе участники получают его. Поправки на экспозицию нет — состав задал автор (как у вариантов PRD-17, PRD-55 FR-20); выдача всё равно учитывается. В SCORM-пакет запекается только он
Ожидаемая экспозицияPRD-55 FR-33; при выдаче 1 из n — 100/n %Только у случайной выдачи. Тот же баннер, что у темы; выше 70% (банк из одного сценария) — предупреждение
Сводкаслучайный — число сценариев, диапазон сцен, вес изображений пула; фиксированный — сцены, ловушки, проверки цели, весВес важен для SCORM-пакета
«Открыть банк»«Банк контента» с фильтром по теме и типу «Сценарий»Там каждый сценарий можно сыграть; у фиксированного — ещё и «Сыграть» здесь
Страницы тестаcontent_pagesДо теста — стартовая страница и свои страницы; затем задание на весь экран; после — свои страницы и итоги теста
Сценарий в составе роутераtest_scenarios, ключ пункта scenario:<id>Стоит в одном списке с темами и нумеруется вместе с ними; свойства пункта: название в меню участника (test_scenarios.title, по умолчанию — название темы), банк, выдача, обязательность. Выдачи, вариантов, порядка вопросов и квот у сценария нет. Правила разблокировки задаются так же, как для тем (в редакторе их интерфейса пока нет)
«Добавить сценарий»в группе тем, рядом с «Добавить тему в группу»Доступно в тесте со сценарием прохождения «Через страницу-маршрутизатор». Одну тему можно добавить несколькими пунктами — например, разными фиксированными сценариями
Пиктограмма сценарияlucide monitor-playОтличает сценарий от темы в общем списке
«Открывается»flowPolicyJson.router.sectionUnlockRules[<ключ пункта>].mode: always / after_sections_completed / after_sections_passedТехдолг №8 трека. Поле в свойствах КАЖДОГО пункта роутера — темы и сценария одинаково — сразу под «Обязательная/Обязательный». Значения: «Сразу» (по умолчанию, правила нет), «После завершения пунктов», «После успешного прохождения пунктов». Правило соблюдают оба хоста общим isSectionUnlocked; хаб показывает закрытый пункт «Недоступен/Недоступна»
«Каких пунктов»sectionUnlockRules[…].sectionIds — ключи пунктов (<topicId> / scenario:<id>)Появляется, когда выбрано условие. Combobox с множественным выбором: остальные пункты состава с их номерами и названиями, в порядке состава; сам пункт в списке не предлагается. Пусто при выбранном условии — ошибка поля «Выберите хотя бы один пункт»
«Успешное прохождение» сценарияsectionResults[…].passedУ пункта-сценария нет порога раздела: как условие «успешного прохождения» он засчитывается, когда завершён — так считает общий код и сейчас
Подзаголовок свёрнутой карточкииз правилаХвост «· откроется после 1, 2» — номера пунктов по составу; правила нет — хвоста нет. Видно условие всех пунктов разом, не разворачивая каждый
Пункты ждут друг другапроверка редактораЦикл в правилах (2 ждёт 3, 3 ждёт 2 — или длиннее) значит, что ни один из этих пунктов не откроется. Ошибка поля у каждого пункта цикла, сохранение заблокировано, как у прочих ошибок ящика. Удалённый из состава пункт удаляется и из чужих условий
Режим потокаrouter_by_topicsПоле есть только у теста «Через маршрутизатор»: в линейных потоках пункты идут по порядку и правил разблокировки нет. При переключении режима правила хранятся, как и прочие параметры маршрутизатора

Пояснения — оценка сценариев (Э5а)

Узел эскизаДанныеПоведение
Штрафы сценариев по умолчаниюновое поле теста; пусто — системное умолчание DEFAULT_SIM_PENALTIES (shared/sim/scoring.ts)Видно, только когда в тесте есть сценарий (тест «Сценарий» или пункт-сценарий роутера). Шесть штрафов — шесть счётчиков прогона: промахи, недоступные действия, неверные значения, шаги в сторону, ловушки, подсказки
Единица штрафадоля цены вопроса, хранится долей (0,05), показывается процентами (5 %)Штраф за каждый случай; сумма вычитается из доли цели. Балл не уходит ниже нуля
Засчитывать частичное выполнениефлаг теста и переопределение вопросаВключено (по умолчанию): исход «частично» даёт долю цели по весам пройденных проверок. Выключено: «частично» — ноль, как провал
Цепочкасистема → тест → вопрос в тесте (test_question_scoring)Каждый штраф переопределяется сам по себе: пустое поле берёт значение уровнем выше, оно показано в поле серым
Карточка пункта-сценарияпул пункта: сценарии темы-банка или один фиксированныйСтоит в общем списке, как раздел темы; «выдаётся 1 из n». Цена ответа — «Штрафы»; «задано в тесте» — у вопроса есть свои штрафы
Окно «Оценка вопроса в тесте»то же окно, что у прочих вопросов (решение владельца 2026-10-06)Вместо выбора способа оценки — таблица штрафов и переключатель частичного выполнения: градуированные способы (PRD-10) к сценарию не применяются
Пересчётпрогон хранится с исходом и счётчикамиНовые штрафы действуют на новые попытки; сохранённые попытки не пересчитываются — как при смене цены вопроса
