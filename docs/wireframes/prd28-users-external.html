Пояснения — «Пользователи»

ДельтаТребованиеПримечание
Отметка «Внешний»FR-07, §8Тег рядом с адресом, тон info. Отдельной колонки нет: признак есть у меньшинства записей, пустая колонка съела бы ширину. Внешние показаны в общем списке наравне со штатными
Фильтр по видуFR-07, §8Четвёртый селектор в существующем ряду фильтров: «Все виды / Штатные / Внешние участники». Порядок и поведение остальных фильтров не меняются
«Сделать штатным»FR-05, FR-06, §3Пункт есть ТОЛЬКО у внешней записи. Обратного пункта нет ни у кого: обратный перевод — это блокировка под видом смены вида, для неё есть «Заблокировать»
«Сбросить пароль» у внешнегоFR-02, §4Погашен: пароля нет. Пункт оставлен видимым, чтобы меню внешней и штатной записи не разъезжались по составу
«Отправить приглашение» в менюFR-04Не показан: в существующем коде он есть только у записи со статусом «Ожидает», а для внешней записи приглашение отклоняется сервером. У внешних этот пункт не появляется вовсе
Признак в форме созданияFR-08, §8Чек-бокс «Внешний участник». При включённом признаке погашены пароль, «Сгенерировать», «Требовать смену пароля» и «Отправить приглашение» — задавать нечего
Роли в формеFR-01При включённом признаке роль зафиксирована: «Обычный пользователь», выбор погашен. Это следствие FR-01, а не отдельное решение
Ярлык роли—Спека называет роль «Ученик», интерфейс — «Обычный пользователь» (ROLE_LABELS.learner). В эскизах взят ярлык интерфейса; расхождение терминов стоит закрыть в спеке
Статус новой записи§4Обычный «Ожидает». Активной запись становится по факту первого прохождения по ссылке — отдельного статуса не заводится
