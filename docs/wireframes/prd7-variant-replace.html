У выбранного варианта пустая schema — после смены страница станет шаблонной (без редактируемых полей). Контент задаётся целиком в шаблоне.

Аннотации состояний

Модал смены варианта на существующей page-row. Триггер — … row-menu → «Сменить вариант». Применим ко всем kind (info / intro / summary / router / questions). Контракт совместимости параметров описан в PRD-1 §4.3.3.

StateНазначениеFR / решение
s-replace-modal Основное: список вариантов того же kind из текущего шаблона. Текущий вариант помечен меткой «Текущий» и disabled. Под списком — diff-block с двумя группами: «Будут удалены» (warning-фон) и «Будут сохранены» (success-фон). При выборе другого варианта diff пересчитывается по правилу «имя поля = контракт между вариантами одного kind». PRD-1 §4.3.3
s-replace-empty-diff Спокойный случай: schema нового варианта содержит все те же поля, что и текущий (имена и совместимые типы). Показывается только группа «Все параметры будут сохранены» (без warning-блока). Используется, когда варианты структурно симметричны (например, «Минимальный» и «Расширенный» комплекты вопросов с одинаковыми флагами). PRD-1 §4.3.3
s-replace-no-fields У нового варианта пустая schema (нет редактируемых полей). Показывается diff-блок «Будут удалены» (все параметры текущего варианта) + info-note «У выбранного варианта пустая schema — страница станет шаблонной». В page-row после смены не отрисовывается chevron (нечего редактировать). PRD-1 §4.3.3
