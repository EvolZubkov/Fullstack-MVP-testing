Пояснения — раздел «Импорт» как единая точка (Э6)

ЭлементПоведение / APIПримечание
Единая точкаРаздел принимает книгу с вопросами, выгрузку отчёта LMS, пакет теста, список пользователей, шаблон оформления. Вид определяется по файлу; после распознавания на той же странице встаёт форма этого видаРешение владельца 2026-10-02. Пакет, пользователи и шаблоны загружаются и на своих местах; участники назначения — только в окне «Назначить»
Определение вида.xlsx и .csv — POST /api/workbook/inspect (kind: workbook / lmsExport / users); .tbtest и .zip — по расширениюРазбор надо научить узнавать список пользователей в .xlsx по колонкам шаблона (email, name, role…)
ПраваРаздел виден при любом праве импорта. Вид без права не перечисляется и не принимается: книга — questions.importExport; выгрузка LMS — analytics.import + область теста; пакет — tests.create; пользователи — users.create; шаблон — adminTemplates.manageРазбор файла открывается любым правом импорта — сегодня он закрыт questions.importExport, отсюда D4
«Что можно загрузить»Строка на вид — только те, на которые у читателя есть право; шаблон файла и руководство — там, где они естьПод менеджером две строки
Менеджер и пользователиСтрока с ролью выше участника помечается ошибкой «роль «Автор» вам назначать нельзя» уже в предпросмотре, в счёт «Ошибок» и не в число импортируемыхСервер и сегодня отклоняет такую строку (потолок ролей PRD-13), но только после записи
Роль в предпросмотреНазванием роли, а не кодом: «Участник», «Автор»Сейчас окно «Массовая загрузка пользователей» печатает код роли (learner, author) — исправляется вместе с переносом формы
Отказ по правуФайл распознан, права на вид нет: строка файла и отказ «Недостаточно прав для выполнения операции» — без пояснений и без перечня доступногоРешение владельца 2026-10-02: отказ не объясняет. Без «Импортировать» — делать нечего
Загрузки выгрузок LMSЧасть шага выгрузки LMS, а не раздела: после распознавания файла — загрузки его теста; при входе из меню теста — загрузки этого теста сразу, без файла. «В расчётах» и откат — PATCH и DELETE /api/analytics/lms-import/batches/:id, список — GET .../batches/:testIdРешение владельца 2026-10-02: на общей странице раздела списку не место — он не относится к другим видам файлов. В аналитике теста списка больше нет
Вход из меню тестаПункт «Загрузить выгрузку LMS» в меню «Действия» строки теста → /author/import?testId=…. Раздел встаёт сразу на выгрузку LMS этого теста: подзаголовок — название теста, ниже — его загрузки, без файла. Тест задаёт ФАЙЛ: выгрузка другого теста грузится в свой тест, подзаголовок и загрузки переключаются на него — это не ошибкаОкно в аналитике теста отвергало чужой файл (fixedTestId, ответ 422): там на экране была аналитика конкретного теста. Здесь её нет, и тест из меню — только начальный вид. Обычный вид раздела — пунктом «Импорт» бокового меню
АналитикаКнопка «Загрузить выгрузку LMS» и окно LmsImportDialog уходят с обеих страниц аналитикиОтдельного состояния нет: удаление на эскизе не рисуется. Шапка аналитики теста остаётся с «Экспорт Excel», «Прохождения теста», «Обновить»
Формы видовНе изобретаются: книга — согласованный эскиз prd14; выгрузка LMS — prd54; пользователи — окно «Массовая загрузка пользователей»; пакет — окно «Импорт теста»; шаблон — окно «Загрузка шаблона». Формы выносятся в общие компоненты и встают и в своё окно, и на страницуВ эскизе каждый вид показан одним характерным состоянием; прочие состояния — в согласованных эскизах и в коде окон
