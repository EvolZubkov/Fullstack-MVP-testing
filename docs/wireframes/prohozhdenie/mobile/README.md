# Мобильные эскизы прохождения теста

Эскизы мобильной адаптации шаблона «Стандартный». Рамка телефона — 360x800,
контрольный планшет — 768x1024. Разметка повторяет реальные layout'ы шаблона
(`server/scorm/templates/default/layouts/`), стили — инлайн на токенах DS, как в
соседних десктопных эскизах этого же потока.

## Состав

| Файл | Что показывает |
| --- | --- |
| `Старт.mobile.html` | Обложка: заголовок 28px, факты в две колонки, изображение под текстом, подвал в два ряда |
| `Прохождение теста.mobile.html` | Вопрос без медиа: шапка без карты, варианты 56px, подвал в два ряда |
| `Прохождение теста - с медиа.mobile.html` | Тот же экран с медиа: сетка «медиа 5 / ответы 7» развёрнута в одну колонку |
| `Прохождение теста - ранжирование.mobile.html` | Ранжирование на тач: грип как ручка перетаскивания плюс стрелки 44px |
| `Страница контента.mobile.html` | Контент с картинкой: изображение сверху (3:2), текст снизу |

## Почему это понадобилось

Замер живого SCORM-пакета на ширине 360 (до правок):

- Подвал экрана вопроса требует 383px при доступных 312. Кнопка «Отправить
  ответ» уходит за правый край экрана (`right: 419` при ширине сцены 360) —
  основное действие частично недоступно.
- Сетка «картинка + текст» на странице контента остаётся двухколоночной:
  колонки 120px и 168px.
- Шапка экрана вопроса занимает 210px из 740 (28% экрана).
- Кегль вопроса остаётся 32px, варианта — 22px независимо от ширины.
- Точка карты вопросов — 26px при рекомендованном тач-минимуме 44px.

## Согласованные решения

1. **Карта вопросов на телефоне скрыта целиком.** В шапке остаются только
   счётчики «отвечено / пропущено». Переход к пропущенному вопросу идёт через
   экран обзора, где карта сохраняется и увеличена до тач-размера (точка 44px,
   легенда на месте). Шапка экрана вопроса сокращается с 210px до 107px (178px
   при двух идущих таймерах), поле вопроса растёт с 465px до 501-572px.

2. **Перетаскивание в ранжировании идёт с ручки-грипа.** `touch-action: none`
   ставится только на `.ou-rank__grip` — узкую полосу слева во всю высоту
   строки. Жест с грипа перетаскивает, жест с тела строки прокручивает список.
   Стрелки вверх/вниз 44px остаются основным путём. Вариант с
   `touch-action: none` на всей строке отвергнут: он отнимает у пальца
   прокрутку тела вопроса.

3. **Подвал в два ряда.** Вторичные кнопки (ghost/secondary) делят верхний ряд с
   уменьшенным кеглем 13px; основная кнопка занимает нижний ряд во всю ширину.
   Порядок задаётся свойством `order`, чтобы основная кнопка всегда была
   последней независимо от порядка в разметке (менять разметку нельзя —
   `tests/template-layout-parity.test.ts` требует побайтового совпадения с
   шаблоном `certification`).

4. **768 остаётся двухколоночным.** Порог развала сеток — 700px, а не 768:
   на планшете композиция «медиа слева, ответы справа» осмысленна (медиа около
   291px, текст около 385px). Подвал на 768 остаётся одной строкой.

## Найденный при отрисовке конфликт с DS

DS на `@media (max-width: 480px)` схлопывает строку ранжирования в три колонки и
скрывает грип (`vendor/ui-kit/css/university-rt.css:5653-5659`). Возврат грипа на
тач-устройстве обязан вернуть и четырёхколоночную сетку — иначе блок стрелок
переносится на вторую строку и высота строки вырастает вдвое. Учтено в эскизе и
подлежит переносу в `theme.css`.
