Поведение экрана

МестоКогдаЧто происходит
Счётчик остатка всегда над группой «Осталось: N из 7», при нулевом остатке — «Вы использовали все баллы». Формулировки взяты из референса. Область aria-live: изменение остатка озвучивает экранный диктор.
Доступный максимум строки после каждого изменения Равен min(максимум на вариант, значение строки + остаток). Ползунок и поле публикуют именно его, поэтому перебор невозможен ПО ПОСТРОЕНИЮ — и для мыши, и для клавиатуры, и для вставки. Состояния «перебор» не существует, сообщения об ошибке для него нет.
Недоступный хвост дорожки когда потолок строки ниже бюджета Шкала ползунка ФИКСИРОВАНА бюджетом: длина дорожки всегда означает одно и то же. Иначе значение строки визуально прыгало бы при изменении СОСЕДНЕЙ строки, хотя сама строка не менялась. Подвижен только стоп — он равен «значение + остаток», и он показан глушёной зоной с чертой. Без неё учащийся упирается в невидимую стену и не понимает, почему ползунок дальше не идёт.
Готовность ответа сумма равна бюджету Только тогда вопрос считается отвеченным. Нетронутый и частично распределённый вопрос — пропущенный: «Далее» заблокирована, счётчик пропущенных и возврат к незавершённым работают штатно.
Ненулевой минимум на вариант автор задал минимум больше нуля Поля стартуют со значения минимума, счётчик показывает остаток после него. Опуститься ниже минимума ввод не даёт. Предзаполнение, а не запрет: иначе учащийся распределит весь бюджет и застрянет с нулевым утверждением.
Узкий экран ступени сцены 900 / 700 / 520 Своих порогов тип НЕ вводит — берёт действующие ступени шаблона (@container tbscene в theme.css). На S1 (сцена 900px и уже) колонка вопроса переходит с 75% на всю ширину — это уже существующее правило .tb-scene__col, не решение этого эскиза. На S2 (700px) ползунок уезжает ПОД текст утверждения: это та же ступень, на которой у шкалы PRD-26 дорожка встаёт вертикально; без перехода подпись рвётся на пять строк рядом с полупустой дорожкой. На S3 (520px) карта вопросов в шапке скрывается, как и для остальных типов.
Обзор и повторный просмотр после отправки Те же строки только для чтения, БЕЗ разметки верности: правильного распределения не существует. Числовое поле заменяется значением.
Размер подписей утверждений всегда Тот же механизм, что у вариантов остальных типов: переменная --tb-answer-fs, которую ставят два общих прохода — длиновой (optionFont по самому длинному утверждению, до рендера) и рантаймовый по высоте (fitQuestionScene, чтобы список влез в поле без прокрутки). Своего размера тип не задаёт: литерал в разметке отнял бы у второго прохода единственный рычаг. На узком поле диапазон сужается ступенью S3 шаблона, как и для остальных типов.
Клавиатура всегда Числовое поле — обычный ввод. Ползунок — стрелки и Home/End. У каждой пары aria-label из текста утверждения: без него диктор читает четыре одинаковых «Значение».
Порядок утверждений по признаку вопроса Подчиняется общей настройке «Следование вариантов ответов» (умолчание — случайный порядок). Ротация утверждений, которую референс ведёт вручную ключом на листе механики, обеспечивается этим общим механизмом.

Вопросы к согласованию

МестоНеоднозначностьРешение в эскизе
Пара «ползунок и поле» Нужны ли оба элемента, или хватило бы одного. Оба, как принято в спеке: ползунок даёт быстрое распределение и показывает доли, поле — точное значение и клавиатурный ввод. Они синхронны. Альтернатива (только степпер) требует много нажатий при бюджете 7 и не показывает пропорцию.
Подсветка строки с баллом Отмечать ли строку, которой учащийся дал вес. Отмечена мягко — акцентная рамка (is-weighted) на строках ВЫШЕ минимума. Это НЕ «правильно», а «сюда положен вес»; цвета вердикта у типа нет вовсе. Правило именно «выше минимума», а не «не ноль»: при ненулевом минимуме поля предзаполнены, и правило «не ноль» подсветило бы все строки сразу — подсветка сказала бы «вы это выбрали» там, где выбор сделала система (видно в состоянии «С минимумом»).
Формулировка счётчика Что писать над группой. «Осталось: N из 7» и «Вы использовали все баллы» — взяты из референса дословно. Альтернативы: «Распределено N из 7», «Нераспределённых баллов: N».
Подсказка типа Строка под текстом вопроса. «Распределите 7 баллов между вариантами» — число подставляется из бюджета вопроса.
Недоступный хвост Показывать ли, докуда ползунок дойти не может. Показываем глушёной зоной с чертой стопа. Альтернатива — не показывать: тогда перебор по-прежнему невозможен, но причина остановки ползунка остаётся необъяснённой. Элемента с таким смыслом в дизайн-системе нет, он добавляется вместе с составным компонентом.
Порог узкого экрана На какой ступени ползунок уходит под текст. На S2 (сцена 700px) — существующая ступень шаблона, та же, что у шкалы PRD-26. Новых порогов тип не вводит. Значение подтверждается на браузерной приёмке вместе с остальными типами.
Карточка редактора Эскиз карточки автора в этот файл не вошёл. Три поля («Бюджет», «Минимум на вариант», «Максимум на вариант») ставятся в существующую карточку вопроса рядом со списком вариантов; блок правильного ответа для типа скрыт. Отдельного эскиза не потребовалось: это форма из существующих полей без новой раскладки. Если нужен отдельный эскиз — добавляется до фазы 4.
