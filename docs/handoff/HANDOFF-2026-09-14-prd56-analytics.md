серверных правок обязателен перезапуск — `tsx` работает без `--watch`.

```bash

  node scripts/check/acceptance-shot.mjs /author/analytics out.png ".ou-grid"
```

## 6. Принятые решения

Согласованы с владельцем:

- **Порог наблюдений — 10** (FR-06d). Обоснование: доверительный интервал доли при n = 5
  около ±44 п.п., при 10 — ±31, при 20 — ±22; ниже десяти число ничего не утверждает.
- **Исключение вопроса из выдачи — СОСТОЯНИЕ, а не разовая команда**, и живёт в
  `test_question_scoring`: негодное здесь задание может быть годно в другом тесте.
- **Тегом состояние выдачи не метится** — тег читается как ярлык содержания; метка —
  перечёркнутый круг с подсказкой.
- **Колонки «вердикт» у темы нет** и третьего состояния («на грани») в модели не будет: порог
  судит одну попытку, у среднего исхода нет.
- **Траекторию адаптивного прохождения перенести в окно реестра ДО снятия вкладки «Попытки»**
  (решение от 2026-09-14) — иначе функция исчезла бы молча.
- **Версия публикации должна проноситься в LMS** (FR-19a) — иначе разрез по версиям слеп к
  прохождениям из пакета.

Решения исполнителя, которые преемнику не стоит переигрывать молча:

- Доля пропусков считается ТОЛЬКО по веб-прохождениям: состав выданной формы пакет по попытке
  не сообщает, а склейка из двух разных окон (экспозиция помесячная, ответы за всё время) дала
  бы число, которое нельзя объяснить. Об ограничении сказано в подзаголовке таблицы заданий.
- Проверка «можно ли исключить» и само действие считаются ОДНИМ вызовом `assessTestPublish`
  с параметром `alsoExcludedQuestionIds`. Вариант «записать признак, спросить, откатить»
  отвергнут: между записью и откатом чужая попытка стартует с неутверждённым пулом.
- Порог в баллах (`{type: "count"}`) в процентной шкале не рисуется вовсе: сколько это
  процентов, зависит от достижимых баллов прохождения, а они у разных вариантов разные.

## 7. Грабли

- **`npx drizzle-kit export --sql` пишет первой строкой `DATABASE_URL: …`.** Попав в
  `tests/it/schema.sql`, она роняет ВСЕ интеграционные тесты синтаксической ошибкой — выглядит
  как поломка харнесса. Первую строку надо удалять, файл должен начинаться с `CREATE TABLE`.
- **Миграцию, написанную руками, `drizzle-kit migrate` не применяет.** Он идёт по
  `drizzle/meta/_journal.json`, который заполняет только `drizzle-kit generate`; команда при
  этом рапортует об успехе, а колонки в базе нет. Создавать миграции только генератором.
- **Старт попытки возвращает ПЕРЕНЕСЁННЫЙ вариант незавершённой попытки.** Проверяя выдачу
  вживую, сначала удалите открытые попытки этого участника по тесту, иначе «задание не выдано»
  ничего не значит — состав просто не пересобирался.
- **Дев-сервер не подхватывает серверные правки** (`tsx` без `--watch`): после каждой правки
  сервера — перезапуск, иначе ручка отвечает старым кодом, а ошибка выглядит как дефект
  клиента.
- **Дев-база общая для всех рабочих копий.** Данные, заведённые для приёмки (срезы, попытки,
  изменённые пороги), надо убирать за собой; в этой сессии убрано, `excluded_from_delivery`
  нигде не стоит.
- **Git Bash превращает путь-аргумент со слэша** (`/author/...`) в путь Windows: скрипты
  приёмки запускать с `MSYS_NO_PATHCONV=1`.
