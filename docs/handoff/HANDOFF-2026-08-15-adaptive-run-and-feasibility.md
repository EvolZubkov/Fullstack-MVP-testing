## 4. Как проверить

Стенд поднимается вторым инстансом, реквизиты учётных записей — в личной памяти сессии
(`reference_dev_acceptance_account`), в репозиторий они не пишутся.

```bash
PORT=8098 npm run dev
npx tsx scripts/dev/seed-adaptive-fixture.ts --base http://localhost:8098 \
  --email <учётка> --password "<пароль>"
```

Скрипт идемпотентен и печатает адрес теста. Ручные проверки:

1. **Завершение по времени.** Открыть адаптивный тест с общим лимитом, ответить на пару
   вопросов, дождаться нуля. Ожидание: экран итогов с разрезом по темам; в базе у попытки
   заполнены `finished_at` и `result_json`. До правки было «Результаты не найдены» и NULL
   в обеих колонках.
2. **Обратный отсчёт.** На экране вопроса адаптивного теста в шапке чип `ou-timer` с
   текстом «тест M:SS», значение убывает. Чип раздела показывается только если у раздела
   задан свой лимит.
3. **Предупреждение редактора.** Открыть тест с адаптивным уровнем, под диапазон сложности
   которого в теме нет вопросов, изменить что-нибудь и сохранить. Ожидание: диалог «Тест
   сохранён, но выдать вопросы по нему нельзя» с разбором по уровню.
4. **Отладочный прогон.** Тот же тест, «Выполнить отладку». Ожидание: лента над сценой
   «Выдать вопросы по этому составу нельзя — прогон встанет», сцена под ней рабочая.
5. **Публикация.** Тот же тест, попытка публикации. Ожидание: `409 publish_infeasible` с
   `adaptive_shortfall`. Это поведение существовало и до сессии.

## 6. Принятые решения

1. **Истечение времени в адаптиве — отдельный маршрут, а не переиспользование
   `expire-topic-adaptive`.** Тот двигает лестницу дальше, а по звонку прогон окончен:
   недостигнутые темы и уровни остаются несыгранными.
2. **При сбое запроса завершения попытка НЕ помечается завершённой** — остаётся
   возобновляемой. Это лучше страницы результата, которой нечего показать.
3. **Отладочный прогон при невыполнимой выдаче НЕ блокируется.** PRD-15 FR-05 назначает
   черновику предупреждение без блокировки; вдобавок в многотемном тесте сломан может быть
   один уровень, а отлаживать остальные автор вправе.
4. **Предупреждение редактора читается ЧАСТЬЮ сохранения (`await`), а не фоном.** Сохранение
   закрывает ящик редактора: фоновый запрос приезжает, когда показывать находки уже некому.
   Это выяснилось в браузере — первая версия с баннером внутри ящика молчала.
5. **Постановка задачи в реестре была неточной, и это важно для преемника.** Пункт
   формулировался как выбор «предупреждать или запрещать публикацию». Проверка показала,
   что публикация была защищена всегда (`assessTestPublish`, FR-06), а дыра была в другом:
   сервис выполнимости звался ТОЛЬКО из двух путей публикации. Продуктового решения не
   потребовалось — политику уже назначил PRD-15 FR-05.
6. **Явное «не проверять» у ключа чинится, хотя наблюдаемого дефекта нет.** Строка ключа без
   правила рисуется как «Не проверять», движок считает отсутствие структуры информационным —
   автор видел то, что выбрал. Но `default` движок уже понимает, а редактора у него нет; в
   день, когда редактор появится, «отсутствует» станет значить «наследует умолчание».
7. **Пустое тело запроса чинится ОДНИМ middleware, а не 39 правками в маршрутах.**
   Подставляется пустой объект: дальше маршрут сам решит, чего не хватает, и ответит своим
   кодом. Ложные, но ОПРЕДЕЛЁННЫЕ значения (`null`, пустая строка) не трогаются — это
   разобранное тело, а не его отсутствие, и подмена врала бы обработчику о том, что прислал
   клиент.
8. **Учётная запись разбора удалена только ПОСЛЕ передачи владения.** Фикстура целиком
   принадлежала ей (тест, тема, 12 вопросов, обе папки — их завёл скрипт под этой учёткой), а
   внешних ключей на `users` в схеме НЕТ: удаление прошло бы молча и оставило висячие ссылки.
   Владение и авторство переданы учётной записи приёмки одной транзакцией.
9. **Регресс на разрыв страницы отчёта не заводится.** В jsdom `getBoundingClientRect`
   отдаёт нули, и тест проверял бы собственную фикстуру, а не пагинацию. Пороговая часть уже
   закреплена модульными тестами на чистой функции `sliceBySafeLines`.

## 7. Грабли

1. **Серверные правки dev не подхватывает.** `tsx` работает без `--watch`. После правки
   сервера — перезапуск, иначе проверяется старый код.
2. **Остановка фоновой задачи не убивает процесс на порту.** Порт остаётся занятым, новый
   запуск падает с `EADDRINUSE`. Снимать по PID:
   `Get-NetTCPConnection -LocalPort 8098 -State Listen`.
3. **Ученический экран живёт в Shadow DOM.** `document.body.innerText` пуст. Снимок
   доступности Playwright пробивает тень надёжнее ручных обходов; обходить `querySelectorAll`
   по корню бесполезно, если содержимое лежит глубже.
4. **Листы предпросмотра отчёта масштабированы.** Прямоугольники внутри них живут в других
   единицах, чем живой корень отчёта. Смешение единиц дало ложный вывод «карточки разрезаны»;
   истину показали снимки границы листов.
5. **Ученик видит только НАЗНАЧЕННЫЕ тесты.** Публикации мало, нужно назначение. Скрипт
   засева назначает тест запустившей учётной записи.
6. **Гочи API при заведении адаптивного теста:** сценарий читается из `flowPolicyJson.mode`
   (`linear_by_topics`), а не из поля `flowMode`; адаптив в `linear_flat` запрещён
   валидатором; код темы — только строчные буквы; вариант ответа — простая строка плюс
   `correctJson.correctIndex`, а не объект с id.
7. **`DELETE /api/tests/:id` требует тело с `confirmTitle`.** Раньше без него был `500`,
   теперь `400` (`b4b6f0e4`), но подтверждение по-прежнему обязательно.
8. **Тест миграции падает, если погашен демон Docker** — dev-БД живёт в контейнере
   `test-builder-db`. Это среда, а не код.
9. **Внешних ключей на `users` в схеме НЕТ.** Удаление учётной записи не упадёт и ничего не
   каскадирует — оно просто оставит висячие `owner_id` и `created_by`. Перед удалением любой
   учётки, под которой что-то заводили, владение надо передать явно.
10. **Учётная запись приёмки — только `administrator`.** Роли `learner` у неё нет, поэтому
    ученический прогон под ней невозможен: роль добавляется отдельной строкой в `user_roles`
    (см. `reference_dev_acceptance_account`).
