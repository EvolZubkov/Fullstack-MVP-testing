## 1. Задача

Две связанные линии.

Первая — PRD-22 «Поля контентной страницы и последовательности страниц»
([docs/specs/prd-22/page-fields-and-sequences.md](../specs/prd-22/page-fields-and-sequences.md),
37 требований). Повод: вариант «Галерея» шаблона `certification` был недоступен в «Структуре».
Разбор показал три системных пробела, а не единичную ошибку: авторская страница жёстко
приравнена к одному виду варианта; свойства страницы (точки навигации, подпись кнопки, фон)
не объявлены ни в одном манифесте; количество точек вводилось автором вручную. Решение:
галерея — обычная информационная страница со своим макетом; состав полей задаёт ТОЛЬКО
манифест (`placeholders[]` — содержимое, новый `settings[]` — свойства); последовательности
вычисляются ядром из структуры теста. Все этапы PRD-22 (Э0-Э7) реализованы.

Вторая — план [docs/plans/PLAN_PRD22_PREVIEW_AND_VARIANTS.md](../plans/PLAN_PRD22_PREVIEW_AND_VARIANTS.md)
из 10 этапов, согласованный 2026-07-22 по итогам приёмки: четыре дефекта предпросмотра
шаблона плюс два требования заказчика (сетка из 6 раскладок контентной страницы в двух
семействах; понятные названия цветов). Выполнен только Э1.

Требования, изменённые заказчиком по ходу и зафиксированные в плане:

- фоллбек варианта не должен быть тихим: решение о замене принимает автор через
  сопоставление, вариант № 1 — лишь то, что показывается ДО сопоставления, и предвыбор в
  диалоге;
- тесты с проблемными страницами подсвечиваются в списке тестов жёлтым знаком.

## 4. Как проверить

Стенд поднимается локально:

```bash
npm run dev          # http://localhost:8081
npm run scorm:player # http://localhost:5050, играет пакеты из out/
```

Учётные записи стенда — в базе разработки (параметры подключения в `.env`); пароль
администратора при необходимости переустанавливается инструментом `npm run create-admin`.

Проверка правок Э1 вручную: «Шаблоны» -> у карточки «Стандартный» меню -> «Предпросмотр» ->
«Перепроверить». Ожидается «Проверка пройдена, 16 из 16 экранов», предупреждений нет. Для
«Сертификация (РТК)» — 15 из 15.

Проверка навигации галереи: «Тесты» -> «Сертификационный тест для руководителей» -> меню ->
«Тестовый прогон» -> «Начать тестирование» -> раздел «О компании» -> «Начать». На галерее
кнопка «Далее» листает три слайда, индикатор двигается, после третьего идут вопросы.

Сборка пакета для локального плеера:

```bash
node --import tsx scripts/generate-template-scorm.ts uploads/templates/<id>
```

## 6. Принятые решения

- Отдельного вида страницы «галерея» нет: это вариант информационной страницы со своим
  макетом. Первоначальная попытка завести отдельный вид была отвергнута заказчиком и
  полностью откачена (этап Э0 PRD-22).
- Вкладка «Структура» НЕ меняется — жёсткое требование заказчика. Всё новое умещается в уже
  реализованную форму страницы (FR-20).
- Свойства страницы объявляются в манифесте отдельным блоком `settings[]`, а не в
  `placeholders[]`: разведены по природе — содержимое против свойств.
- Последовательность — отрезок не короче двух подряд идущих страниц одного участка с
  одинаковым непустым `sequenceId`. Группировка смотрит на идентификатор, а НЕ на вариант:
  поэтому демо-набор из страниц разных вариантов образует одну последовательность.
- Ожидание слота `page-content` снято для макетов варианта: поля попадают на экран через
  `data-placeholder`. Взамен введена проверка, что объявленные поля имеют область в макете.
- Фоллбек не тихий: `templateKey` в базе не переписывается, вариант меняется только через
  модалку «Сменить вариант» (она уже показывает теряемые поля). Это согласовано 2026-07-22 и
  отменяет более раннее предложение молча деградировать к варианту № 1.
- Правило «макет vs fallback» (отчёт `docs/reports/AUDIT_TEMPLATE_LAYOUT_FALLBACK.md`)
  согласовано ещё 2026-07-17, этапы 1-5 по нему выполнены. Не считать его открытым вопросом.

## 7. Грабли

- Дев-сервер не перезапускается сам: `tsx` работает без `--watch` намеренно (vite 8 виснет
  под `tsx watch`). После правки серверного TypeScript нужен ручной перезапуск `npm run dev`,
  иначе проверяется старый код.
- Рантайм-JS пакета (`server/scorm/template/app/**`) и `shared/template` подхватываются
  пересборкой пакета, а не перезапуском сервера. Отладочный плеер собирает пакет на лету —
  достаточно перезагрузить страницу отладки.
- Локальный SCORM-плеер залипает на состоянии попытки: «Сброс попытки», очистка localStorage
  и новый `object_id` не помогают. Надёжно помогает только загрузка пакета под НОВЫМ именем
  файла.
- `university-rt.css` существует в двух копиях: `vendor/ui-kit/css/` — источник,
  `client/src/styles/vendor/` — то, что реально грузится. Править обе.
- Предпросмотр шаблона в реестре собирается ОТДЕЛЬНЫМ маршрутом `smoke-bundle`
  ([server/routes/admin-templates.ts](../../server/routes/admin-templates.ts)), а не
  `readTemplateBundle`. Правку, касающуюся макетов, нужно вносить в оба места — на этом уже
  один раз потерялась подстановка базового пути.
- Смена идентичности экранов делает СОХРАНЁННЫЕ отчёты проверки устаревшими: точки в рельсе
  серые до нажатия «Перепроверить». Гейт активации при этом работает.
- База стенда — не seed-овая: `admin@test.com / admin123` не подходит, в ней лежат настоящие
  пользователи.
- `npx` тихо правит `package.json` (бампает `tsx`). Вызывать бинарники из `node_modules/.bin/`.
