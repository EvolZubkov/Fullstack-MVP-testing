## 4. Грабли, которые стоили времени

- **Отладочный плеер PRD-18 отключает защиту PRD-34 намеренно** (FR-25). Приёмка периметра
  там проверяет его ОТСУТСТВИЕ: первый прогон дал «текст задания не защищён» именно поэтому.
  Периметр принимать на веб-хосте участника или на стенде.
- **`tests/scorm-latency.test.ts` выдёргивает функции из `resultsPage.js` по списку имён.**
  С Э3 туда добавился `correctPatternFor`, список не обновили — три теста падали с
  `ReferenceError` с тех пор, потому что набор никто не гонял. Починено.
- **heredoc превращает `\b` в регулярках в управляющий символ** (0x08), и выражение молча
  перестаёт совпадать. Полчаса на поиск. Регулярки писать через Edit, а после записи файла
  скриптом проверять, что управляющих символов в нём нет.
- **Сериализация HTML не экранирует угловые скобки в значении атрибута.** Исходник листинга,
  положенный в `data-source` как есть, обрывал разбор узла на первой `>`. Кодируется
  `encodeURIComponent`.
- **Границы атома нельзя искать выражением:** внутри атома кода лежит подсветка, то есть
  свои `<span>`. Ищутся счётчиком вложенности.
- **Сравнивать `innerHTML` со строкой бесполезно:** браузер нормализует разметку, и сравнение
  всегда отвечает «текст изменился». Решение «подставлять вид» принимается по флагу «автор
  печатал».
- **Задание в банке создаётся плавающей кнопкой дерева** (`ct-fab-toggle` →
  `ct-fab-question`), а не кнопкой с подписью: приёмка, ищущая «Создать вопрос», не найдёт
  ничего.
- **`ModalDialog` не пробрасывает `data-testid`** на корень — окно опознаётся по заголовку.
- **`GET /api/questions/:id` не существует** — вопрос перечитывается списком
  `/api/questions?topicId=`.
- **Гард полноты справки шаблона книги** требует описания КАЖДОЙ колонки каждого листа: новая
  колонка сразу валит набор, пока её не опишешь. Так и задумано.

## 5. Решения, принятые в этой работе

- **Формат текста задания — три значения, а не два.** `richText` и `html` хранят одно и то
  же; помнить их по отдельности нужно, чтобы автор возвращался в тот редактор, которым
  набирал.
- **Хеш содержимого формат не включает.** Иначе один проход сдвинул бы его у каждого
  существующего задания и ложно зажёг индикатор устаревших переопределений оценки.
- **Правила проверки в книге живут в колонке эталона.** Они И ЕСТЬ эталон и лежат в том же
  `correct_json`, который уже возят снимок публикации, выпечка пакета и перенос теста.
- **Вид механик в визуальном поле берётся у сервера.** Подсветка и MathJax живут только там;
  запросов это стоит столько, сколько раз текст заменили не набором.
- **Перевод разметки в HTML печатает листинг стандартной записью** `<pre><code
  class="language-sql">`, а не внутренней формой выдачи: её узнаёт автор, понимает внешний
  редактор, и по ней выдача восстанавливает подсветку.
