## 1. Задача

Повод: тест «Определение ведущего стиля человекоцентричного лидерства» перенесли из dev в
прод книгой Excel. В проде показатель напечатал `vdo` — сырой ключ шкалы вместо названия
стиля, диаграммы не было, встал дефолтный порог 70%.

Причина не в рендере: книга — формат СОДЕРЖАНИЯ и не несёт jsonb, в котором живут исходы
показателей, вводный блок, оформление, настройки отчёта, правило прохождения и конфигурация
экрана итогов. Импорт при этом не выдаёт ни одной ошибки.

Задача, поставленная владельцем: сделать перенос без потерь. По ходу требование расширено
(его же решением): форма выбора, какие части теста импортировать, и режим upsert/replace
там, где возможна потеря.

Документы: спека `docs/specs/prd-48/test-transfer.md`, план срезов
`docs/plans/2026-08-11-test-transfer-without-losses.md`, план реализации формы
`docs/plans/2026-08-12-prd48-selective-import.md`, эскиз формы

## 6. Принятые решения

Согласованы с владельцем, молча не переигрывать.

1. **JSON-пакет для переноса, книга — точечно.** Книга остаётся форматом содержания; в неё
   добавляется только лист «Исходы показателей».
2. **Полнота по построению.** Пакет сериализует строки таблиц целиком (основа —
   `TestSnapshotContent`), а не перечень полей. Перечень остался ровно в одном месте —
   списке таблиц теста, и он защищён гардом.
3. **Критерий приёмки — перенос в ЧИСТУЮ базу.** Круг «выгрузил-загрузил» на одной базе
   отменён как критерий: он проходит, даже если пакет не несёт ничего.
4. **Импорт сохраняет исходные идентификаторы.** Идентификатор — сам себе свидетельство
   происхождения. Перенумерация остаётся только для режима «создать копию».
5. **Пять частей в форме выбора**, режим upsert/replace только там, где возможна потеря.
6. **Режим для «Структуры и вопросов» задаётся ПО ТЕМЕ**, а не на всю часть.
7. **Права на темы проверяются на сервере.** В коде это обязательный порт `canManageTopic`
   у `applyTransfer` — роут не может забыть проверку.
8. Права на выгрузку пакета — `tests.read` (как у книги), не SCORM-скоуп.
9. **План пересчитывается на сервере**, а не принимается от клиента: увиденное автором есть
   основание согласия, а не список записей.

## 7. Грабли

1. **Круг на одной базе слеп к переносу.** Дефект виден только на настоящем приёмнике.
2. **`sort_order` контентных страниц — НЕ идентичность.** Импорт книгой оставляет все
   страницы с `sort_order = 0`. Сопоставлять страницы по `kind`, и только когда вид на
   приёмнике один.
3. **`content_hash` вопросов не годится как ключ.** В dev: 1334 вопроса, 990 с хешем, 812
   различных значений.
4. **Экран итогов и отчёт настраиваются в РАЗНЫХ местах.** `scalesChartKind`, `scoreSummary`,
   цвета шкал — в `content_pages.settings_json` страницы `results`; у отчёта — в
   `tests.report_settings_json`.
5. **Колонки называются не так, как кажется.** У вопроса это `prompt`, у шкалы `label`, у
   контентной страницы заголовка НЕТ вовсе. Фикстура, выдумавшая `text`/`title`, дала
   зелёные тесты при пустых подписях на настоящих строках — поймано только сверкой со
   схемой.
6. **Строка `tests` принадлежит ТРЁМ частям формы** (оценивание, итоги и оформление,
   остальное). Отсюда `omitFields` у операции: снятая часть удерживает свои колонки, всё
   прочее едет по умолчанию.
7. **`TaskStop` не убивает дочерний процесс.** После остановки фонового `npm run dev` порт
   остаётся занятым; освобождать через `Get-NetTCPConnection -LocalPort <порт>` и
   `Stop-Process -Force`.
8. **`psql` из Git Bash отдаёт cp1251** — нужен `PGCLIENTENCODING=UTF8`; кириллицу в
   запросах лучше заменять поиском по идентификатору. Вывод curl/python в консоль тоже
   искажает кириллицу — судить по кодам ответа и числам, а не по виду строк.
9. **Секреты прода не находятся по якорю.** `grep '^DATABASE_URL='` по
   `/srv/app/test_builder/env/.env` не находит строку — искать без `^`.
10. **Тема дизайн-системы в эскизах** задаётся классами `ou ou--dark ou--normal` на `body`,
    НЕ атрибутом `data-tone`.
11. **Прод-БД доступна по сети** (`192.168.1.200:5432`), туннель не нужен.
12. **Схема в рабочей копии живёт своей жизнью.** 2026-08-12 другая сессия добавила в
    `shared/schema.ts` колонку `pass_decision_policy`, которой в dev-базе ещё нет, и ВЕСЬ
    API тестов начал отдавать `500` («Failed query: select … pass_decision_policy … from
    tests»). Признак чужой правки, а не своей: `git status shared/` показывает изменения,
    которых ты не делал. Обходной путь для уборки в dev — SQL напрямую, повторяя порядок
    удаления из `TestsRepository.deleteTest`.
