## 3. Решения владельца, принятые в диалоге

Их нет в других документах целиком, поэтому здесь.

1. **Фильтр и срез — разные сущности.** Фильтр отвечает «покажи эти прохождения» и может
   охватывать несколько тестов. Срез — «вот выборка ОДНОГО теста, считай по ней». Реализовано
   колонкой `kind`, а не второй таблицей: условия у обеих ролей — один словарь, и две таблицы под
   одни данные разошлись бы на первой новой оси отбора.
2. **Срез из выборки по нескольким тестам — с вопросом, по какому.** Не пачка срезов на каждый
   тест: она плодит объекты с именами, которые придумал не человек, а сравнивать их между собой всё
   равно нельзя (FR-07e).
3. **Псевдоним из четырёх полей, без кода.** Код в реальных выгрузках пуст, а поле, которое то
   есть, то нет, разводит человека на два ключа.
4. **Подразделение и должность хранятся рядом с прохождением, даже при обезличивании** (вариант В
   из разбора). Они входят в псевдоним и меняются, поэтому без них разъезд ключей после перевода
   человека был бы молчаливым.
5. **`learner_id` — отдельное поле у пользователя, не `external_key`.** Источники дают разные
   идентификаторы одного человека, и оба существуют одновременно.
6. **Порядок связывания:** `learner_id` → код против внешнего ключа → псевдоним. Первые два точные,
   третий вычисляемый и хрупкий.
7. **Уже импортированные строки не трогаем** — это тестовые записи.

## 4. Грабли, которые стоили времени

- **Правило показа, написанное под ОДИН тип вопроса, молча применяется ко всем девяти.** Оба
  дефекта патча 2.31.1 из этого класса: «до пяти градаций — словами» писалось под шкалу Ликерта, а
  применилось к опроснику, где варианты — предложения; расчёт распределения отдавал массив нулей
  для `allocation`, где выбранной градации не существует. Демо-данные с одной шкалой Ликерта этого
  не ловили — в фикстуру добавлена шкала «Ведущий стиль» из `allocation` и выбора с длинными
  вариантами.
- **Ширины колонок в таблицах ДС задаются ТЕКСТУ, а не колонке.** `table-layout: auto` игнорирует
  проценты, а у замороженной колонки `width` не доходит до ячейки вовсе. Лечится `min-width` /
  `max-width` в `ch` на самом тексте. Проверять фактические ширины из DOM, а не доверять долям.
- **Когда таблица не помещается, сначала смотреть на текстовые кнопки действий.** Две кнопки в
  реестре заданий занимали 263 px — пятую часть; уехали под троеточие, и условие задания получило
  452 px вместо 297.
- **Дев-сервер идёт без watch: серверные правки видны только после перезапуска**, а перезапуск
  гасит сессии в памяти — кука приёмки протухает, браузер уходит на `/login`. Стоило одного ложного
  «не работает».
- **Локальные копии вынесенных шаблонов отстают от своих origin.** Паритетные тесты падали не
  потому, что работа не сделана, а потому что `skillum-template-certification` и
  `skillum-template-standard-rt` были на 4 коммита позади. Первым делом — `git status -sb` в них.
- **Генератор журнала изменений строит раздел от последнего ТЕГА.** Тег ставится на коммит бампа
  версии ДО `npm run changelog`, иначе раздел выходит пустым.
