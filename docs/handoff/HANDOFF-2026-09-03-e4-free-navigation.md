# Передача работы: Э4 «Свободная навигация внутри раздела»

Дата: 2026-09-03. Ветка старта: `main`. Трек: [перестройка настроек редактора
теста](../plans/2026-09-02-editor-settings-restructure.md), этап Э4.
Статус: **не начат**. Требования приняты владельцем 2026-09-02, кода нет.

Это один из ЧЕТЫРЁХ параллельных треков разделённого плана. Ваш — Э4. Соседние: Э5
(именование и книга), Э6 (шаблоны и контракт), Э7.1-Э7.3 (документация). Приёмку и Э7.4-Э7.6
ведёт сессия-интегратор.

## 1. Задача

Сегодня фронтир прохождения запрещает прыжок к невыданному вопросу при ЛЮБОМ наборе
настроек: к вопросу можно вернуться, но нельзя уйти вперёд. Владелец завёл настройку теста
«Свободная навигация внутри раздела» — булеву, по умолчанию ВЫКЛ: при ВКЛ внутри ТЕКУЩЕГО
раздела доступен любой вопрос, включая ещё не показанный, и понятие «не выдан» внутри
раздела исчезает.

Требования: [PRD-19](../specs/prd-19/skip-return-navigation.md) §3.4, FR-11a - FR-11d.
Читать целиком — там четыре границы свободы, и каждая проверяется отдельно.

## 2. Что сделать

Порядок ваш; ниже — по шагам плана.

- **Э4.1. Колонка и миграция.** Новое поле теста рядом с `allow_return_to_unanswered`
  (`shared/schema.ts`, таблица `tests`). Умолчание ВЫКЛ ОБЯЗАТЕЛЬНО: существующие тесты не
  меняют поведения без правки автора (FR-11c). Миграция — `drizzle-kit generate`, номер
  следующий за `0026_prd50_breakdown_feedback.sql`.
- **Э4.2. Правило доступности.** ДВА места считают одно и то же и обязаны согласиться:
  `shared/template/question-progress-context.ts` (правило `clickable`, веб-хост и предпросмотр)
  и `server/scorm/template/app/render/mainRender.js` (фронтир рантайма пакета). Доступность
  считается ПО РАЗДЕЛУ, а не по текущей позиции.
- **Э4.3. Зависимость и проброс.** Настройка гаснет с подписью причины при выключенном
  «Разрешить возврат к неотвеченным» — так же, как уже сделано для «Позволить изменять ответ»
  (образец: `NavigationPane` в `client/src/features/tests/editor/sections/basic-settings-section.tsx`,
  ищите `changeDisabled`). Проброс значения: снимок публикации
  (`server/services/test-snapshot.ts` — везёт строку теста целиком, проверьте), `TEST_DATA`
  пакета (`server/scorm/builders/test-json.ts`), книга Excel (лист «Настройки»), формат
  переноса `.tbtest`.
- **Э4.4. Тесты.** Карта вопросов, экран обзора, оба хоста, границы раздела и адаптивный
  режим (там настройка ИГНОРИРУЕТСЯ — порядок ведёт лестница уровней).

## 3. Где это в интерфейсе

Настройка живёт во вкладке «Правила прохождения», подраздел «Навигация» — файл
`client/src/features/tests/editor/sections/basic-settings-section.tsx`, панель
`NavigationPane`. Ящик переехал на семь вкладок 2026-09-03, рейлы у каждой свои: пункты
`data-testid` вида `rules-rail-navigation` / `rules-pane-navigation`.

Эскиз состояния: `docs/wireframes/editor-settings-target.html`, состояние `wf-rules` —
настройка там уже нарисована («Свободная навигация внутри раздела» второй строкой). Эскизы
карты вопросов и экрана обзора — `docs/wireframes/prd19-learner-real.html`, состояние
«свободная навигация»: пиллы раздела кликабельны все, статуса «не выдан» нет, «Пропустить»
уступает место паре «Назад» / «Далее».

## 4. Грабли

- **Два расчёта доступности.** Веб и пакет считают доступность независимо. Разойдутся — и
  ученик получит разную навигацию в вебе и в LMS. Правьте оба и закройте тестом ОБА.
- **Адаптивный режим.** Настройка к нему не применяется. Проверьте это отдельным тестом:
  иначе лестница уровней начнёт пускать вперёд.
- **Книга Excel — контракт.** Новый параметр листа «Настройки» добавляется, а не
  переименовывается: уже выданные книги обязаны читаться. Смежный трек Э5 в этом же файле
  правит АЛИАСЫ существующих параметров — синхронизируйтесь с ним перед правкой
  `server/utils/workbook-settings.ts`.
- **Снимок публикации.** Экспорт опубликованного теста берёт снимок: после правок пакет
  остаётся прежним, пока тест не перепубликован.
- **Мок хранилища.** Новый метод `IStorage` ломает разом восемь файлов с моками; точечные
  прогоны этого не показывают.
- **`npm run dev` не перезапускает сервер** сам: правку серверного кода видно только после
  перезапуска.

## 5. Приёмка

Своя приёмка этапа — в браузере, на живом dev: тест с ВЫКЛ настройкой ведёт себя как
сегодня, с ВКЛ — пускает вперёд внутри раздела и не пускает за его границу. Учётка для
приёмки и порты — `docs/references` и память проекта. Итог этапа опишите отчётом в
`docs/reports/`, как это сделано для предыдущих этапов трека.

Полный прогон `npm test` — ТОЛЬКО по явному разрешению владельца: он занимает машину на
восемь минут, а сессий параллельно четыре. В работе — точечные прогоны `npm test -- <путь>`.
