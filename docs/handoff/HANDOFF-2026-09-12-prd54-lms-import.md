## 1. Задача

Повод вскрылся разбором настоящей выгрузки WebTutor
(`docs/references/7684237229762827328-1.xlsx`): у теста «Определение ведущего стиля
человекоцентричного лидерства» на проде ВЫКЛЮЧЕНА телеметрия и ноль строк в `scorm_packages` —
то есть ни одно прохождение в LMS до нас не доехало, а единственным их следом остался файл Excel.

Требовалось: загружать такие выгрузки и доливать их в аналитику наравне с телеметрией.

Требование менялось по ходу, все изменения — решения владельца, зафиксированы в разделе 2 спеки:
обезличивание участника (решения 7-11), связывание с учётной записью по явному ключу (решение 12),
массовое заполнение ключей колонкой в загрузке пользователей, три точки входа вместо одной.

## 6. Принятые решения

Двенадцать решений владельца — в разделе 2 [спеки](../specs/prd-54/lms-export-import.md), их
пересматривать молча нельзя. Ключевые, которые легко переиграть по незнанию:

- **Числа берутся ИЗ ФАЙЛА и не пересчитываются.** Пакет мог быть собран под более ранней версией
  теста, и пересчёт дал бы не то, что видел участник.
- **Хранилище общее с телеметрией**, а не отдельные таблицы. Выбрано сознательно: иначе каждый
  потребитель аналитики пришлось бы учить третьему источнику вручную и навсегда.
- **Псевдоним считается ВСЕГДА**, независимо от режима обезличивания. Параметр решает только,
  лежит ли рядом имя. Иначе переключение параметра рвало бы связь с уже загруженными строками.
- **Сопоставление по ФИО запрещено**, пользователи-призраки не заводятся. Связь только по явно
  заданному `users.external_key`.
- **Формат ответа с 0-based индексацией у распределения НЕ меняем** — обоснование в ROADMAP §0.3.

Решение по ходу, не согласованное отдельно и потому помечаю его особо: отбор в выгрузках Excel
переведён с пакетов на тест, то есть загруженные выгрузки теперь попадают и в
`POST /api/export/excel-lms`. Логика — они такие же прохождения в LMS, просто приехали книгой.
Если это нежелательно, менять надо в `server/routes/analytics/export.ts`.

## 7. Грабли

- **Общая dev-база.** Миграция `0029` уже применена. Чужие сессии не поднимутся, пока не выполнят
  `npm run db:migrate`. После любых опытов прибирать за собой: партии откатывать, внешние ключи
  снимать — база общая.
- **Порты 8093-8099 разобраны параллельными сессиями.** `npm run dev` на занятом порту падает с
  `EADDRINUSE`, но ЧУЖОЙ сервер продолжает отвечать на запросы. Я на этом потерял время: аналитика
  возвращала ноль строк и ответ старой формы, и это выглядело как дефект правок, а оказалось
  разговором с чужим кодом. Перед приёмкой выбрать свободный порт и убедиться, что в логе нет
  `EADDRINUSE`.
- **Наивные метки времени.** Колонки `timestamp without time zone`; `toISOString()` над такой
  меткой в проверочном скрипте даёт сдвиг на часовой пояс и выглядит как дефект. Сверять сырым
  текстом из Postgres (`started_at::text`).
- **exceljs отдаёт даты объектами `Date`**, и `String(date)` даёт локализованную строку, которую на
  другой локали не разобрать. Оба читателя книги приводят дату к ISO явно — не «упрощать».
- **Интеграционный харнесс поднимает базу из `tests/it/schema.sql`**, экспорта из `shared/schema.ts`,
  а НЕ из миграций. После правки схемы перегенерировать:
  `npx drizzle-kit export --sql | grep -v '^DATABASE_URL:' > tests/it/schema.sql`.
- **Индекс по `lower(external_key)` живёт ТОЛЬКО в миграции**, в модели drizzle его нет. Значит
  `npm run db:push` его снесёт, а на pglite уникальность ключа не проверить — её там просто нет.
- **Токены ДС живут под классом `.ou`.** Эскиз с голым `<body>` отрисовался неформатированным HTML,
  и гейт `check:wireframes:ds` этого не ловит — видно только в браузере.
- **Загрузка файлов через Playwright** берёт файлы только из корня репозитория или
  `.playwright-mcp`; из временного каталога отказывает.
