## 1. Задача

Этап Э1 снял ВЕРДИКТ у подтемы: подтема считается и показывается, но не судится (решение
владельца 2026-09-03). Из контекста строки разреза исчезли три поля — `passed`, `passClass`,
`statusLabel`. Раскладки обоих поставляемых шаблонов их ещё печатают: `{{#if statusLabel}}`
теперь всегда ложно, а классы `is-pass`/`is-fail` не приходят. Мёртвая разметка не ломает
выдачу, но лжёт разработчику шаблонов, который читает раскладку как образец.

Заодно поднимается контракт формата шаблонов: этих полей в нём больше нет.

## 2. Что сделать

- **Э6.1. Эталонный шаблон.** Убрать метку исхода и классы из строки разреза:
  `server/scorm/templates/default/layouts/results.html`, `results.adaptive.html`,
  `layouts/report/breakdown.html`, `layouts/report/topics.html`,
  `layouts/report/adaptive/breakdown.html`, `layouts/report.html`, `report.adaptive.html`.
  Полный перечень мест — `grep -rn 'statusLabel\|passClass' server/scorm/templates/default`.
- **Э6.2. Шаблон «Сертификация».** Те же правки в `templates/certification/layouts/**`;
  `tb-report__breakdown-status` уходит из `layouts/report/topics.html`, CSS чистится
  (`templates/certification/styles/report.css`).
- **Э6.3. Шапка карточки блока со счётчиком** у «Сертификации»: новые тесты блоков разделов
  не заводят (карточка «Блоки итогов» из редактора убрана решением 12), поэтому шапка не
  должна оставлять пустую полосу. Деградацию без групп отыграть на растре.
- **Э6.4. Гард селекторов и паритета** шаблонов обновляется под снятые узлы — иначе он
  продолжит требовать разметку, которой больше нет.
- **Э6.5. Контракт бампится ВТРОЁМ:** спецификация формата, руководство разработчика
  шаблонов и PDF (`npm run docs:pdf`). Из контекста строки разреза исчезают `passed`,
  `passClass`, `statusLabel`. Бамп версии требует git-тега `vX.Y.Z` — правило владельца.
- **Э6.6. Версия «Сертификации» поднимается, шаблон ПЕРЕЗАЛИВАЕТСЯ в реестр**
  (`PUT /api/admin/templates/certification/update`).

## 3. Грабли (проверены на этом треке)

- **Правка файла шаблона не видна приложению.** Реестр читает КОПИЮ в
  `uploads/templates/<id>`, а манифест живёт в БАЗЕ. Без перезалива вы правите то, что никто
  не рендерит, — и это уже съедало время на PRD-51.
- **Паритет «Сертификации» держится вручную.** Она не наследует эталон: правку нужно внести
  в оба шаблона, и гард ловит расхождение раскладок, а не смысла.
- **Инлайн рантайма перебивает CSS шаблона.** Если после чистки CSS что-то осталось
  окрашенным — ищите инлайновый стиль рантайма, а не свой селектор.
- **`base.css` — это fallback**, а `theme.css` — только тёмная тема. Правка «просто цвета»
  в `base.css` меняет поведение всех шаблонов без своей темы.
- **Экспорт опубликованного теста берёт снимок:** пакет остаётся прежним, пока тест не
  перепубликован. Проверять правку шаблона надо на черновике или после перепубликации.
- **Растр отчёта чувствителен к сбросу стилей хоста** (`preflight.css` однажды уже сбивал
  html2canvas). Приёмку отчёта делать на PDF, а не на экране предпросмотра.

## 4. Приёмка

Точечные прогоны: `npm test -- tests/report-shipped-templates.test.ts`,
`npm test -- tests/certification-report-document.test.ts`,
`npm test -- tests/breakdown-block-layout.test.ts`, `npm test -- shared/template`.
Затем `npm run scorm:template` + локальный плеер (`npm run scorm:player`) — строка разреза
печатается БЕЗ метки исхода; и PDF-отчёт обоих шаблонов на бумаге (Э7.5 ведёт интегратор, но
свою часть проверьте сами).

Полный прогон `npm test` — ТОЛЬКО по явному разрешению владельца: параллельно работают
четыре сессии.
