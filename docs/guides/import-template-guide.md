# Руководство по заполнению шаблона импорта теста (Excel)

Документ описывает, как заполнить Excel-книгу для импорта теста в систему: какие
листы бывают, что значит каждая колонка, в каком формате писать значения и как
устроены связи между листами. Это практическое руководство; формальный контракт —
в [спецификации формата](../specs/questions-import/format.md).

**Статус:** актуально; соответствует коду импортёров `server/routes/workbook.ts`,
`server/routes/tests-workbook.ts` и `server/services/workbook-import.ts` (PRD-14).
**Дата актуализации:** 2026-07-01

## 1. Что делает импорт

Импорт читает книгу `.xlsx` и записывает:

- **вопросы** — в общий банк вопросов (лист «Вопросы»);
- **структуру теста** — разделы, выдачу по тегам, пороги прохождения (листы
  «Структура» и «Квоты»);
- **обвязку подсчёта** — шкалы, показатели результата и вклады вопросов (листы
  «Шкалы», «Показатели», «Вклады вопросов»).

Лист «Вопросы» — глобальный (вопросы не привязаны к тесту). Всё остальное
относится к ОДНОМУ тесту, который выбирается при импорте (существующий) или
создаётся новый.

Минимально достаточно одного листа «Вопросы». Остальные листы — по необходимости.

## 2. Как импортировать

1. Раздел **«Импорт»** в боковой навигации.
2. **«Скачать шаблон»** — пустая книга с заголовками всех листов и листом
   «Справка».
3. Заполните нужные листы, сохраните `.xlsx`.
4. Перетащите файл в загрузчик. Система определит листы автоматически:
   - только «Вопросы» → импорт в общий банк, целевой тест не нужен;
   - есть «Структура»/«Шкалы»/«Показатели»/«Вклады вопросов» → нужно выбрать
     **целевой тест**: существующий или **«＋ Создать новый тест»**.
5. **«Проверить»** — предпросмотр (dry-run): покажет план и построчные ошибки,
   ничего не записывая.
6. **«Импортировать»** — запись.

## 3. Листы книги

| Лист | Назначение | Обязательность |
| --- | --- | --- |
| `Вопросы` | Банк вопросов (глобальный) | как минимум один лист в книге |
| `Структура` | Разделы теста: тема, выборка, порог, обязательность | опционально |
| `Квоты` | Квоты выдачи по тегам (для разделов «Структуры») | опционально |
| `Оценка` | Оценка вопросов в этом тесте: балл, цена ответа, сложность | опционально |
| `Шкалы` | Шкалы-«копилки» для подсчёта (PRD-5) | опционально |
| `Показатели` | Показатели результата (формулы) | опционально |
| `Вклады вопросов` | Вклады «вопрос → шкала» | опционально |

Имена листов распознаются по названию (регистр и пробелы не важны). Лишние листы
игнорируются. Заголовки — в строке 1, данные — со строки 2. Пустые строки
пропускаются.

## 4. Лист «Вопросы»

Одна строка = один вопрос. Колонки (порядок не важен, лишние игнорируются):

| Колонка | Обяз. | Описание |
| --- | --- | --- |
| `Ключ строки` | нет | Локальный код вопроса в пределах книги. На него ссылается лист «Вклады вопросов». В БД не хранится. |
| `ID` | нет | Пусто → создать новый вопрос. Заполнен и найден → обновить существующий (см. §12). |
| `Тема` | да | Имя темы. Если темы нет — создаётся автоматически (без учёта регистра). |
| `Тип вопроса` | да | `multiple_choice` (одиночный) / `multiple_response` (множественный) / `matching` (сопоставление) / `ranking` (ранжирование). Алиас колонки: `Тип`. |
| `Текст вопроса` | да | Формулировка. Алиас: `Вопрос`. |
| `Балл` | нет | Целое; по умолчанию `1`. Значение `0` сохраняется как `0`. |
| `Сложность` | нет | Целое `0..100`; по умолчанию `50`. |
| `Тексты вариантов ответа` | да | Варианты/пары/элементы (формат по типу — ниже). Алиас: `Варианты`. |
| `Номера правильных ответов` | да | Правильный ответ (формат по типу — ниже). 1-based. Алиас: `Правильный ответ`. |
| `Следование вариантов ответов` | нет | `Random` (по умолчанию, перемешивать) / `Fixed` (фиксированный порядок). |
| `Обратная связь` | нет | Общая обратная связь (режим «общая»). |
| `Теги` | нет | Подтемы; разделители `;` и `,`. Используются для выдачи по квотам (§7). |
| `Режим ОС` | нет | `общая` (по умолчанию) / `условная`. |
| `ОС при верном` | нет | Текст; учитывается при `Режим ОС = условная`. |
| `ОС при неверном` | нет | Текст; учитывается при `Режим ОС = условная`. |
| `Балл` | нет | Цена вопроса в импортируемом тесте (§5.3). Целое; по умолчанию `1`. |
| `Цена ответа` | нет | Градуированная оценка (§5). Пусто = точное совпадение (0/1). |

> Важно: `Балл` и `Цена ответа` — свойства не вопроса, а ТЕСТА (вопрос
> глобальный, цена у него своя в каждом тесте). При импорте они применяются к
> вопросу именно в выбранном целевом тесте. Это можно задать как колонками на
> листе «Вопросы» (как описано здесь), так и отдельным листом «Оценка» — см.
> §5.3.

### 4.1 Форматы по типам вопросов

Разделитель вариантов — `#` (предпочтительно) либо `|`. Нумерация правильных
ответов — **с единицы** (1-based).

**`multiple_choice` (одиночный выбор)**

- `Тексты вариантов ответа`: `Москва # Париж # Берлин` (минимум 2 варианта).
- `Номера правильных ответов`: один номер, напр. `2`.

**`multiple_response` (множественный выбор)**

- `Тексты вариантов ответа`: `A # B # C # D`.
- `Номера правильных ответов`: список, напр. `1,3` (разделители `,` `.` пробел).

**`matching` (сопоставление)**

- `Тексты вариантов ответа`: левый список, затем разделитель сторон `||`, затем
  правый список: `Кошка # Собака # Рыба || Мяу # Гав # Буль`. Правый список может
  быть длиннее (дистракторы).
- `Номера правильных ответов`: пары `левый-правый` (1-based): `1-1, 2-2, 3-3`.
  Пусто → позиционное соответствие (1-й слева ↔ 1-й справа и т.д.).

**`ranking` (ранжирование)**

- `Тексты вариантов ответа`: элементы в порядке показа: `Шаг А # Шаг Б # Шаг В`.
- `Номера правильных ответов`: правильный порядок как последовательность 1-based
  позиций: `3,1,2` (сначала 3-й элемент, затем 1-й, затем 2-й). Пусто → элементы
  уже в правильном порядке.

## 5. «Цена ответа» — градуированная оценка

Колонка `Цена ответа` задаёт, как начислять баллы за частично верный ответ
(PRD-10). Пусто или `точное` → точное совпадение (всё верно = `Балл`, иначе `0`).

Есть два режима.

### 5.1 `веса` — только для одиночного выбора

За каждый вариант начисляется свой балл (например, компетенции 2/1/0).

```text
веса: 2 # 1 # 0 # 0
```

- По одному весу на вариант, в порядке вариантов.
- Весов меньше числа вариантов → недостающие = `0`. Больше → ошибка строки.
- Опционально: `; sMax=<число>` (иначе максимум = наибольший вес).

Ту же цену можно записать буквенным ключом — так оформлены исходные банки
сертификации:

```text
%A2B1C0D0
```

- Буква называет вариант по позиции, число — его вес; читается точно как
  `веса: 2 # 1 # 0 # 0`.
- Буквы обязаны идти по порядку `A`, `B`, `C`, … — пропуск или перестановка
  даёт ошибку строки.
- Буквы только латинские: кириллические `А`/`В`/`С` неотличимы на вид, но стоят
  в другом порядке алфавита, поэтому не принимаются.
- Правила по числу весов те же. `sMax` в этой записи не задаётся.
- Экспорт всегда пишет каноническую форму `веса:`.

### 5.2 `ступени` — для множественного / сопоставления / ранжирования

Таблица ступеней: первая подходящая ступень задаёт балл, иначе `0`.

```text
ступени: correct == total & wrong == 0 => 2; correct >= 1 & wrong <= 1 => 1
```

Переменные (система считает их при проверке ответа):

- `correct` — сколько **верных** единиц выбрал ученик;
- `wrong` — сколько **неверных** единиц выбрал;
- `total` — сколько верных единиц **всего** в вопросе.

Правила записи:

- ступени разделяются `;` (или `,`); условия внутри ступени — через `&` (И);
- операторы: `==`, `>=`, `<=`, `<`, `>`;
- правая часть условия — число или ключевое слово `total`;
- балл ступени — неотрицательное число, **десятичный разделитель — точка**
  (`1.5`);
- опционально `; sMax=<число>`.

Пример выше читается так: «всё верно и без ошибок → 2; хотя бы один верный и не
более одной ошибки → 1; иначе 0».

Пример для сопоставления (1 балл за каждую верную пару, до 3):

```text
ступени: correct >= 3 => 3; correct >= 2 => 2; correct >= 1 => 1
```

> Старые односимвольные токены `c` (верных) / `x` (неверных) / `T`/`P`/`N`
> (всего) при импорте всё ещё принимаются, но экспорт и шаблон пишут читаемые
> `correct` / `wrong` / `total`.

### 5.3 Лист «Оценка» — оценка вопросов теста

`Балл`, `Цена ответа` и переопределение `Сложность` относятся к ТЕСТУ, поэтому
их можно вынести на отдельный лист «Оценка» (по одной строке на вопрос). Это
канонический способ; экспорт теста пишет оценку именно сюда.

| Колонка | Обяз. | Описание |
| --- | --- | --- |
| `Вопрос` | да | `ID` существующего вопроса **или** `Ключ строки` из листа «Вопросы». |
| `Балл` | нет | Цена вопроса в этом тесте. Пусто = не переопределять. |
| `Цена ответа` | нет | Градуированная оценка (§5). Пусто = не переопределять; `точное` = явное точное совпадение. |
| `Сложность` | нет | Переопределение сложности `0..100` для этого теста. Пусто = не переопределять. |

Правила выбора источника:

- если лист **«Оценка» есть** — оценка берётся из него (он главный; пустой лист
  «Оценка» очищает переопределения теста), а колонки `Балл`/`Цена ответа` листа
  «Вопросы» игнорируются;
- если листа **«Оценка» нет**, но на листе «Вопросы» есть колонки `Балл`/`Цена
  ответа` — оценка берётся из них (удобно держать вопрос и его цену в одной
  строке);
- пустая ячейка = переопределения нет: цена «проваливается» по цепочке
  (умолчание раздела → умолчание теста → системное `1`, точное);
- три колонки независимы: если «Цена ответа» не разобралась, строка выдаёт
  ошибку по этой ячейке, но `Балл` и `Сложность` той же строки применяются.
  Отброшенной оказывается только градуированная цена — вопрос получает свой
  балл при точном совпадении.

## 6. Лист «Структура»

Одна строка = один раздел теста. Импорт «Структуры» **заменяет разделы теста
целиком** и включает режим «со страницей-маршрутизатором» (страницу-маршрутизатор
система создаёт сама).

| Колонка | Обяз. | Описание |
| --- | --- | --- |
| `Раздел` | да | Имя темы. Должна существовать в банке или присутствовать на листе «Вопросы». |
| `Порядок` | нет | Целое; задаёт порядок разделов. Пусто → порядок строк. |
| `Вопросов в выборке` | да | Сколько вопросов темы выдавать в попытке (`draw_count`), целое ≥ 1. |
| `Тип порога` | нет | `Сумма баллов` / `Процент` / `Нет` (не проверять) / `Как у теста` (наследовать). Пусто = «Как у теста». |
| `Порог` | при `Сумма баллов`/`Процент` | Число: для `Сумма баллов` — баллы, для `Процент` — проценты. |
| `Обязательный` | нет | `да` (по умолчанию) / `нет`. Влияет на общий зачёт «пройдены все обязательные темы». |

Особенности:

- Порог **`Сумма баллов`** сравнивается с **градуированной** суммой баллов
  раздела (с учётом «Цены ответа»), а не с числом вопросов — это даёт точный
  порог по правилам начисления.
- Раздел резолвится по имени темы (регистр и пробелы не важны).

## 7. Лист «Квоты»

Квоты выдачи по тегам для разделов «Структуры» (PRD-11). Одна строка = одна квота
(страта). Отсутствие квот у раздела = равномерная случайная выдача.

| Колонка | Обяз. | Описание |
| --- | --- | --- |
| `Раздел` | да | Имя темы (как на листе «Структура»). |
| `Тег` | да | Подтема. Должна совпадать со значением в колонке `Теги` соответствующих вопросов. |
| `Количество` | да | Сколько вопросов с этим тегом тянуть, целое ≥ 1. |
| `Режим` | нет | `Ровно` (по умолчанию, ровно `Количество`) / `Не менее` (минимум `Количество`). |

Правила:

- на каждый раздел **`Σ Количество ≤ «Вопросов в выборке»`** (иначе ошибка
  строки);
- остаток выборки (если `Σ Количество < «Вопросов в выборке»`) добирается случайно
  из вопросов без `Ровно`-тегов;
- если вопросов с тегом меньше квоты — это предупреждение (выдаётся сколько есть),
  не блокирует.

## 8. Лист «Шкалы»

Шкала — именованная «копилка» (PRD-5), складывающая вклады вопросов в одно число.
Нужна только для составных показателей; для порогов раздела хватает «Структуры».

| Колонка | Обяз. | Значения |
| --- | --- | --- |
| `Ключ` | да | `^[a-z][a-z0-9_]{0,63}$` (латиница), уникум в пределах теста. |
| `Название` | да | Отображаемое имя. |
| `Описание` | нет | Текст. |
| `Тип` | да | `number` / `boolean` / `category` / `level`. |
| `Агрегация` | нет | `sum` (по умолчанию) / `avg` / `weighted_avg` / `max` / `min`. |
| `Нормализация` | нет | `none` (по умолчанию) / `percent` / `custom`. |
| `Направление` | нет | `positive` (по умолчанию) / `inverse`. |
| `Диапазоны` | нет | Интерпретация сырого значения в уровни (грамматика ниже). |
| `Показывать ученику` | нет | `да` / `нет`. |
| `SCORM` | нет | `none` (по умолчанию) / `suspend_data` / `interaction` / `both`. |

Грамматика `Диапазоны` (для `category`/`level`): `min..max код «подпись»`,
диапазоны через `;`/`,`, подпись опциональна, границы включительно:

```text
0..16 low «Низкий»; 17..26 mid «Средний»; 27..54 high «Высокий»
```

## 9. Лист «Показатели»

Показатель — вычисляемое значение результата (PRD-2) по формуле.

| Колонка | Обяз. | Значения |
| --- | --- | --- |
| `Имя` | да | `^[a-z][a-z0-9_]{0,63}$`, уникум в пределах теста. |
| `Метка` | да | Отображаемое имя. |
| `Тип` | да | `boolean` / `number` / `string`. Должен совпадать с типом, который возвращает формула. |
| `Формула` | да | Выражение на DSL (ниже). |
| `Показывать ученику` | нет | `да` / `нет`. |
| `SCORM` | нет | `interaction` / `suspend_data` / `both` (по умолчанию) / `none`. |
| `Управляет статусом` | нет | `нет` (по умолчанию) / `успех` / `завершение`. Не более одного `успех` и одного `завершение` на тест. |

### 9.1 Язык формул (DSL)

- Источники: `scaleById("ключ").raw` (`.normalized`/`.percent`/`.level`/`.label`/
  `.hasValue`), `topicById("id").score` (`.percent`/`.passed`), `percent` (общий
  процент), `var("имя")` (значение показателя выше по списку).
- Агрегаты: `countPassed()` (сколько тем пройдено), `countTopics()`,
  `avgPercent()`.
- Условие: `IF(<условие>, <тогда>, <иначе>)` (регистр важен — `IF` заглавными).
- Логика/сравнения: `AND`, `OR`, `NOT` (заглавными); `=`, `!=`, `>`, `>=`, `<`,
  `<=`; арифметика `+ - * /`.
- Строки — в двойных кавычках: `"Целевой"`.

Примеры:

```text
boolean  scaleById("company").raw >= 15
string   IF(scaleById("company").raw >= 15, "Целевой", "Начальный")
boolean  countPassed() >= 4          (Управляет статусом = успех)
```

> Важно: тип в колонке `Тип` должен соответствовать формуле (сравнение/AND/OR →
> `boolean`; арифметика/счётчики → `number`; кавычки → `string`). Для порогов
> разделов проще задавать правило в «Структуре» (`Сумма баллов`); `scaleById`/
> `topicById` нужны для составных индикаторов.

## 10. Лист «Вклады вопросов»

Вклад одной единицы вопроса в шкалу (PRD-5). Одна строка = один вклад.

| Колонка | Обяз. | Описание |
| --- | --- | --- |
| `Вопрос` | да | `ID` существующего вопроса **или** `Ключ строки` из листа «Вопросы». |
| `Шкала` | да | `Ключ` шкалы. |
| `Источник` | да | `вопрос` / `вариант` / `пара` / `позиция`. |
| `Ключ источника` | да (кроме `вопрос`) | **0-based** индекс (см. ниже); для `вопрос` — пусто. |
| `Значение` | да | Число (0 и отрицательные допустимы). |
| `Вес` | нет | Число; по умолчанию `1`. |

Формат `Ключ источника` (нумерация **с нуля**):

- `вариант` — индекс варианта: `0`, `1`, `2`, …;
- `пара` — `левый:правый` (оба 0-based): `0:0`, `1:2`;
- `позиция` — `элемент:позиция` (оба 0-based): `0:0`, `2:1`;
- `вопрос` — ключ пустой; вклад начисляется при любом ответе на вопрос.

## 11. Порядок импорта и связи

Импорт обрабатывает листы в порядке:

```text
Вопросы → Шкалы → Вклады вопросов + Показатели → Оценка → Структура + Квоты
```

Связи между листами:

- **`Ключ строки`** на листе «Вопросы» позволяет «Вкладам вопросов» сослаться на
  вопрос, создаваемый в этой же книге (до того как у него появится `ID`).
- **`Тема`** связывает вопрос с разделом «Структуры» (по имени).
- **`Тег`** связывает вопрос с квотой выдачи (по совпадению значения).
- **`Ключ` шкалы** связывает «Вклады вопросов» и `scaleById(...)` в показателях.

## 12. Предпросмотр, ошибки, обновление

- **Предпросмотр (dry-run)** — кнопка «Проверить»: считает план
  (создать/обновить/пропустить) и построчные ошибки, ничего не записывая.
- **Построчные ошибки** — формат «Лист, строка N: причина». Невалидная строка
  пропускается, остальные импортируются.
- **Обновление по `ID`** — если `ID` задан и вопрос найден, выполняется
  обновление. Правило колонок при обновлении:
  - колонка **отсутствует** в файле → поле НЕ меняется;
  - колонка **есть, но пустая** → поле сбрасывается к значению по умолчанию.
- **Дедупликация при создании** (без `ID`): повтор вопроса с тем же содержимым в
  той же теме пропускается.

## 13. Что сделать после импорта

Импорт со «Структурой» создаёт тест с разделами, порогами и квотами и включает
режим «со страницей-маршрутизатором». После импорта в редакторе теста стоит:

1. Проверить разделы и пороги во вкладке «Состав» / настройках.
2. При необходимости задать общий зачёт теста — политика «пройдены все
   обязательные темы».
3. Просмотреть предупреждения импорта (например, вопросы без тега или с
   несоответствием).
4. Опубликовать тест.

Структуру вариантов, адаптивные уровни и контент-страницы импорт не переносит —
это настраивается в редакторе.

## 14. Мини-пример книги

### Лист «Вопросы» (пример)

Три вопроса темы «Финансы» (`Ключ строки` = q1/q2/q3):

- **q1** — `multiple_choice`, «Что такое OIBDA?», Балл `1`, варианты
  `Прибыль # Выручка # Актив`, правильный `1`, тег `основы`, «Цена ответа» пусто.
- **q2** — `multiple_response`, «Формы отчётности?», Балл `2`, варианты
  `ОПУ # ОДДС # Прочее`, правильные `1,2`, тег `основы`, «Цена ответа»
  `ступени: correct == total & wrong == 0 => 2; correct >= 1 & wrong <= 1 => 1`.
- **q3** — `matching`, «Сопоставьте», Балл `3`, варианты `A # B # C || 1 # 2 # 3`,
  пары `1-1, 2-2, 3-3`, тег `метрики`, «Цена ответа»
  `ступени: correct >= 3 => 3; correct >= 2 => 2; correct >= 1 => 1`.

### Лист «Структура» (пример)

| Раздел | Порядок | Вопросов в выборке | Тип порога | Порог | Обязательный |
| --- | --- | --- | --- | --- | --- |
| Финансы | 1 | 3 | Сумма баллов | 4 | да |

### Лист «Квоты» (пример)

| Раздел | Тег | Количество | Режим |
| --- | --- | --- | --- |
| Финансы | основы | 2 | Ровно |
| Финансы | метрики | 1 | Ровно |

Результат: тема «Финансы» с 3 вопросами; в попытке выдаётся 2 вопроса с тегом
«основы» и 1 с тегом «метрики»; раздел пройден при сумме баллов ≥ 4.

## 15. Частые ошибки

- **Тег в «Квотах» не совпадает с тегом в «Вопросах»** — квота не находит
  вопросов (регистр и пробелы нормализуются, но опечатки — нет). Пишите теги
  одинаково.
- **`Σ Количество` в «Квотах» больше «Вопросов в выборке»** — ошибка строки.
  Уменьшите квоты или увеличьте выборку.
- **Порог `Сумма баллов` больше суммы баллов раздела** — раздел станет
  непроходимым. Порог должен быть ≤ максимально возможной сумме баллов раздела.
- **Сопоставление без `||`** — левый и правый списки не разделятся (сработает
  старый позиционный разбор). Всегда ставьте `||` между сторонами.
- **`Тип` показателя не совпадает с формулой** — например, `boolean` для
  `scaleById(...).raw` (это число). Согласуйте тип и формулу.
- **`Ключ источника` 1-based** — индексы во «Вкладах вопросов» нумеруются **с
  нуля** (первый вариант = `0`).
- **`веса` для не-одиночного вопроса** — режим `веса` допустим только для
  `multiple_choice`; для остальных используйте `ступени`.
