## 8. Промпт для новой сессии (Sonnet)

Скопировать в новую сессию Claude Code (модель Sonnet) в каталоге проекта
`c:/Repositories/test-builder`. Промпт самодостаточен и учитывает опыт
предыдущих заходов, которые упирались в output-лимит Sonnet.

```text
Контекст. Я работаю над PRD-7 в проекте SCORM Test Constructor. Редактор теста
должен быть реализован как wide Drawer с вкладками
Состав | Настройки | Оформление | Структура. Сейчас есть два согласованных
по содержанию HTML-wireframes старого формата (page-level layout, не Drawer):

- docs/wireframes/design-tab.html — вкладка "Оформление".
- docs/wireframes/pages-tab.html — вкладка "Структура", только режим
  linear_by_topics.

И есть готовый Drawer-контейнер: docs/wireframes/prd7-editor-drawer.html,
общий CSS docs/wireframes/prd7-shared.css.

Целевые требования: docs/architecture/test-settings-parameter-structure.md.
План работ и критерии готовности: docs/issues/wireframes-drawer-todo.md
(этот файл; читай его целиком перед началом).

Задача. Привести wireframes вкладок "Оформление" и "Структура" в формат
Drawer (PRD-7) без потерь согласованного содержания из старых файлов и
с добавлением недостающих режимов flowMode и состояний согласно требованиям.

Бюджет и анти-паттерны (важно: предыдущие сессии Sonnet здесь падали).

- Размер каждого целевого файла — 1200–1800 строк HTML, это 15–22K
  выходных токенов. В один Write такой файл не помещается (output-лимит
  Sonnet ~8K токенов за ход) — Write молча обрывается на середине либо
  следующий tool call не вызывается. Поэтому каждый файл собирается
  инкрементально (см. workflow ниже), а не одним Write.
- Не запускай суб-агентов через Agent для записи этих HTML-файлов.
  В прошлый раз general-purpose agent с детальным брифом потратил
  ~350 секунд, упёрся в свой токен-лимит и не записал ни одной строки.
  Пиши сам через Write + Edit.
- Не перечитывай ссылочные файлы повторно. Прочитал prd7-shared.css один
  раз — запомни классы и больше к нему не возвращайся. Прочитал
  design-tab.html — выпиши список состояний и набор полей в один блокнот
  в голове, дальше работай по нему. Каждое лишнее чтение крупного файла
  съедает контекст, который потом нужен для Write.
- Не пиши длинные планы и пересказы в обычный текст между tool calls.
  Один короткий абзац максимум, потом сразу Write/Edit. Все "сейчас
  напишу" без следующего за ними Write — это потраченный бюджет.

Workflow для каждого целевого HTML-файла.

1. Скелет одним Write. В скелете:
   - <!DOCTYPE>, head с <link rel="stylesheet" href="prd7-shared.css">.
   - Локальный <style> только с wireframe-специфичными классами,
     которых нет в prd7-shared.css (param-сетки, color-picker popover,
     gallery-*, preview-sketch, changed-chip/changed-areas,
     топ/раут-блоки для structure-файлов и т.п.).
   - SVG sprite со всеми нужными иконками.
   - <template id="tpl-bg-page"> с фоновой страницей списка тестов
     (можно взять из prd7-editor-drawer.html без изменений).
   - Wireframe-nav (.wf-nav) со списком кнопок состояний, ссылка
     "← К другому файлу" в конце.
   - Маркер вставки состояний — одна строка-якорь, например:
       <!-- ═══════════ STATES_INSERT_POINT ═══════════ -->
     помещается между nav/template и acceptance-блоком.
   - Acceptance-секция (<section class="acceptance">) с таблицей FR/NFR,
     которые этот файл покрывает.
   - <script> с injectBgPage(), show(id), showMobile() (взять из
     prd7-editor-drawer.html без изменений) и подгрузкой wf-links.js.
   Размер скелета ~400–550 строк, помещается в один Write.

2. Дописывание состояний батчами через Edit. На каждый Edit:
   - old_string = тот самый маркер STATES_INSERT_POINT.
   - new_string = HTML 2–3 состояний + тот же маркер на новой строке
     (чтобы остался якорь для следующего Edit).
   Размер одного Edit-батча — 150–300 строк (~3–4K выходных токенов).
   Делай столько Edit, сколько нужно, по 2–3 состояния за раз; в конце
   уберёшь маркер последним Edit (old_string = маркер + перевод строки,
   new_string = пустая строка).

3. Когда все состояния вписаны и маркер удалён — файл готов. Не делай
   "финальный Read" для проверки: Edit вернул бы ошибку при провале.
```
