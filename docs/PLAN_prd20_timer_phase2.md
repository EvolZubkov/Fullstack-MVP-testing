# План реализации PRD-20 Фаза 2 (устойчивый timed-таймер)

**Статус:** реализовано и локально верифицировано 2026-07-02 (коммит `2632991`,
2932 теста + Playwright); LMS-валидация reload/suspend-семантики целевой LMS —
техдолг ДО включения в прод. Спека: [PRD-20](specs/prd-20/timer-integrity-resume.md).

Фаза 1 сделана и верифицирована (монотонный `performance.now()`, `stopTestTimer`,
удаление `updateTimerDisplay`). Валидация reload/suspend-семантики на целевой LMS
отнесена в техдолг; поэтому каждый этап обязан **деградировать к Фазе 1** при
отсутствии/сбое персистентности. Ниже — фактически реализованный план;
существенные отклонения от исходного черновика отмечены пометкой
«[отклонение]».

## 1. Модель активного времени

Лимит времени — свойство ПОПЫТКИ (N минут). `cmi.total_time` копит активное
время по всей регистрации SCO (все попытки и сессии). Поэтому «израсходовано в
этой попытке» вычисляется от базовой отметки, снятой на старте попытки:

```text
consumed = (total_time_now - baselineTotalSec)          // закоммиченные сессии этой попытки
         + floor((performance.now() - sessionStartPerf) / 1000)  // живое время текущей сессии
remaining = limitSeconds - consumed
```

- `baselineTotalSec` снимается один раз при старте попытки (значение
  `cmi.total_time` в секундах) и хранится в `suspend_data`.
- `total_time` обновляется LMS только на завершении сессии, поэтому текущая
  сессия учитывается через `performance.now()` (монотонно, kill не важен для
  живого отсчёта).
- Семантика получается «активное время»: время, пока SCO закрыт, не идёт
  (`total_time` его не копит) — это закрывает открытый вопрос политики (5.13) в
  пользу «пауза при закрытии», честной для экзамена.

## 2. Изменения suspend_data

Аддитивно, корневой объект дополняется ключом `timer` (существующие ключи не
трогаются):

```json
{
  "attemptsUsed": 0,
  "attempts": [],
  "currentSession": { "...": "как в PRD-4/PRD-19" },
  "timer": { "limitMinutes": 0, "baselineTotalSec": 0, "sig": "" }
}
```

- Отсутствие ключа `timer` = legacy/деградация → поведение Фазы 1.
- `sig` — keyed djb2-checksum над `limitMinutes` + `baselineTotalSec`, пишется
  **всегда** (tamper-evidence вошла в v1, см. этап 2f). [отклонение] В черновике
  подпись предполагалась опциональной (только при анти-чит-объёме) и HMAC-объёма;
  по факту — обязательное поле `sig` с обфускация-грейд djb2 (ключ в пакете),
  подписывающее только anchor, а не весь блоб `suspend_data`.

## 4. Этапы (каждый самостоятельно верифицируем + деградация)

- **2a. Плуминг baseline (read-only).** [реализовано] Аксессор `total_time`
  (`readTotalTimeSec`) + парсер `parseScormDuration`; снятие `baselineTotalSec`
  и запись блока `timer` на старте попытки (`writeTimerAnchor`). Поведение
  таймера НЕ меняется. Риск: низкий. Проверка: блок записан, регрессий нет.
- **2b. Восстановление из активного времени (P1).** [реализовано] В `initTimer`:
  если anchor есть — `remaining` из `total_time` (см. §1); если истёк —
  истечение по 5.14; иначе старт с восстановленным остатком. Нет anchor /
  `total_time` ненадёжен → Фаза 1. Риск: средний.
- **2c. Периодический commit (kill-устойчивость).** [реализовано] Раз в **10 с**
  (`TIMER_COMMIT_MS`, решение §8) `SetValue(cmi.session_time, elapsed)` +
  `Commit` (`commitSessionTime`/`startTimerCommit`). Аддитивно, на завершении
  перезаписывается финальным значением. Риск: низкий.
- **2d. Возобновление прогресса timed (P2).** [реализовано] Снят ранний `return`
  в `saveCurrentSession` (остаётся только для adaptive); `determineRecovery`
  отдаёт `restore` для timed, когда anchor позволяет восстановить остаток, иначе
  `show_last_attempt`/`start_fresh` (ученик не получает полный лимит молча).
  Зависит от 2b. Риск: средний (общий путь persistence).
- **2e. Единообразное продолжение router (mid-topic).** [реализовано]
  Персистятся `currentRouterTopic` + `currentPageIndex`; на восстановлении, если
  тема незавершена и не адаптивна — `RouterFlow.resumeRouterTopic`
  реконструирует её чанк (`buildTopicChunk`) и входит на сохранённой позиции
  вместо сброса к странице-маршрутизатору; при неудаче — откат на router-page.
  Зависит от 2d. Риск: средний (трогает router-флоу PRD-4).
- **2f. Анти-чит (вошёл в v1).** [реализовано, с отклонением] Tamper-evidence на
  anchor: keyed **djb2-checksum** (ES5-безопасно, без `Math.imul`/`SubtleCrypto`)
  над `limitMinutes` + `baselineTotalSec`, поле `sig`. Несовпадение подписи или
  legacy без подписи → anchor трактуется как отсутствующий (нет resume) + флаг
  `state.timerAnchorTampered`. [отклонение] В черновике был HMAC-обёртка ВСЕЙ
  `suspend_data` (высокий риск — оборачивает всю персистентность всех тестов);
  по факту подписывается ТОЛЬКО anchor, поэтому высокий риск не материализовался.
  [отклонение] Watchdog отката настенных часов **не реализован**: модель
  активного времени не держит клиентские часы в контуре доверия, клок-откат
  выигрыша не даёт; вместо него — флаг аномалии при регрессе `total_time` ниже
  baseline (`consumed < 0` клампится к 0). [отклонение] Счётчики reload/сессий
  **отложены** (низкая ценность в модели активного времени). Верификация подписи
  деградирует мягко (провал → игнор anchor + флаг, не крах persistence).

### Взаимодействие с режимами PRD-4 (единообразное продолжение)

Цель — продолжение с точной позиции везде, где осуществимо.

| Режим | Продолжение контента | Как |
| --- | --- | --- |
| `linear_flat` / `linear_by_topics` / `section_linear` | Точный вопрос, в т.ч. внутри темы | `restore` → `currentIndex` (снятие timed-guard, 2d) |
| `router_by_topics` (не-адаптивная тема) | Внутри незавершённой темы | 2e: персист `currentRouterTopic` + `currentPageIndex`, реконструкция чанка |
| Адаптив (standalone или тема в router) | Не восстанавливается (исключение) | переигрывание / последний результат |

Тест-таймер восстанавливается во всех режимах (active-time anchor). Секционные
таймеры — сброс при повторном входе (PRD-4). Переигрывание не даёт «фри тайм»:
active-time считает израсходованное время независимо от повтора контента.

## 5. Деградация (условие безопасной отсрочки валидации)

Единый принцип для всех этапов: любой сбой персистентности возвращает к
поведению Фазы 1, не ломая прохождение, в том числе тестов без лимита. Триггеры
деградации:

- нет ключа `suspend_data.timer` (legacy);
- ошибка чтения/парсинга `cmi.total_time` или `GetLastError != 0`;
- непройденная подпись (этап 2e);
- `total_time` ведёт себя аномально (например, меньше baseline).

## 6. Риски и техдолг

- **Радиус поражения на suspend_data.** Ключ `timer` аддитивен; снятие guard
  меняет персистентность timed. Сеть безопасности — деградация (§5).
- **Нет валидации на WebTutor сейчас** — в техдолге, обязательна ДО включения в
  прод. Деградация гарантирует отсутствие регресса, если LMS ведёт себя иначе.
- **Запись `session_time`** — аддитивна, перезаписывается на terminate.
- **Tamper-evidence (2f)** — реализована как keyed djb2-checksum ТОЛЬКО на anchor,
  а не HMAC на весь блоб; исходный «наивысший риск» (обёртка всей персистентности)
  тем самым снят. Провал подписи деградирует мягко (игнор anchor + флаг).

## 7. Верификация

Локально (до техдолга LMS):

- Playwright/рантайм: anchor присутствует/отсутствует; форсированные значения
  `total_time`; истечение на восстановлении; деградация при отсутствии anchor.
- Парсер ISO-длительности и расчёт `consumed` — точечные проверки.
- Сборка SCORM-пакета + существующий тест-сьют зелёные.

Техдолг (на целевой LMS, до выката): reload в середине, kill вкладки при
периодическом commit, откат часов, множественные reload — по PRD-20 §10 Фаза 2.

## 8. Решения (приняты при реализации)

1. **Объём анти-чит (этап 2f)** — анти-чит ВКЛючён в v1, но не HMAC на всю
   персистентность: keyed djb2-checksum ТОЛЬКО на anchor (`limitMinutes` +
   `baselineTotalSec`), обфускация-грейд (ключ в пакете) — дезтеррент без высокого
   риска. Watchdog отката часов и счётчики reload/сессий — не вошли (см. 2f).
2. **Интервал периодического commit** — **10 сек** (`TIMER_COMMIT_MS`); окно
   потери при kill ≤ 10 сек.
3. **UX истечения (5.14)** — грейс-тост «Время теста истекло» + `submit(true)`
   при истечении на восстановлении (не немой submit, без отдельного экрана).
