# PRD-49. Настраиваемые заголовки блоков итогов

Дата: 2026-08-12. Статус: СПЕЦИФИКАЦИЯ СОГЛАСОВАНА, реализация не начата.

## 1. Задача

Заголовки блоков на экране итогов зашиты в макет шаблона: «По шкалам», «Ваш результат»,
«Результаты по темам», «Рекомендации». Автор теста не может ни переформулировать их под свою
методику, ни убрать. Настройками регулируется только показ блока целиком.

Вторая беда — дублирование внутри карточки показателя. Карточка состоит из четырёх слотов
(название, значение, уровень, пояснение), и когда показатель несёт не вердикт, а пояснительный
текст, автору приходится занимать подводкой сразу два слота: название переменной и метку исхода.
На экране это читается как два заголовка об одном и том же. Убрать лишний нечем: очистка метки
исхода гасит весь баннер вместе с текстом.

Автор получает право переформулировать и выключать надписи, а карточка показателя — независимое
управление своими слотами.

## 2. Решения, которые нельзя пересматривать

1. **Надпись объявляет ШАБЛОН, значение хранит ТЕСТ.** Перечень надписей и их умолчания живут в
   манифесте шаблона; тест хранит только отклонения от них. Шаблон, не объявивший надписей,
   печатает свои строки как сегодня.
2. **Формулировка общая для всех экранов, с правом переопределить в отчёте.** Автор правит один
   раз — меняется на итогах, адаптивных итогах, итогах раздела и в отчёте. Отчёт может говорить
   иначе, если автор этого захотел.
3. **Выключение — тумблер, а не пустая строка.** Три состояния различимы явно: не трогал (текст
   шаблона), своя формулировка, надписи нет.
4. **Данные не стираются ради вида.** Метка уровня и название показателя остаются в базе — они
   нужны отчёту, аналитике и выгрузке. Гасится показ слота, а не содержимое.
5. **Разрешение надписей — одна функция на всех.** Веб-хост, пакет SCORM и отчёт читают один и
   тот же ответ; ни один хост не считает надписи сам.

## 3. Структура экрана итогов

Экран получает два уровня заголовков вместо одного.

```text
[вводный блок автора]                        без заголовка, как сегодня
H2  Ваш результат                            results.heading
    H3  Общий балл       кольцо и три числа       results.summary
    H3  По шкалам        диаграмма и шкалы        results.scales
    H3  По показателям   карточки показателей     results.indicators
    H3  По темам         карточки тем             results.topics
H2  Рекомендации                              results.recommendations
        Пройти обучение / Мероприятия / Материалы
```

Порядок четырёх подблоков — настройка теста `resultsBlockOrder`. Умолчание — «Общий балл, По
шкалам, По показателям, По темам»: оно совпадает с нынешним порядком макета, поэтому вид уже
собранных тестов не меняется сверх переезда самих заголовков. Ключ, отсутствующий в сохранённом
порядке, дописывается в конец по порядку шаблона — подблок, добавленный будущим шаблоном, не
ломает сохранённый выбор. Неизвестный ключ игнорируется.

Правила печати.

- Зонтик «Ваш результат» печатается, только если виден хотя бы один подблок.
- Видимость подблока и его заголовок независимы: выключенный заголовок не убирает блок, скрытый
  блок уносит свой заголовок с собой. Видимость по-прежнему решает `shared/template/results-blocks`.
- Разделители между подблоками остаются при выключенном заголовке: они разграничивают блоки, а не
  подписывают их.
- Та же иерархия и те же ключи действуют на адаптивных итогах, на итогах раздела и в отчёте.

Следствие для существующих тестов: надпись «Ваш результат» переезжает с блока показателей на
зонтик, а показатели получают «По показателям». Значений автора это не рушит — их сегодня нет.

## 4. Модель надписи

**Надпись** — именованная строка интерфейса, объявленная шаблоном, с текстом по умолчанию,
которую автор теста может переформулировать или выключить.

### 4.1. Объявление в манифесте

Надписи объявляются разделом верхнего уровня `labels[]`, а не полем внутри
`contentTemplates[].settings[]`: одна надпись живёт на нескольких экранах, а `settings[]` по
природе принадлежат одному варианту.

```json
{
  "key": "recommendations.courses",
  "group": "Группы рекомендаций",
  "label": "Подпись группы курсов",
  "default": "Пройти обучение",
  "defaults": { "report": "Рекомендации по курсам" }
}
```

- `key` — семантический ключ, по нему макет обращается к надписи.
- `group` — группировка в редакторе; пятнадцать полей сплошным списком нечитаемы.
- `label` — подпись поля для автора.
- `default` — текст по умолчанию, обязателен.
- `defaults.<экран>` — умолчание того экрана, где оно отличается от общего.

### 4.2. Хранение значений

- Общий словарь — `tests.design_settings_json.labels`: `{ "results.scales": { "on": false } }`,
  `{ "results.indicators": { "on": true, "text": "Профиль стилей" } }`. Ключа нет — берётся текст
  шаблона.
- Порядок подблоков — `tests.design_settings_json.resultsBlockOrder`.
- Переопределения отчёта — `tests.report_settings_json.labels`. Пусто — как на экране итогов.

Новых колонок не заводится.

### 4.3. Разрешение

`shared/template/labels.ts` отвечает на вопрос «какой текст печатать» для конкретного экрана:
умолчание шаблона, поверх него значение теста, поверх него переопределение экрана. Результат —
карта «ключ → строка», где пустая строка означает «не печатать». Роль та же, что у
`shared/template/results-blocks` для видимости блоков.

Макеты печатают из контекста и гейтят на пустоте:

```text
{{#if labels.results.scales}}<h3 class="tb-scene__subhead">{{labels.results.scales}}</h3>{{/if}}
```

## 5. Перечень надписей

| Группа | Ключ | Умолчание |
| --- | --- | --- |
| Первый уровень | `results.heading` | Ваш результат |
| Первый уровень | `results.recommendations` | Рекомендации |
| Второй уровень | `results.summary` | Общий балл |
| Второй уровень | `results.scales` | По шкалам |
| Второй уровень | `results.indicators` | По показателям |
| Второй уровень | `results.topics` | По темам |
| Группы рекомендаций | `recommendations.courses` | Пройти обучение (отчёт: Рекомендации по курсам) |
| Группы рекомендаций | `recommendations.events` | Мероприятия (отчёт: Рекомендуемые мероприятия) |
| Группы рекомендаций | `recommendations.assets` | Материалы |
| Числа сводки | `facts.questions` | вопросов |
| Числа сводки | `facts.correct` | верно |
| Числа сводки | `facts.points` | баллов |
| Карточка темы | `topic.correct` | Правильно |
| Карточка темы | `topic.points` | Баллов |
| Итоги раздела | `section.eyebrow` | Итоги раздела |

Заголовки самих экранов («Тест завершён» на адаптивных итогах, «Раздел «X»» на итогах раздела) в
перечень не входят: это заголовки экрана, а не блока.

## 6. Слоты карточки показателя и шкалы

Карточка остаётся композицией из четырёх слотов, но каждый слот получает независимое управление
показом.

| Слот | Источник | Чем управляется |
| --- | --- | --- |
| Название | метка переменной результата или имя шкалы | тумблер «Показывать название» |
| Значение | вычисленное значение | «Видимость для обучающегося» (`learner_visibility`) |
| Уровень | метка исхода или метка зоны | тумблер «Показывать уровень» |
| Пояснение | текст исхода или зоны | наличие текста |

Тумблеры хранятся в `config_json` переменной результата и шкалы (`showName`, `showLevel`), новых
колонок не требуется. В редакторе они стоят рядом с «Видимостью для обучающегося», которая уже
управляет слотом значения.

Обязательная правка макетов: баннер печатается, если есть метка уровня ИЛИ пояснение. Сегодня
`{{#if levelLabel}}` оборачивает и пояснение, поэтому «текст без заголовка» невыразим, а очистка
метки уносит текст молча.

Почему гасится показ, а не чистятся данные (решение 4 раздела 2): пустая метка сегодня не даёт
пустого слота. У числовой зоны нормализатор выбрасывает пустую метку
(`shared/scales/interpretation.ts`), а читатель печатает `label ?? level` — на экран выходит КОД
уровня. У строкового исхода результат зависит от того, дошла ли до сервера пустая строка или ключ
отброшен: во втором случае нормализатор подставляет код исхода. Ни то, ни другое автору не видно.

Правило для руководства автора: одна надпись — один смысловой слот. Зонтик говорит, что за экран,
подзаголовок — что за блок, название карточки — что измеряли, заголовок баннера — вердикт, текст —
пояснение. Лишний слот выключается, а не заполняется пересказом соседнего.

## 7. Где автор правит

- «Оформление» → блок «Итоги» получает подраздел «Заголовки и подписи»: строка на надпись —
  тумблер и поле, в поле подсказкой стоит текст шаблона. Строки сгруппированы по `group`.
- Там же — порядок четырёх подблоков.
- «Оформление» → «Отчёт»: тот же список, каждая строка по умолчанию в состоянии «как на экране
  итогов» и переводится в свою формулировку по месту. Признак `scope` этих полей — `appearance`:
  они про облик документа, а не про то, что в него попадает.
- Тумблеры «Показывать название» и «Показывать уровень» — в редакторе переменной результата и в
  редакторе шкалы.

## 8. Проводка

- Веб-хост читает разрешённый словарь при сборке контекста итогов и отчёта.
- SCORM: сборщик кладёт УЖЕ РАЗРЕШЁННЫЙ словарь и порядок подблоков в `test.json` рядом с прочими
  настройками дизайна. В LMS другого источника факта у рантайма нет — так же устроен признак
  выдачи отчёта.
- Отчёт PDF читает тот же словарь со слоем переопределений.
- Публикация: снапшот замораживает ряд теста целиком вместе с `design_settings_json`, поэтому
  надписи фиксируются вместе с версией. Отдельного механизма не нужно.

## 9. Контракт шаблона и совместимость

- Спека формата шаблона поднимается до 1.4.0: раздел манифеста `labels[]`, контекст `labels.*`,
  умолчания по экранам, порядок подблоков итогов.
- Статические проверки при загрузке шаблона: надпись, использованная макетом, должна быть
  объявлена; объявленная надпись обязана иметь `default`.
- Сохранённое у теста значение с ключом, которого шаблон не знает, игнорируется молча: шаблон
  могли сменить.
- Шаблон без `labels[]` печатает свои жёсткие строки, подраздел настроек у него не показывается.
- Шаблон «Сертификация» приводится к тому же набору вручную: паритет между шаблонами гард не
  ловит, он проверяет только раскладки.

## 10. Проверка

- Юнит: разрешение надписей (умолчание, своя формулировка, выключение, неизвестный ключ,
  переопределение отчёта); порядок подблоков (лишний ключ, недостающий ключ); разъединение слотов
  карточки — пояснение без метки печатается.
- Рендер экрана итогов: зонтик при одном видимом подблоке, выключенный заголовок, переставленный
  порядок.
- Приёмка в браузере: ученический прогон итогов и отчёта.
- Отладочный плеер: прогон собранного пакета — надписи и порядок доехали до рантайма.
- Отчёт PDF проверяется отдельно, включая переопределённую формулировку.

## 11. Порядок работ

1. Ядро: разрешение надписей, контракт манифеста, четыре макета стандартного шаблона, контекст
   обоих хостов.
2. Редактор: подраздел «Заголовки и подписи» и порядок подблоков.
3. Карточка показателя и шкалы: разъединение слотов, два тумблера.
4. Отчёт: слой переопределений.
5. Паритет шаблона «Сертификация», документация — спека формата 1.4.0, руководство автора.

## 12. Что сознательно не делается

- Заголовки экранов не настраиваются: настраиваются заголовки блоков и подписи групп.
- Перенос пояснительного текста показателя в блок рекомендаций или во вводный блок итогов не
  рассматривается: текст зависит от исхода показателя и принадлежит показателю.
- Формулировки за автора не переписываются: дублирование порождено моделью карточки, а не словами.
