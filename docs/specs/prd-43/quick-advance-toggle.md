# PRD-43: Быстрый переход к следующему вопросу — отдельный переключатель

**Версия:** 1.0
**Статус:** Требования согласованы 2026-08-05, реализация не начата
**Связанные документы:** [PRD-19](../prd-19/skip-return-navigation.md) (возврат к неотвеченным
вопросам, откуда вынесен переключатель)
**Зависимости:** PRD-19 (`allowReturnToUnanswered`, `shared/template/question-nav.ts`,
паритет веб/SCORM через `buildQuestionNav`)

## 1. Обзор

### 1.1 Контекст

Переключатель «Разрешить возврат к неотвеченным вопросам» (`allowReturnToUnanswered`, PRD-19)
сейчас задаёт ДВА независимых по смыслу эффекта разом:

1. доступность навигации «Назад» / «Пропустить» / «К обзору» и карты-индикатора прогресса;
2. требуется ли отдельное нажатие «Далее» после «Отправить ответ», или ответ фиксируется и
   происходит переход к следующему вопросу одним кликом.

Сейчас эффект (2) жёстко привязан к эффекту (1) наоборот: возврат ВЫКЛючен — один клик и
фиксирует ответ, и переходит дальше; возврат ВКЛючен — два клика («Отправить ответ», затем
отдельно «Далее»). Автору теста бывает нужна независимая комбинация: например, разрешить
возврат к пропущенным вопросам, но при этом не заставлять учащегося лишний раз нажимать «Далее»
после каждого ответа.

### 1.2 Цель

1. Вынести эффект (2) в отдельный переключатель `quickAdvance`, независимый от
   `allowReturnToUnanswered`. Работоспособны все 4 комбинации.
2. Существующие тесты не меняют поведения после выкатки: значение нового поля при миграции
   вычисляется из текущего `allowReturnToUnanswered` каждой строки.
3. Паритет веб- и SCORM-хоста сохраняется через общее ядро `shared/template/question-nav.ts`
   (тот же принцип, что и у остальной навигации PRD-19).

### 1.3 Метрики успеха

| Цель | Метрика |
| --- | --- |
| Независимость переключателей | Все 4 комбинации `allowReturnToUnanswered` x `quickAdvance` дают корректную навигацию на обоих хостах |
| Обратная совместимость | Тест без явной миграции (весь существующий парк) не меняет поведения и SCORM-экспорта |
| Единая семантика | `buildQuestionNav` — единственное место, решающее «один клик или два»; веб и SCORM читают из него одно и то же |

## 2. Пользователи

Автор теста включает/выключает переключатель в панели настроек теста (блок «Ограничения»,
рядом с «Разрешить возврат к неотвеченным вопросам» и «Позволить изменять ответ»). Учащийся видит
результат в виде количества кликов на футере вопроса — эффект появляется в существующей вёрстке
экрана вопроса, без нового экрана.

---

## 3. Ключевые понятия

### 3.1 Новое поле `tests.quick_advance`

Булево, `NOT NULL DEFAULT false`. Независимо от `allow_return_to_unanswered`. По умолчанию
`false` — совпадает с сегодняшним дефолтом нового теста (`allowReturnToUnanswered = true` →
сегодня это всегда два клика), то есть создание теста «с нуля» после выкатки ведёт себя как
сегодня, пока автор явно не включит быстрый переход.

### 3.2 Разделение `flexible` и `twoStep` в `buildQuestionNav`

`shared/template/question-nav.ts` сейчас использует один флаг `flexible`
(`allowReturnToUnanswered`) для двух разных решений. Он остаётся ответственным ТОЛЬКО за
видимость «Назад» / «Пропустить» / «К обзору». Решение «один клик или два» выносится в новый
вычисляемый вход `quickAdvance` (передаётся хостом из настроек теста) и комбинируется с уже
существующим `showAccept` (режим «Показывать правильность ответа» — там показ фидбека уже
требует отдельного шага и имеет приоритет):

```text
twoStep = showAccept || !quickAdvance

не committed, twoStep:
    основная кнопка фиксирует ответ (не переходит) — «Отправить ответ» / «Принять»

не committed, !twoStep:
    основная кнопка фиксирует ответ И сразу переходит дальше — «Далее» / «Завершить тест»

committed (в т.ч. учащийся вернулся к уже отвеченному вопросу):
    основная кнопка только переходит дальше — «Далее»
```

`showBack` / `showSkip` / `showReview` остаются производными исключительно от `flexible`, как
сейчас. Это даёт 4 работоспособные комбинации:

| `allowReturnToUnanswered` | `quickAdvance` | Навигация Назад/Пропустить/Обзор | Клики на ответ |
| --- | --- | --- | --- |
| выкл | выкл (НОВАЯ комбинация) | нет | 2 («Отправить ответ» → «Далее») |
| выкл | вкл (сегодняшнее поведение) | нет | 1 |
| вкл | выкл (сегодняшнее поведение) | да | 2 |
| вкл | вкл (НОВАЯ комбинация) | да | 1 |

`quickAdvance` принудительно не действует, когда включено «Показывать правильность ответа»
(`showAccept`) — фидбек обязан быть показан отдельным шагом до перехода, это не меняется.

### 3.3 SCORM-рантайм уже содержит нужный примитив

В `server/scorm/template/app/actions/answers.js` функция `next()` уже сегодня идемпотентно
фиксирует ответ (`questionStatuses[...] = 'answered'`) И переходит дальше — независимо от
`flexible`. Разделение «один клик/два» на SCORM-хосте достигается тем, КАКОЕ действие
`buildQuestionNav` выбирает для основной кнопки (`answer-submit` → `confirmAnswer()`, только
фиксирует; `answer-next` → `next()`, идемпотентно фиксирует и переходит). После правки
`buildQuestionNav` и передачи `quickAdvance` в `TEST_DATA` рантайм-функции `next()` /
`confirmAnswer()` менять не требуется.

На веб-хосте (`client/src/pages/learner/take-test.tsx`) сегодня для действия `answer-next`
жёстко вызывается `handleStandardContinue` (только переход, без фиксации) — исторически
рассчитанный на то, что «Далее» появляется лишь после отдельного «Отправить ответ». Есть
неиспользуемый `handleNext` (фиксирует и переходит), написанный ранее, но никуда не подключённый.
Веб-хост приводится к тому же паттерну, что и SCORM: обработчик действия `answer-next`
объединяется в одну идемпотентную функцию «зафиксировать (если ещё не зафиксирован) + очистить
фидбек-состояние + перейти дальше», а не в выбор между двумя отдельными хендлерами.

### 3.4 Адаптивный режим — вне охвата

Адаптивный тест (`testMode === "adaptive"`) не связан с `allowReturnToUnanswered` вовсе: его
навигационное состояние строится отдельным, всегда «строгим» блоком
(`flexible: false` захардкожено и на веб-хосте, и в `adaptiveRender.js`), и его собственный
обработчик `answer-next` уже сегодня либо продолжает после показанного фидбека, либо фиксирует
и переходит одним кликом — то есть уже ведёт себя как `quickAdvance = true`, когда фидбек не
показан. `quickAdvance` — поле уровня «стандартного» теста (наравне с `allowReturnToUnanswered`,
`allowAnswerChange`, `showSectionResults`) и на адаптивный режим не распространяется; правок в
адаптивной ветке не требуется.

## 4. Функциональные требования

| ID | Требование |
| --- | --- |
| FR-01 | Автор может включить `quickAdvance` независимо от `allowReturnToUnanswered` |
| FR-02 | Все 4 комбинации `allowReturnToUnanswered` x `quickAdvance` дают корректную навигацию на обоих хостах (см. таблицу §3.2) |
| FR-03 | `quickAdvance` заблокирован (принудительно неактивен, с пояснением) в панели автора, пока включено «Показывать правильность ответа» |

| FR-06 | Решение «один клик или два» — единая функция `buildQuestionNav` (`shared/template/question-nav.ts`); ни один хост не дублирует эту логику у себя |
| FR-07 | Адаптивный режим не читает и не зависит от `quickAdvance` (§3.4) |

## 5. Модель данных

### 5.1 `tests.quick_advance` (новая колонка)

```ts
// shared/schema.ts, рядом с allowReturnToUnanswered / allowAnswerChange
quickAdvance: boolean("quick_advance").notNull().default(false),
```

Миграция генерируется штатным трактом (`drizzle/README.md`), НЕ через легаси `migrations/`
(тот каталог с 2026-07-18 — история, деплой его не катит):

```bash
node_modules/.bin/drizzle-kit generate --name=prd43_quick_advance
```

даёт `ALTER TABLE tests ADD COLUMN quick_advance boolean DEFAULT false NOT NULL;`. Бэкфилл —
отдельная data-миграция (`drizzle/README.md`, «Data-миграция»):

```bash
node_modules/.bin/drizzle-kit generate --custom --name=prd43_quick_advance_backfill
```

пустой файл заполняется вручную:

```sql
UPDATE tests SET quick_advance = NOT allow_return_to_unanswered;
```

`shared/schema.ts` и оба файла из `drizzle/` (+ `drizzle/meta/`) коммитятся вместе. Колонка не
зависит от `allow_return_to_unanswered` на уровне ограничений БД (как и `allow_answer_change`
сегодня не имеет CHECK на мьютекс с `show_correct_answers` — мьютекс FR-03 проверяется только в
UI редактора).

### 5.2 `QuestionNavState` (`shared/template/question-nav.ts`)

Новое поле `quickAdvance: boolean`. `buildQuestionNav` вычисляет `twoStep = showAccept ||
!quickAdvance` и использует его вместо сегодняшнего безусловного разделения по `flexible`
(см. §3.2 для точной таблицы решений).

### 5.3 Проброс поля по цепочке (по образцу `allowReturnToUnanswered`)

- `server/services/test-settings.ts` — тип payload + дефолт `false` при создании теста;
- `server/routes/tests.ts` — zod-поле, чтение/запись при создании и обновлении теста (4 места,
  как у `allowReturnToUnanswered`);
- `server/routes/attempts.ts` — поле в ответе старта/резюме попытки;
- `server/scorm/builders/test-json.ts` — поле в `TEST_DATA` для SCORM-пакета;
- `server/scorm/template/app/render/mainRender.js` — проброс `!!TEST_DATA.quickAdvance` в вызов
  `buildQuestionNav` (единственная правка рантайма, см. §3.3);
- `client/src/pages/learner/take-test.tsx` — поле в `navSettings`, в построении `questionNav`
  (стандартный, НЕ адаптивный блок), объединение обработчика действия `answer-next` (§3.3);
- `client/src/features/tests/editor/test-editor.types.ts` /
  `client/src/features/tests/editor/test-editor.mappers.ts` — поле модели редактора: дефолт
  нового теста, чтение существующего (отсутствие поля в ответе API → консервативно `false`,
  как у `allowAnswerChange`), сборка payload на сохранение.

## 6. UI автора

В панели «Ограничения» (`basic-settings-section.tsx`), третьим переключателем после «Позволить
изменять ответ до завершения»:

- **«Переходить к следующему вопросу сразу после ответа»**, описание «Без отдельного нажатия
  «Далее»: ответ фиксируется и сразу открывается следующий вопрос.»;
- НЕ зависит от состояния «Разрешить возврат к неотвеченным вопросам» — включён/выключен
  самостоятельно;
- заблокирован (`disabled`, с пояснением тем же паттерном, что у `changeDisabled`), пока включено
  «Показывать правильность ответа»: «Недоступно при показе правильности ответа: нужно увидеть
  фидбек перед переходом.».

## 7. Совместимость и миграция

- Миграция БД обязательна (новая NOT NULL колонка + отдельная data-миграция с бэкфиллом
  `quick_advance = NOT allow_return_to_unanswered`, см. §5.1). После миграции поведение и
  SCORM-экспорт существующих тестов не меняются.
- Тест, экспортированный в SCORM ДО выкатки, не содержит поля `quickAdvance` в своём
  `TEST_DATA` — не в охвате (SCORM-пакеты не обновляются ретроактивно, как и для прошлых полей
  PRD-19).
- Компенсирующих правок в адаптивном режиме не требуется (§3.4).

## 9. Критерии приёмки

- [ ] Панель автора: новый переключатель, независимый от «возврата к неотвеченным», блокируется
      при включённом «Показывать правильность ответа».
- [ ] Все 4 комбинации из таблицы §3.2 воспроизведены на веб-хосте (ручная/Playwright-проверка).
- [ ] Тот же результат воспроизведён в SCORM-пакете (`npm run scorm:sample` /
      `npm run scorm:player`) для всех 4 комбинаций.
- [ ] `shared/template/question-nav.test.ts` содержит кейсы на все комбинации `flexible` x
      `quickAdvance` x `showAccept`.
- [ ] Существующий тест (без ручной правки нового поля) после миграции ведёт себя как до
      выкатки — регрессионная проверка на живой/dev-копии.
- [ ] Адаптивный тест не регрессирует (не читает и не зависит от `quickAdvance`).

## 10. Решённые вопросы

| Вопрос | Решение |
| --- | --- |
| Нужны ли все 4 комбинации `allowReturnToUnanswered x quickAdvance`, или только связка с выкл-возвратом? | Все 4 — полная развязка переключателей |
| Что происходит с `quickAdvance`, когда включено «Показывать правильность ответа»? | Переключатель заблокирован (аналог мьютекса `allowAnswerChange` / `showCorrectAnswers`), фидбек всегда требует отдельного шага |
| Как мигрировать существующие тесты, чтобы их поведение не изменилось? | `quick_advance = NOT allow_return_to_unanswered` на момент миграции |
| Распространяется ли переключатель на адаптивный режим? | Нет — адаптивный режим не использует `allowReturnToUnanswered`/`quickAdvance`, его собственная навигация уже ведёт себя как быстрый переход при выключенном фидбеке |
