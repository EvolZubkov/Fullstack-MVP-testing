## 1. Обзор

### 1.1 Контекст

Аудит UX авторских разделов (`docs/AUDIT_UX_AUTHOR_CONTENT.md`, UX-01..13) выявил отсутствие
сквозной работы по оси контента и ряд несоответствий модели в редакторе вопроса. По итогам
проектирования утверждён эскиз `content-bank-explorer.html`; бизнес-решения зафиксированы в
`brd-content-axis.md` (BRC-CA-01..44). Настоящий PRD переводит их в функциональные требования.

Ключевая модель: ось контента (`Папка ⊃ Тема ⊃ Вопрос`) и ось сборки (тест ссылается и выбирает
из пула тем) — ОРТОГОНАЛЬНЫ. PRD-16 затрагивает ось контента и редактор вопроса; редактор тестов
(PRD-7) на старте не меняется.

### 1.2 Цель

- Объединить «Темы» и «Вопросы» в один раздел «Темы и вопросы» (единое дерево в языке списка
  «Тесты»), закрыв UX-01/03/06/07.
- Привести модель вопроса к требованиям: сложность (число, опциональная), медиа (только загрузка
  файла), конструкторы с валидацией, порядок и перемешивание вариантов.
- Согласовать терминологию типов с i18n.

### 1.3 Метрики успеха

| Метрика | Целевое значение |
| --- | --- |
| Тема и её вопросы в одном разделе со сквозной навигацией | Достигнуто (один раздел, дерево) |
| Сохранение вопроса без правильного ответа или с < 2 вариантами | 0 случаев (валидация блокирует) |
| Воспроизведение медиа вопроса в LMS офлайн | 100% (только загруженные файлы, бандлятся в SCORM) |
| Навязанная фиксированная таксономия сложности | 0 (сложность — число; уровни — свойство теста) |
| Расхождение терминов типов с i18n | 0 (подписи из `t.questions.*`) |

## 3. Функциональные требования

### 3.1 Блок A — единый раздел «Темы и вопросы»

- **FR-01.** Раздел «Темы и вопросы» (`/author/content`) показывает единое дерево
  `Папка (необязательная, вложенная) ⊃ Тема ⊃ Вопрос` в визуальном языке списка «Тесты»:
  колонки Название | Сложность | Вопросов | действия; корневой ярлык «Все темы (N)»; папки «(N тем)».
- **FR-02.** Тип вопроса — монохромная пиктограмма в ячейке названия (single=CircleDot,
  multiple=CheckSquare, matching=Unplug, ranking=ListOrdered); сложность — число в своей колонке;
  число вопросов темы — в колонке «Вопросов».
- **FR-03.** Над деревом: поиск по подстроке и панель фасетов (Тип, Сложность, Теги, Медиа, Автор,
  Область) с чипами активных условий и «Очистить всё»; дерево автораскрывается к совпадениям;
  счётчик «найдено / всего». Состояние фильтра переживает навигацию.
- **FR-04.** Создание — через FAB (папка/тема/вопрос); действия строки — через всегда видимое
  меню; редактирование темы и вопроса — в Drawer. Выбор темы/папки — Combobox с группировкой по
  папкам.
- **FR-05.** Переносы: вопрос → тема и тема → папка (через выбор-пикер, с проверкой выполнимости и
  прав); режим выбора с массовыми операциями (перенос, удаление); разрушающие операции — под
  `content-guard` (dry-run + `ContentImpactDialog`).
- **FR-06.** Cutover навигации: пункты «Темы» и «Вопросы» заменяются на «Темы и вопросы»;
  `/author/topics` и `/author/questions` редиректят на `/author/content`; старые страницы
  ретайрятся после паритета.

### 3.2 Блок B — сложность вопроса

- **FR-10.** `questions.difficulty` — целое 0–100, ОПЦИОНАЛЬНОЕ (nullable). Пусто = «Не задано».
  Миграция снимает `NOT NULL`; существующие значения сохраняются.
- **FR-11.** В дереве и списках сложность показывается ЧИСЛОМ; для `null` — «Не задано».
  Фиксированной таксономии уровней (легко/средне/сложно) на уровне вопроса нет.
- **FR-12.** В редакторе вопроса сложность задаётся конкретным значением: слайдер 0–100 + поле
  ввода числа + переключатель «Не задано»; при включении «Не задано» контролы установки значения
  скрываются, сохраняется `null`. Для НОВОГО вопроса по умолчанию «Не задано» включён (`null`).
- **FR-13.** Фасет «Сложность» в фильтре банка — интервал 0–100 (DS `Slider` range) + переключатель
  «Не задана» как гейт: при включении контролы интервала скрываются, фильтр отбирает вопросы без
  сложности.
- **FR-14.** Именованные уровни/метки сложности (имя + интервал, произвольное число) — свойство
  ТЕСТА (`adaptive_levels`), не темы/вопроса; в банке их нет. Серверные резолверы выдачи и
  аналитики корректно обрабатывают `null` (без подстановки значения).

### 3.3 Блок C — медиа вопроса

- **FR-20.** Медиа вопроса — один опциональный файл (изображение/аудио/видео), добавляемый ТОЛЬКО
  загрузкой через DS `FileUploader` в модальном окне «Загрузка медиа»; тип определяется
  автоматически по MIME.
- **FR-21.** Свободный ввод URL и ручной выбор «Тип медиа» исключаются. Внешние ссылки не
  поддерживаются: в SCORM-пакет бандлятся только загруженные файлы (`/uploads/...`,
  `server/scorm/builders/media-assets.ts`).
- **FR-22.** В Drawer вопроса медиа показывается вложением (DS `FileItem`): превью + «Заменить» +
  «Удалить».

### 3.4 Блок D — конструкторы вариантов и валидация

- **FR-30.** Конструктор вариантов соответствует типу: Один ответ — radio (ровно один правильный);
  Несколько ответов — чекбоксы (≥1 правильный); Соответствие — пары «левое ↔ правое»;
  Ранжирование — список с эталонным порядком.
- **FR-31.** Валидация выполняется до сохранения: тема выбрана; текст непустой; ≥2 непустых
  варианта; задан правильный ответ согласно типу (Один ответ — выбран; Несколько ответов —
  отмечен ≥1; Соответствие — все пары заполнены; Ранжирование — ≥2 элемента). Ошибки показываются
  баннером (`ou-banner--error`) вверху формы; «Сохранить» заблокирована.
- **FR-32.** Смена типа вопроса СОХРАНЯЕТ введённые варианты (тексты переносятся между типами без
  подтверждения; для Соответствия — в левую колонку); пересобирается только структура ответа
  (один правильный / несколько правильных / пары / порядок). Состояние каждого типа в форме
  сохраняется, поэтому возврат к прежнему типу восстанавливает его специфику (например, правую
  колонку Соответствия). Решение 2026-06-16 — заменяет прежнее подтверждение с потерей данных.

### 3.5 Блок E — порядок и перемешивание вариантов

- **FR-40.** Для типов Один ответ, Несколько ответов, Соответствие автор задаёт базовый порядок
  вариантов вручную (перетаскивание за ручку); порядок хранится как порядок элементов в
  `questions.dataJson`.
- **FR-41.** Переключатель «Случайный порядок вариантов» (= `questions.shuffle_answers`, по
  умолчанию включён) рядом с вариантами: включён — показ ученику в случайном порядке; выключен —
  в заданном базовом порядке. Миграция не требуется.
- **FR-42.** Ранжирование — исключение: заданный порядок есть эталон ответа, перемешивание при
  выдаче обязательно и без переключателя.
- **FR-43.** Тест по умолчанию выдаёт варианты строго по настройкам вопроса (порядок + «Случайный
  порядок вариантов»); отдельной настройки на уровне теста на старте нет.

### 3.6 Блок F — терминология

- **FR-50.** Названия типов вопросов берутся из i18n (`t.questions.singleChoice`/`multipleChoice`/
  `matching`/`ranking`): Один ответ / Несколько ответов / Соответствие / Ранжирование — во всех
  поверхностях (фасет фильтра, сегмент типа, тултипы пиктограмм, чипы). Хардкод подписей не
  допускается.

## 4. Модель данных

- `questions.difficulty` — снять `NOT NULL` (становится nullable; отсутствие = «Не задано»),
  default сохранить. Новая миграция.
- `questions.shuffle_answers` — без изменений (положительный смысл «Случайный порядок вариантов»,
  default `true`).
- Базовый порядок вариантов — порядок элементов в `questions.dataJson`; отдельной схемы нет.
- `questions.mediaUrl` / `questions.mediaType` — без изменений на уровне схемы; меняется модель
  ввода (только загрузка файла, тип авто).
- Новых таблиц на старте не требуется (переопределение выдачи тестом отложено, см. раздел 5).

## 5. Вне охвата и отложенное

- **FR-90 (ОТЛОЖЕНО — гипотеза).** Переопределение выдачи вариантов на уровне теста — возможность
  теста переопределить для конкретного вопроса (а) порядок вариантов и (б) случайность —
  ОТЛОЖЕНО до подтверждения гипотезы необходимости (решение 2026-06-16). При реализации — как
  расширение семьи переопределений пары (тест, вопрос) (PRD-15 блок D, `test_question_scoring`):
  резолвер «переопределение теста, иначе настройка вопроса», фиксация снапшотом, UI в модале
  «Оценка вопроса в тесте». До подтверждения редактор тестов (PRD-7) и вкладка «Оценка» не
  меняются. См. BRC-CA-44.
- Медиатека (повторное использование загруженных файлов) — отдельный будущий PRD.
- Cross-axis «где используется тема» из редактора теста — отдельная задача (UX-01).
- Серверные фильтры списка и bulk-эндпоинты — оптимизация при росте банка.

## 7. Приёмка

- Раздел соответствует утверждённому эскизу (светлая/тёмная темы); сквозная навигация работает.
- Миграция `difficulty` применяется; редактор сохраняет и очищает сложность; фильтр-интервал и
  «Не задана» сужают дерево.
- Медиа добавляется только загрузкой; внешние URL не вводятся; SCORM-пакет содержит файл.
- Невозможно сохранить вопрос без правильного ответа или с < 2 вариантами; ошибки — баннером.
- Смена типа вопроса сохраняет введённые варианты (без подтверждения), пересобирая только
  структуру ответа.
- Порядок вариантов меняется перетаскиванием; «Случайный порядок вариантов» переживает сохранение;
  Ранжирование всегда перемешано при выдаче.
- Термины типов едины с i18n.
- `npm run check`, `npm test`, сборка зелёные; покрытие не «накручивается» вне кода задач.
