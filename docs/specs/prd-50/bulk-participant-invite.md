# PRD-50. Приглашение участников теста списком

Дата: 2026-08-12. Статус: СПЕЦИФИКАЦИЯ СОГЛАСОВАНА, реализация не начата.
Связанные документы: `docs/plans/PLAN_MAGIC_LINK_SCOPE.md`.
Зависимости: PRD-13 (роли и права), механизм ссылки-приглашения (magic link) и его область.

## 1. Задача

Организатору нужно провести тестирование группы людей, которых в системе ещё нет: у него есть
список адресов и имён. Сегодня это собирается из двух не связанных между собой сценариев на
разных экранах: сначала импорт пользователей на странице «Пользователи», затем поиск этих людей
в диалоге назначения теста. По дороге теряются три вещи:

- участник получает ДВА письма — приглашение задать пароль и уведомление о назначении;
- результат рассылки нигде не виден: письма о назначении отправляются «выстрелил и забыл»
  (`server/routes/assignments.ts`), и организатор не узнаёт, кому письмо не дошло;
- если почта не доходит, раздать ссылки другим каналом нечем.

Требуется один сквозной сценарий: загрузить список, увидеть предпросмотр, назначить тест,
разослать ссылки и получить отчёт с возможностью выгрузить ссылки файлом.

## 2. Что уже есть и не переделывается

Ограничение доступа участника решено ранее и переиспользуется как есть.

1. Ссылка `/access/<token>` не является входом в систему: она ставит в сессию метку
   `session.magic = { assignmentId, testId }` (`server/routes/access.ts`).
2. Область такой сессии задана единым белым списком маршрутов
   (`server/middleware/magic-scope-rules.ts`): только этот тест, свои попытки по нему, свой
   результат и файлы отчёта. Всё остальное отдаёт `403 MAGIC_SCOPE`.
3. Клиент по метке пускает только `/learner/test/<id>` и `/learner/result/*`, остальное уводит
   на форму входа (`client/src/App.tsx`). Гейт первого входа при этом не срабатывает, поэтому
   пароль участнику не нужен.
4. У токена есть срок действия, отзыв и перевыпуск; в базе хранится только SHA-256.
5. Аккаунту с любой ролью, кроме `learner`, разовая ссылка не выдаётся — правило D-3, единая
   точка `server/services/assignment-link.ts`.

Отдельная роль «ограниченный пользователь» не заводится. Ограничение проверяется таблицей
маршрутов; вторая, ролевая, проверка разъедется с ней при первом же новом маршруте.

## 3. Решения, которые нельзя пересматривать

1. **Участнику не выпускается токен задания пароля.** Задав пароль, человек войдёт обычным
   входом, метки `magic` в сессии не будет, и он окажется в полноценном кабинете ученика.
   Признак «отправить приглашение» в этом сценарии не предлагается вовсе.
2. **Сырой токен нигде не сохраняется.** Выгрузка ссылок возможна только из отчёта только что
   выполненного прогона. Хранение сырых токенов равносильно хранению паролей открытым текстом.
3. **Роль участника — только «Ученик», группа не создаётся.** Колонки `role` и `group` во
   входном файле игнорируются: участник разовой рассылки не должен оседать в структуре
   организации и попадать под чужие групповые назначения.
4. **Точка входа — существующий диалог назначения теста.** Отдельный экран не заводится.
5. **Выпуск ссылки остаётся в единой точке** `assignment-link.ts` вместе с правилом D-3.

## 4. Сценарий

Вкладка «Списком из файла» в диалоге назначения теста (`client/src/components/assign-test-dialog.tsx`,
рядом с «Текущие», «Пользователи», «Группы»). Четыре состояния одного полотна, без модального
окна поверх модального.

1. **Загрузка.** Выбор файла (xlsx), ссылка на шаблон, поля «срок сдачи» и «срок действия
   ссылки» — те же, что на соседних вкладках, с той же связкой: срок ссылки подтягивается из срока
   сдачи, пока его не изменили вручную.
2. **Предпросмотр.** Таблица разобранных строк со статусом на каждой. Строки со статусом «ошибка»
   выбрать нельзя, остальные выбраны по умолчанию и снимаются вручную.
3. **Выполнение.** Один запрос, один ответ. Фонового задания и опроса состояния нет: при потолке
   строк из настроек (раздел 8) прогон занимает единицы секунд.
4. **Отчёт.** Сводка, перечень проблемных адресов с причинами и кнопка выгрузки ссылок. Возврат на
   вкладку «Текущие», где работают привычные отзыв и переотправка.

Входной файл: книга xlsx с колонками `email` и `name`. Прочие колонки игнорируются. Формат csv не
принимается: читатель книг (`server/utils/excel.ts`) отвергает всё, что не является пакетом OOXML.
Смежное расхождение в существующем импорте пользователей — поле выбора файла предлагает
`.csv,.xlsx,.xls`, хотя csv тот же читатель отвергнет, — зафиксировано как известный дефект и в
охват этой работы не входит.

## 5. Правила прохода по строке

| Ситуация | Действие |
| --- | --- |
| Адреса нет в системе | Создаётся учётка: роль «Ученик», статус `pending`, случайный пароль, `createdBy` — оператор. Письмо о задании пароля не отправляется |
| Адрес есть, роль только «Ученик» | Учётка переиспользуется. Имя из файла ставится, только если у учётки его нет |
| Адрес есть, роль с правами | Учётка не изменяется, тест назначается, письмо уходит без разовой ссылки |
| Учётка деактивирована | Строка помечается ошибкой и не обрабатывается |
| Тест уже назначен этому человеку | Второе назначение не создаётся: у существующего перевыпускается ссылка, прежняя отзывается |
| Адрес повторяется внутри файла | Схлопывается на предпросмотре: один адрес — одна строка |
| Адрес пуст или не похож на почтовый | Строка помечается ошибкой |

Строка обрабатывается независимо от прочих: сбой на одной не прерывает прогон, она попадает в
отчёт с причиной.

## 6. Письма

Видов писем два, оба существуют, меняется одна деталь.

- Участнику — письмо о назначении с разовой ссылкой `/access/<token>`.
- Аккаунту с правами — то же письмо без разовой ссылки, но адрес в нём ведёт на сам тест
  `/learner/test/<id>`, а не на общую страницу входа. Открывается через обычную авторизацию.
  Причина отсутствия быстрой ссылки в письме по-прежнему не раскрывается.

Исход отправки собирается по каждому адресу и возвращается в отчёте. Недоставка не отменяет
выпуск ссылки: ссылка остаётся действующей и попадает в выгрузку.

## 7. Выгрузка ссылок

Файл xlsx собирается на клиенте из уже полученного отчёта, второго обращения к серверу нет.
Колонки: адрес, имя, статус, ссылка, действует до.

Выгрузка доступна, пока открыт отчёт прогона. После закрытия диалога ссылку восстановить нельзя
(раздел 3, пункт 2); чтобы получить файл, придётся перевыпустить ссылки, а это отзовёт прежние,
включая уже доставленные письмами.

На шаге отчёта показывается предупреждение, что файл содержит действующие ключи доступа. Факт
выгрузки записывается в журнал: кто, какой тест, сколько ссылок. Сами ссылки в журнал не попадают.

## 8. Настройки системы

Раздел `limits` в `config/*.config.jsonc`, типизированный в `AppConfig` (`server/config.ts`).

```jsonc
"limits": {
  "participantsImportMaxRows": 500,
  "passwordEmailsPerHour": 3
}
```

- `participantsImportMaxRows` применяется и к предпросмотру участников, и к существующему импорту
  пользователей (`server/routes/users.ts`), где цифра сейчас зашита. Значение по умолчанию
  сохраняет нынешнее поведение.
- `passwordEmailsPerHour` заменяет зашитый предел в восстановлении пароля
  (`server/routes/auth.ts`) и в приглашении (`server/routes/users.ts`). Счётчик у них общий:
  оба выпускают токен задания пароля. Рассылки участников настройка не касается — там токены
  другого рода.

## 9. Функциональные требования

| Ном. | Требование |
| --- | --- |
| FR-01 | В диалоге назначения теста есть вкладка «Списком из файла» с четырьмя состояниями: загрузка, предпросмотр, выполнение, отчёт |
| FR-02 | Принимается книга xlsx с колонками `email` и `name`; колонки `role` и `group` игнорируются |
| FR-03 | Доступен шаблон файла для скачивания |
| FR-04 | Предпросмотр показывает по каждой строке статус: новый, существующий ученик, аккаунт с правами, деактивирован, уже назначен, ошибка с причиной |
| FR-05 | Строки со статусом ошибки не выбираются; прочие выбраны по умолчанию и снимаются вручную |
| FR-06 | Срок сдачи и срок действия ссылки задаются на вкладке и действуют на весь прогон |
| FR-07 | Отсутствующие учётки создаются с ролью «Ученик» и статусом `pending` |
| FR-08 | В этом сценарии не выпускается ни одного токена задания пароля |
| FR-09 | Существующая учётка переиспользуется; имя перезаписывается, только если оно пусто |
| FR-10 | Деактивированная учётка не обрабатывается и помечается ошибкой |
| FR-11 | Повторное назначение того же теста не создаёт второго назначения: ссылка перевыпускается, прежняя отзывается |
| FR-12 | Аккаунту с ролью, отличной от «Ученик», разовая ссылка не выдаётся; письмо ведёт на адрес теста |
| FR-13 | Отчёт содержит сводку и перечень проблемных адресов с причинами, включая недоставленные письма |
| FR-14 | Из отчёта выгружается файл xlsx со ссылками; выгрузка доступна только до закрытия диалога |
| FR-15 | Факт выгрузки и факт прогона записываются в журнал; сырые ссылки в журнал не пишутся |
| FR-16 | Потолок строк на файл и почасовой предел писем с ключом задания пароля берутся из настроек системы |
| FR-17 | Эндпоинты требуют права `assignments.manage` и `users.create` и области `assign` по данному тесту |

## 10. Критерии приёмки

1. Файл на 10 строк, из которых три адреса уже есть в системе (ученик, автор, деактивированный),
   один адрес повторяется дважды, один записан без «собаки». Предпросмотр показывает девять строк
   с верными статусами; строка без «собаки» и деактивированная не выбираются.
2. После прогона: новые учётки созданы с ролью «Ученик», письма о назначении ушли, писем о
   задании пароля не выпущено ни одного (проверяется по `password_reset_tokens`).
3. Ссылка из письма открывает тест, позволяет пройти его до конца и посмотреть результат.
   Попытка перейти в кабинет уводит на форму входа.
4. Аккаунт автора из списка получил письмо без разовой ссылки, адрес в письме ведёт на тест и
   открывается после входа по паролю.
5. Выгруженный файл содержит ссылки для всех участников прогона, включая тех, кому письмо не
   дошло; ссылка из файла работает так же, как из письма.
6. Повторный прогон тем же файлом не создаёт вторых назначений; ранее выданная ссылка перестаёт
   работать, новая работает.
7. Файл сверх потолка строк отклоняется с понятным сообщением; изменение потолка в настройках
   меняет границу без правки кода.

## 11. Вне охвата

- Признак «внешний участник» как свойство учётной записи (PRD-28) — здесь не вводится.
- Автоматическое гашение или удаление учёток после прохождения теста.
- Импорт участников из внешних систем и синхронизация списков.
- Массовая рассылка по уже назначенным участникам вне контекста загруженного файла — для этого
  остаются существующие переотправка и отзыв.
- Фоновое выполнение прогона с опросом состояния.

## 12. Объём работ

Схема базы не меняется, миграции нет.

Сервер:

1. Раздел `limits` в `server/config.ts` и трёх файлах `config/*.jsonc`, замена двух зашитых
   значений.
2. Новый сервис `server/services/participants-invite.ts`: разбор файла в строки со статусами и
   проход по выбранным строкам со сбором отчёта.
3. Два эндпоинта в `server/routes/assignments.ts`: предпросмотр и выполнение.
4. `server/services/assignment-link.ts` — вернуть выпущенную ссылку вызывающему.
5. `server/email.ts` — письмо без разовой ссылки ведёт на адрес теста.
6. Аудит прогона и выгрузки.

Клиент:

1. Эскизы вкладки и всех четырёх состояний — до написания React.
2. Вкладка выносится в отдельный файл: `assign-test-dialog.tsx` уже занимает 663 строки, диалог
   остаётся оболочкой с вкладками.
3. Сборка xlsx на клиенте и строки интерфейса.

Проверка:

1. Юниты на разбор файла и статусы строк, на каждое правило прохода, на отчёт при недоставке;
   отдельными тестами — отсутствие токенов задания пароля и отсутствие сырой ссылки в журнале.
2. Роут-тесты: права, чужой тест, превышение потолка.
3. Приёмка в браузере на адресе для приёмки: полный прогон, проверка области действия ссылки,
   выгрузка файла.
