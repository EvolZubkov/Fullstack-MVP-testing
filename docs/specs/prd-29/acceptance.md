# Приёмочная матрица - PRD-29 (итоги измерительного теста)

Документ фиксирует приёмку трека PRD-29 (задача 16 плана): соответствие требованиям
[measurement-results.md](./measurement-results.md), разделам 3-9 и критериям приёмки
раздела 11.

Дата прогона: 2026-08-01. Приёмка выполнена на коммите `8e0a0e9`.

## Стенд

| Параметр | Значение |
| --- | --- |
| Приложение | отдельный экземпляр `PORT=8099 npm run dev` из изолированного git worktree на `8e0a0e9` |
| База | dev-БД (Docker, `localhost:55432`), миграция `0006_prd29_measurement_results` применена |
| Браузер | chromium из `ms-playwright`, headless, управление по CDP (Playwright в проекте нет) |
| Пакет SCORM | `GET /api/tests/:id/export/scorm` -> `out/prd29-acceptance.zip` (916 КБ), плеер `npm run scorm:player` на `:5050` |
| Учётная запись | временный администратор `prd29-accept@local.test` (удаляется после приёмки) |

Изолированный worktree понадобился потому, что в рабочем дереве лежали незакоммиченные
правки другой сессии (PRD-30, колонка `test_sections.question_order`), из-за которых любой
запрос к `test_sections` падал на dev-БД. Приёмка проверяет зафиксированное в коммитах
состояние PRD-29, а не смешанное дерево.

Сколько блоков видно без прокрутки:

| Окно | Видно без прокрутки |
| --- | --- |
| 1280 x 800, веб | шапка, «Ваш результат» целиком, заголовок «По шкалам», первая шкала целиком, вторая шкала до текста толкования (обрыв в середине секции шкал) |
| 1024 x 640, веб | шапка, «Ваш результат» целиком, заголовок «По шкалам», первая шкала целиком, начало второй (обрыв в середине секции шкал) |
| 1280 x 800, пакет | то же, что в вебе при 1280 x 800, плюс закреплённый подвал с кнопками |

Прокрутка на экране итогов принята как норма (решение владельца 2026-07-31), и это
подтверждено: первый экран даёт ориентировку (профиль виден целиком, блок шкал начался),
обрыв приходится на середину секции, а не встык с границей блока.

НЕ выполняется другое требование того же шага: **подвал доступен без прокрутки**. В вебе
при содержимом выше окна прокручивается весь документ, а шапка и подвал уходят за кромку.
В пакете контракт сцены соблюдён. Это расхождение хостов - см. дефект D-2.

## Наблюдения вне объёма PRD-29

- Экран «Итоги раздела» измерительного теста показывает «0 %», «0 вопросов», «0 / 0 верно».
  Это та же бессмыслица, ради устранения которой затевался PRD-29, но раздел 2 спеки прямо
  выводит итоги раздела за границы работы.
- Блок «Результаты по темам» на итогах измерительного теста показывает «Правильно 0 / 0».
  Переключателя у этого блока нет: раздел 8.1 вводит ровно три настройки
  (`scoreSummary`, `indicators`, `scales`). Формально соответствует букве спеки и
  противоречит её замыслу из раздела 1.
- Референсная книга заполняет колонку «Диапазоны» в порядке, обратном документированному
  синтаксису (`мин..макс код «подпись»`): методолог записал `0..14 Низкий «low»`, поэтому
  импорт положил `level = "Низкий"`, `label = "low"`, и ученику показывался бы код `low`.
  Дефекта импорта здесь нет - книга заполнена не по формату; при подготовке теста метки
  и коды переставлены в редакторе. Перенос новых полей PRD-29 в книгу вынесен в
  раздел 13.4 спеки и здесь не проверялся.
