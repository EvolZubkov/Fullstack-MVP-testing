## 1. Обзор

### 1.1 Контекст

Сейчас прохождение теста строго линейно: ученик обязан ответить на текущий вопрос, чтобы
перейти к следующему; пропустить вопрос и вернуться к нему позже нельзя. Завершение теста и
кнопка «Завершить тест» частично вшиты в визуальные шаблоны (layout'ы результатов), что
смешивает слой СТРУКТУРЫ теста (что и когда показывать/завершать) со слоем ВИЗУАЛИЗАЦИИ
(шаблон). Для тестов с периодом охлаждения (PRD-6) старт отличается от обычного: показывается
отдельный «гейт-шелл» со своей кнопкой «Начать тестирование», то есть появляются ДВЕ стартовые
страницы.

### 1.2 Цель

1. Дать ученику возможность пропустить вопрос и вернуться к нему позже в пределах попытки
   (управляется настройкой автора).
2. Сделать завершение раздела/теста явным, понятным и необратимым; неотвеченные после
   завершения засчитывать как неверные.
3. Дать быструю навигацию по вопросам через элемент прогресса с пиллами из DS.
4. Закрепить разделение слоёв: завершение — структурный шаг потока, не элемент шаблона;
   дефолтный шаблон гарантирует все нужные экраны, подгружаемые — валидируются.
5. Убрать неоднородность старта для cooldown-тестов: если период вышел, старт неотличим от
   обычного теста.

### 1.3 Метрики успеха

| Цель | Метрика |
| --- | --- |
| Пропуск/возврат работают | При включённой настройке ученик пропускает и возвращается к неотвеченным в пределах раздела/теста |
| Завершение явное | Завершение раздела/теста требует подтверждения при наличии пропусков |
| Неотвеченный = неверный | 100% неотвеченных после завершения дают 0 баллов и вердикт «неверно» |
| Один старт | Cooldown-тест с истёкшим периодом имеет ровно одну стартовую страницу |
| Контракт шаблонов | Подгружаемый шаблон без обязательного экрана отклоняется/сигнализирует аномалию |

## 2. Пользователи

### 2.1 Ученик

Проходит тест; при включённой настройке может пропускать вопросы и возвращаться к неотвеченным;
видит прогресс-пиллы со статусами; завершает раздел/тест с экрана-обзора.

### 2.2 Автор теста

Включает/выключает возврат к неотвеченным (по умолчанию включено, на все разделы теста).

### 2.3 Администратор шаблонов (PRD-3)

Загружает внешние шаблоны; получает валидацию против контракта обязательных экранов с
сигнализацией аномалий.

## 3. Функциональные требования

### 3.1 Настройка и навигация

- **FR-01.** Настройка теста «Разрешить возврат к неотвеченным вопросам» — булева, по умолчанию
  ВКЛ, уровень ТЕСТА (действует на все разделы). Миграция выставляет СУЩЕСТВУЮЩИМ тестам ВЫКЛ
  (сохраняет текущую линейность); дефолт ВКЛ действует только для НОВЫХ тестов.
- **FR-02.** Настройка ВЫКЛ → строго линейно (текущее поведение): ни пропуска, ни возврата;
  «Далее» доступна только после ответа на текущий вопрос.
- **FR-03.** Настройка ВКЛ → ученик может пропустить вопрос (перейти дальше без ответа) и
  вернуться к нему позже.
- **FR-03a.** Отправка ответа — ЯВНОЕ действие (кнопка «Далее»/«Принять»); переход без ответа —
  кнопка «Пропустить» (доступна при FR-01 ВКЛ). Вопрос считается «отвечен», только если нажата
  ОТПРАВКА (а не «Пропустить»), независимо от корректности. Кнопка отправки доступна, когда ответ в
  отправляемом состоянии: одиночный/множественный/сопоставление — ≥1 выбор/пара; **ранжирование —
  ВСЕГДА** (дефолтный/перемешанный стартовый порядок — валидный отправляемый ответ). При
  недоступной отправке доступен только «Пропустить».
- **FR-03b.** Черновик: если ученик начал/выбрал ответ, но нажал «Пропустить» (не «Отправить»),
  выбор СОХРАНЯЕТСЯ как черновик; вопрос остаётся «не отвечен» до «Отправить». При возврате ученик
  видит свой черновик и может продолжить (черновик всегда редактируем — он ещё не отправлен,
  FR-04a касается только ОТПРАВЛЕННЫХ ответов). Черновик переживает перезагрузку (FR-21).
- **FR-04.** По умолчанию (FR-04a ВЫКЛ) при возврате можно только ЗАПОЛНИТЬ неотвеченные; уже
  данный ответ зафиксирован и не редактируется (read-only). Изменение — см. FR-04a.
- **FR-04a.** Настройка теста «Позволить изменять ответ до завершения раздела/теста» — булева, по
  умолчанию ВЫКЛ. ВКЛ → возврат к уже отвеченному вопросу позволяет ИЗМЕНИТЬ ответ до завершения
  раздела/теста.
- **FR-04b.** Зависимости FR-04a: имеет смысл только при FR-01 ВКЛ (доступна навигация назад) и
  при `showCorrectAnswers` ВЫКЛ. Комбинация FR-04a ВКЛ + `showCorrectAnswers` ВКЛ недопустима
  (раскрытая корректность + смена ответа = читерство): ответ блокируется после «Принять», смена
  запрещена; в UI настроек — взаимоисключение/недоступность.
- **FR-04c.** Кнопки страницы вопроса — два РАЗНЫХ действия: «Отправить ответ» (СПРАВА; «Далее»; при
  `showCorrectAnswers` ВКЛ — «Принять» = фиксация + корректность/фидбэк, затем «Далее»), доступна
  когда ответ отправляем (FR-03a); и «Пропустить» (СЛЕВА) — переход дальше БЕЗ ответа (вопрос
  остаётся «не отвечен»). При FR-01 ВКЛ присутствуют ОБЕ; при FR-01 ВЫКЛ — только «Отправить ответ»
  (строго линейно, доступна только при отправляемом ответе). Дополнительно СЛЕВА — «Вернуться»
  (быстрый переход к пропущенным через экран-обзор), показывается ТОЛЬКО при наличии пропущенных
  вопросов. Кнопок завершения на странице вопроса нет (FR-16). Отдельной «Назад» нет — произвольный
  возврат через пиллы.
- **FR-04d.** Вид уже отвеченного вопроса при возврате: read-only (выбранный ответ подсвечен,
  контролы неактивны) при FR-04a ВЫКЛ; редактируемый (можно сменить ответ, «Далее» фиксирует) при
  FR-04a ВКЛ. При `showCorrectAnswers` ВКЛ дополнительно показаны корректность и фидбэк (всегда
  read-only).

### 3.2 Завершение

- **FR-05.** Завершение поэтапное. Секционные тесты («по темам»): «Завершить раздел» (с
  экрана-обзора) фиксирует текущий раздел (пропуск/возврат — в его пределах) → экран ИТОГОВ РАЗДЕЛА
  (FR-05a) → следующий раздел (linear) или роутер (router, FR-05b); в конце — «Завершить тест» →
  результаты теста. Flat (linear_flat): одно завершение в конце, пропуск/возврат — по всему тесту.
- **FR-05a.** Итоги раздела (`section-results`) — ОПЦИОНАЛЬНЫЙ узел по настройке теста
  `showSectionResults`: ВКЛ → после «Завершить раздел» показывается экран итогов раздела +
  «Продолжить» (→ следующий раздел / роутер); ВЫКЛ → сразу следующий раздел / роутер (итоги —
  только по тесту в целом). Явный запрос PRD-19 включает эту возможность — переопределяет
  post-MVP-отсрочку `showSectionResult`.
- **FR-05b.** Router-сценарий (PRD-8, свободный порядок тем): «Завершить раздел» → возврат на
  роутер-страницу (выбор следующей темы); завершённые темы на роутере заблокированы; пиллы — в
  пределах текущей темы; «Завершить тест» доступно с роутера, когда все темы пройдены.
- **FR-06.** Завершение явное и необратимое: завершённый раздел/тест заблокирован для ответов;
  вернуться к его вопросам нельзя.
- **FR-07.** Неотвеченный вопрос после завершения раздела/теста засчитывается как НЕВЕРНЫЙ
  (0 баллов, вердикт «неверно»), а не как нейтральное «нет ответа».

### 3.3 Экран-обзор и подтверждение

- **FR-08.** Экран обзора — СИСТЕМНЫЙ экран; дизайн задаётся ШАБЛОНОМ (варианты оформления, как
  `start`/`results`). Это ОЧЕВИДНЫЙ способ навигации (в дополнение к пиллам): показывает статусы
  всех вопросов (по FR-10/FR-10a) + ЯВНЫЙ список неотвеченных, каждый с кнопкой «Перейти» к вопросу;
  плюс «Завершить раздел» / «Завершить тест». Достижим в ЛЮБОЙ момент кнопкой «Вернуться» со страницы
  вопроса (FR-04c) и в конце раздела/теста. Итог — ДВА дублирующих способа возврата: (1) пиллы —
  быстро, но неочевидно; (2) экран обзора — дольше, но очевиднее.
- **FR-08a.** В редакторе СТРУКТУРЫ теста элемент «обзор» виден ДОСТУПНЫМ, если настройка возврата
  (FR-01) ВКЛ; при ВЫКЛ — DISABLED с комментарием, что для включения нужно включить настройку
  возврата к неотвеченным.
- **FR-09.** При нажатии «Завершить» с неотвеченными — модал-подтверждение («перед завершением» —
  отдельный модал, не экран): «N вопросов без ответа будут засчитаны как неверные. Завершить?»
  (Завершить / Отмена).

### 3.4 Прогресс-пиллы (DS)

- **FR-10.** Быстрая навигация — элемент прогресса с пиллами из DS; пиллы ЗАМЕНЯЮТ линейный
  прогресс-бар (единственный индикатор прогресса). Базовые состояния пилла: текущий / отвечен /
  пропущен / не выдан (за фронтиром, недоступен) / заблокирован (после завершения раздела). Клик =
  быстрый переход в пределах допустимого (FR-11) — быстрый, но НЕОЧЕВИДНЫЙ способ; очевидный
  дублирующий способ навигации — экран обзора (FR-08).
- **FR-10a.** Маркировка пилла по умолчанию НЕ раскрывает корректность ответа — только «отвечен» /
  «не отвечен». Если включена настройка теста «показ корректности ответа ученику»
  (`showCorrectAnswers`), маркировка результата имеет три варианта: «корректно» / «некорректно» /
  «не отвечен». То же правило действует для статусов на экране-обзоре (FR-08).
- **FR-11.** Скоуп пиллов: текущий раздел (секционные) / весь тест (flat). Переход — ТОЛЬКО к уже
  ВЫДАННЫМ вопросам (отвечен / пропущен / текущий); ещё не выданные (за текущей позицией) недоступны
  для перехода — «прыжок вперёд» к невиденному вопросу запрещён. Завершённый раздел полностью
  заблокирован — назад нельзя, его пиллы недоступны. При ВЫКЛ-настройке пиллы только индицируют
  прогресс (без навигации). DS-замечание: `QuizMap` нуждается в locked-статусе точки «не выдан»
  (T0.3).
- **FR-12.** Доступность: пиллы — навигация с клавиатуры, корректные роли/aria.

### 3.5 Скоринг и SCORM

- **FR-13.** «Неотвеченный = неверный» (после завершения) реализуется в едином движке скоринга
  (shared/scoring), без хост-специфичной логики.
- **FR-14.** SCORM-отчёт (score / interactions) корректно отражает неотвеченные-как-неверные.
- **FR-15.** При заданном таймауте истечение времени = авто-завершение; неотвеченные — неверные.

### 3.6 Слой структуры vs шаблон

- **FR-16.** Кнопка и логика завершения — структурный шаг потока, НЕ элемент шаблонных layout'ов.
  Шаблон даёт визуальную оболочку (экран-обзор/результатов); завершение добавляет структура.
- **FR-17.** Дефолтный шаблон ГАРАНТИРУЕТ все обязательные экраны контракта (start, question,
  обзор/summary, results, transition, blocked).
- **FR-18.** Подгружаемые шаблоны (PRD-3) валидируются против контракта обязательных экранов;
  отсутствие/некорректность экрана = понятная сигнализация аномалии (не «тихий» сбой в рантайме).

### 3.7 Cooldown-гейт (PRD-6)

- **FR-19.** Период охлаждения вышел → старт НЕОТЛИЧИМ от обычного теста: одна стартовая страница
  (обычная), без отдельного гейт-шелла «Начать тестирование». Cooldown при eligible НЕ добавляет
  НИ ОДНОГО экрана/шага в путь ученика — гейт невидим, ученик попадает на обычный старт как всегда.
  Отложенный старт SCORM-сессии обеспечивается обычной стартовой страницей (Initialize — по клику
  «Начать тестирование»).
- **FR-20.** Период НЕ вышел → cooldown-логика на ТОЙ ЖЕ стартовой странице (не отдельный экран):
  «пока недоступно» + дата следующей попытки + прошлый результат (балл/вердикт) + «Скачать отчёт»
  (если отчёт по прошлой попытке доступен для скачивания); кнопка «Начать тестирование» — disabled.

### 3.8 Сопутствующее

- **FR-21.** Resume: статусы вопросов (отвечен/пропущен), черновики (FR-03b) и текущая позиция
  переживают перезагрузку (suspend_data).
- **FR-22.** Адаптивные темы: пропуск/возврат НЕВОЗМОЖНЫ в принципе (следующий вопрос зависит от
  ответа — движок ведёт последовательность сам); прогресс-индикатор адаптивной темы — read-only (без
  навигации); настройка `allowReturnToUnanswered` скрыта/игнорируется для адаптивных тем.
- **FR-23.** PRD-14: новая настройка теста экспортируется/импортируется в листе настроек теста.
- **FR-24.** PRD-18 (отладчик): статусы пропуска/возврата видны в «Протоколе»/«Состоянии».

## 4. UX и экраны

| Экран/элемент | Содержание |
| --- | --- |
| Вопрос | Справа «Отправить ответ» (Далее/Принять); слева «Пропустить» (при FR-01 ВКЛ) и «Вернуться» (только при наличии пропущенных); + пиллы. Уже отвеченный при возврате — read-only или редактируемый (FR-04a/FR-04d) |
| Прогресс-пиллы | Заменяют линейный прогресс-бар. Статусы (отвечен/пропущен/не выдан; +корректно/некорректно при `showCorrectAnswers`); клик = быстрый переход (быстрый, но НЕОЧЕВИДНЫЙ способ); скоуп раздел/тест |
| Экран обзора (системный, шаблонный) | ОЧЕВИДНЫЙ способ навигации: статусы всех вопросов + ЯВНЫЙ список неотвеченных с «Перейти» на каждый + «Завершить раздел/тест». Достижим кнопкой «Вернуться» и в конце. В структуре — доступен/disabled по настройке возврата (FR-08a) |
| Итоги раздела | После «Завершить раздел»: результат раздела + «Продолжить» → следующий раздел/роутер |
| Модал завершения | При пропусках: «N без ответа → неверные. Завершить?» |
| Настройки теста | Раздел «Настройки › Правила прохождения»: «Разрешить возврат к неотвеченным» (дефолт ВКЛ), «Позволить изменять ответ до завершения» (дефолт ВЫКЛ; взаимоисключение с `showCorrectAnswers`, disabled+причина), «Показывать итоги раздела» (дефолт ВКЛ, секционные) |

Все ученические экраны рендерятся из общих шаблонов на ОБОИХ хостах (паритет PRD-12).

Терминология: «раздел» и «Завершить раздел» — только в секционных сценариях (`linear_by_topics` /
`router_by_topics`). В `linear_flat` разделов нет: единица — весь тест («Завершить тест», обзор
теста).

## 5. Контракт структуры и обязательных экранов

Полная slot-модель структуры (вариант B: дерево слотов по flowMode, обязательные/опциональные узлы,
явная фиксация завершения) — в отдельном документе
[Контракт структуры теста](test-structure-contract.md).

Кратко: структура = упорядоченное дерево слотов, форму задаёт flowMode; каждая страница в одном
слоте. Обязательные системные узлы: `start`, `questions`, `section-finish` (фиксация раздела —
секционные), `test-finish` (фиксация теста), `results`, `router-hub` (router). Опциональные:
`section-results` (по настройке `showSectionResults`), авторские `info` в зонах. Дефолтный шаблон
гарантирует все обязательные узлы; подгружаемые валидируются с сигнализацией аномалий (PRD-3).
