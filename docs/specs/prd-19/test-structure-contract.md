**Связанные документы:** [PRD-19](skip-return-navigation.md),

## 1. Модель

Структура теста — это УПОРЯДОЧЕННОЕ ДЕРЕВО СЛОТОВ. Форму дерева задаёт `flowMode`
(`linear_flat` / `linear_by_topics` / `router_by_topics`). Каждая страница лежит РОВНО В ОДНОМ
слоте; размещение задаётся единственным признаком `slot`, а не тройкой `kind`+`position`+`topicId`.

Принципы:

1. **flowMode = форма.** Один выбор автора; разворачивается в фиксированный набор слотов.
2. **Слот = единственный признак размещения** (`test-before`, `topic-before:<id>`, `topic-after:<id>`,
   `test-after`, `router-hub` и т.д.).
3. **Системные узлы гарантированы формой** — автор их не удаляет, только переключает вариант
   оформления; завершение и итоги — это структура, не шаблон (PRD-19 FR-16).
4. **Слоты бывают обязательные и опциональные.** Опциональный слот автор может не заполнять.

## 2. Типы узлов

- **Системные узлы** — гарантированы формой; автор меняет только визуальный вариант. Бывают
  обязательные и опциональные.
- **Авторские страницы** (`info`, PRD-1) — опциональные, размещаются в зонах (полный CRUD).

## 3. Слоты по flowMode

Каноническая последовательность (О = обязательный, П = опциональный).

### 3.1 linear_flat

| Слот / узел | Тип | О/П |
| --- | --- | --- |
| `start` | системный (стартовый экран) | О |
| `test-before` (зона: авторские `info`) | авторские | П |
| `flat-questions` (плоский блок вопросов) | системный | О |
| `test-finish` (обзор + «Завершить тест», фиксация) | системный | О |
| `results` (итоги теста) | системный | О |
| `test-after` (зона: авторские `info`, post-results) | авторские | П |

### 3.2 linear_by_topics

| Слот / узел | Тип | О/П |
| --- | --- | --- |
| `start` | системный | О |
| `test-before` (авторские `info`) | авторские | П |
| на каждую тему: `topic-before` (авторские `info`) | авторские | П |
| на каждую тему: `questions` / `adaptive-session` | системный | О |
| на каждую тему: `topic-after` (авторские `info`) | авторские | П |
| на каждую тему: `section-finish` (обзор + «Завершить раздел», фиксация) | системный | О |
| на каждую тему: `section-results` (итоги раздела) | системный | П (настройка `showSectionResults`) |
| `test-finish` (фиксация завершения теста) | системный | О |
| `results` (итоги теста) | системный | О |
| `test-after` (авторские `info`, post-results) | авторские | П |

### 3.3 router_by_topics

| Слот / узел | Тип | О/П |
| --- | --- | --- |
| `start` | системный | О |

## 4. Обязательные и опциональные узлы (сводно)

| Узел | О/П | Примечание |
| --- | --- | --- |
| `start` | обязательный | один на тест |
| `flat-questions` / `questions` / `adaptive-session` | обязательный | тест без вопросов недопустим |
| `router-hub` | обязательный (только router) | хаб выбора тем |
| `section-finish` / экран обзора (фиксация раздела) | обязательный (секционные) | системный экран-обзор шаблона (варианты); навигация (пиллы + явный список) + «Завершить раздел». В редакторе структуры доступен/disabled по настройке возврата (PRD-19 FR-08a) |
| `section-results` (итоги раздела) | ОПЦИОНАЛЬНЫЙ | по настройке `showSectionResults` (дефолт ВКЛ); автор может показывать только итоги теста |
| `test-finish` (фиксация теста) | обязательный | явное завершение теста |
| `results` (итоги теста) | обязательный | финальные итоги |
| авторские `info` в зонах | опциональные | контент до/после теста/темы |

## 5. Фиксация завершения

- **Завершение раздела и теста фиксируется ЯВНО** и ОБЯЗАТЕЛЬНО — через узлы `section-finish` и
  `test-finish` (обзор + кнопка «Завершить раздел/тест», PRD-19 FR-08/FR-09).
- **После фиксации результаты фиксируются**; возврат к вопросам и их корректировка НЕВОЗМОЖНЫ
  (PRD-19 FR-06): завершённый раздел/тест заблокирован, его пиллы недоступны.
- Опциональные итоги раздела (`section-results`) показываются ПОСЛЕ фиксации раздела, если включён
  `showSectionResults` (дефолт ВКЛ для секционных); иначе сразу следующий раздел / роутер.
- Для секционных тестов завершение ПОСЛЕДНЕГО раздела (`section-finish`) и завершение теста
  (`test-finish`) — РАЗДЕЛЬНЫЕ явные шаги (НЕ сливаются): сначала фиксация последнего раздела,
  затем явная фиксация теста.
- Экран обзора (узел `section-finish`/`test-finish`) — СИСТЕМНЫЙ, дизайн через шаблон (варианты);
  очевидный способ навигации (статусы + явный список неотвеченных с «Перейти») + «Завершить»;
  дублирует быструю навигацию пиллами (PRD-19 FR-08). В редакторе структуры доступен/disabled по
  настройке возврата к неотвеченным (FR-08a).

## 6. Размещение страниц

- Каждая авторская/системная страница имеет единственный `slot` — он определяет позицию.
- Тройка `kind`+`position`+`topicId` схлопывается в `slot` (выводится детерминированно и
  валидируется на сохранении). `kind` остаётся только различителем «системный узел» vs «авторский
  `info`».
- Режим выборки вопросов (uniform / квоты PRD-11 / варианты PRD-17) — свойство узла `questions`
  (ссылка на параметры темы из вкладки «Состав»); `formSet` явно перекрывает `drawCount`/`drawAll`/
  `drawBlueprint`.
- Узел `adaptive-session` НЕ поддерживает пропуск/возврат (PRD-19 FR-22): последовательность ведёт
  адаптивный движок; прогресс-индикатор — read-only. Пропуск/возврат и навигация по пиллам —
  свойство узла `questions`, не `adaptive-session`.

## 7. Валидация

- **Дефолтный шаблон** обязан содержать варианты для ВСЕХ обязательных системных узлов (раздел 4).
- **Подгружаемые шаблоны** (PRD-3) валидируются против контракта: отсутствие варианта для
  обязательного узла = аномалия с понятной сигнализацией (не «тихий» сбой). Опциональные узлы
  (`section-results`) при отсутствии в шаблоне — допустимы (узел просто не показывается).
