## 1. Обзор

### 1.1 Контекст

Шаблон `certification` поставляет две палитры: базовую в `:root` и тёмную в
`@media (prefers-color-scheme: dark)` с явным перекрытием `:root[data-theme="dark"]`. Ученик
видит ту, что выбрана у него в системе. Платформа об этом не знает ничего.

Из этого следуют три дефекта, замеченные при приёмке PRD-22.

Первое: автор не может зафиксировать вид теста. Сертификационный тест у одного участника
открывается светлым, у другого тёмным, и это не решение автора, а побочный эффект системной
настройки. Способа сказать «этот тест всегда светлый» нет.

Второе: цвет в панели один на параметр, а палитр — две. Задав «фон экрана» белым, автор красит
им обе темы: у участника с тёмной системной темой получается белый фон с почти белым текстом
шаблонной тёмной палитры. Одно значение физически не обслуживает два набора.

Третье: переопределения печатаются инлайн-стилем на корне сцены. Инлайн нельзя ограничить
медиа-запросом, поэтому даже при известных двух значениях напечатать их раздельно нечем.

Отдельно — размещение: цвета лежат в «Брендировании» вперемешку со шрифтом и логотипом, хотя
логика у них принципиально сложнее «значение параметра → рендер»: наследование из палитры
шаблона, формат хранения, значение на каждую тему.

### 1.2 Цель

Дать шаблону способ объявить палитры, которые он умеет, автору — выбор вида теста и цвет на
каждую палитру, а отрисовке — печать переопределений по темам на обоих хостах. Шаблон, который
тем не объявляет, продолжает работать ровно как сейчас, без переиздания.

### 1.3 Метрики успеха

- Автор задаёт цвет для светлой и тёмной палитры независимо и не теряет ни одну при переключении
  вида теста.
- Тест с фиксированной темой выглядит одинаково при любой системной настройке участника — на
  веб-прогоне, в SCORM-пакете и в отладчике.
- Ни один уже загруженный шаблон не требуется переиздавать, чтобы платформа осталась рабочей.

## 2. Пользователи

### 2.1 Разработчик шаблона

Объявляет в манифесте перечень палитр, которые поставляет. Получает отказ загрузки или активации,
если объявил палитру, которой нет в стилях, — вместо молчаливой пустой колонки у автора теста.

### 2.2 Автор теста

Выбирает вид теста: «Светлая», «Тёмная», «Авто». Подбирает цвета таблицей «параметр × тема»,
видит происхождение каждого значения и возвращает его шаблону.

### 2.3 Ученик

Видит тест в теме, которую задал автор, либо — при «Авто» — в своей системной. Читаемость обеих
палитр обеспечивается тем, что автор задаёт значения для каждой.

## 3. Функциональные требования

### 3.1 Объявление тем шаблоном

**FR-01.** Манифест шаблона МОЖЕТ объявлять перечень тем `themes[]`. Поле необязательное:
отсутствие поля или менее двух записей означает, что шаблон тем не поддерживает.

**FR-02.** Идентификатор темы — из закрытого перечня платформы (`light`, `dark`). Перечень ведётся
в одном реестре `shared/template`, как реестр типов полей PRD-22; расширение перечня — правка
одного места.

**FR-03.** Смысл идентификатора фиксирован: `light` — базовая палитра (`:root`,
`:root[data-theme="light"]`), `dark` — палитра блока `prefers-color-scheme: dark` либо
`:root[data-theme="dark"]`.

**FR-04.** Валидация выполняется при загрузке И при активации (NFR-05/06 PRD-3): идентификаторы
из перечня, без повторов, у каждой темы есть подпись. Сообщение об отказе называет тему.

Сверка объявления с палитрой — «тема объявлена, а токенов в стилях нет» — требует файлов пакета и
потому выполняется при загрузке; гейт активации видит только сохранённый манифест и проверяет само
объявление. Обратный случай — шаблон поставляет вторую палитру, но её не объявляет — не блокирует,
а сообщается предупреждением: автор такой палитры не достигнет.

### 3.2 Выбор вида теста

**FR-05.** У теста есть выбор темы: `light`, `dark`, `auto`. Значение по умолчанию — `auto`:
отсутствие сохранённого значения читается как «Авто», что совпадает с сегодняшним поведением.

**FR-06.** Переключатель показывается ТОЛЬКО у шаблона с темами. У шаблона без тем раздел «Цвета» —
плоский список параметров, как сейчас.

### 3.3 Значение цвета на каждую тему

**FR-07.** У шаблона с темами цветовой параметр хранит значение на каждую объявленную тему,
независимо от выбранного вида теста. Смена вида теста подобранные значения не изменяет и не
удаляет.

**FR-08.** Таблица «параметр × тема» показывается всегда, когда шаблон поддерживает темы, а не
только при «Авто»: подобранная палитра не должна прятаться при смене выбора.

**FR-09.** Происхождение значения показывается на каждую тему отдельно: не заданное автором
значение помечается как взятое из шаблона, заданное — сопровождается возвратом к шаблонному.

### 3.4 Размещение параметров по разделам

**FR-10.** Цветовые параметры выводятся в разделе «Цвета» по ТИПУ параметра (`type === "color"`).
Объявленный в манифесте `section` для них игнорируется — иначе каждый уже загруженный шаблон
пришлось бы переиздавать.

**FR-11.** Раздел рельсы, в котором у шаблона нет ни одного параметра, не показывается. Сегодня
такой раздел открывается баннером «в шаблоне нет параметров» — пунктом, который ничего не делает.

### 3.5 Отрисовка

**FR-12.** Выбранная тема ставится на корень сцены атрибутом `data-theme`: в SCORM-пакете — на
`<html>`, на веб-хосте — на shadow-host. При «Авто» атрибут не ставится, и работает медиа-запрос
шаблона.

**FR-13.** Переопределения теста печатаются `<style>`-блоком, повторяющим структуру `theme.css`
шаблона, а не инлайн-стилем: инлайн нельзя ограничить медиа-запросом.

```css
:root { --primary: <светлое> }
@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { --primary: <тёмное> } }
:root[data-theme="dark"] { --primary: <тёмное> }
```

**FR-13.1.** На веб-хосте те же правила печатаются от `:host`, причём условие обязано идти
ФУНКЦИОНАЛЬНОЙ формой — `:host([data-theme="dark"])`, `:host(:not([data-theme="light"]))`. Форма
`:host[data-theme="dark"]` невалидна: браузер отбрасывает правило целиком, и закреплённая тема
молча не применяется. По той же причине веб-хост, переписывая `:root` шаблона в `:host`, обязан
переносить условие внутрь скобок, а не оставлять суффиксом.

**FR-14.** Блок переопределений печатается последним в тот же корень: селекторы совпадают с
шаблонными по специфичности, поэтому побеждает порядок. Правило одинаково для веб-хоста,
SCORM-рантайма и отладчика (PRD-18) — печать живёт в одном модуле `shared/template`.

**FR-15.** Выбранная тема и значения по темам попадают в SCORM-пакет при экспорте и в снапшот
публикации (PRD-15) наравне с остальными настройками оформления.

### 3.6 Предпросмотр

**FR-16.** Предпросмотр шаблона показывает выбранную тему. При «Авто» доступны обе — переключением
внутри стенда.

### 3.7 Совместимость

**FR-17.** Тест, у которого цвета сохранены плоскими значениями, при работе под шаблоном С темами
читается так: плоское значение — значение ОБЕИХ тем. При первом сохранении оно переезжает в
хранение по темам. Автор не теряет подобранный цвет ни при смене шаблона, ни при обновлении
платформы.

## 4. UX и экраны

Раскладка — по согласованному эскизу
[prd23-template-themes.html](../../wireframes/approved/prd23-template-themes.html); каркас вкладки
«Оформление» (рельса подразделов, список полей, подвал редактора) не меняется.

| Состояние | Что показано |
| --- | --- |
| Шаблон без тем | Раздел «Цвета» — плоский список цветовых параметров, переключателя нет |
| Тема зафиксирована | Переключатель с выбранной темой, под ним таблица «параметр × тема» |
| «Авто» | Тот же экран, активен пункт «Авто», пояснение под переключателем другое |
| «Брендирование» | После выноса цветов остаются шрифт и логотип |

Контролы — только компоненты дизайн-системы: `SegmentedControl` для выбора темы, `Table` для
таблицы цветов, `ColorPicker` в ячейке, `IconButton` `ghost` `s` для возврата к шаблонному цвету.

## 5. Контракт манифеста

```json
{
  "themes": [
    { "id": "light", "label": "Светлая" },
    { "id": "dark",  "label": "Тёмная" }
  ]
}
```

| Поле | Тип | Обязательность | Смысл |
| --- | --- | --- | --- |
| `themes` | массив | нет | Палитры, которые поставляет шаблон. Нет поля или меньше двух записей — тем нет |
| `themes[].id` | строка | да | Идентификатор из закрытого перечня платформы: `light`, `dark` |
| `themes[].label` | строка | да | Подпись колонки в таблице цветов и пункта переключателя |

## 6. Модель данных

Хранение — в `tests.design_settings_json`; колонка типа JSON, миграция не требуется.

```json
{
  "templateId": "certification",
  "theme": "auto",
  "params": { "fontFamily": "Rostelecom Basis" },
  "paramsByTheme": {
    "light": { "primaryColor": "…" },
    "dark":  { "primaryColor": "…" }
  }
}
```

| Ключ | Смысл |
| --- | --- |
| `theme` | Вид теста: `light`, `dark`, `auto`. Отсутствие читается как `auto` |
| `params` | Нецветовые параметры и все параметры шаблона без тем — как сегодня |
| `paramsByTheme` | Цветовые переопределения по темам. У шаблона без тем не создаётся |

## 7. Граница и зависимости

Входит: контракт манифеста и его валидация, хранение, печать тем в отрисовку на обоих хостах,
раздел «Цвета» в редакторе, предпросмотр, объявление тем шаблоном `certification` и починка его
декоративной плашки обложки (залита фиксированным оранжевым мимо токена основного цвета).

Не входит:

- **Светлая палитра «Стандартного».** У него единственная палитра в `:root` — тёмная. Пока светлых
  токенов нет, темы он не объявляет и остаётся плоским. Отдельная задача.
- **Выбор темы учеником во время прохождения.** «Авто» следует системной настройке участника;
  тумблера на экране прохождения нет.
- **Темы сверх `light`/`dark`.** Перечень расширяем правкой одного реестра, но в этом объёме
  закрыт двумя.

## 8. План реализации

Этапы Э0-Э9 — в [плане PRD-23](../../plans/PLAN_PRD23_TEMPLATE_THEMES.md). Э1-Э3 не имеют UI и

## 9. Риски

Перечень рисков и способ снятия каждого — раздел 4 плана. Главные: приёмка UI требует браузера
(сценарии кладутся в репозиторий и не зависят от MCP), плоские цвета уже сохранённых тестов
(правило FR-17 плюс барьерные тесты) и смена приоритетов каскада при переходе с инлайна на
`<style>` (FR-14 плюс проверка вычисленного значения).

## 10. Открытые вопросы

- **ОВ-01.** Нужен ли ученику тумблер темы на экране прохождения. Сейчас нет: «Авто» следует
  системной настройке.
- **ОВ-02.** Нужна ли третья тема (например, высококонтрастная) и кто её объявляет — платформа
  или шаблон.
- **ОВ-03.** Когда «Стандартный» получит светлую палитру и объявит темы.
