## 1. Контекст и постановка задачи

Аудит UX авторских разделов (`docs/AUDIT_UX_AUTHOR_CONTENT.md`, находки UX-01..13) выявил, что
ось контента (`Папка ⊃ Тема ⊃ Вопрос`) и ось сборки (тест ссылается и выбирает из пула тем)
не показаны автору, а редактор вопроса содержит ряд моделей, не соответствующих требованиям.
По итогам проектирования утверждён эскиз `docs/wireframes/approved/content-bank-explorer.html`.

Настоящий BRD фиксирует бизнес-требования, вытекающие из утверждённого эскиза: единый раздел
«Темы и вопросы», модель сложности вопроса, модель медиа, конструкторы вариантов и валидацию,
а также модель порядка и перемешивания вариантов ответа с переопределением на уровне теста.

Требования по владению, целостности и публикации остаются в `brd-content-ownership.md`
(PRD-15); настоящий документ их не дублирует, а ссылается.

## 2. Бизнес-цели и метрики

| Цель | Метрика |
| --- | --- |
| Единый рабочий процесс над контентом | Тема и её вопросы видны и редактируются в одном разделе; сквозная навигация без закрытия редактора |
| Корректная модель сложности | Сложность — число 0–100, опциональное; нет навязанной фиксированной таксономии уровней |
| Надёжная выдача медиа | Медиа вопроса всегда воспроизводится в LMS офлайн (только загруженные файлы, бандлятся в SCORM) |
| Защита от некорректных вопросов | Невозможно сохранить вопрос без правильного ответа или с недостаточным числом вариантов |
| Управляемый порядок выдачи | Автор задаёт порядок вариантов; перемешивание и порядок переопределяемы на уровне теста |
| Согласованная терминология | Названия типов вопросов едины с используемыми в системе (i18n) |

---

## 3. Терминология

Названия типов вопросов берутся из существующего словаря интерфейса (`client/src/lib/i18n.ts`):
**Один ответ** (single), **Несколько ответов** (multiple), **Соответствие** (matching),
**Ранжирование** (ranking). Использование иных синонимов («Одиночный», «Порядок» и т. п.)
не допускается; код берёт подписи из i18n, а не хардкодит.

## 4. Требования

Идентификаторы: `BRC-CA-NN`.

### 4.1. Единый раздел «Темы и вопросы» (ось контента)

- **BRC-CA-01.** Разделы «Темы» и «Вопросы» объединяются в один раздел «Темы и вопросы» —
  единое дерево `Папка (необязательная, вложенная) ⊃ Тема ⊃ Вопрос` в визуальном языке списка
  «Тесты»: колонки Название | Сложность | Вопросов | действия, корневой ярлык «Все темы (N)».
- **BRC-CA-02.** Тип вопроса отображается монохромной пиктограммой в ячейке названия; сложность —
  числом в своей колонке; число вопросов темы — в колонке «Вопросов».
- **BRC-CA-03.** Над деревом — поиск по подстроке и панель фасетов (Тип, Сложность, Теги, Медиа,
  Автор, Область) с чипами активных условий; дерево автораскрывается к совпадениям; счётчик
  «найдено / всего».
- **BRC-CA-04.** Создание — через FAB (папка/тема/вопрос); действия над строкой — через
  всегда видимое меню; редактирование темы и вопроса — в Drawer. Детали раскладки и состояний —
  в эскизе и плане реализации.

### 4.2. Сложность вопроса

- **BRC-CA-10.** Сложность вопроса — это ЧИСЛО в диапазоне 0–100. Поле опциональное: пустое
  значение означает «Не задано» (`questions.difficulty` становится nullable).
- **BRC-CA-11.** Фиксированной таксономии уровней (легко/средне/сложно) на уровне вопроса НЕТ.
  В колонке дерева и в списках показывается ЧИСЛО (для «Не задано» — соответствующая отметка).
- **BRC-CA-12.** В редакторе вопроса сложность задаётся конкретным значением: слайдер 0–100 +
  поле ввода числа (как в текущем редакторе) + переключатель «Не задано». При включении «Не задано»
  контролы установки значения скрываются.
- **BRC-CA-13.** Фильтр банка по сложности — это интервал 0–100 (слайдер) плюс переключатель
  «Не задана» как гейт: при его включении выбор интервала скрывается (не применим к вопросам
  без сложности).
- **BRC-CA-14.** Именованные «метки» / уровни сложности (имя + интервал, произвольное число) —
  это свойство КОНКРЕТНОГО ТЕСТА (адаптивные уровни, `adaptive_levels`), а НЕ темы или вопроса.
  В банке контента меток сложности нет.

### 4.3. Медиа вопроса

- **BRC-CA-20.** Медиа вопроса — один опциональный файл (изображение, аудио или видео).
  Добавляется ТОЛЬКО загрузкой файла через компонент `FileUploader` дизайн-системы в модальном
  окне «Загрузка медиа». Тип медиа определяется автоматически по содержимому файла (MIME).
- **BRC-CA-21.** Свободный ввод URL и ручной выбор «Тип медиа» из модели исключаются. Внешние
  ссылки не поддерживаются: в SCORM-пакет бандлятся только загруженные файлы (`/uploads/...`,
  `server/scorm/builders/media-assets.ts`), внешний URL остался бы битым офлайн в LMS.
- **BRC-CA-22.** В Drawer вопроса медиа показывается вложением: превью + действия «Заменить» и
  «Удалить».

### 4.4. Конструкторы вариантов и валидация

- **BRC-CA-30.** Тип вопроса задаёт конструктор вариантов: Один ответ — radio (ровно один
  правильный); Несколько ответов — чекбоксы (не менее одного правильного); Соответствие — пары
  «левое ↔ правое»; Ранжирование — список с эталонным порядком.
- **BRC-CA-31.** Валидация выполняется ДО сохранения (ранее проверялись только тема и текст).
  Гарды: тема выбрана; текст вопроса непустой; не менее двух непустых вариантов; задан правильный
  ответ согласно типу (Один ответ — выбран; Несколько ответов — отмечен ≥1; Соответствие — все
  пары заполнены; Ранжирование — ≥2 элемента). Ошибки показываются баннером вверху формы;
  кнопка «Сохранить» заблокирована до исправления.
- **BRC-CA-32.** Смена типа вопроса СОХРАНЯЕТ введённые варианты: тексты переносятся между типами
  без подтверждения (для Соответствия — в левую колонку), пересобирается только структура ответа
  (один правильный / несколько правильных / пары / порядок). Решение 2026-06-16 — заменяет прежнее
  подтверждение с потерей данных.

### 4.5. Порядок и перемешивание вариантов ответа

- **BRC-CA-40.** Для типов Один ответ, Несколько ответов и Соответствие автор задаёт БАЗОВЫЙ
  порядок вариантов вручную — перетаскиванием за ручку (порядок хранится как порядок элементов
  в составе вопроса).
- **BRC-CA-41.** У вопроса есть переключатель «Случайный порядок вариантов» (поле
  `questions.shuffle_answers`, по умолчанию включён): включён — варианты показываются ученику в
  случайном порядке; выключен — в заданном базовом порядке (например, когда есть «Все
  перечисленное» / «Ничего из перечисленного»).
- **BRC-CA-42.** Ранжирование — исключение: заданный автором порядок и есть эталон ответа,
  поэтому перемешивание вариантов при выдаче обязательно и без переключателя.
- **BRC-CA-43.** ПОВЕДЕНИЕ ПО УМОЛЧАНИЮ (старт). Тест выдаёт варианты по настройкам ВОПРОСА из
  банка: базовый порядок вариантов + «Случайный порядок вариантов» (для Ранжирования —
  обязательное перемешивание). Отдельной настройки выдачи на уровне теста на старте НЕТ; редактор
  тестов (PRD-7) и его вкладка «Оценка» (PRD-15 блок D) не меняются.
- **BRC-CA-44 (ОТЛОЖЕНО — гипотеза).** Переопределение выдачи на уровне теста — возможность теста
  переопределить для конкретного вопроса (а) ПОРЯДОК вариантов и (б) СЛУЧАЙНОСТЬ порядка —
  ОТЛОЖЕНО до подтверждения гипотезы необходимости. При реализации — как расширение семьи
  переопределений пары (тест, вопрос) (PRD-15 блок D, `test_question_scoring`): резолвер
  «переопределение теста, иначе настройка вопроса», фиксация снапшотом публикации (PRD-15 блок B);
  для Ранжирования перемешивание остаётся обязательным. До подтверждения гипотезы UI редактора
  тестов не затрагивается.

## 5. Влияние на данные

- `questions.difficulty` — снять `NOT NULL` (становится nullable; отсутствие = «Не задано»).
  Существующие значения и значение по умолчанию сохраняются для обратной совместимости.
- `questions.shuffle_answers` — сохраняется как есть (положительный смысл «Случайный порядок
  вариантов», по умолчанию `true`).
- Базовый порядок вариантов хранится как порядок элементов состава вопроса (`questions.dataJson`),
  отдельная схема не требуется.
- Переопределение выдачи на уровне теста (порядок + случайность) — ОТЛОЖЕНО (BRC-CA-44). На старте
  хранилища и резолвера переопределения не требуется: выдача читает настройки вопроса
  (`questions.shuffle_answers` + порядок в `questions.dataJson`). При подтверждении гипотезы —
  новое хранилище на пару (тест, вопрос) по образцу `test_question_scoring` и общий резолвер
  (как `shared/scoring/effective-scoring`).
- `questions.mediaUrl`/`questions.mediaType` — колонки сохраняются; меняется только модель ввода
  (только загрузка файла, тип авто).

## 6. Вне охвата

- Медиатека (повторное использование загруженных файлов) — отдельный будущий PRD.
- Cross-axis «где используется тема» из редактора теста — отдельная задача (см. аудит UX-01).
- Серверные фильтры списка и bulk-эндпоинты — оптимизация при росте банка (см. план).
- Глобальная библиотека меток сложности вне адаптивных уровней теста.

## 7. Открытые вопросы

1. Гипотеза необходимости переопределения выдачи на уровне теста — требует подтверждения
   (BRC-CA-44). До подтверждения функционал не реализуется.
2. ОТЛОЖЕНО (зависит от п. 1): форма хранения переопределения (расширить `test_question_scoring`
   полями порядка/перемешивания или отдельная таблица `test_question_delivery`) и его размещение
   в редакторе теста (вкладка «Оценка» или состав/настройки секции).

Принято по умолчанию (старт): тест выдаёт варианты строго по настройкам вопроса из банка
(порядок + «Случайный порядок вариантов»); переопределения на уровне теста нет.
