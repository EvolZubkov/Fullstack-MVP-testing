# PRD-38: Медиа вопроса как часть вопроса и вид аудио-вопроса

**Версия:** 1.0

**Статус:** требования согласованы 2026-08-03, реализация не начата

**Связанные документы:** [PRD-12](../prd-12/web-runtime-parity.md),
[PRD-26](../prd-26/scale-question-type.md), [PRD-34](../prd-34/copy-protection.md),
[спецификация платформы шаблонов](../spec-template-platform.md)

**Зависимости:** PRD-12 (единый рендеринг на обоих хостах), PRD-26 (шкальный вопрос — тот тип
ответа, на котором дефект проявляется), PRD-34 (слот медиа входит в перечень защищаемых
областей)

## 1. Обзор

### 1.1 Контекст

Непустой слот `question-media` сегодня превращает `.tb-qbody` в две колонки `5fr | 7fr`, где
слева стоит медиа, а справа — **весь блок ответов**
([`server/scorm/templates/default/styles/theme.css:394-398`](../../../server/scorm/templates/default/styles/theme.css),
макет [`layouts/question.html:53-59`](../../../server/scorm/templates/default/layouts/question.html)).
Текст вопроса при этом остаётся выше, во всю ширину.

Такая композиция утверждена эскизом `s-question-media`
([`docs/wireframes/tpl-standard-scene-ds.html:528`](../../wireframes/tpl-standard-scene-ds.html)),
но рисовалась она под вопрос с вариантами-карточками: узкая колонка карточкам не мешает.

Дефект вскрылся на шкальном вопросе PRD-26. Горизонтальный степпер на шесть градаций получает
7 модулей из 12, и подписи градаций слипаются в сплошную строку («НикогдаОчень редкоРедкоЧасто»).
Причина не в степпере: медиа по смыслу относится к формулировке задания, а забирает ширину у
элемента ответа.

Аудио-вопрос не оформлен вовсе. Оба хоста печатают голый `<audio controls>`
([`server/scorm/template/app/render/questionMedia.js:26-35`](../../../server/scorm/template/app/render/questionMedia.js),
[`client/src/pages/learner/template-question-screen.tsx:123-133`](../../../client/src/pages/learner/template-question-screen.tsx)),
а правил для `audio` нет ни в одной `theme.css`. Вид плеера целиком отдан браузеру, палитру
сцены он не наследует, в тёмной теме рисуется светлым. Вдобавок звук занимает левую колонку
5 из 12, хотя визуальной площади у него нет — половина ширины сцены пропадает впустую.

Третья причина работы обнаруживается при попытке починить первые две: **хосты печатают разную
разметку**. В пакете медиа обёрнуто в `.question-media` и несёт инлайн `max-height:250px;margin:16px auto`;
в вебе обёртки нет, а инлайн другой — `max-height:260px;margin:8px auto`. Это нарушение принципа
PRD-12 «оба хоста рендерят из общего кода» и прямая причина того, что шаблонный CSS не может
управлять размером медиа: инлайн рантайма перебивает `theme.css`.

### 1.2 Цель

Сделать медиа частью блока вопроса, а не соседом блока ответов, и придать аудио-вопросу вид,
принадлежащий шаблону. Попутно свести две копии рендерера медиа в одну.

### 1.3 Метрики успеха

- Элемент ответа любого типа получает полную ширину колонки независимо от наличия медиа.
- Разметка медиа на обоих хостах побайтово одна.
- Размер и отступы медиа задаются `theme.css`, а не инлайном рантайма.

## 2. Ограничение, определяющее решение

`tests/template-layout-parity.test.ts` держит 19 макетов побайтово одинаковыми у шаблонов
`default` и `certification`, а DSL шаблонов не имеет выражений. Следовательно **макет не может
ветвиться по типу медиа**: разметка обязана быть одна, а разница «изображение слева, аудио
сверху» делается только средствами CSS.

Это ограничение, а не пожелание: оно определяет и разметку раздела 3, и то, что общий рендерер
раздела 4 обязан выставлять тип медиа атрибутом.

## 3. Композиция сцены вопроса

### 3.1 Разметка

Слот `question-media` переезжает из `.tb-qbody` внутрь `.tb-scene__q`, первым дочерним
элементом — перед заголовком вопроса. Правка идентична в обоих шаблонах, поэтому паритет
сохраняется.

```html
<div class="tb-scene__q">
  <div data-slot="question-media"></div>
  <h2 class="tb-scene__qtitle" data-slot="question-text"></h2>
  <div class="tb-scene__qmeta">…</div>
</div>
<div class="tb-qbody">
  <div class="tb-qbody__answers">…</div>
</div>
```

`.tb-qbody` остаётся одноколоночным всегда; двухколоночное правило и обёртка `.tb-qbody__media`
удаляются.

Порядок в DOM выбран так, что во всех одноколоночных случаях медиа само оказывается над
текстом — отдельного правила порядка не требуется.

### 3.2 Правила раскладки

| Условие | Раскладка |
| --- | --- |
| Медиа нет | Одна колонка, как сегодня |
| Изображение или видео, сцена шире 700px | Две колонки `minmax(0,5fr) minmax(0,7fr)`: медиа слева на обе строки (заголовок и подсказка), текст справа |
| Аудио, любая ширина | Одна колонка: плеер строкой над текстом, во всю ширину колонки |
| Сцена не шире 700px | Одна колонка: медиа над текстом |

Порог 700px — уже существующий контейнерный запрос
([`theme.css:989`](../../../server/scorm/templates/default/styles/theme.css)); новый порог не
заводится. Ветвление по типу опирается на атрибут `data-media-type` из общего рендерера:

```css
.tb-scene__q:has([data-slot="question-media"]:not(:empty)) { grid-template-columns: minmax(0,5fr) minmax(0,7fr); }
.tb-scene__q:has([data-media-type="audio"]) { grid-template-columns: 1fr; }
```

Ширина медиа 5 из 12 повторяет нынешнюю пропорцию сетки: меняется только то, что стоит справа.

Кнопка раскрытия на весь экран у изображения и видео сохраняется вместе с существующим
оверлеем `qmOpenFromEl` — при ширине 5 из 12 она нужнее, чем раньше.

## 4. Общий рендерер медиа

Заводится `shared/template/question-media.ts` с единственной функцией
`renderQuestionMedia({ mediaUrl, mediaType })`, возвращающей строку HTML. Она экспортируется из
`runtime-entry.ts`, то есть доступна обоим хостам: вебу — прямым импортом, пакету — через глобал
`TBTemplate`.

Контракт разметки один для всех типов:

```html
<div class="question-media" data-media-type="image|audio|video">…</div>
```

Инлайновые стили размеров и отступов из HTML убираются: размер медиа задаёт `theme.css`. Это и
есть условие, при котором раскладка раздела 3 вообще управляема.

Правки на местах:

- веб: локальная `mediaHtml` в `template-question-screen.tsx` удаляется, слот заполняется общей
  функцией;
- полноэкранный оверлей изображения и видео тоже становится общим. Сегодня он живёт только в
  рантайме пакета и открывается инлайновым `onclick="qmOpenFromEl(this)"`, поэтому общая
  разметка привела бы к кнопке, которая в вебе ничего не делает. Оверлей переезжает в
  `shared/template` функцией `attachQuestionMediaFullscreen(root)`, работающей делегированием
  по `[data-media-fullscreen]`; инлайновых обработчиков в разметке не остаётся. Веб цепляет её
  на теневой корень рядом с `attachPointerDnd`, пакет — на документ;
- пакет: `questionMedia.js` печать разметки делегирует `TBTemplate.renderQuestionMedia`, а
  оверлей — общей функции, сохраняя глобал `qmOpenFromEl` ради совместимости с внешними
  шаблонами. Файл по-прежнему подклеивается в рантайм
  ([`server/scorm/index.ts:389`](../../../server/scorm/index.ts)); при правке проверить, что имя
  `renderQuestionMedia` не переопределяется ниже по склейке — рантайм собирается плоско, и
  последний в порядке файл перекрывает предыдущие;
- вызовы `renderQuestionMedia(q)` в `mainRender.js:591`, `mainRender.js:674` и
  `adaptiveRender.js:110` сохраняют сигнатуру. Вызов на строке 674 — легаси-экран без макета
  шаблона; он печатает медиа сразу после текста вопроса, что новому правилу уже соответствует.

## 5. Аудио-вопрос

Плеер остаётся нативным `<audio controls>`, но перестаёт быть неоформленным:

- обёртка `.question-media[data-media-type="audio"]` получает фон, рамку и радиус из токенов
  сцены;
- ширина — по колонке, то есть совпадает с шириной плашек вариантов ответа;
- `color-scheme` пробрасывается из темы сцены, иначе в тёмной теме Chrome и Firefox рисуют
  светлый плеер поверх тёмного фона;
- `preload="metadata"` — длительность видна сразу, файл до нажатия не качается.

Внутренности плеера остаются браузерными и будут отличаться в Chrome, Firefox и Safari. Это
осознанная плата за срок, зафиксированная в разделе 9.

## 6. Функциональные требования

| Номер | Требование |
| --- | --- |
| FR-01 | Медиа вопроса принадлежит блоку вопроса, а не блоку ответов: слот `question-media` стоит внутри `.tb-scene__q` |
| FR-02 | Блок ответов занимает полную ширину колонки при любом наличии и типе медиа |
| FR-03 | Изображение и видео на сцене шире 700px стоят слева от текста вопроса, доля ширины — 5 из 12 |
| FR-04 | Аудио стоит строкой над текстом вопроса и занимает полную ширину колонки на любой ширине сцены |
| FR-05 | На сцене не шире 700px медиа любого типа стоит над текстом вопроса |
| FR-06 | Тип медиа выражен атрибутом `data-media-type` на обёртке; макет по типу не ветвится |
| FR-07 | Разметку медиа печатает один рендерер `shared/template/question-media.ts`, общий для веба и пакета |
| FR-08 | Разметка медиа не содержит инлайновых стилей размера и отступов; их задаёт `theme.css` шаблона |
| FR-09 | Кнопка раскрытия на весь экран сохраняется у изображения и видео и отсутствует у аудио |
| FR-10 | Аудио-плеер оформлен плашкой шаблона: фон, рамка и радиус из токенов сцены |
| FR-11 | Аудио-плеер наследует тему сцены через `color-scheme`, включая тёмную |
| FR-12 | Аудио грузит метаданные, но не файл: `preload="metadata"` |
| FR-13 | Правки вносятся одинаково в шаблоны `default` и `certification`; побайтовый паритет макетов сохраняется |
| FR-14 | Слот `question-media` не переименовывается, поэтому область защиты PRD-34 продолжает попадать в цель |
| FR-15 | Полноэкранный просмотр изображения и видео работает на обоих хостах и открывается общим кодом, а не глобалом рантайма пакета |
| FR-16 | Разметка медиа не содержит инлайновых обработчиков событий; кнопка помечена `data-media-fullscreen`, обработка идёт делегированием |

## 7. Совместимость

Слот сохраняет имя и назначение, меняется только его место в макете, поэтому:

- перечень защищаемых областей PRD-34
  ([`shared/template/protection/spec.ts:68`](../../../shared/template/protection/spec.ts))
  правки не требует;
- внешние шаблоны, загруженные через админ-реестр PRD-3, продолжают работать: слот
  необязательный, а его отсутствие и раньше означало «медиа не показывать»;
- модель данных вопроса не меняется: `mediaUrl` и `mediaType` остаются как есть.

Отладочный плеер PRD-18 собирает пакет из живого состояния и получает новую композицию
автоматически.

## 8. Критерии приёмки

Юнит-тесты:

- новый тест общего рендерера: разметка и `data-media-type` для трёх типов медиа, пустая строка
  при отсутствии адреса или типа;
- обновление `tests/question-scene-layout.test.ts` под новое место слота;
- обновление набора слотов в
  [`shared/template/preview-context.ts:580`](../../../shared/template/preview-context.ts);
- `tests/template-layout-parity.test.ts` остаётся зелёным без правки;
- `shared/template/__tests__/protection-apply.test.ts` и `tests/content-protection.test.ts`
  подтверждают, что область медиа по-прежнему защищается: сам селектор перечислен в
  `QUESTION_REGIONS` (`shared/template/protection/spec.ts`), а оба набора проходят по этому
  перечню.

Приёмка в реальном браузере (Playwright), на обоих хостах:

- шкальный вопрос с изображением — случай, с которого началась работа: степпер во всю ширину,
  подписи градаций не слипаются;
- вопрос с вариантами и изображением: медиа слева от текста, ответы во всю ширину;
- аудио-вопрос: плеер строкой над текстом, по ширине плашек вариантов, в светлой и тёмной теме;
- кнопка «во весь экран» открывает оверлей и закрывается по фону, крестику и Esc — на обоих
  хостах, включая веб, где полноэкранного просмотра раньше не было;
- сцена не шире 700px: всё складывается в одну колонку;
- то же самое в собранном SCORM-пакете.

Шаблоны: перегенерация `preview.html` для обоих и бамп версии в манифестах.

Порядок работ: эскиз в `docs/wireframes` на согласование, затем код.

## 9. Техдолг

**Пример SCORM не содержит медиа.** `scripts/generate-sample-scorm.ts:66-67` жёстко проставляет
`mediaUrl: null` и `mediaType: null`, поэтому документированный путь приёмки (`npm run scorm:sample`
плюс `npm run scorm:player`) композицию медиа не проверяет вообще — в собранном пакете нет ни
одного непустого `mediaType`. Приёмка PRD-38 обошла это, собрав пакет экспортом живого теста, но
следующей работе с медиа придётся повторять обход. Добавить в пример по одному вопросу с
изображением и с аудио.

**Собственный аудио-плеер `ou-audio` в ui-kit.** Компонент DS (кнопка воспроизведения, полоса
перемотки, время) плюс framework-free разметка и поведение в `shared/template`. DS-CSS уже
вкладывается в пакет сборщиком
[`server/scorm/builders/ds-styles.ts:32`](../../../server/scorm/builders/ds-styles.ts), то есть
второй путь доставки заводить не придётся. Общий рендерер раздела 4 — та точка, куда плеер
подставляется без правки макетов и хостов. Правило файла ui-kit: `university-rt.css` лежит в
репозитории в двух копиях, править нужно обе.

## 10. Вне охвата

- Собственный DS-компонент аудио-плеера (раздел 9).
- Медиа на прочих экранах: страницы контента, стартовый экран, обратная связь.
- Редактор вопроса: способ загрузки и хранения медиа не меняется.
- Множественное медиа в одном вопросе.
