## Терминология

- **Тег вопроса** = значение в `questions.tags` (напр. `finance_base`). Подтема = тег; отдельной
  сущности «подтема» нет, иерархии тем нет. ВАЖНО: поле `questions.tags` в схеме было, но **способа
  задать тег вопросу не существовало** (ни UI, ни проброса в API) — поэтому тегирование вопросов
  внесено в охват PRD-11 как пререквизит (см. §3a).
- **Квота выдачи** = объём вопросов с заданным тегом ВНУТРИ общей выборки темы `drawCount`,
  с режимом `mode`: `exact` (РОВНО `count`) или `min` (НЕ МЕНЕЕ `count`). Режим — свойство КАЖДОГО
  тега (страты), не темы; дефолт `exact`. Остаток выборки — случайный из вопросов без `exact`-тегов.
  (Решение 2026-06-04: тогл «Общий/По тегам» / `modeGranularity` убран как лишнее усложнение —
  режим всегда per-тег.)

Это механизм **ДОСТАВКИ** (какие вопросы выдать обучающемуся), ортогональный и расчёту, и
«Цене ответа» (PRD-10). В скоринг не вмешивается.

## 1. Обзор

### 1.1 Контекст

Сейчас выдача вопросов на тему равномерно случайна: `shuffle(вопросы_темы).slice(0, drawCount)`
([app.js](../../../server/scorm/assets/app.js)). Гарантировать «N вопросов определённой подтемы
в форме» нельзя: отбор не различает подтемы/теги. Единственная стратификация — адаптивный режим
(`adaptive_levels`: квота по диапазону СЛОЖНОСТИ внутри темы), но это другая ось.

Ближайший потребитель — РТК-сертификация: внутри раздела (напр. «Финансы») есть подтемы
(`finance_base`/`finance_metrics`/`finance_invest`), и форма должна покрывать их в нужном объёме.

### 1.2 Метрики успеха

| Цель | Метрика |
| --- | --- |
| Гарантированное покрытие подтем | при заданной квоте каждая попытка содержит `count` (`exact`) либо не менее `count` (`min`) вопросов на тег (в общей выборке `drawCount`) |
| Обратная совместимость | тесты без квоты выдаются как сейчас (равномерно), без изменений |
| Прозрачность нехватки | нехватка вопросов с тегом видна автору и в выдаче (warning) |

## 3a. Тегирование вопросов (пререквизит, в охвате PRD-11)

Квоты опираются на `questions.tags`. Поле в схеме есть (PRD-2 §8.2:
`tags jsonb $type<string[]> default []`), но способа ЗАДАТЬ тег вопросу не было — ни UI (нет
chip-инпута в редакторе вопроса), ни проброса в API (`POST/PUT /api/questions` и `storage` поле
`tags` игнорировали). Тег нельзя было ни добавить, ни сохранить — поле-призрак. Без тегирования
квота-Select пуст и фича бесполезна, поэтому тегирование внесено в охват PRD-11.

Что входит:

- **API** — `tags: string[]` принимается в create/update вопроса (route `questions.ts` + `storage`),
  по образцу `scoringJson` (PRD-10 Стадия 1). Бэкомпат: отсутствие `tags` → `[]`.
- **UI** — chip/Tag-инпут в форме вопроса (`questions.tsx`, shadcn): добавить/удалить тег;
  автодополнение из уже использованных тегов (distinct `questions.tags`).
- **Эскиз** — отдельный эскиз chip-инпута (DS-handbook first) + согласование до React-кода (NFR-14).
- Связь с квотами: Select подтемы в квота-блоке (§7) показывает РЕАЛЬНЫЕ теги вопросов темы.

### Правила именования тега (РЕШЕНО 2026-06-04: свободные метки + нормализация)

Тег — человекочитаемая подтема, которую набирает автор; нигде не используется как идентификатор
в коде/URL (только сопоставляется внутри и показывается в чипах/Select), контент кириллический,
поэтому слаг-формат не навязывается. **Пробелы внутри разрешены.** Корректность совпадений
обеспечивает нормализация (без неё `"Финансы"` ≠ `" финансы"` → квота молча недобирает).

Нормализация на входе (одинаково в API и в UI перед сохранением):

- `trim` краёв; внутренние последовательности пробельных символов схлопываются в один пробел
  (`\s+` → `" "`);
- длина после нормализации **1–50** символов; пустой / только из пробелов — отклоняется;
- управляющие символы запрещены; прочие (буквы любых алфавитов, цифры, пробел, `-`, `_`, пунктуация) —
  допускаются.

Регистр и уникальность:

- регистр **сохраняется как введён** (для отображения), но сравнение и дедуп —
  **регистронезависимо** (`toLocaleLowerCase`, корректно для кириллицы);
- в пределах одного вопроса дубли по нормализованной регистронезависимой форме схлопываются
  (нельзя добавить «Финансы» дважды);
- автодополнение по distinct тегам банка дедуплит регистронезависимо; первая встреченная форма —
  каноничная для показа.

Сопоставление в выдаче (`shared/draw/blueprint.ts` + JS-порт): обе стороны (тег вопроса и `tag`
страты) приводятся к нормализованной нижнерегистровой форме перед сравнением — near-miss по регистру/
пробелам совпадает.

Вне охвата: namespace/иерархия тегов, глобальное переименование/слияние (будущее).

## 4. Модель данных

Без новых сущностей: переиспользуется `questions.tags` (классификация) и расширяется
`test_sections` одним опциональным `jsonb` (как уже `topic_pass_rule_json`/`feedback_json`).

```text
test_sections.draw_blueprint_json (опционально; отсутствие = равномерная выдача):
  strata: [ { tag: string, count: number, mode?: "exact" | "min" } ]
           # count >= 1; mode — НА КАЖДЫЙ тег, дефолт "exact". Без modeGranularity/топик-mode.

  # эффективный режим страты: strata[i].mode ?? "exact"

questions.tags: string[]                        # тег = подтема; ЗАДАЁТСЯ в редакторе вопроса (§3a)
```

Квоты — количества на тег (`exact` — ровно, `min` — не менее) внутри общей выборки `draw_count`
(`Σ count <= draw_count`); остаток добирается случайно из вопросов без `exact`-тегов (§5).
Режим `mode` — свойство КАЖДОЙ страты (тега), а не темы (решение 2026-06-04).

## 5. Логика выдачи

Расширение отбора ([app.js](../../../server/scorm/assets/app.js) и парного рантайма):

```text
если есть blueprint.strata:
  selected = []; used = {}
  effMode(s) = s.mode ?? "exact"                       # режим — на тег (без modeGranularity)
  exactTags = множество тегов страт, где effMode = "exact"
  для каждой страты {tag, count} по порядку:           # шаг 1: набрать count на тег
    pool = вопросы_темы.filter(q => !used[q.id] && q.tags.includes(tag))
    take = shuffle(pool).slice(0, count)               # take.length < count -> warning
    selected += take; пометить used
  # шаг 2: остаток до drawCount — из вопросов БЕЗ exact-тегов
  #        (mode=exact остаётся ровно count; mode=min может дорасти; untagged участвуют):
  free = вопросы_темы.filter(q => !used[q.id] && нет общих тегов с exactTags)
  selected += shuffle(free).slice(0, drawCount - selected.length)
  выдать selected                                        # |selected| <= drawCount
иначе:
  shuffle(вопросы_темы).slice(0, drawCount)              # как сейчас
```

- Дедупликация через общий `used` (вопрос в нескольких стратах — один раз, FR-04).
- Нехватка (`take.length < count`) → диагностический warning, выдаётся сколько есть (FR-06).
- Применяется в обоих местах отбора: рантайм SCORM-пакета и построение варианта попытки.

## 6. Валидация

- На сохранении темы: `Σ count <= draw_count` (квоты — минимумы внутри общей выборки; иначе
  ошибка валидации); на каждую страту `count <= число вопросов темы с этим тегом` — иначе
  **warning** (не блокирует, как баннеры покрытия в шкалах): «подтема `<tag>`: вопросов меньше
  квоты (`<доступно>` из `<count>`)».
- Пустой `strata` или `count < 1` — ошибка валидации.

## 7. UI (квота-редактор — эскиз СОГЛАСОВАН 2026-06-04)

Эскиз `docs/wireframes/prd11-draw-quotas.html` (свич + инлайн-блок в строке темы `tb-topic-row`,
ui-kit). Стартует ПОСЛЕ тегирования (§3a, под-трек B) — иначе Select подтем пуст.

- В теле строки темы, рядом с «Вопросов в тест» (`draw_count`), — **Switch «Квоты по подтемам
  (тегам)»** (выкл = равномерная выдача). Без модалки (конфиг мелкий; модалка — у «Обратной связи»).
- Включён → инлайн-блок: строки `[тег → сколько → режим]`: тег — Select РЕАЛЬНЫХ тегов вопросов
  темы (`questions.tags`), `count` — NumberInput, **режим — SegmentedControl `Ровно`/`Не менее` В
  КАЖДОЙ строке** (дефолт `Ровно`); «Добавить квоту»; сумма квот vs `draw_count`.
- Состояния: выключено (равномерно), включено, нехватка (warning-баннер + колонка «Доступно»),
  ошибка (`Σ > draw_count` → сохранение блокируется).
- Тогл «Общий/По тегам» убран (режим — на тег). DS-примитивы (`ou-switch`/`ou-seg`/`ou-select`/
  `ou-field`/`ou-banner`/`ou-tag`); новых компонентов DS не требует.

- Поле `draw_blueprint_json` опционально; отсутствие = сегодняшняя равномерная выдача (NFR-10);

## 9. Вне охвата

- **«Свежесть на retry»** (anti-repeat — исключить вопросы прошлой попытки; ротация фиксированных
  форм РТК) — НЕ реализуема внутри автономного SCORM-пакета на WebTutor. ПОДТВЕРЖДЕНО 2026-06-04:
  WebTutor не поддерживает `adl.data` (Shared Data Buckets, `GetValue("adl.data._count")` → err 401),
  а `cmi.suspend_data` живёт только within-attempt → cross-attempt стора нет, пакет начинает новую
  попытку «слепым». Квота PRD-11 — stateless и от этого НЕ зависит. «Retry-different», если нужно,
  решается на уровне назначения/registration в LMS (вне пакета), либо descope. Память
  `reference_webtutor_scorm_runtime`; фиксированные формы РТК — issue #23.
- **Пороги/правила прохождения на уровне тега** (per-tag pass rule) — не вводятся; правила
  прохождения остаются на теме/тесте (РТК их на подтему не требует).
- **Стратификация по сложности** — уже есть в адаптивном режиме (`adaptive_levels`).
