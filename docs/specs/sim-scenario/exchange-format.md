# Сценарий в ИС: контракт сценария, версия 2

Статус: версия 2, 2026-10-16 (версия 1 — 2026-10-06). Модель — общая часть и варианты по устройствам, вариант —
граф сцен. Основание — раздел 1 и подразделы 2.1–2.6 [v2-design.md](v2-design.md).

Состав папки:

- [scenario.schema.json](scenario.schema.json) — JSON Schema (draft 2020-12) файла `scenario.json`;
- [result-format.md](result-format.md) и [result.schema.json](result.schema.json) — контракт
  результата, который возвращает плеер;
- [example/](example/) — эталонный квест «Регистрация входящего письма»: `scenario.json` и
  изображения в `media/`;
- [user-journey.md](user-journey.md) — пользовательский путь;
- [v2-design.md](v2-design.md) — требования и проект версии 2.

Код контракта — `shared/sim/contract.ts`: типы повторяют схему один в один. Плеер —
`shared/sim/engine.ts` (логика) и `shared/sim/player.ts` (отрисовка). Версию 1 читает и переводит в
версию 2 `shared/sim/upgrade.ts` (раздел 7).

## 1. Как сыграть сценарий

```bash
npm run sim:play                         # эталонный квест
npm run sim:play -- <папка сценария>     # своя папка: scenario.json + media/
npm run sim:play -- <папка> --open       # и сразу открыть браузер
```

Плеер открывается на `http://localhost:5070/`: экран правил → «Старт» → полный экран →
окно результата. Каждый завершённый результат сохраняется в `out/sim-results/<время>.json`.

## 2. Зачем нужен формат

Формат переносит сценарий целиком, с изображениями. Пока редактора нет, сценарий собирается
руками: автор кладёт изображения в `media/` и пишет `scenario.json`. Тот же файл потом
импортируется в вопрос, экспортируется из редактора и запекается в SCORM-пакет.

В формат не входит то, что сценарию не принадлежит:

| Не входит | Где живёт |
| --- | --- |
| Цена и штрафы | Оценка в тесте: умолчания теста и переопределение по вопросу |
| Тема, сложность, теги вопроса | Вопрос банка |
| Результаты прохождений | Результат плеера ([result-format.md](result-format.md)) и аналитика |

`scenario.json` — та же модель, что хранится в вопросе и уходит в пакет; отличаются только ссылки
на изображения. Поэтому «экспорт → импорт» ничего не теряет, а новое поле модели одновременно
становится полем формата.

## 3. Контейнер

ZIP-архив `<имя>.scenario.zip` или просто папка:

```text
registraciya-vhodyashego/
├── scenario.json          описание, UTF-8 без BOM
└── media/                 библиотека изображений
    ├── list.png
    ├── file-menu.png
    └── ...
```

Изображения — PNG, JPEG или WebP, не больше 3840 px по стороне и 1 МБ каждое. Для полупрозрачных
диалогов с затемнением нужен PNG с прозрачностью. Формат определяется по содержимому файла, а не по
расширению. Архив целиком — не больше 40 МБ. `scenario.json` лежит в корне архива; архив, в который
упаковали папку сценария, тоже принимается — `scenario.json` тогда на уровень глубже.

После приёма имя файла архива не используется: сценарий называется по `meta.title`, изображения
уходят в медиатеку, а «Скачать» собирает архив заново из сохранённого.

## 4. Модель

Сценарий состоит из **общей части** — вид, задание, библиотека изображений, поля, цель, этапы — и
**вариантов** по устройствам (подраздел 4.11). Вариант — граф **сцен**. Сцена — холст заданного размера,
на котором лежат **элементы** — изображения из библиотеки. Порядок элементов — порядок слоёв:
последний сверху. **Зоны** на сцене ведут на другие сцены. Значения, которые участник вводит или
выбирает, хранятся в **полях**. Сцена с **концом** завершает прогон (подраздел 4.8).

Все координаты — в пикселях сцены. Полный экран масштабирует сцену целиком, поэтому от экрана
участника координаты не зависят.

Как это похоже на PowerPoint: сцена — слайд; дублировали сцену и добавили изображение меню —
получили сцену «меню открыто». При переходе между сценами перерисовывается только разница
(раздел 5).

Нумерация подразделов сохранена от версии 1; новые подразделы — 4.11 «Вариант», 4.12 «Маршрут» и 4.13 «Этапы».

### 4.1. Корень

| Поле | Обязательно | Описание |
| --- | --- | --- |
| `format`, `version` | да | `skillum.sim-scenario`, `2` |
| `kind` | да | `control` — контрольный: судится целью и ролями действий; `research` — исследовательский: поведение без вердикта |
| `meta` | да | `title`, `task` (текст задания), `language`, `system`, `createdAt`, `tool` |
| `settings` | нет | Раздел 4.2 |
| `media` | да | Библиотека: `{ id, file, w, h }` — путь в архиве и размер изображения; общая на все варианты |
| `fields` | нет | Поля (раздел 4.5), общие |
| `goal` | нет | Только `control`: `{ checks }` — проверки цели, общие для всех вариантов (подраздел 4.8) |
| `stages` | нет | Этапы задачи: `[{ id, title }]`, общие; сцена ссылается на этап полем `stage` |
| `variants` | да | Варианты по устройствам, не более одного на устройство (подраздел 4.11) |

Правила по видам:

| | `control` | `research` |
| --- | --- | --- |
| Роль зоны | Обязательна: `path`, `alt`, `detour`, `trap`, `neutral` | Необязательна; зона без роли — действие, не ошибка |
| Конец | Хотя бы одна сцена `success`, достижимая по `path` и `alt` | Хотя бы один `finale` или кнопка «Я закончил» |
| `goal.checks` | Есть | Нет |
| «Я закончил» на панели | Нет | По умолчанию есть, выключается (`settings.finishButton`) |
| Исход прогона | `success`, `partial`, `fail`, `exited`, `timeout` | `finale`, `declared`, `exited`, `timeout` |

### 4.2. Настройки

Настройки общие для всех вариантов. Размер сцены и минимальная ширина окна принадлежат устройству и
переехали в вариант (подраздел 4.11).

| Поле | По умолчанию | Описание |
| --- | --- | --- |
| `normSeconds` | нет | Норма времени: превышение штрафуется оценкой в тесте |
| `limitSeconds` | `null` | Жёсткий лимит: по истечении — исход `timeout` |
| `hints.enabled`, `hints.afterMisses` | `true`, `3` | Подсказка после N ошибок подряд на сцене |
| `counters.actions`, `.misses`, `.detours` | `false` | Какие счётчики видит участник; решает разработчик сценария |
| `finishButton` | `true` | Только `research`: участник может закончить кнопкой «Я закончил» |
| `costs` | умолчания системы | Стоимость действий по виду: `{ "click": 1, "key": 0.5, ... }`; виды — подраздел 4.6 |
| `otherRouteRating` | нет | Оценка прогона вне всех объявленных маршрутов, в `(0; 1]`; нет — прогон судится по оптимуму (подраздел 4.12) |

### 4.3. Сцена

| Поле | Описание |
| --- | --- |
| `id`, `title` | Идентификатор и название |
| `size` | Размер; нет — `stage` варианта |
| `elements` | Элементы: изображения по порядку слоёв |
| `fields` | Где на этой сцене стоят поля: `{ field, x, y, w, h, editable }` |
| `zones` | Зоны действий |
| `keys` | Сочетания клавиш |
| `onMissGoto` | Клик мимо всех зон — ошибка и переход сюда. Так закрывается раскрытое меню |
| `stage` | Этап задачи, к которому относится сцена: `id` из `stages` корня |
| `end` | Конец прогона (подраздел 4.8) |

Заготовки `goal` и `views` версии 1 в сцене больше нет: цель переехала в корень и в `end`, раскладку для
телефона заменил вариант `phone`.

### 4.4. Элемент

| Поле | Описание |
| --- | --- |
| `id` | Идентификатор в пределах сцены. Одинаковый `id` на разных сценах — один и тот же предмет: так работает перерисовка разницы |
| `media` | Изображение библиотеки |
| `x`, `y`, `w`, `h` | Место; `w` и `h` по умолчанию — размер изображения |
| `hidden` | Скрыт при первом появлении; показывается эффектом `show` или `toggle` |
| `autoHideMs` | Показанный элемент скрывается сам — сообщения системы |
| `appear` | Появление: `mode` — `with-previous` (вместе с предыдущим) или `after-previous` (после него), `delayMs`, `effect` — `none` или `fade`, `durationMs` |
| `scroll` | Элемент прокручивается внутри своей рамки (длинный список); зоны с `in` — в координатах изображения |

Видимость элемента хранится по его `id` на весь сценарий, как значение поля: отмеченный флажок
остаётся отмеченным, когда участник открывает меню на сцене-дубле.

### 4.5. Поле

Объявляется в корне (`fields`), ставится на сцены их `fields`.

| Поле | Описание |
| --- | --- |
| `id`, `title` | Идентификатор и название |
| `fill` | `keyboard` — участник набирает; `effect` — значение вписывает эффект `set` (выбор из справочника, списка) |
| `initial` | Значение до начала |
| `check` | Правила ответа PRD-57 (`AnswerRuleSet`) — тот же движок, что у короткого ответа |
| `checkWhen` | `input` — неверное значение при вводе сразу ошибка; `goal` — проверка только в цели |
| `tabIndex`, `allowPaste`, `hint` | Порядок Tab, разрешена ли вставка, подсказка к полю |

### 4.6. Зона и сочетание клавиш

Зона — место на сцене, форма задаётся полем `shape`. Сочетание клавиш — то же без места, с полем
`keys` (`Ctrl+S`, `Shift+F10`, `Escape`; буква — физическая клавиша, раскладка не важна).

| Форма | Поля | Для чего |
| --- | --- | --- |
| `rect` (по умолчанию) | `x, y, w, h`; `radius` — скругление углов | Кнопки, пункты меню, строки таблиц; со скруглением — кнопки-«таблетки», карточки |
| `ellipse` | `x, y, w, h` — эллипс, вписанный в прямоугольник; круг при `w = h` | Круглые значки, аватары, переключатели |
| `polygon` | `points: [[x, y], ...]` — вершины по порядку обхода, без `x, y, w, h` | Вкладки-трапеции, области схем и карт, фигуры неправильной формы |

Клик на границе формы — попадание. В срезанный угол скруглённого прямоугольника — промах.
Прямоугольник многоугольника не хранится, а вычисляется по вершинам, поэтому они не могут
разойтись. Подсказка и выделение копируемой зоны обводят её форму.

```json
[
  { "id": "avatar", "shape": "ellipse", "x": 1800, "y": 16, "w": 64, "h": 64, "role": "detour", "effects": [{ "show": "profile-menu" }] },
  { "id": "tab-archive", "shape": "polygon", "points": [[420, 120], [600, 120], [620, 168], [400, 168]], "role": "path", "effects": [{ "goto": "archive" }] },
  { "id": "send", "x": 1600, "y": 980, "w": 240, "h": 56, "radius": 28, "role": "path", "effects": [{ "goto": "sent" }] }
]
```

| Поле | Описание |
| --- | --- |
| `id`, `title` | Идентификатор и название для автора и аналитики |
| `role` | `path` — основной путь; `alt` — другой верный путь; `detour` — допустимое лишнее действие; `trap` — правдоподобная ошибка с последствиями; `neutral` — ни действие, ни ошибка. Обязательна в `control`, в `research` необязательна: действие без роли — просто действие |
| `error` | Только у `trap`: название ошибки — «Удалил чужой документ вместо создания нового» |
| `action` | Только у зоны. Мышь, вариант `desktop`: `click` (по умолчанию), `dblclick`, `rightclick`, `hover`, `drag`. Жесты, вариант `phone`: `tap`, `doubletap`, `longpress`, `swipe-left`, `swipe-right`, `swipe-up`, `swipe-down`. Действие чужого устройства — ошибка проверки |
| `hoverMs`, `drop`, `in` | Задержка наведения, куда отпустить при перетаскивании, прокручиваемый элемент |
| `copyText` | Только у нейтральной зоны: копируемый текст (раздел 4.9) |
| `cost` | Стоимость действия в шагах, число не меньше нуля; нет — умолчание сценария (`settings.costs`) или системы по виду действия |
| `when` | Условие |
| `effects` | Что происходит, по порядку |
| `otherwise` | Что происходит, если условие не выполнено; это ошибка — «система отказала» |
| `hint` | Подсказка, если участник застрял на сцене |

Стоимость действия — это вид действия: зона даёт свой `action` (`click`, `tap`, ...), сочетание клавиш — `key`,
фиксация значения поля — `field`. Умолчания системы:

| Вид действия | Стоимость по умолчанию |
| --- | --- |
| `click`, `rightclick`, `dblclick` | 1 |
| `hover` | 0,5 |
| `drag` | 1,5 |
| `key` | 0,5 |
| `field` | 1 |
| `tap`, `doubletap`, `longpress`, `swipe-*` | 1 |

Виды действия для стоимости (`settings.costs`): `click`, `dblclick`, `rightclick`, `hover`, `drag`, `tap`,
`doubletap`, `longpress`, `swipe-left`, `swipe-right`, `swipe-up`, `swipe-down`, `key`, `field`.

Стоимость прогона — сумма стоимостей принятых действий. Промахи, отказы, ловушки и подсказки в неё не входят: это
ось точности, не стоимость пути.

Виды неправильного поведения:

| Вид | Пример | Как считается |
| --- | --- | --- |
| Клик мимо | По пустому месту | Ошибка |
| Отказ системы | «Сохранить» с пустыми полями | Ошибка |
| Неверное значение | Номер без префикса | Ошибка значения |
| В сторону | Открыл «Исходящие» | Лишнее действие |
| Ловушка | «Удалить → Да» | Названная ошибка; может вести на сцену-провал |
| Неверный финал | Не тот корреспондент | По проверкам цели |

### 4.7. Эффекты и условия

| Эффект | Что делает |
| --- | --- |
| `{ "goto": "<сцена>" }` | Переход на сцену |
| `{ "show" \| "hide" \| "toggle": "<элемент>" }` | Видимость элемента текущей сцены |
| `{ "set": "<поле>", "value": "..." }` | Вписать значение |
| `{ "clear": "<поле>" }` | Очистить поле |

| Условие | Истинно, когда |
| --- | --- |
| `{ "filled": ["a", "b"] }` | Все поля непусты |
| `{ "field": "a", "check": {...} }` | Значение проходит правила |
| `{ "visible": "<элемент>" }` | Элемент показан |
| `{ "all" \| "any": [...] }`, `{ "not": ... }` | Логика |

### 4.8. Конец прогона и цель

Сцена с `end` завершает прогон при входе на неё. `end` — одна из трёх форм:

| Форма | Смысл |
| --- | --- |
| `{ "outcome": "success", "message" }` | Только `control`. Исход решают проверки цели корня |
| `{ "outcome": "fail", "message" }` | Сцена-провал: исход `fail`, `message` объясняет, что случилось. Обычно на неё ведёт ловушка |
| `{ "outcome": "finale", "title", "message", "target" }` | Только `research`. Именованный финал; `target: true` помечает целевые финалы, до которых измеряется эффективность |

Проверки цели лежат в корне, общие для всех вариантов — так исходы на разных устройствах сравнимы:
`goal: { checks: [{ field, check, critical, weight }] }` (проверка по умолчанию — проверка самого поля,
`critical` по умолчанию `true`, вес — 1):

| Что прошло | Исход |
| --- | --- |
| Все проверки | `success` |
| Не прошла хоть одна критичная | `fail` |
| Все критичные, но не все остальные | `partial`, доля = вес прошедших / вес всех |

Засчитывать ли `partial` долей балла, решает оценка в тесте.

### 4.9. Копирование

Текст на изображении нельзя выделить, поэтому то, что в работе копируют, автор отмечает
нейтральной зоной с `copyText`. Двойной щелчок или правый клик выделяет её, Ctrl+C копирует в
буфер плеера и, если браузер разрешает, в системный; Ctrl+V в поле вставляет. Копирование не
ошибка и не действие. Защита теста от копирования на него не действует.

### 4.10. Телефон

Вариант `phone` — отдельный граф сцен для телефона, у него свой размер сцены, свои изображения и зоны с
жестами вместо мыши (подраздел 4.6). Задание, поля, проверки цели и этапы общие с десктопным вариантом.
Заготовка `views` версии 1 убрана: перевод версии 1 не теряет ничего, потому что в ней `views` были пусты.
Приоритет реализации: сначала десктоп; исполнять вариант `phone` плеер начнёт позже, формат его
хранит и проверяет уже сейчас.

### 4.11. Вариант

`variants: [{ device, stage, minViewportWidth, start, scenes, routes }]`.

| Поле | Описание |
| --- | --- |
| `device` | `desktop` или `phone`; на одно устройство не больше одного варианта |
| `stage` | Размер сцены по умолчанию, например `{ "w": 1920, "h": 1200 }` |
| `minViewportWidth` | Самое узкое окно участника, в котором играет вариант; на десктопе по умолчанию `1280` |
| `start` | Стартовая сцена варианта |
| `scenes` | Сцены варианта |
| `routes` | Объявленные маршруты варианта (подраздел 4.12) |

Идентификаторы сцен, зон, полей и изображений уникальны в пределах сценария; библиотека изображений общая —
один скриншот может служить обоим устройствам.

### 4.12. Маршрут

Объявленный путь к цели с оценкой автора. Маршруты свои у каждого варианта, потому что зоны у вариантов свои.

```json
"routes": [
  { "id": "create", "title": "Кнопка «+ Создать»", "rating": 1,
    "keys": [{ "scene": "inbox", "action": "create" }, { "scene": "card", "action": "save" }] },
  { "id": "file-menu", "title": "Через меню «Файл»", "rating": 0.8,
    "keys": [{ "scene": "inbox", "action": "file" }, { "scene": "inbox-file", "action": "file-new" }] }
]
```

| Поле | Описание |
| --- | --- |
| `id`, `title` | Идентификатор и название маршрута |
| `rating` | Оценка автора в `(0; 1]`: 1 — лучший путь |
| `keys` | Ключевые действия по порядку: пары «сцена + зона или сочетание клавиш» |

- `keys` сопоставляются как подпоследовательность принятых действий прогона: лишние действия между ключами
  маршрут не ломают.
- Подходят несколько маршрутов — берётся с большей оценкой, при равенстве — дешевле.
- Стоимость маршрута вычисляется сама: самый дешёвый путь до цели, проходящий ключевые действия по порядку.
  Автор вводит только оценку.
- Эффективность прогона: попал в маршрут `r` — `rating(r) × min(1, C(r) / C(прогон))`; не попал и задан
  `settings.otherRouteRating` — `otherRouteRating × min(1, C* / C(прогон))`; не попал и не задан —
  `min(1, C* / C(прогон))`. Здесь `C*` — стоимость самого дешёвого пути от старта до сцены `success`, где проходят
  все проверки цели (у исследовательского сценария — до целевого финала). Подробности — v2-design.md, раздел 2.

### 4.13. Этапы

`stages: [{ id, title }]` в корне; сцена ссылается на этап полем `stage`. Этапы общие для вариантов:
устройства сравниваются по этапам при разных сценах. Этап на балл не влияет — это разрез аналитики.

## 5. Как плеер исполняет сценарий

Правила одни для плеера разработки, веба, SCORM-пакета и тестов — это один код,
`shared/sim/engine.ts`. Движок работает с одним вариантом — тем, что соответствует устройству участника.

1. Старт на сцене `start` варианта; поля — `initial`.
2. Клик разбирается по зонам текущей сцены с учётом их формы; при перекрытии побеждает та, что
   раньше в массиве.
3. Нейтральная зона клик поглощает. У зоны `dblclick` одиночный клик ничего не делает.
4. Зона действия: выполнено `when` (или его нет) — `effects`, действие засчитывается по роли;
   иначе — `otherwise` и ошибка «отказ системы». Принятое действие добавляет к стоимости прогона свою
   стоимость.
5. Мимо всех зон — ошибка с координатами; на сцене с `onMissGoto` — ещё и переход туда.
6. Поле `keyboard` фиксирует значение по Enter, Tab или уходу из поля. При `checkWhen: input`
   неверное значение — ошибка; его можно исправить.
7. Сочетание клавиш ищется в `keys` сцены. Ctrl+C при выделенной копируемой зоне копирует.
   Неописанное сочетание ничего не делает и ошибкой не считается.
8. После `hints.afterMisses` ошибок подряд на сцене — подсказка: сначала пустое или неверное поле
   ввода с подсказкой, иначе первая полезная зона основного пути. Засчитанное действие или переход
   сбрасывает счётчик.
9. Переход между сценами: элементы с тем же `id`, изображением и местом остаются на экране;
   пропавшие исчезают; новые появляются по `appear`.
10. Вход на сцену с концом завершает сценарий (подраздел 4.8): `success` судится общими проверками цели,
    `fail` — сцена-провал, `finale` — исход `finale` с названием финала.
11. В исследовательском сценарии участник может закончить сам кнопкой «Я закончил» (`settings.finishButton`):
    исход `declared`. Досрочный выход — исход `exited`, истечение `limitSeconds` — `timeout`.

## 6. Проверки при импорте

Ошибки, импорт отклоняется:

- `format`, `version`; версия новее поддерживаемой; неуникальный или кривой `id`;
- `kind` не `control` и не `research`; в сценарии нет вариантов; вариант для одного устройства объявлен дважды;
  неизвестное устройство варианта; не задан или не найден `start` варианта;
- у исследовательского сценария есть `goal` или конец `success`; у контрольного есть финал; конец должен быть
  `fail` или `finale` (у контрольного — `success` или `fail`); у финала нет названия;
- этап объявлен дважды или без названия; сцена ссылается на необъявленный этап;
- ссылки `goto`, `onMissGoto`, `media`, поля в `set`, `clear`, условиях и целях, элементы в
  `show`, `hide`, `toggle`, `visible` (элемент должен быть на той же сцене) никуда не ведут;
- элемент, поле или зона выходит за пределы сцены (у многоугольника — любая вершина); не задан размер ни у
  сцены, ни у варианта;
- у зоны неизвестная форма; у `polygon` меньше трёх вершин, повторяется вершина или стороны
  пересекаются; у `polygon` есть `x, y, w, h` или `radius`; `radius` у формы, отличной от `rect`,
  или больше половины меньшей стороны;
- у зоны действия нет эффектов, у нейтральной есть; у ловушки нет `error`; `otherwise` без `when`;
  `copyText` у не-нейтральной зоны; `drag` без `drop`; сочетание не по шаблону;
- в контрольном сценарии у действия нет роли или она неизвестна;
- действие зоны не бывает на устройстве варианта (жест на десктопе, мышь на телефоне);
- стоимость (`cost`, `settings.costs`) не число или меньше нуля; неизвестный вид действия в `settings.costs`;
  `otherRouteRating` вне `(0; 1]`;
- у контрольного сценария нет конца `success`, или до него нельзя дойти только по зонам `path` и `alt`; у
  исследовательского нет ни финала, ни кнопки «Я закончил», или до финалов нельзя дойти;
- проверка цели по полю без проверки; вес не больше нуля;
- сцена без конца без единого действия — тупик;
- маршрут: оценка вне `(0; 1]`, два маршрута с одинаковыми ключевыми действиями, ключевое действие ссылается на
  несуществующую сцену или действие, до цели нельзя дойти через ключевые действия по порядку;
- изображения нет в архиве, не тот тип, тяжелее 1 МБ или сторона больше 3840 px.

Предупреждения: недостижимая сцена; поле ввода без проверки; размер изображения не совпадает с
`media.w`, `media.h`; файл в `media/`, который сценарий не использует; шаг в сторону даёт путь дешевле основного
(роли зон перепутаны); ни у одного маршрута нет оценки 1 (максимум балла меньше 100%); превышен предел поиска
оптимума (100 000 состояний) — эффективность считается только по объявленным маршрутам; примечания перевода
версии 1.

Проверки — `shared/sim/validate.ts`. Одни и те же правила работают при приёме архива и при
сохранении вопроса; во втором случае пути изображений — адреса медиатеки `/api/media/<id>`. Сценарий версии 1
проверяется как его перевод в версию 2.

## 7. Версии

`version` растёт при несовместимых изменениях. Импорт отклоняет версию выше поддерживаемой, то есть выше 2.
Неизвестные поля внутри версии игнорируются — так добавляются необязательные поля.

**Чтение версии 1.** Любая точка входа (архив, вопрос, снимок публикации, пакет) читает сценарий как версию 2:
версию 1 переводит при чтении `shared/sim/upgrade.ts`. Перевод механический, без потерь: сцены уходят в
вариант `desktop`, размер сцены и минимальная ширина окна из `settings` — в вариант, проверки единственной
сцены-цели поднимаются в корень `goal`, `scene.goal` становится `scene.end`, вид — `control`. Если в версии 1
несколько сцен-целей с разными проверками, перевод отказывает с объяснением. Хранится и выгружается только
версия 2; снимки публикации неизменяемы и навсегда остаются в версии 1.

## 8. Решения

| Вопрос | Решение, 2026-10-06 |
| --- | --- |
| Модель | Граф сцен; элементы из библиотеки слоями; переход перерисовывает разницу; простое появление |
| Мелкие состояния | Сцены-дубли плюс видимость элементов |
| Ошибочные пути | Роль `trap` с названием ошибки и сцены-провалы |
| Частичный исход | Критичные проверки и веса; частичный зачёт включается в оценке теста |
| Штрафы | Не в формате: цепочка «система → тест → вопрос» |
| Копирование | Нейтральная зона с `copyText` |
| Инструменты записи | Только этот формат; свой рекордер — отдельный трек |
| Режим обучения | Не в первой версии |
| Телефон | Следующий этап; `views` уже в формате (заменено 2026-10-16 вариантом `phone`) |
| Порядок работ | Сначала плеер и контракт; редактор — сильно позже, сценарии собираются руками |

| Вопрос | Решение, 2026-10-16 |
| --- | --- |
| Вид сценария | `kind`: контрольный `control` и исследовательский `research` (без вердикта) |
