# Сценарий в ИС: план встраивания в тесты

Статус: на согласование, 2026-10-06. Дополнено в тот же день: пункт-сценарий берёт сценарий
из темы-банка — случайный с поправкой на экспозицию или фиксированный.

Основа — готовые контракт и плеер: [exchange-format.md](exchange-format.md),
[result-format.md](result-format.md), `shared/sim/`. Здесь — как сценарий становится частью
продукта: вопрос, тест «Сценарий» и пункт роутера.

## 1. Решения владельца

| Вопрос | Решение, 2026-10-06 |
| --- | --- |
| Тип вопроса | «Сценарий»: содержимое — контракт сценария, изображения — в медиатеке |
| Тип теста | Третий режим теста — «Сценарий»: один пункт-сценарий, без тем и разделов |
| Банки сценариев | Сценарии — вопросы типа «Сценарий», разложенные по темам, как обычный банк. Тема и есть банк сценариев |
| Что запускает пункт | Пункт-сценарий ссылается на ТЕМУ. Выдача — на выбор автора: случайный сценарий темы с поправкой на экспозицию (PRD-55) или фиксированный сценарий этой темы |
| Что выдаётся из темы | ТОЛЬКО сценарии. Прочие вопросы темы-банка пункт-сценарий не выдаёт и не учитывает ни в пуле, ни в экспозиции, ни в снимке |
| Сценарий в обычном разделе | Выдаётся. Раздел стандартного теста выдаёт сценарии своей темы наравне с прочими вопросами: тот же отбор, квоты и поправка на экспозицию; участник видит форму вопроса с кнопкой «Пройти» и проходит сценарий на весь экран (user-journey.md). Пакет такого теста несёт сценарии всех банков его разделов |
| SCORM-пакет | Случайная выдача — в пакет запекается весь пул с весами; фиксированная — только выбранный сценарий |
| Старт теста «Сценарий» | Стартовая страница с заданием и правилами; «Начать» сразу разворачивает плеер на весь экран |
| Финал теста «Сценарий» | Окно результата плеера → обычный экран итогов теста (балл, вердикт, текст по исходу, отчёт, сертификат) |
| Сценарии в роутере | Отдельная сущность «сценарии теста» рядом с разделами, не вид раздела |
| Место в хабе | Наравне с темами: один список в порядке автора, у сценария те же свойства пункта — обязательность, правила разблокировки, результат пункта; повторный запуск — по правилу теста «менять ответ» |
| Редактор сценария | Сильно позже; сценарий загружается архивом `.scenario.zip` |

## 2. Модель данных

| Что | Как |
| --- | --- |
| `questions.type` | Новое значение `simulation`. `dataJson` — `scenario.json` контракта, где пути `media/…` заменены идентификаторами медиатеки. Признаки типа — в `shared/questions/question-type.ts` и зеркале `qtype.js` |
| `tests.mode` | Новое значение `scenario` рядом с `standard` и `adaptive` |
| `test_scenarios` | Новая таблица: `id`, `test_id`, `topic_id` (банк сценариев), `question_id` (фиксированный сценарий; `null` — случайный), `title`, `required`, `time_limit_minutes`, `image`, порядок. В тесте «Сценарий» — ровно одна строка; в тесте с роутером — сколько угодно. Пул пункта — вопросы типа `simulation` этой темы; прочие вопросы темы пункт не видит |
| Выбор сценария | Фиксированная выдача — сценарий `question_id`, поправки на экспозицию нет: состав задал автор, как у вариантов PRD-17 (PRD-55 FR-20). Случайная — один сценарий из пула: `computeWeights` + `weightedPick(pool, 1, …)` из `shared/draw/exposure.ts` — тот же код, что выбирает вопросы раздела. Выбор делается на старте попытки и фиксируется в ней, как состав формы раздела; повторный запуск пункта в той же попытке играет тот же сценарий |
| Экспозиция | Выбранный сценарий — выдача по PRD-55 при ЛЮБОМ способе выдачи: счётчик `question_exposure` растёт на старте попытки (веб) и телеметрии (пакет). Веб берёт веса по живым счётчикам, пакет — запечённые при сборке. Новая попытка — новый выбор |
| Ключ пункта роутера | Сейчас правила разблокировки и состояние хаба ключуются `topicId`. Вводится общий ключ пункта: `topic:<id>` и `scenario:<id>`; голый `topicId` читается как `topic:<id>`, поэтому старые тесты не мигрируют |
| Порядок пунктов хаба | `router.itemOrder` — список ключей пунктов. Нет — сначала темы в нынешнем порядке, затем сценарии |
| Снимок публикации | Включает пункты-сценарии и содержимое сценариев, которые они могут выдать: весь пул у случайной выдачи, один сценарий у фиксированной |
| Ответ в попытке | Результат плеера (`SimResult`) — ответ на вопрос-сценарий. Протокол целиком — в ответ и телеметрию, в `cmi.suspend_data` — только итог |
| Оценка | Балл = цена × доля цели (`success` — 1, `partial` — `goal.share`, если тест засчитывает частично, иначе 0) − штрафы по цепочке «система → тест → вопрос», не ниже нуля |

## 3. Этапы

Каждый этап заканчивается проверкой и согласованием; следующий начинается по команде.

### Э0. Эскизы

По нашему порядку работы — до кода интерфейса. Состояния:

1. Ящик вопроса: тип «Сценарий», загрузка архива `.scenario.zip`, проверка при импорте с
   перечнем ошибок, «Сыграть» для проверки.
2. Ящик теста: режим «Сценарий» — выбор темы-банка сценариев вместо структуры и выдача: случайный
   сценарий темы (число сценариев в пуле и ожидаемая экспозиция «каждый сценарий темы увидят около
   N% участников», PRD-55 FR-33) или фиксированный сценарий (выбор сценария темы и «Сыграть»).
3. Ящик теста с роутером: «Добавить сценарий» в структуре, общий список тем и сценариев с
   перетаскиванием порядка, свойства пункта-сценария (название в меню, тема-банк, выдача, обязательность,
   лимит, картинка).
4. Хаб у участника: карточка сценария рядом с карточками тем, состояния «не начат», «завершён»,
   «закрыт правилом». Хаб, как и для тем, говорит, ЧТО пункт закрыт, а не КАК он пройден.
5. Стартовая страница теста «Сценарий»: задание и правила; затем полный экран.

### Э1. Вопрос «Сценарий» и импорт архива

Тип вопроса, загрузка `.scenario.zip` в ящике вопроса (проверки контракта на сервере, изображения
в медиатеку), «Сыграть» — тот же плеер в окне. Вопрос пока нельзя положить в тест.

Сделано 2026-10-07, на приёмке:

- тип `simulation` и признаки `isSimulation`, `isDeliverable` в `shared/questions/question-type.ts`
  и зеркале `qtype.js`; пиктограмма — lucide `monitor-play`;
- проверки контракта — `shared/sim/validate.ts`, одни для архива и для сохранённого вопроса;
  приём и сборка архива — `server/services/sim/scenario-archive.ts`, маршруты
  `POST /api/questions/scenario-archive` и `GET /api/questions/:id/scenario-archive`;
- ящик вопроса: блок «Сценарий» по эскизу, «Сыграть» на весь экран; банк: строка с названием
  сценария, фильтр «Тип: Сценарий», краткий просмотр строки;
- книга Excel сценарии не переносит: экспорт их пропускает, импорт называет архив.

До Э2 сценарий не выдаётся участнику: источники выдачи (`server/services/test-snapshot.ts`) отбрасывают
вопросы, для которых `isDeliverable` ложно. Это одно место переключения — его снимает Э2 для веба
и Э4 для пакета. Без этого раздел обычного теста выдал бы сценарий, который хост ещё не умеет
показать.

### Э2. Тест «Сценарий» в вебе

Режим `scenario`, таблица `test_scenarios`, выбор темы-банка в ящике теста, выдача случайного сценария
с поправкой на экспозицию или фиксированного, учёт выдачи, старт → полный экран →
результат → итоги теста. Сохранение результата в попытку, оценка со штрафами, общий лимит времени
теста на панели плеера, досрочный выход. Снимок публикации.

Сделано 2026-10-07, на приёмке:

- режим `tests.mode = scenario`, таблица `test_scenarios` (миграция `0053`), пункт сохраняется вместе с
  тестом в одной транзакции; в редакторе — третий режим «Сценарий» и вкладка «Задание» по эскизу;
- выдача: источник данных (`server/services/test-snapshot.ts`) отдаёт пункт ОДНИМ разделом темы-банка
  (`scenarioSection`), поэтому старт, завершение, итоги, отчёт и снимок публикации — общие со
  стандартным тестом; пул пункта — сценарии темы или один фиксированный, отбор — тот же взвешенный
  по экспозиции (PRD-55), выдача учитывается;
- прохождение: «Начать» просит полный экран в самом щелчке, плеер на месте экрана вопроса, лимит
  плеера — остаток времени теста, «Перейти к итогам» — завершение попытки и обычный экран итогов;
- оценка: `shared/sim/scoring.ts` — доля цели минус штрафы, штрафы долей цены, пока системные
  умолчания (цепочка настроек — Э5);
- сервер не верит присланному исходу: протокол переигрывается тем же движком по хранимому
  сценарию (`shared/sim/replay.ts`), оценивается и сохраняется переигранный результат;
- участник получает изображения сценария: правило доступа к медиа ведёт вопрос к тесту и через
  пункт-сценарий;
- тест «Сценарий» явно не выгружается в SCORM до Э4.

Пункт-сценарий пока НЕ знают (закрывается защитой раздела 4 на Э3): охрана содержимого при
удалении вопроса или темы, перенос теста между установками, пул выдачи аналитики
(`server/services/delivery-pool.ts`) и книга Excel теста.

### Э3. Сценарии в роутере в вебе

Ключ пункта и порядок пунктов, правила разблокировки и обязательность для сценариев, карточка в
хабе, возврат в хаб, результат пункта, повторный запуск по правилу «менять ответ».

Сделано 2026-10-07, принято в браузере на dev-экземпляре:

- ключ пункта `topic:<id>` / `scenario:<id>` и исчерпывающий разбор по виду (`shared/test-items.ts`);
  общий порядок тем и сценариев — `router.itemOrder`, выдача читает его, пока он задан;
- «Состав» роутера: сценарий — строка общего сортируемого списка с темами (номер, ручка, шеврон,
  пиктограмма `monitor-play`), перетаскивание между темами и в группы, «Добавить сценарий» в панели
  состава и в подвале группы, окно выбора с поиском; членство в группе — `test_scenarios.group_key`
  (миграция `0054`); «Название в меню» обязательно, по умолчанию — название темы;
- хаб: карточка сценария с меткой «Сценарий» и подписями мужского рода, запуск во весь экран в
  самом щелчке, «Вернуться к разделам» после конца сценария, итоги считают пункт вопросом;
- охрана содержимого и проверка публикации: пункт, оставшийся без сценария, — находка
  `scenario_item_empty`;
- реестр мест, читающих разделы теста (`server/test-item-consumers.ts`), и архитектурный тест к нему.

Перенос и книга (2026-10-07):

- пакет `.tbtest` несёт пункты-сценарии: вид строки `scenario` части «Структура», по
  идентификатору, удаление — только при «полной замене» его темы; составные ключи
  `topic:<id>` / `scenario:<id>` в порядке и правилах роутера перенумеровываются вместе с
  идентификаторами (`remapItemKey`) — точная подстановка строк их не узнавала;
- книга Excel сценарии не переносит (вопрос едет архивом, тест целиком — пакетом) и потому их не
  трогает: правила разблокировки пунктов переживают книгу, порядок тем из книги применяется
  вокруг сценариев (`reflowItemOrder`); параметр «Режим теста» знает значение «Сценарий».

Не сделано на Э3: повторный запуск сценария по правилу «менять ответ»; правила разблокировки
пунктов задаются только данными — интерфейса нет ни у тем, ни у сценариев.

### Э4. SCORM-пакет

Бандл плеера в пакете, запекание сценариев с изображениями (весь пул с весами экспозиции у
случайной выдачи, один сценарий у фиксированной), выбор сценария в рантайме тем же алгоритмом,
тест «Сценарий» и роутер в рантайме пакета, взаимодействие `performance`, телеметрия протокола.
Проверка на стенде WebTutor — полный экран там уже подтверждён.

Сделано 2026-10-07, принято в отладочном плеере (настоящий пакет из живого состояния теста):

- сборка (`server/scorm/build-export-data.ts`): раздел пункта уходит темой-банком под ключом
  `scenario:<id>` и именем пункта; пул — сценарии темы с весами экспозиции или один
  фиксированный; изображения упаковываются общим упаковщиком медиа; пункт без сценариев —
  отказ 422, а не пакет без задания;
- рантайм (`server/scorm/template/app/render/simulation.js`): плеер `TBTemplate.mountPlayer` —
  тот же код, что у веба, — слоем на всё окно; полный экран просится в щелчке «Начать» теста
  «Сценарий» и карточки хаба; после окна результата — «Перейти к итогам» или «Вернуться к
  разделам»; перерисовка не перезапускает прогон, уход с экрана снимает слой;
- попытка: в `cmi.suspend_data` — компактная ячейка прогона (исход, доля цели, счётчики,
  секунды), протокол уходит телеметрией целиком; оценка — общий `simulationRatio`;
- LMS: взаимодействие `performance`, ответ шагами `outcome[.]success[,]goal[.]100[,]…`, эталона
  нет, в `result` — доля цены числом: достигнутая цель со штрафом не читается как провал.

Не сделано на Э4: приёмка на стенде WebTutor (нужен вход владельца); импорт выгрузки отчёта LMS
не знает числового `result` и шагов `performance` — это Э5 вместе с прочей аналитикой сценариев.

### Э5. Оценка и аналитика

Блок «Штрафы сценариев по умолчанию» во вкладке «Оценка», окно «Оценка вопроса в тесте» для
сценария, разбор по сценам, таблица ловушек «Типичные ошибки», карта промахов. Экспозиция и медиана
времени сценария в аналитике банка — как у вопросов (PRD-55 FR-31 - FR-32).

Э5 разбит на два шага: Э5а — оценка, Э5б — аналитика.

Э5а сделан 2026-10-08, принят в браузере на dev-экземпляре (эскизы sim-e5-* в
`docs/wireframes/sim-scenario-test-editor.html` согласованы):

- цепочка «система → тест → вопрос в тесте»: штрафы теста — `tests.sim_scoring_json`, штрафы
  вопроса — вид `simulation` в `test_question_scoring.scoring_json`, балл пункта —
  `test_scenarios.default_points` (миграция `0055`); `resolveSimScoring` сливает уровни поштучно;
- контекст оценки теста кладёт в вопрос-сценарий разрешённое значение, по нему считают веб и пакет
  (в пакет печатается всегда — иначе пропал бы уровень теста);
- «Оценка ответа»: блок «Штрафы сценариев по умолчанию», карточки пунктов-сценариев в порядке
  состава; «Оценка вопроса в тесте» для сценария — таблица штрафов и «Как в тесте / Засчитывать /
  Не засчитывать».

Отклонение от эскиза: в окне сценария нет «Предпросмотра балла» — предпросмотр устроен под варианты
ответа; для прогона его надо проектировать отдельно.

Э5б сделан 2026-10-08, принят в браузере на dev-экземпляре (эскизы sim-questions, sim-question и
sim-docs в `docs/wireframes/sim-scenario-analytics.html` согласованы):

- расчёт (`server/services/analytics/simulation-stats.ts`): прогон читается в трёх видах — полный
  результат веба, компактная ячейка, шаги `performance` из выгрузки LMS; исходы и плитки — по всем
  прогонам, сцены, ошибки и карта промахов — только по прогонам с протоколом;
- страница вопроса: шесть плиток, «Исходы», «По сценам» в порядке основного пути с пометками
  «Узкое место», «Бросают», «Подсказка» и «Шаг в сторону», «Типичные ошибки», «Карта промахов»;
- карта промахов — по состояниям экрана: у каждой сцены есть вид при входе, а промахи при открытом
  слое (сообщение об ошибке, справочник) — отдельное состояние с этим слоем на подложке; состояния
  выбираются в рейле. Слои при промахе восстанавливает повтор протокола движком
  (`replayRun(..., { onMiss })`), протокол сам их не пишет;
- «Вопросы теста»: строку сценария называет название сценария, «Что отвечали» — доли исходов.

Не сделано на Э5б: передача протокола в LMS и обратно выгрузкой — требование владельца
2026-10-08 (всё, что аналитика берёт из телеметрии и веба, должно уходить в LMS и забираться
выгрузкой). Без него у прогона из выгрузки есть исход и счётчики, но нет сцен и карты промахов.
Решение: псевдо-взаимодействия `sim_<questionId>_<n>` по образцу `scale_*` и `var_*`.

Подпись слоя в рейле — название изображения из библиотеки сценария; у изображений примера
(`docs/specs/sim-scenario/example`) названий нет, и там видны идентификаторы элементов.

Позже, отдельными треками: редактор сценария, телефонная раскладка, свой рекордер.

## 4. Защита от расхождения сценария и раздела

Сценарий — второй вид пункта теста рядом с разделом. Главная опасность — место, которое знает
только разделы и молча пропускает сценарий: хаб не покажет карточку, правило разблокировки не
сработает, снимок публикации потеряет сценарий, книга Excel сотрёт его при переносе. Защита
строится так, чтобы такое место нельзя было написать незаметно.

1. **Один тип пункта.** В `shared/test-items.ts` — `TestItem = { kind: "topic", … } | { kind:
   "scenario", … }` с общими свойствами пункта (ключ, обязательность, лимит времени, картинка,
   порядок). Пункты теста выдаёт одна функция `listTestItems`; хаб, правила разблокировки, политика
   завершения, результаты пунктов, снимок, выдача, SCORM и аналитика берут пункты только из неё, а
   не из `sections` напрямую.
2. **Исчерпывающий разбор.** Ветвление по виду пункта идёт через `matchTestItem(item, { topic,
   scenario })`: обработчик для каждого вида обязателен, а проверка `never` в конце не даст
   скомпилировать код, если появится третий вид. Цепочки `if (item.kind === "topic")` без ветки
   для сценария запрещены — это тот же класс ошибок, что разобран в PRD-26 для типов вопросов.
3. **Реестр мест.** `ITEM_CONSUMERS` — список модулей, которые работают с пунктами теста; у каждого
   записано решение по сценарию: «обрабатывает» или «неприменимо — потому что …». Архитектурный
   тест проходит по коду и падает, если модуль читает разделы теста (`testSections`, `sections`,
   `topicId` в потоке и роутере), но в реестре его нет. Новое место без явного решения в ветку не
   попадёт. Образец — тест признаков типов вопроса, требующий решения по каждому признаку.
4. **Круговые тесты.** Тест с темами и сценариями проходит без потерь по кругу: сохранение →
   снимок публикации → книга Excel → импорт → SCORM-сборка. Пункты, их порядок и свойства на
   выходе совпадают со входом.
5. **Паритет хостов.** Один набор прохождений проигрывается и в вебе, и в рантайме пакета;
   результаты (`SimResult`) и состояние хаба должны совпасть побайтно.
6. **Одинаковые правила для обоих видов.** Обязательность, разблокировка, завершение хаба и
   результат пункта считаются одним кодом для темы и для сценария; вид пункта влияет только на то,
   что запускается по карточке.

## 5. Риски

- **Второй вид пункта роутера.** Хаб, правила разблокировки, результаты разделов, снимки,
  аналитика и импорт книги Excel сегодня знают только разделы. Каждое место нужно найти и научить;
  опасность — тихо пропущенное место, где сценарий просто не учтётся. Защита — общий тип «пункт
  роутера» и тест, перечисляющий все места, где он нужен.
- **Один движок на два хоста.** Веб и SCORM обязаны вести себя одинаково — паритет хостов
  проверяется одним набором сценариев на обоих.
- **Медиа.** Сценарий — десятки изображений; стенд режет загрузку больше 1 МБ на файл. Пакет со
  случайной выдачей несёт ВЕСЬ пул пункта, поэтому его вес растёт с размером банка; фиксированная
  выдача несёт один сценарий. Импорт архива проверяет размеры
  заранее; ящик теста показывает суммарный вес пулов.
- **Маленький банк.** Пул из одного-двух сценариев выдаётся почти каждому участнику — сценарий
  быстро становится известен. Защита та же, что у вопросов: ожидаемая экспозиция видна автору при
  настройке пункта (PRD-55 FR-33).
- **Книга Excel.** Тест «Сценарий» и сценарии роутера должны переноситься книгой без потерь —
  иначе это класс ошибок «книга тихо стирает новое поле».

## 6. Технический долг трека

Заведён 2026-10-07 по решению владельца: расхождения с планом разбираются позже, работа идёт
дальше. При вливании ветки пункты переносятся в общий реестр (`docs/ROADMAP.md`, §0.0.4 и §0.3).

1. **Книга Excel не переносит сценарии.** План (раздел 5) требует переноса теста «Сценарий» и
   сценариев роутера книгой без потерь. Сделано иначе и без согласования: книга сценарии не
   переносит, а только не стирает их; переносят пакет теста `.tbtest` и архив
   `.scenario.zip`. Перенос книгой — новый лист и смена формата книги.
2. **Нет функции `listTestItems`.** Раздел 4, пункт 1 предписывает одну функцию выдачи пунктов.
   Сделано через источник выдачи (`deliverySections` в `server/services/test-snapshot.ts`): места,
   читающие разделы через него, получают сценарии сами, остальные учтены реестром.
3. **Нет кругового теста всей цепочки.** Раздел 4, пункт 4: «сохранение → снимок → книга →
   импорт → SCORM-сборка» одним тестом. Есть тесты звеньев по отдельности.
4. **Паритет хостов неполный.** Раздел 4, пункт 5: один набор прохождений на вебе и в пакете с
   побайтным совпадением. Совпадение доказано только для балла прогона и для хаба.
5. **Сценарий в обычном разделе не выдаётся.** *Закрыто 2026-10-08.* Обычный раздел
   стандартного теста выдаёт сценарии своей темы наравне с прочими вопросами; адаптивный обход —
   нет (`isDeliverable(type, "adaptive")`: его экран прогона на весь экран не знает). Экран —
   макет вопроса шаблона с обложкой в области ответа и окном правил (эскиз
   `sim-scenario-learner.html`, состояния section-*, согласован; обложка завершённого — IconBadge и
   заголовок по выбору владельца). Обложку и правила рисует общий `shared/sim/cover` для веба и
   пакета, вёрстку даёт ядро встроенными стилями — шаблонам ничего добавлять не нужно. Прогон —
   ответ на вопрос и фиксируется обычным «Далее»; телеметрия фиксации шлёт полный прогон с
   протоколом. Цена сценария уходит в веб всегда — штрафы нужны тексту правил. Принято в
   браузере на вебе и в отладочном плеере пакета.
6. **Суммарный вес пулов не показан.** Раздел 5 требует показывать в ящике теста суммарный вес
   пулов; сейчас у пункта видны только теги с весом изображений.
7. **Повторный запуск по правилу «менять ответ»** (Э3) не сделан.
8. **Правила разблокировки пунктов без интерфейса** — задаются только данными, как и у тем.
9. **Приёмка пакета в WebTutor** (Э4) не проведена — нужен вход владельца.
