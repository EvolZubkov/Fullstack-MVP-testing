# Сценарий в ИС: контракт результата

Статус: версия 2, 2026-10-16 (версия 1 — 2026-10-06).

Что возвращает плеер, когда прохождение закончилось. Схема — [result.schema.json](result.schema.json),
типы — `SimResult` в `shared/sim/contract.ts`, источник — `run.result()` движка
`shared/sim/engine.ts`. Плеер разработки (`npm run sim:play`) сохраняет каждый результат в
`out/sim-results/`.

Результат — сырьё. Балл из него считает оценка теста (цена, штрафы, частичный зачёт), SCORM-пакет
делает из него взаимодействие `performance`, аналитика — разбор по сценам, ловушкам и промахам.
Самого балла в результате нет: один и тот же результат даст разный балл в тестах с разными
штрафами.

## 1. Документ

| Поле | Описание |
| --- | --- |
| `format`, `version` | `skillum.sim-result`, `2`; результат версии 1 тоже допустим (раздел 6) |
| `scenario.title` | Название сценария |
| `variant` | Сыгранный вариант, `desktop` или `phone`. Нет — результат версии 1, десктоп |
| `startedAt` | Начало, ISO 8601 |
| `durationMs` | Длительность до завершения, мс |
| `outcome` | Исход (раздел 2) |
| `goal` | Достигнутый конец `success` или `fail`, либо `null`: `scene`, `message`, `checks`, `share` |
| `finale` | Достигнутый финал исследовательского сценария или `null`: `scene`, `title`, `target` |
| `counts` | Счётчики (раздел 3) |
| `cost` | Сумма стоимостей принятых действий, число не меньше нуля. Нет — результат версии 1 |
| `traps` | Ловушки по порядку: `{ id, error, t }` |
| `fields` | Итоговые значения полей |
| `events` | Протокол (раздел 4) |

## 2. Исход

| `outcome` | Когда |
| --- | --- |
| `success` | Цель `success`, прошли все проверки |
| `partial` | Цель `success`, прошли все критичные, но не все проверки; `goal.share` — доля по весам |
| `fail` | Сцена-провал, или не прошла критичная проверка |
| `finale` | Исследовательский сценарий: достигнут финал; его описание — в поле `finale` |
| `declared` | Исследовательский сценарий: участник сам закончил кнопкой «Я закончил» |
| `exited` | Участник вышел досрочно |
| `timeout` | Истёк `limitSeconds` сценария |

`goal.checks[]` — `{ field, passed, critical, weight }` по каждой проверке цели.

Исходы `success`, `partial` и `fail` бывают у контрольного сценария, `finale` и `declared` — у
исследовательского; `exited` и `timeout` — у обоих.

## 3. Счётчики

| Поле | Что считается |
| --- | --- |
| `actions` | Засчитанные действия всех ролей, кроме нейтральной: путь, другой путь, в сторону, ловушка |
| `misses` | Клики мимо всех зон |
| `blocked` | Действия, которые система не дала выполнить (`when` не выполнено) |
| `wrongValues` | Неверные значения полей при `checkWhen: input` |
| `detours` | Действия в сторону |
| `traps` | Ловушки |
| `hints` | Показанные подсказки |

Стоимость прогона `cost` — сумма стоимостей принятых действий (ось эффективности); промахи, отказы, ловушки и
подсказки в неё не входят.

Ошибки для штрафа «за ошибку» — `misses + blocked`; «за неверное значение» — `wrongValues`; «за
действие в сторону» — `detours`; «за ловушку» — `traps`; «за подсказку» — `hints`; «за время» —
`durationMs` сверх `normSeconds`.

## 4. Протокол

Каждое событие несёт `t` — миллисекунды от начала.

| `type` | Поля | Когда |
| --- | --- | --- |
| `enter` | `scene` | Вход на сцену, включая стартовую |
| `action` | `scene`, `id`, `role`, `error` | Засчитанное действие; `error` — у ловушки; `role` нет у действия исследовательского сценария без роли |
| `blocked` | `scene`, `id` | Система отказала |
| `miss` | `scene`, `x`, `y` | Клик мимо, в пикселях сцены — для карты промахов |
| `value` | `scene`, `field`, `value`, `correct` | Зафиксировано значение поля; `correct: null` — не проверялось при вводе |
| `hint` | `scene`, `target` | Показана подсказка: поле или зона, на которую она указывает |
| `copy` | `scene`, `id` | Скопирован текст копируемой зоны |
| `goal` | `scene`, `outcome`, `finale` | Достигнут конец; `finale` — название финала, только у исхода `finale` |
| `declare` | — | Участник нажал «Я закончил» |
| `exit` | — | Досрочный выход |
| `timeout` | — | Истекло время |

Протокол восстанавливает прохождение целиком: какой путь выбран, где участник ошибался, куда
уходил и на чём застрял. В `cmi.suspend_data` SCORM-пакета он не пишется — только в телеметрию.

## 5. Кодек протокола

В LMS протокол уходит компактной строкой (`shared/sim/protocol-codec.ts`): версия, затем события через `;`.
Событие `declare` кодируется буквой `d`. Строка без `d` по-прежнему пишется как версия 1, поэтому пакеты контрольных
сценариев байт в байт совпадают с собранными до версии 2; с `d` — версия 2. Декодер читает обе версии, но `d` в
строке версии 1 отвергает как повреждённую. Финал при импорте восстанавливается переигрыванием протокола.

## 6. Версии

Результат версии 1 — без `variant`, `finale`, `cost`, исходов `finale` и `declared`, события `declare`; у события
`action` роль обязательна. Он остаётся допустимым: его читают аналитика и переигрывание, как результат десктопного
варианта. Версия 2 — то, что пишет движок сейчас; схема принимает обе.

## 7. Пример

Сокращённый результат эталонного квеста:

```json
{
  "format": "skillum.sim-result",
  "version": 2,
  "scenario": { "title": "Регистрация входящего письма" },
  "variant": "desktop",
  "startedAt": "2026-10-06T18:50:03.412Z",
  "durationMs": 4120,
  "outcome": "success",
  "goal": { "scene": "done", "checks": [{ "field": "corr", "passed": true, "critical": true, "weight": 2 }], "share": 1 },
  "counts": { "actions": 9, "misses": 1, "blocked": 0, "wrongValues": 0, "detours": 0, "traps": 0, "hints": 0 },
  "cost": 9,
  "traps": [],
  "fields": { "corr": "ООО «Ромашка»", "num": "ВХ-1183" },
  "events": [
    { "t": 0, "type": "enter", "scene": "home" },
    { "t": 640, "type": "miss", "scene": "home", "x": 1700, "y": 1100 },
    { "t": 910, "type": "action", "scene": "home", "id": "home-inbox", "role": "path" }
  ]
}
```
