## 1. Обзор

### 1.1 Контекст

Лимиты времени считают АКТИВНОЕ время: лимит раздела — на обоих хостах (согласовано 2026-07-29), лимит
всего теста — в SCORM-пакете (PRD-20 §5.13). Уход замораживает остаток, возврат продолжает с него.
Выданные вопросы при возобновлении те же. Отсюда сценарий, от которого продукт сегодня не защищён:

1. ученик открывает вопрос;
2. закрывает браузер — таймер стоит;
3. ищет ответ;
4. возвращается к тому же вопросу с тем же остатком и отвечает.

Цикл повторяется без ограничений: одна итерация стоит около 30 секунд в вебе и около интервала коммита
(10 секунд) в SCORM. Для оцениваемого теста высоких ставок (сертификация руководителей) это фрод.

Деление на разделы здесь ни при чём: уязвим любой лимит, который стоит, пока ученика нет. Лимит всего
теста в вебе сегодня идёт по часам от `startedAt` — там уход стоит времени и равносилен поиску в соседней
вкладке, но хосты обязаны вести себя одинаково, поэтому правило действует и там.

Почему закрытие, а не «часы идут, пока ученика нет»: пакету для этого нужно время с машины ученика, а
системные часы переводятся. Закрытию часы не нужны — оно срабатывает на новом запуске (§3.3).

### 1.2 Цель

Дать автору настройку теста «Закрывать раздел при выходе»: раздел, из которого ученик ушёл, закрывается,
и вернуться в него, чтобы дорешать, нельзя. В тесте без разделов весь тест — один раздел, и выход
завершает попытку. Поведение одинаково на веб-хосте и в SCORM-пакете.

### 1.3 Метрики успеха

| Цель | Метрика |
| --- | --- |
| Сценарий 1.1 закрыт | При включённой настройке любой способ уйти и вернуться (перезагрузка, закрытие браузера, вторая вкладка, выход в маршрутизатор) приводит к закрытому разделу или завершённой попытке — на обоих хостах |
| Честный ученик не страдает от сбоя сети | Обрыв связи до 2 минут на той же странице ничего не закрывает (веб) |
| Ученик предупреждён | Правило автор пишет на вводной странице теста — один раз до начала; ядро объясняет только возврат в закрытый раздел |
| Обратная совместимость | Существующие тесты и уже выгруженные пакеты не меняют поведения (дефолт — выключено) |

## 2. Пользователи

- **Автор теста** включает настройку во вкладке «Правила прохождения» → «Ограничения» → «Ограничения
  попытки».
- **Учащийся** узнаёт о правиле со вводной страницы теста и получает сообщение при возврате в закрытый
  раздел или в завершённую попытку.

## 3. Ключевые понятия

### 3.1 Раздел под действием настройки

Настройка действует на раздел, у которого есть ЛИМИТ ВРЕМЕНИ — свой (`test_sections.time_limit_minutes > 0`)
или общий лимит теста (`tests.time_limit_minutes > 0`). Раздел без своего лимита в тесте без общего
лимита не затрагивается: таймера, который можно обойти, у него нет.

Тест без разделов (`linear_flat`) — один раздел, совпадающий с попыткой: закрыть его значит завершить
попытку.

Раздел считается НАЧАТЫМ с первого показанного вопроса — с того же момента, что и отсчёт раздела
(заставка и страницы до вопросов время не списывают, `contentFlow.js` `maybeUpdateSectionTimer`). Уход со
страниц до первого вопроса раздел не закрывает. Тест без разделов начат с первого вопроса.

### 3.2 Что считается выходом

| Событие | Выход? |
| --- | --- |
| Переход к обзору СВОЕГО раздела (узел `review`, PRD-19) и возврат из него к вопросам | Нет — обзор внутри раздела, таймер идёт |
| Переход дальше обзора: итоги раздела (`section-results`), следующий раздел, итоги теста | Да (для последнего раздела и теста без разделов это штатное завершение) |
| Выход в маршрутизатор (`router_by_topics`), в т.ч. «Назад» с первой страницы раздела | Да |
| Новый запуск: перезагрузка страницы, закрытие и повторное открытие, вторая вкладка или устройство | Да |
| Веб: та же страница, связи не было до 2 минут | Нет — время списывается полностью |
| Веб: та же страница, связи не было больше 2 минут (сон ноутбука, долгий обрыв) | Да |
| Переключение на другую вкладку или приложение без перезагрузки | Нет — страница открыта, таймер идёт |

### 3.3 Признак нового запуска

Выход ловится по смене СЕССИИ прогона, а не по таймауту (решение 2026-09-24):

- **SCORM.** Каждый запуск SCO — новая сессия. Раздел, найденный при загрузке «открытым» (§3.5), значит,
  что прошлая сессия оборвалась внутри него. Раздел закрывается на загрузке. Таймаутов пакету не нужно:
  зонд 2026-09-24 на машине владельца показал, что `performance.now()` идёт во время сна ноутбука (703 с и
  490 с сна — такой же прирост), поэтому сон и так списывается через `cmi.session_time`.
- **Веб.** Страница прохождения при монтировании создаёт идентификатор прогона (`runId`, случайный UUID)
  и шлёт его в каждом пинге. Сервер хранит текущий `runId` попытки. Пинг с другим `runId` при открытом
  разделе — новый запуск: раздел закрывается. Сессия входа (cookie) для этого не годится: она живёт
  24 часа и переживает закрытие браузера. Прощальный пинг при уходе со страницы не надёжен и остаётся
  лишь ускорителем.

### 3.4 Перерыв на той же странице (только веб)

Признак сессии не ловит случай «страница та же, но ученика не было»: крышка ноутбука закрыта, страница
проснулась с тем же `runId`. Сегодня за такой перерыв сервер списывает не больше `GRACE_MS = 30 с`, то
есть сон дарит время. При включённой настройке:

| Перерыв между пингами одного `runId` | Действие |
| --- | --- |
| До 2 минут (`CLOSE_GAP_MS = 120 000`) | Перерыв списывается ПОЛНОСТЬЮ, раздел продолжается |
| Больше 2 минут | Раздел закрывается |

Без настройки поведение прежнее (кредит не больше 30 с, заморозка).

### 3.5 Открытый и закрытый раздел

Состояние хранится рядом с бюджетами разделов (SCORM — `suspend_data`, веб — `attempts.section_timer_json`):

- `openSection: string | null` — раздел, в котором ученик сейчас (начатый и не покинутый). Для раздела со
  своим лимитом это дублирует идущий бюджет, для раздела под общим лимитом — единственный признак. Тест
  без разделов записывает сюда служебный ключ всего теста.
- `closedSections: string[]` — закрытые разделы.

Закрытие раздела: он попадает в `closedSections`, его бюджет (если есть) обнуляется
(`remainingMs = 0`, `runningSince = null`). Дальше работает существующий механизм исчерпанного лимита:
раздел в `lockedTopics` (веб) или истекает (SCORM), ученика переводит к следующему разделу, в
маршрутизаторе тема получает статус «Пройдена». Ответы, данные до выхода, сохраняются и оцениваются;
остальные вопросы раздела — без ответа.

Закрытие теста без разделов: попытка сдаётся с данными ответами — тем же путём, что и истечение лимита
теста (`submit(true)` в пакете, `finish` в вебе). В вебе сдачу запускает клиент, получив от сервера
закрытый `__test__`; ответы к этому моменту сервер уже заморозил (FR-10), поэтому содержимое запроса
на исход не влияет. Попытка, к которой ученик не вернулся, остаётся незавершённой, как любая брошенная.

## 4. Функциональные требования

| ID | Требование |
| --- | --- |
| FR-01 | Настройка `closeSectionOnLeave` уровня теста, по умолчанию выключена |
| FR-02 | Настройка действует на разделы со своим лимитом и на все разделы теста с общим лимитом (§3.1) |
| FR-03 | Выход по таблице §3.2 закрывает начатый раздел на обоих хостах |
| FR-04 | Тест без разделов при выходе завершается: попытка сдаётся с данными ответами (§3.5) |
| FR-05 | SCORM: раздел, открытый на момент загрузки SCO, закрывается (§3.3) |
| FR-06 | Веб: пинг с новым `runId` при открытом разделе закрывает его (§3.3) |
| FR-07 | Веб: перерыв одного `runId` до 2 минут списывается полностью, больше 2 минут — закрывает раздел (§3.4) |
| FR-08 | Обзор своего раздела (PRD-19 `review`) — внутри раздела: таймер идёт, возврат к вопросам доступен |
| FR-09 | Маршрутизатор: выход из начатого раздела помечает тему «Пройдена», а не возвращает её в «Не начата» |
| FR-10 | Веб, сервер: ответы на вопросы закрытого или исчерпанного раздела замораживаются — `save-progress` и `finish` берут их из сохранённого состояния попытки, а не из тела запроса |
| FR-11 | Вход в раздел под действием настройки проходит без сообщений: правило автор пишет на вводной странице теста (§7.2). Снято 2026-09-29 — сообщение при входе в каждый раздел отнимало внимание на первом вопросе |
| FR-12 | Сообщение при возврате в закрытый раздел или в завершённую попытку (§7) |
| FR-13 | Выключенная настройка не меняет поведения ни одного хоста (регрессия PRD-4 / PRD-20) |
| FR-14 | Поле проходит все каналы теста: редактор, API, снимок публикации, SCORM `TEST_DATA`, книга Excel |

FR-10 закрывает и существующую дыру, найденную при разборе: сегодня сервер вычисляет `lockedTopics`, но
только возвращает его клиенту — `save-progress` принимает ответы целиком без проверки. Заморозка
действует при любом значении настройки, в том числе для раздела, исчерпанного по времени.

## 6. Поведение хостов

### 6.1 Общая модель (`shared/flow/section-budget.ts`)

Модуль получает чистые функции открытия и закрытия раздела над состоянием §3.5: `openSection`,
`closeOpenSection` (закрывает открытый раздел и обнуляет его бюджет, если он есть), `isClosed`. Выбор
между заморозкой (`pauseAll`) и закрытием при выходе делает хост по настройке теста. Модуль остаётся
единственным местом этой арифметики; шапка модуля дополняется правилом PRD-67.

### 6.2 SCORM-пакет

- `timer.js`: при загрузке и включённой настройке — закрытие раздела, открытого на момент обрыва (FR-05);
  для теста без разделов — сдача попытки с сообщением (путь «Время теста истекло»); `stopSectionTimer`
  при выходе закрывает, а не замораживает;
- `contentFlow.js` (`maybeUpdateSectionTimer`): раздел открывается на первом вопросе и под общим лимитом;
  страница `review` своего раздела держит его открытым, страница `section-results` закрывает; вход в
  закрытый раздел пропускается так же, как истёкший;
- `routerFlow.js` (`returnToHub`): начатый раздел при настройке помечается `completed` (FR-09);
- сообщения §7 — через существующий `showToast` рантайма; ему добавляется необязательная длительность
  показа (сегодня 3 с — мало для двух предложений).

### 6.3 Веб-хост

- `use-section-timer.ts`: `runId` на время жизни страницы (`useState(() => crypto.randomUUID())`, а не
  вычисление в рендере — StrictMode двойной рендер не должен породить два идентификатора); `runId` в
  теле пинга; пинг идёт и в разделе под общим лимитом, и в тесте без разделов; на обзоре своего раздела
  пинг несёт `topicId` раздела;
- `section-timer.ts`: смена `runId` и перерыв больше `CLOSE_GAP_MS` → закрытие открытого раздела; выход в
  другой раздел или наружу → закрытие вместо заморозки; перерыв до `CLOSE_GAP_MS` кредитуется полностью;
  закрытый раздел отвечает нулём секунд и попадает в `closedTopics`, поэтому клиент уводит из него
  прежним путём истечения, а закрытый `__test__` сдаёт попытку (§3.5);
- страница прохождения: под настройкой итоги раздела и хаб маршрутизатора — выход (хук молчит там);
  хаб показывает закрытые темы пройденными;
- `routes/attempts.ts`: заморозка ответов закрытых разделов в `save-progress` и `finish` (FR-10);
- адаптивный режим веба идёт через тот же серверный арбитр (`useAdaptiveSectionTimer` → существующий
  `expire-topic-adaptive`), отдельной логики не требует.

## 7. UI

### 7.1 Автор

Переключатель «Закрывать раздел при выходе» (`Switch` в `ou-switch-field`, label + desc) — последним
полем раздела «Ограничения попытки». Виден, когда задан хоть один лимит: лимит времени теста больше 0
или включены «Индивидуальные лимиты для тем». Тексты описания:

- включён: «Если ученик покинул раздел — перешёл дальше, вернулся к списку разделов или закрыл браузер, —
  вернуться и дорешать нельзя. В тесте без разделов выход завершает попытку.»;
- выключен: «Выключено — при выходе время замирает, а по возвращении ученик продолжает с того же места.»

Скрытие переключателя значение не сбрасывает.

### 7.2 Учащийся

Экраны ученика рисуют шаблоны, но макеты НЕ меняются: сообщения выводит ядро хоста (веб — DS `Toast`,
SCORM — `showToast`), как уже сделано для «Время теста истекло».

Вход в раздел сообщений НЕ вызывает (решение 2026-09-29). Первая редакция показывала предупреждение на
первом вопросе каждого раздела; в SCORM это было модальное окно по центру экрана на 8 секунд — поверх
вопроса, под идущим лимитом, и одно и то же правило повторялось в каждом разделе. Правило одно на тест,
поэтому говорится один раз до начала: автор пишет его на вводной странице теста, шаблон может напечатать
его сам по `course.closesOnLeave` (§7.3).

| Когда | Вид | Заголовок | Текст |
| --- | --- | --- | --- |
| Возврат в закрытый раздел | info | Раздел «{название}» закрыт | Вы вышли из него до завершения. Ответы, данные до выхода, сохранены. |
| Возврат в тест без разделов | info | Попытка завершена | Вы вышли из теста до завершения. Засчитаны ответы, данные до выхода. |

В SCORM заголовок и текст идут одной строкой через точку.

### 7.3 Контекст шаблона

Для будущих макетов в контекст стартового экрана добавлено `course.closesOnLeave: boolean` — истина,
когда настройка включена и у теста есть хоть один лимит (общее правило `testClosesOnLeave`, его
вызывают оба хоста). Поле ставится только при истине: у теста без настройки контекст прежний.
Минорный подъём контракта до 3.13.0 — спека платформы (§10.9), руководство разработчика шаблонов
(§7.1, номер версии в трёх местах), PDF. Поставляемые макеты не меняются, версии их манифестов не
двигаются.

Первая редакция спеки называла `section.current.closesOnLeave`. При реализации выяснилось, что
`section.current` — внутренняя привязка SCORM-рантайма, а не часть общего контракта: у веб-хоста её
нет, и поле там нарушило бы паритет хостов. Поэтому признак переехал в `course.*`, который оба хоста
собирают одним построителем.

## 8. Совместимость

- Дефолт `false`: существующие тесты не меняют поведения.
- Пакеты, выгруженные до выкатки, поля не содержат и работают как раньше; настройка действует после
  переэкспорта (политика выката PRD-20 §5.15: оцениваемый тест в идущем цикле не переэкспортируется).
- Строки попыток без новых полей в `sectionTimerJson` читаются без закрытия (§5.3).
- FR-10 меняет поведение и без настройки: ответ в исчерпанный по времени раздел, присланный в обход
  клиента, больше не принимается. Это исправление, а не регрессия.

## 9. Вне охвата

- Закрытие только УВИДЕННЫХ вопросов вместо всего раздела (при возврате блокируются показанные вопросы,
  ученик продолжает с первого неувиденного; случайная перезагрузка стоит одного вопроса, а не раздела
  или попытки). Решение владельца 2026-09-24: в будущем к реализации, заведено в ROADMAP §0.0.2.
  Требует хранить множество показанных вопросов на обоих хостах и стыковать его с возвратом к вопросам
  PRD-19. Состояние §3.5 проектируется так, чтобы его можно было расширить без смены формата.
- Адаптивный режим в SCORM: его состояние не сохраняется в `suspend_data`, и после перезапуска адаптивная
  сессия проходится заново (PRD-20 §5.12). Это отдельная уязвимость того же класса, заводится отдельно.
- Расхождение хостов в лимите ВСЕГО теста без настройки: веб считает по часам от `startedAt`, SCORM — по
  активному времени. PRD-67 закрывает дыру при включённой настройке, но сама разница остаётся.
- Устаревшая шапка `sessionRecovery.js` («With timer → cannot restore», «Section timers are not
  persisted») — исправлена попутно, поведения не меняет.
- Веб без настройки: хук таймера раздела остаётся включённым на хабе маршрутизатора и на итогах
  раздела, поэтому время раздела там идёт — вопреки правилу «вне раздела время не тратится» модуля
  `section-budget`. Под настройкой исправлено (там это выход), без неё поведение сохранено (FR-13) —
  кандидат в отдельную правку.
- Веб, адаптивный режим: незавершённая адаптивная попытка не возобновляется — повторный вход создаёт
  новую, а незавершённые попытки не считаются в лимит. Это позволяет смотреть вопросы новыми
  попытками без ограничения; уязвимость того же класса, заводится отдельно.

## 9a. Найдено и исправлено по ходу

- SCORM: `sectionBudgets` не сбрасывался между попытками одной регистрации — раздел, исчерпанный в
  первой попытке, был исчерпан и во второй с первой секунды. Теперь бюджеты и закрытые разделы
  сбрасываются на старте каждой новой попытки.
- SCORM: `showToast`, вызванный повторно, не скрывался сам — таймер скрытия ссылался на элемент
  другого вызова. Исправлено вместе с добавлением длительности показа.

## 10. Критерии приёмки

Приёмка 2026-09-24 шла на прод-сборке ветки поверх общей dev-БД (браузер — headless Chromium через
CDP), пакет — в локальном плеере `scorm:player`. Отметка «в браузере» — проверено живым прогоном,
«тестами» — только автоматическими тестами.

- [x] Редактор: переключатель сверен с эскизом (состояние `s-on`) в браузере — место, подписи дословно,
      обёртка `ou-formfield`. Скрытие без лимитов и круговой путь книги Excel — тестами.
- [x] Веб, перезагрузка внутри раздела — в браузере: раздел закрыт, сообщение «Раздел «…» закрыт» (тон
      `info`, замок), ученик переведён в следующий раздел с полным лимитом (предупреждение о нём тоном
      `warning` снято 2026-09-29, FR-11). Вторая вкладка — тестами (тот же признак `runId`). Обзор своего раздела — тестами.
- [x] Веб: раздел без своего лимита в тесте с общим лимитом закрывается так же — тестами.
- [x] Веб: тест без разделов — перезагрузка сдаёт попытку — тестами (сервер и хук).
- [x] Веб: перерыв 90 с — остаток уменьшился на 90 с; перерыв больше 2 мин — закрыт — тестами сервера.
- [x] Веб: `save-progress` с изменённым ответом закрытого раздела не меняет сохранённый — на живом API.
- [x] Маршрутизатор: выход в хаб из начатого раздела — тема «Пройдена», повторно не открывается — тестами

- [x] SCORM в локальном плеере: перезапуск SCO посреди раздела — раздел закрыт, ученик на заставке
      следующего раздела, центральный тост объясняет причину.
- [ ] SCORM на стенде WebTutor: перезагрузка SCO и убийство вкладки посреди раздела; тест без разделов.
- [x] Выключенная настройка: существующие тесты таймера, состояния пакета и стартового экрана зелёные;

## 12. Решённые вопросы

| Вопрос | Решение (2026-09-24) |
| --- | --- |
| Где настройка | Уровень теста, «Ограничения» → «Ограничения попытки» |
| На какие лимиты действует | На любой: свой лимит раздела и общий лимит теста — разделение на разделы не меняет уязвимости |
| Что закрывается под общим лимитом | Текущий раздел; в тесте без разделов — вся попытка |
| Как быть с обрывом связи в вебе | Перерыв до 2 минут на той же странице ничего не закрывает |
| Чем опознавать выход | Сменой сессии прогона (SCORM — новый запуск SCO, веб — новый `runId`); таймаут — только для перерыва той же страницы |
| Нужен ли таймаут в пакете | Нет: `performance.now()` идёт во сне (зонд на машине владельца), сон списывается сам |
| Предупреждать ли ученика | Пересмотрено 2026-09-29: при входе в раздел — нет; правило пишет автор на вводной странице, ядро объясняет только возврат в закрытый раздел |
| Обзор своего раздела | Внутри раздела: таймер идёт, возврат к вопросам доступен |
