## 1. Принципы плана

- Источник истины по правам — `role-model.md`; изменения прав начинаются с правки этого файла.
- Каждая фаза самодостаточна: завершается зелёным `npm test` + `npm run check` и не меняет
  поведение для пользователей, пока соответствующая функциональность не включена целиком.
- Сначала чистые shared-модули (резолвер цены, логика выполнимости) с unit-тестами, затем данные,
  затем сервер, затем клиент.
- UI-задачи проходят этап эскизов и согласования до React-кода (правило wireframes-first);
  компоненты — только из `@universityrt/ui-kit`.
- Миграции аддитивны; единственное удаление (колонки оценки из `questions`) — отдельным релизом
  после подтверждения паритета golden-тестами.
- Серверная проверка — источник истины; клиент только скрывает недоступное.

## 5. Риски плана

| Риск | Реакция |
| --- | --- |
| Снапшоты затрагивают весь рантайм попыток (самая дорогая фаза) | Переходный режим: тесты без снапшота играют по-старому; перевод по одному действию публикации |
| Дрейф пулов считается дорого на больших банках | Вычисление по запросу (открытие редактора/списка), кэш по `contentHash` |
| Параллельность блока D с активным треком PRD-14 | T-38 согласуется с владельцем трека PRD-14 до начала; общие файлы — `workbook-*` |
| Производное чтение (мягкий отзыв) расширяет поверхность доступа | Реализация строго в контексте теста получателя; отдельные тесты на отсутствие доступа к банку |
| Удаление колонок ломает старые ветки/скрипты | Отдельный релиз, объявление в команде, поиск использований перед T-40 |
