## 1. Обзор

### 1.1 Контекст

PRD-6 «Ограничение повторного прохождения» поставил рантайм retake gate: тест выбирает
eligibility-плагин и его конфигурацию, плагин вычисляет допуск, при активном cooldown
показывается блок-экран. В Phase 1 реестр плагинов и их конфигураций read-only и сидируется
в коде: одна активная конфигурация на плагин, изменение endpoint'ов/фильтров/парсинга даты
требует правки исходников.

BR-07 при этом требует, чтобы хрупкая LMS-specific логика (endpoint'ы WebTutor, фильтр
«полноценной попытки», парсинг даты) администрировалась без изменения Core, чтобы под разные
типы курсов существовало несколько конфигураций одного плагина, и чтобы администратор мог
выполнить тестовую проверку плагина на конкретном курсе/пользователе. Эта администрируемая
часть выделена из PRD-6 в отдельный трек, потому что рантайм-ценность cooldown уже поставлена
без неё, это самостоятельная административная фича со своим объёмом, а её приёмка (тестовая
проверка) зависит от доступа к живой LMS (WebTutor). Доступ появился 2026-08-06, и на нём
подтверждены и рантайм cooldown, и контракт плагина `webtutor_cooldown` — то есть исходное
основание отложить трек исчерпано.

### 1.2 Цель

Дать администратору/внедренцу управлять eligibility-плагинами и их конфигурациями через UI,
без релиза Core:

1. редактировать конфигурацию LMS-плагина (endpoint'ы, параметры запроса, фильтр
   статусов/прогресса/даты, парсинг даты, версия адаптера, политика ошибки);
2. хранить несколько конфигураций одного плагина под разные типы курсов и выбирать нужную
   в настройках теста;
3. выполнять тестовую проверку плагина на выбранном курсе/пользователе с полной трассой решения.

### 1.3 Метрики успеха

| Цель | Метрика |
| --- | --- |
| Провайдер администрируем | Администратор меняет endpoint/параметры/фильтр без релиза Core |
| Несколько конфигураций | Один плагин имеет >= 2 конфигураций; тест выбирает одну |
| Диагностируемость | Тестовая проверка показывает сырые/отфильтрованные записи, выбранную попытку и решение |

## 2. Пользователи

- **Администратор / внедренец** — настраивает набор плагинов и их конфигурации, выполняет
  тестовую проверку.
- **Автор теста** — выбирает плагин и одну из готовых конфигураций в настройках теста (базовый
  выбор реализован в PRD-6; здесь добавляется выбор из >= 2 конфигураций).

## 3. Функциональные требования

| ID | Требование | Основание |
| --- | --- | --- |
| FR-01 | Администрируемый CRUD конфигураций плагина: endpoint'ы, параметры запроса, фильтр статусов, regex прогресса, поле и парсинг даты, версия адаптера, политика ошибки — без изменения Core | BR-07-11 |
| FR-02 | Один плагин хранит >= 2 конфигураций; тест выбирает конфигурацию по `configId` | BR-07-08, BR-07-16 |
| FR-03 | Тестовая проверка плагина на выбранном курсе/пользователе: сырые записи -> отфильтрованные -> выбранная попытка -> итоговое решение (`allowed`, `availableDate`, `reason`) | BR-07-16 |
| FR-04 | Плагины версионируются; обновление конфигурации не требует пересборки Core | NFR-12 |
| FR-05 | Реестр гейтится админ-ролью (RBAC PRD-13); read-only сидирование из кода остаётся как fallback | BR-07-12 |

## 4. Модель данных

Таблицы уже предусмотрены разделом модели данных BRD; в PRD-6 не материализованы (реестр
живёт в коде):

- `eligibility_plugins` — реестр плагинов допуска: ключ, версия, описание, схема конфигурации.
- `eligibility_plugin_configs` — администрируемые настройки LMS-плагина: endpoint'ы, параметры,
  фильтр попыток, парсинг даты, версия адаптера.

Тест по-прежнему ссылается на плагин и конфигурацию через `tests.retake_policy_json`
(`eligibilityPlugin.key` + `configId`) — контракт PRD-6 не меняется.

## 5. Вне охвата

- Рантайм retake gate, контракт плагина `context -> allowed`, блок-экран — реализованы в PRD-6.
- Новые провайдеры-плагины сверх существующих (`webtutor_cooldown`, `suspend_data_cooldown`,
  `custom`) — по отдельному запросу.

## 6. Критерии приёмки

- [ ] Администратор создаёт/редактирует/удаляет конфигурацию плагина через UI без изменения Core.
- [ ] Один плагин имеет >= 2 конфигураций; автор выбирает конфигурацию в настройках теста.
- [ ] Тестовая проверка показывает сырые записи, отфильтрованные записи, выбранную попытку
      и итоговое решение.
- [ ] Реестр доступен только администратору (RBAC); при пустом реестре работает read-only
      сидирование из кода (совместимость с PRD-6).
- [ ] Рантайм cooldown из PRD-6 не регрессирует.

## 7. Открытые вопросы

- OQ-01. **Закрыт 2026-08-06.** Вопрос стоял так: тестовая проверка требует живой LMS, а
  WebTutor недоступен — нужен ли режим проверки на мок-данных как временная замена. Стенд
  доступен, поэтому временная замена не нужна и в объём не вводится; проверка проектируется
  сразу против живой LMS.
- OQ-02. Нужен ли экспорт/импорт конфигураций между средами (dev/prod) в первой версии.
