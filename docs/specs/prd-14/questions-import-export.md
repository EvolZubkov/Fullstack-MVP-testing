## Терминология

- **Контракт файла** — набор колонок и форматов значений Excel; формализован в
  [спецификации формата](../questions-import/format.md).
- **Round-trip (обратимость)** — свойство «экспорт → импорт того же файла воспроизводит те
  же вопросы без потерь».
- **Паритет с моделью** — состояние, при котором импорт/экспорт покрывает все поля вопроса,
  которые автор может задать в редакторе.
- **Дескриптор медиа** — человекочитаемый идентификатор медиа-файла (id из реестра или имя),
  пригодный для указания в ячейке Excel; в отличие от текущего обезличенного URL.

## 1. Обзор

### 1.1 Контекст

Импорт/экспорт вопросов реализован
([questions.ts](../../../server/routes/questions.ts) `/import`, `/export`), но покрывает лишь
часть модели вопроса и теряет данные на нескольких типах:

- `matching` — импорт игнорирует колонку правильных ответов, навязывает позиционное
  соответствие `i ↔ i`, требует равного числа элементов и не поддерживает дистракторы;
  экспорт пишет реальное сопоставление, которое импорт прочитать не может (round-trip сломан).
- `ranking` — импорт всегда считает элементы перечисленными в правильном порядке, игнорируя
  колонку правильных ответов (round-trip сломан).
- Поля `tags` (PRD-11/PRD-2), условная обратная связь (`feedbackMode`/`feedbackCorrect`/
  `feedbackIncorrect`), «Цена ответа» (`scoringJson`, PRD-10) и медиа
  (`mediaUrl`/`mediaType`) ни импортом, ни экспортом не охвачены.
- `Балл = 0` и `Сложность = 0` ошибочно подменяются значениями по умолчанию из-за
  `parseInt(...) || default`.

Шкалы (PRD-5) и показатели (PRD-2) — test-scoped, в банк вопроса не входят; их импорт — это
отдельная процедура и отдельный этап (см. §5.4).

### 1.2 Метрики успеха

| Цель | Метрика |
| --- | --- |
| Обратимость экспорта/импорта | файл, полученный экспортом, при импорте воспроизводит исходные вопросы без потерь по всем типам |
| Паритет с моделью | импорт/экспорт покрывает теги, условную ОС и «Цену ответа» (медиа — отдельный будущий PRD) |
| Обратная совместимость | старые файлы (10-колоночный контракт) импортируются без изменения поведения |
| Прозрачность ошибок | каждая невалидная строка даёт понятную построчную причину; валидные строки импортируются |

## 2. Пользователи

- **Автор / администратор контента** — массово создаёт и правит банк вопросов через Excel,
  ожидает, что выгрузка и загрузка не теряют данные и покрывают возможности редактора.

## 5. Фазы реализации

### 5.1 Фаза 0 — исправление дефектов (контракт не меняется)

Цель — восстановить обратимость и устранить подмену нулей. Охват: FR-01..FR-05. Старые файлы
продолжают импортироваться. Приёмка — round-trip для `matching`/`ranking` и корректные `0`.

### 5.2 Фаза 1 — паритет с моделью (новые опциональные колонки)

Охват: FR-06..FR-11. Добавляются `Теги`, условная обратная связь, «Цена ответа» в импорт и
экспорт. Поля вопроса, не входящие в строку (например, при обновлении по `ID`), не затираются
благодаря частичному обновлению DAL.

### 5.3 Импорт медиа — ВНЕ охвата PRD-14 (отдельный будущий PRD)

Решение 2026-06-10: импорт медиа в банк вопросов **не входит в PRD-14** и не является
его пререквизитом. Он выделен в отдельный будущий PRD «Медиатека и импорт медиа»,
поскольку требует предварительной формализации процесса работы с медиа, а не «ещё одной
колонки» в файле.

Материал-затравка для будущего PRD (текущее состояние и обоснование выделения):

- загрузка `POST /api/media/upload` → диск `uploads/media/`, имя файла обезличено
  (`<timestamp>_<uuid>.<ext>`), исходное имя теряется;
- реестра медиа нет; в БД у вопроса только `mediaUrl` + `mediaType`;
- раздача `/uploads` статична и без авторизации;
- упаковка в SCORM читает файл с диска по URL ([media-assets.ts](../../../server/scorm/builders/media-assets.ts)).

Следствие: у автора нет человекочитаемого дескриптора файла, пригодного для ячейки Excel.
Рекомендуемый порядок для будущего PRD: реестр медиа (`media_assets`) → медиатека (UI) →
модель ссылки (`assetId`/имя) → интеграция в импорт (дескриптор или companion-ZIP) →
сквозное (авторизация раздачи, дедуп по checksum, сборка сирот). Открытые вопросы —
бывшие OQ-1..3 (§8) — переходят в этот PRD.

### 5.4 Мультилистовой этап — вопросы + шкалы + показатели + измерения

**Статус:** требования согласованы 2026-06-10 (решения 1-3 ниже); **бэкенд реализован 2026-06-10**
(эндпоинты импорта/экспорта, оркестрация, парсеры, тесты зелёные); **авторский UI — раздел «Импорт»
в боковой навигации реализован 2026-06-11** (эскиз `approved/prd14-workbook.html`, §5.5 ниже).
Охват — FR-15.1..FR-15.10. Шкалы (PRD-5), вклады (`question_measurements`) и показатели
(PRD-2) — test-scoped; импортируются отдельной процедурой, но в рамках одной книги на
разных листах. Контракт листов и грамматики — §12 [спецификации формата](../questions-import/format.md).

**Согласованные решения:**

1. **Адресация теста:** одна книга = один тест. Тест выбирается при импорте (параметр
   `testId`, как фильтр экспорта); листы `Шкалы`/`Показатели`/`Вклады вопросов` не содержат
   колонки «Тест». Лист `Вопросы` остаётся глобальным (вопросы не привязаны к тесту).
2. **Ссылка на вопрос в `Вкладах вопросов`:** по `ID`, либо по локальному `Ключ строки` —
   алиасу, заданному на листе `Вопросы` (для вновь создаваемых в той же книге). Алиас
   действует только в пределах книги и в БД не хранится.
3. **Экспорт:** симметричный — выгрузка теста пишет все 4 листа с проставленными
   `Ключ строки`, обеспечивая round-trip.

**Роли листов** (распознавание по имени): `Вопросы` (как Ф0-2), `Шкалы`, `Показатели`,
`Вклады вопросов`. Отсутствующие листы пропускаются; импорт перестаёт читать только первый лист.

**Порядок импорта (многопроходный):** `Вопросы` (создание/обновление, фиксация
`ID`↔`Ключ строки`) → `Шкалы` (upsert по `key`) → `Вклады вопросов` (резолв вопроса по
`ID`/`Ключ строки`, шкалы по `key`) + `Показатели` (валидация формулы). Идентичность и
порядок — ключевой инвариант: ссылки резолвятся только после записи целей.

**Идентификация (upsert по естественным ключам):** шкала — (тест, `Ключ`); показатель —
(тест, `Имя`); вклад — (тест, вопрос, шкала, `Источник`, `Ключ источника`). Повторный
импорт идемпотентен.

**Переиспользование валидации:** `insertScaleSchema` (+уникальность `key`/тест),
`insertResultVariableSchema` + `validateResultVariableFormula` + гард `controlsStatus`,
`measurementRowSchema` + проверка `Источник`/`Ключ источника` против типа вопроса.

### 5.5 Авторский UI — раздел «Импорт» (реализован 2026-06-11)

Эскиз согласован 2026-06-11 ([approved/prd14-workbook.html](../../wireframes/approved/prd14-workbook.html)).
Импорт вынесен ОТДЕЛЬНЫМ пунктом «Импорт» в боковую навигацию (DS `Sidebar`) → страница раздела
([client/src/pages/author/import.tsx](../../../client/src/pages/author/import.tsx)), маршрут
`/author/import`, гейт `questions.importExport`. Весь поток — ИНЛАЙН на странице (без модалок/drawer).

- **Автоопределение по листам** (`POST /api/workbook/inspect`, без `testId`, без записи): только
  «Вопросы» → импорт в общий банк, поле «Целевой тест» НЕ показывается; есть «Шкалы»/«Показатели»/
  «Вклады вопросов» → появляется обязательное поле «Целевой тест».
- **Целевой тест** — `Combobox`: существующий тест или опция «＋ Создать новый тест» (видна при
  `tests.create`) → поле «Название нового теста». «Импортировать» заблокирован, пока тест не выбран /
  имя не задано.
- **Маршрутизация запросов:** только вопросы → `/api/questions/import`; существующий тест →
  `/api/tests/:id/workbook/import`; новый тест → `POST /api/workbook/import-new` (создаёт
  бессекционный черновик-«оболочку показателей» и пишет в него). Каждый путь поддерживает dry-run
  (`?dryRun=true`) — инлайн-предпросмотр плана; затем тот же запрос без `dryRun`.
- **Точность dry-run:** `validateResultVariableFormula` принимает `extraScaleKeys`/`extraVarNames`
  (шкалы/показатели из самой книги), `importWorkbook` их передаёт — формулы, ссылающиеся на ещё не
  записанные (в dry-run или в новом тесте) шкалы, не дают ложных ошибок.
- **Скачать шаблон** — `GET /api/workbook/template` (пустые 4 листа с заголовками + лист «Справка»).
- **Экспорт ТЕСТА** — из меню действий конкретного теста (список тестов), НЕ в этом разделе.
  **Экспорт ВОПРОСОВ** — со страницы «Вопросы», НЕ в этом разделе.

Заголовок страницы пока в контенте (`PageHeader`); переедет в шапку оболочки в рамках задачи
header-title (см. [PLAN_appshell_migration.md](../../PLAN_appshell_migration.md) §9).

## 9. Вне охвата

- Импорт/экспорт адаптивных уровней, секций и настроек теста (это домен редактора теста).
- **Импорт медиа** — вынесен в отдельный будущий PRD «Медиатека и импорт медиа» (§5.3);
  в PRD-14 не входит и пререквизитом не является.
- Форматы, отличные от Excel (CSV/JSON), — не вводятся.
