# PRD-25: Домашняя страница

**Версия:** 1.0
**Статус:** ТРЕБОВАНИЯ СОГЛАСОВАНЫ 2026-07-28 — реализация не начата.
**Дата:** 2026-07-28
**Связанные документы:** [PRD-13](../prd-13/role-based-access-control.md) (роли и права — механизм,
которым гейтятся секции), [PRD-15](../prd-15/content-ownership.md) (владение контентом, снапшоты
публикации и дрейф пула), [PRD-6](../prd-6/retake-cooldown-gate.md) (ограничение повторного
прохождения — источник признака «пересдача доступна»),
[PRD-16](../prd-16/content-axis-and-question-model.md)
(объединённый раздел «Темы и вопросы»), [PRD-18](../prd-18/debug-test-player.md) (тестовый
прогон — действие в карточке теста), [role-model.md](../access-control/role-model.md)
(нормативный источник прав).
**Основание:** маршрут `/` сегодня не страница, а редирект по правам
([client/src/App.tsx](../../../client/src/App.tsx), `homePath`). Пользователь любой роли
приземляется в список объектов раздела и восстанавливает контекст работы вручную.

## Терминология

- **Секция главной** — самостоятельный блок страницы с собственным правом на просмотр,
  собственным источником данных и собственным пустым состоянием.
- **Профиль прав** — набор capability конкретного пользователя. Определяет, какие секции
  он видит и в какой оболочке рендерится страница.
- **Признак внимания** — вычисляемое условие, требующее действия пользователя (незавершённая
  попытка, дрейф пула, черновик без вопросов и т. п.).
- **Оболочка** — рамка приложения: авторская (`AppShell` с боковым меню) либо учебная
  (`LearnerLayout` с горизонтальной шапкой).

## 1. Обзор

### 1.1 Повод

Маршрут `/` реализован как редирект по наиболее привилегированной доступной области. Из этого
следуют три проблемы.

Во-первых, у сервиса нет точки входа «продолжить работу»: автор попадает в общий список тестов,
где его собственные незавершённые правки ничем не выделены, а учащийся — в список назначений без
приоритета незавершённой попытки.

Во-вторых, объекты пользователя разбросаны по трём разделам («Темы и вопросы», «Тесты», учебная
область), и мультиролевой пользователь вынужден обходить их последовательно.

В-третьих, редирект породил защиту от бесконечной петли: `homePath()` может вернуть `null`,
и тогда `ProtectedRoute` рендерит экран «нет доступа», чтобы не редиректить на маршрут, который
пользователю тоже запрещён. Появление реальной страницы на `/` снимает целый класс этих случаев.

### 1.2 Граница

| Подмеханика | Веб-хост | SCORM-пакет |
| --- | --- | --- |
| Домашняя страница | Да | Нет — вне охвата, пакет не имеет точки входа приложения |
| Признаки внимания | Да | Нет |
| Агрегат `GET /api/home` | Да | Нет |
| `topics.updated_at` | Да | Нет — колонка не попадает в выгрузку пакета |

### 1.3 Метрики успеха

- Учащийся с незавершённой попыткой возвращается в неё с главной за одно действие.
- Автор видит свои тесты, требующие публикации или доработки, без захода в раздел.
- Ни одна секция не показывает объект, недоступный пользователю в соответствующем разделе.
- Главная не дублирует раздел «Аналитика»: на ней нет графиков и трендов.

## 2. Пользователи

| Роль | Что видит на главной |
| --- | --- |
| Учащийся | Мне назначено, Мои результаты, признаки внимания по своим попыткам |
| Автор | Плюс Мои тесты, Мои темы и вопросы, быстрые действия по контенту, сводка по своим тестам |
| Менеджер | Мне назначено, Мои результаты, Люди и назначения, сводка |
| Администратор | Все секции, включая Материалы (активный шаблон и документация) |
| Суперпользователь | Все секции без ограничения по владению |

Мультиролевой пользователь видит объединение секций своих ролей — отдельного переключателя
контекста нет.

## 3. Функциональные требования

- **FR-01.** Маршрут `/` рендерит домашнюю страницу для любого аутентифицированного пользователя.
  Редирект `HomeRedirect` удаляется.
- **FR-02.** Состав секций определяется capability пользователя. Сервер не включает в ответ
  данные секции, на которую у пользователя нет права; клиентская проверка отвечает только за
  порядок отрисовки, но не является единственным гейтом.
- **FR-03.** Оболочка выбирается по профилю прав: при наличии хотя бы одной авторской или
  менеджерской capability — авторская оболочка, иначе учебная. Сама страница одна.
- **FR-04.** В обе навигации добавляется пункт «Главная» первым элементом, без гейта по праву.
- **FR-05.** Секция «Требует внимания» показывает признаки по правилам раздела 5. Секция
  отсутствует целиком, если ни один признак не сработал.
- **FR-06.** Секция «Быстрые действия» показывает от трёх до пяти действий, отфильтрованных по
  правам: создать тест, добавить тему или вопрос, импорт из Excel, назначить тест, добавить
  пользователя. Действие ведёт сразу к форме создания. Разделы, где такой точки входа по ссылке
  сейчас нет, получают её в фазе 3 — открывать раздел и заставлять искать кнопку недопустимо.
- **FR-07.** Секция «Мне назначено» показывает до четырёх назначенных тестов: сначала с
  незавершённой попыткой, затем не начатые. В карточке — название, использованные и доступные
  попытки, действие «Продолжить» либо «Начать», ссылка на полный список.
- **FR-08.** Секция «Мои результаты» показывает три последние завершённые попытки: тест, дата,
  процент, зачёт или незачёт, ссылка на историю.
- **FR-09.** Секция «Мои тесты» показывает до шести тестов, отсортированных по `updated_at`
  по убыванию, с подъёмом наверх тестов с признаком внимания. В карточке — название, статус
  (черновик, опубликован, изменён после публикации), число разделов и вопросов, метка владения
  или выданного доступа. Действия: открыть редактор, тестовый прогон, выгрузить SCORM —
  каждое по своему праву.
- **FR-10.** Секция «Мои темы и вопросы» показывает до шести тем, отсортированных по
  `updated_at` по убыванию. В карточке — название, код, число вопросов, метка владения или
  выданного доступа. Действия: открыть, добавить вопрос.
- **FR-11.** Секция «Люди и назначения» показывает сводку: число активных назначений, число
  назначений без единой начатой попытки, число новых пользователей за семь дней.
- **FR-12.** Секция «Сводка» показывает четыре числа за тридцать дней: попытки, доля сдачи,
  средний процент, активные пользователи. Графиков нет; ссылка ведёт в раздел «Аналитика».
- **FR-13.** Секция «Материалы» показывает активный шаблон оформления и ссылки на выгрузку
  руководства и спецификации шаблонов.
- **FR-14.** Данные страницы отдаются одним запросом `GET /api/home`.
- **FR-15.** Отказ источника одной секции не роняет ответ: секция приходит с признаком ошибки
  и рисуется состоянием «не удалось загрузить», остальная страница работает.
- **FR-16.** Видимость объектов определяется существующими сервисами скоупа (`test-access`,
  `topic-access`, `analyticsScope`). Собственной логики видимости главная не заводит.
- **FR-17.** Каждая секция имеет пустое состояние с действием, ведущим к созданию первого
  объекта. Исключение — «Требует внимания» по FR-05.
- **FR-18.** Пользователь, которому недоступна ни одна секция, видит на главной содержимое
  «нет доступа» вместо редиректа.
- **FR-19.** Запрещённый маршрут редиректит на `/`, а не на область по приоритету роли.
- **FR-20.** Тема получает время изменения (`topics.updated_at`), обновляемое при правке темы
  и при создании, изменении или удалении её вопроса.
- **FR-21.** Страница перезапрашивает данные при возврате на вкладку — так же, как список
  назначенных тестов.

## 4. Модель данных

### 4.1 Миграция 036: время изменения темы

Таблицы `topics` и `questions` не имеют колонок времени. Отбор «недавно изменённые» для секции
«Мои темы и вопросы» без них невозможен.

```sql
ALTER TABLE topics ADD COLUMN updated_at timestamp NOT NULL DEFAULT now();
CREATE INDEX topics_updated_at_idx ON topics (updated_at DESC);
```

Колонка аддитивная и заполненная по умолчанию, поэтому существующее поведение не меняется.
Точки обновления: изменение самой темы и любая мутация её вопросов (создание, изменение,
удаление, импорт из Excel). Обновление выполняется в той же транзакции, что и мутация.

Колонку `questions.updated_at` не вводим: секция оперирует темами, а не отдельными вопросами,
и время темы уже покрывает сценарий.

### 4.2 Контракт `GET /api/home`

Ответ — объект, где каждое поле необязательно и присутствует только при наличии права. Отсутствие
поля означает «секция недоступна», поле со значением `{ "error": true }` — «источник отказал».

```json
{
  "attention": [
    { "id": "…", "kind": "attempt-in-progress", "severity": "info", "title": "…",
      "subtitle": "…", "href": "/learner/test/…", "action": "Продолжить" }
  ],
  "quickActions": [{ "id": "test-create", "label": "Создать тест", "href": "/author/tests" }],
  "assigned": { "items": [], "total": 0 },
  "recentResults": { "items": [] },
  "myTests": { "items": [], "total": 0 },
  "myTopics": { "items": [], "total": 0 },
  "peopleAssignments": { "activeAssignments": 0, "notStarted": 0, "newUsers7d": 0 },
  "summary": { "attempts30d": 0, "passRate": 0, "avgPercent": 0, "activeUsers": 0 },
  "materials": { "activeTemplate": null, "docs": [] }
}
```

Секции собираются параллельно. Каждая обращается к существующему репозиторию или сервису; новых
источников данных, кроме агрегатора, не появляется.

## 5. Правила признаков внимания

| Признак (`kind`) | Условие | Право | Действие |
| --- | --- | --- | --- |
| `attempt-in-progress` | У пользователя есть незавершённая попытка | `attempts.self.read` | Продолжить |
| `retake-available` | Cooldown истёк, попытки не исчерпаны | `attempts.self.read` | Пройти снова |
| `test-empty-draft` | Тест в статусе «черновик» без вопросов | `tests.edit` | Открыть редактор |
| `test-edited-after-publish` | `editedAfterPublish` у опубликованного теста | `tests.publish` | Опубликовать заново |
| `test-pool-drift` | `poolDrift` у опубликованного теста | `tests.publish` | Посмотреть расхождения |
| `topic-duplicates` | Отчёт о дубликатах тем непустой | `topics.manage` | Открыть отчёт |
| `assignment-not-started` | Назначение без единой начатой попытки | `assignments.manage` | Открыть назначение |

Признаки `test-edited-after-publish` и `test-pool-drift` вычисляются существующим сервисом
снапшотов, `retake-available` — существующим сервисом cooldown, `topic-duplicates` — существующим
отчётом о дубликатах. Агрегатор не реализует собственных вычислителей.

Признаки по тестам считаются **только для тестов, попавших в выборку секции «Мои тесты»**
(до шести последних по времени изменения). Проверять состояние публикации по всему пулу тестов
на каждый вход запрещено — см. риск R-3.

## 6. Раскладка и интерфейс

Две колонки. Левая, широкая: «Мне назначено», «Мои результаты», «Мои тесты», «Мои темы и
вопросы», «Люди и назначения». Правая, узкая и липкая при прокрутке: «Требует внимания»,
«Быстрые действия», «Сводка», «Материалы».

Если правая колонка пуста для данного профиля прав, страница схлопывается в одну колонку на всю
ширину. На узких экранах правая колонка переносится под левую.

Вёрстка выполняется примитивами дизайн-системы (`Grid`, `Stack`, `Cluster`, `Card`, `Tag`,
`Text`, `EmptyState`). Локальные классы раскладки и типографики запрещены; недостающий примитив
добавляется в ui-kit по согласованию, а не обходится локальным шимом.

Реализации предшествуют эскизы, согласованные отдельно (см. фазу 0).

## 7. Оболочка и маршрутизация

Профиль считается авторским при наличии любой из capability: `tests.read`, `topics.manage`,
`users.read`, `groups.manage`, `analytics.read`, `adminTemplates.manage`,
`questions.importExport`, `logs.read`. Авторский профиль получает авторскую оболочку с боковым
меню, остальные — учебную.

Учебная область по составу не меняется: пункты «Тесты» и «История» остаются на местах, перед ними
добавляется «Главная». Перестройка учебной навигации в боковое меню в этот PRD не входит.

---

## 8. Пустые состояния и деградация

- Секция без данных показывает пустое состояние с действием: учащемуся — «Тестов пока не
  назначено», автору — «Создайте первый тест» с той же кнопкой, что в быстрых действиях.
- Секция с отказавшим источником показывает «Не удалось загрузить» и кнопку повтора; остальные
  секции при этом работают.
- Пользователь без единой доступной секции видит содержимое «нет доступа» на самой главной.

---

## 9. Совместимость

- Ссылки и закладки на `/author/*` и `/learner/*` продолжают работать без изменений.
- Функция `homePath()` удаляется вместе с редиректом; её вызовы в `ProtectedRoute` заменяются
  на редирект на `/`.
- Отсутствие миграции 036 на старой базе делает секцию «Мои темы и вопросы» недоступной, но не
  ломает остальную страницу.

---

## 10. Вне охвата

- Графики и тренды на главной — остаются в разделе «Аналитика».
- Онбординг-плитки разделов — дублируют боковое меню.
- Лента активности по контенту — в базе нет журнала действий; отдельный PRD.
- Ручное закрепление объектов на главной (избранное) — отдельный PRD.
- Персональная история просмотров как источник отбора — отклонена, см. D-3.
- Перевод учебной области на боковое меню — отдельная задача.

---

## 11. Решения

- **D-1.** Главная единая и адаптивная для всех ролей, а не отдельная для авторской и учебной
  областей. Одна точка входа, один маршрут, состав гейтится тем же механизмом, что и меню.
- **D-2.** Назначение страницы — личный рабочий стол-навигатор с быстрыми действиями, а не
  приборная панель показателей. Показатели без действия быстро превращаются в фон и дублируют
  «Аналитику».
- **D-3.** Отбор объектов — по времени изменения плюс признаки внимания. Персональный журнал
  просмотров отклонён: требует новой таблицы и точек записи в каждом разделе при сопоставимой
  пользе.
- **D-4.** Раскладка — две колонки, срочное и действия всегда на экране при прокрутке объектов.
- **D-5.** Оболочка выбирается по правам. Перестройка учебной области под боковое меню
  архитектурно чище, но выходит за рамки задачи и требует своих эскизов.
- **D-6.** Теме добавляется `updated_at`. Альтернатива — сортировка тем по названию — вырождает
  секцию в укороченную копию раздела и противоречит D-3.

## 12. Фазы реализации

- **Фаза 0.** Эскизы главной для четырёх профилей прав, согласование.
- **Фаза 1.** Миграция 036 и точки обновления `topics.updated_at` во всех мутациях темы и её
  вопросов, включая импорт.
- **Фаза 2.** Серверный агрегатор `GET /api/home`: сборка секций по правам, параллельный сбор,
  изоляция отказов, лимиты выборок.
- **Фаза 3.** Клиент: страница, выбор оболочки, маршрут `/`, пункт «Главная» в обеих навигациях,
  удаление `homePath` и редиректа.
- **Фаза 4.** Приёмка в реальном браузере по четырём профилям прав, включая проверку, что чистому
  учащемуся не протекает ни одна авторская секция.

## 13. Риски

- **R-1.** Дублирование раздела «Аналитика». Снижается запретом графиков на главной (FR-12).
- **R-2.** Разъезд видимости между главной и разделами. Снижается требованием FR-16 —
  переиспользование сервисов скоупа без собственной логики.
- **R-3.** Стоимость агрегата на каждый вход: состояние публикации считается по тесту, и проверка
  всего пула была бы линейной по числу тестов. Снижается ограничением из раздела 5 — признаки
  только по выборке до шести тестов.
- **R-4.** Обновление `topics.updated_at` легко пропустить в одной из точек мутации, и секция
  начнёт показывать устаревший порядок. Снижается тестами на каждую точку записи, включая импорт.
- **R-5.** Страница разрастётся секциями по мере развития сервиса. Снижается правилом: новая
  секция требует своего права, своего пустого состояния и обоснования, почему она не является
  дубликатом раздела.
