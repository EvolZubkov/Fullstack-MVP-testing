# PRD-42: Материалы обратной связи — только ссылки, без загрузки файла

**Версия:** 1.0
**Статус:** Реализовано и влито в main 2026-08-05 (ветка `prd-42-feedback-links`).
**Дата:** 2026-08-05
**Связанные документы:** [PRD-32](../prd-32/feedback-assets-delivery.md) (постановка проблемы
доставки вложений), [дизайн-документ PRD-32](../2026-08-02-feedback-assets-delivery-design.md)
(реализованное решение — загрузка PDF в медиатеку), [PRD-27](../prd-27/report-template.md)
(PDF-отчёт, куда попадают ссылки на вложения)
**Основание:** дефект приёмки — ссылки на вложения в PDF-отчёте ведут на несуществующие адреса

## 1. Обзор

### 1.1 Повод

PRD-32 реализовал вложения обратной связи как загрузку PDF в медиатеку: дескриптор хранит
канонический адрес `url = /api/media/<id>`. Это относительный адрес — он резолвится только в
живой странице, у которой есть origin.

PDF-отчёт (`shared/report/export-pdf.ts`) печатает ссылки на вложения не так: макет отчёта
рендерит чипы `.pdf-link-btn[data-url]`
([`server/scorm/templates/default/layouts/report.html:113,129`](../../../server/scorm/templates/default/layouts/report.html)),
`exportReportPdf`
([`shared/report/export-pdf.ts:130-156`](../../../shared/report/export-pdf.ts)) читает
`data-url` и пишет его буквально как цель гиперссылки через `pdf.link({ url })`. У отдельного
PDF-файла нет браузерного origin, чтобы резолвить относительный адрес, — читалка получает
мусор вместо ссылки.

На вебе это `/api/media/<id>` без схемы и хоста. В SCORM-пакете хуже: упаковщик
(`server/scorm/builders/media-resolver.ts:54`, `media-assets.ts`) на этапе сборки
намеренно переписывает тот же адрес на путь ВНУТРИ ZIP (`assets/media/<id>.pdf`) — годный
для навигации внутри плеера, но не существующий вне пакета вообще. Отладочный плеер (PRD-18)
маскирует обе проблемы: он раздаёт собранный пакет same-origin с живой сессией, и относительный
путь там случайно резолвится.

### 1.2 Почему не резолвинг адреса, а изменение модели

Рассматривался вариант резолвить относительный адрес в абсолютный
(`appBaseUrl() + /api/media/<id>`, по образцу `server/config.ts:192`, уже используемого для
magic-ссылок в письмах) перед записью в `pdf.link`. Отклонён: он требует, чтобы у ученика,
открывающего PDF из LMS, был сетевой доступ к серверу Skill'Ум, и продолжает держать SCORM- и
веб-адреса вложения разными сущностями (в SCORM это путь внутри ZIP, а не URL). Вместо этого
модель вложения меняется так, чтобы адрес был настоящим внешним URL с самого начала — точно как
уже устроены секции «Курсы» и «Мероприятия» в том же редакторе. Тогда PDF-, веб- и
SCORM-рендеры получают один и тот же рабочий адрес без резолвинга, а упаковщик SCORM его вообще
не трогает: `mediaAddressPattern` не совпадает с произвольным `http(s)`-URL.

## 2. Охват

В охвате:

- секция «Прикреплённые файлы (PDF)» редактора обратной связи заменяется на секцию «Материалы»
  — список {title, url}, без загрузки файла, по образцу секции «Курсы»;
- маршрут `POST /api/media/upload?purpose=feedback-asset` и его обработчик удаляются;
- типы и схема вложения (`FeedbackAsset`, `feedbackAssetSchema`) упрощаются под новую форму
  ввода.

Вне охвата:

- уже сохранённые вложения (`url: /api/media/<id>`, легаси `scormHref`) — не мигрируются и не
  блокируются валидацией, остаются как есть (см. §7 — технический долг);
- `shared/report/export-pdf.ts`, SCORM-упаковщик, `shared/template/result-context.ts` — не
  меняются, они уже одинаково обрабатывают и legacy media-ref, и обычный внешний URL;
- расширение типов вложения за пределы «ссылка» (например, выбор из медиатеки) — отдельная
  задача, если возникнет потребность.

## 7. Технический долг

`feedbackAssetSchema.url` остаётся простой опциональной строкой без проверки формата — то же
самое поведение, что и сегодня. Это осознанное решение ради обратной совместимости: ужесточение
до `.url()` (как у «Курсы») привело бы к тому, что сохранение ЛЮБОГО теста с уже существующим
legacy-вложением (`url: /api/media/<id>`) начало бы падать на валидации, поскольку такой адрес
не проходит `.url()`.

Следствие: у легаси-вложений, оформленных через загрузку файла (PRD-32), ссылка в PDF-отчёте
остаётся битой — ровно тот дефект, ради которого заведён этот PRD, — пока автор не откроет
редактор и не заменит адрес вручную на настоящий `http(s)`-URL. Отдельного напоминания или
маркера «замените ссылку» редактор не показывает (FR-07): строка выглядит как обычное
редактируемое поле, и автор либо сам сталкивается с проблемой при попытке скачать отчёт, либо
может так и не узнать о ней. Если это окажется недостаточным на практике, следующий шаг —
маркер для строк, чей `url` совпадает с шаблоном `/api/media/<id>` (тот же распознаватель, что
уже применяет упаковщик и индекс использования), — вне охвата этого PRD.

## 8. Критерии приёмки

- Автор открывает редактор обратной связи (тест, тема, раздел, диапазон шкалы, исход
  показателя), в секции «Материалы» вводит название и `https://…`-адрес, сохраняет — вложение
  сохраняется как {title, url}.
- В секции «Материалы» нет кнопки загрузки файла и элемента выбора файла.
- Скачанный PDF-отчёт содержит рабочую (не битую) ссылку на новый материал — и на вебе, и из
  SCORM-пакета.
- Тест с ранее загруженным (PRD-32) вложением (`url: /api/media/<id>`) открывается в редакторе,
  строка редактируема, сохранение теста без изменения этой строки проходит без ошибок
  валидации.
- `POST /api/media/upload?purpose=feedback-asset` отсутствует как маршрут (или отвечает так же,
  как обычная загрузка медиа, без специальной проверки PDF/5 МБ) — обычная загрузка медиа
  вопроса продолжает работать.
- `npm run check` и целевые тесты (`feedback-editor-modal`, `media-upload-route`,
  `results-feedback-assets-scorm`) проходят.

## 9. Риски

| Риск | Митигация |
| --- | --- |
| Автор случайно вставит `/api/media/<id>` или другой относительный путь в новое поле URL — ссылка в PDF снова будет битой | Вне охвата: поведение идентично «Курсы», где та же возможность существует уже сегодня без нареканий |
| Регресс существующих тестов (`feedback-preview.test.tsx`, `feedback-editor-modal-upload.test.tsx`) на удалённую функциональность | Тесты загрузки удаляются вместе с кодом; добавляется покрытие нового поведения «Материалы» (§8) |
