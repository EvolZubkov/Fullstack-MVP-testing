(поднята этим треком до 2.0.0).

## 1. Задача

### 1.1. Что показал разбор референса

Референсный отчёт — три листа A4.

| Лист | Содержимое |
| --- | --- |
| 1. Титул | Логотипы, крупный заголовок, тёмная карточка «вердикт / ФИО / дата» со знаком исхода, абзац-обращение к слушателю, декоративная иллюстрация |
| 2. Результаты | Две карточки-блока («Управленческие компетенции», «Знания»), у каждой серая шапка с названием и оранжевый бейдж-счётчик; внутри строки разделов с пилюлей уровня и подтемами с полосами |
| 3. Методический разворот | «О тесте», «Как читать отчёт», «Рекомендации» — связный авторский текст, часть его в три колонки |

Данные для первых двух листов контракт отдаёт целиком: титул собирается из `course.title`,
`report.verdictHeadline`, `report.learnerName`, `report.attemptDateLabel`, `report.verdictClass` и
картинок варианта, лист результатов — из `result.topicGroups[]` (PRD-50: название блока и счётчик,
умолчание формата которого уже `{passed} / {total}`), строк тем с `verdictLabel` / `passClass` и
вложенных разрезов `breakdown[]`. Ни одного нового поля ДАННЫХ эта работа не заводит.

### 1.2. Чего не хватает

Не хватает документа, который автор СОБИРАЕТ.

Сегодня отчёт — одна раскладка `report.html`, печатающая всё подряд в порядке, зашитом
разработчиком шаблона. У автора теста есть ровно одна свободная область текста (вводный блок
`result.introHtml`) и набор разрозненных выключателей показа. Из этого нельзя составить ни третий
лист референса, ни любой другой документ, устройство которого автор придумал сам:

- второй области авторского текста завести нечем: `placeholders[]` варианту отчёта запрещены
  (`shared/report/report-variants.ts:444-450`), а у `settings[]` нет ни одного типа с разметкой
  (`shared/template/field-types.ts`);
- порядок блоков документа автор не задаёт вовсе; частичный ответ — `resultsBlockOrder` (PRD-49) —
  относится к подблокам итогов и живёт отдельно от документа;
- разрыв листа расставляет только разработчик шаблона (`data-page-break`), поэтому автор не может
  открыть свою страницу с нового листа.

При этом РЯДОМ, в той же программе, уже есть ровно нужный механизм: вкладка «Структура» теста, где
автор добавляет страницы кнопкой-вставкой, перетаскивает их, меняет вариант оформления строки,
удаляет, а системные узлы выключает, но не удаляет.

Задача — сделать отчёт таким же документом: упорядоченным списком блоков, который автор собирает
тем же способом и теми же элементами интерфейса, что структуру теста.

## 2. Решения, которые нельзя пересматривать

1. **Отчёт — список блоков, а не одна раскладка.** Документ состоит из блоков; шаблон объявляет
   раскладку каждого блока и документ по умолчанию; тест хранит свой порядок и состав.
2. **Механика редактора берётся у структуры теста, а не изобретается.** Те же зоны-строки, та же
   ручка перетаскивания, та же кнопка-вставка «+ Добавить», та же палитра вариантов, то же
   раскрывающееся редактирование, то же меню строки. Второго способа собирать список в продукте
   быть не должно.
3. **Системный блок выключается, а не удаляется.** Как системный узел структуры: автор гасит показ,
   но блок остаётся на своём месте в списке и виден в редакторе.
4. **Поля блока — это PRD-22 без исключений.** Содержимое блока — `placeholders[]` его варианта,
   свойства — `settings[]`, типы и режимы ввода из общего реестра, очистка разметки — общей
   функцией. Ни одного поля, устроенного специально для отчёта.
5. **Пусто — значит не печатать.** Незаполненный блок не даёт ни разметки, ни отступа, ни листа.
6. **Совместимость обязательна.** Тест без собранного документа печатает документ по умолчанию
   шаблона; шаблон, не объявивший блоков, печатает свою цельную раскладку, как сегодня.
7. **Экран итогов эта работа не трогает.** Расхождение механик признано и записано в §14.

## 3. Модель документа

### 3.1. Блок

Документ — упорядоченный список блоков. Блок бывает трёх природ:

| Природа | Что это | Удаляется | Содержимое автора |
| --- | --- | --- | --- |
| Системный | Данные попытки: шапка, сводка, темы, разрез, шкалы, показатели, рекомендации | Нет, выключается | Нет |
| Страница | Авторский текст и картинки по варианту шаблона | Да | Да, `placeholders[]` варианта |
| Разрыв листа | Служебный узел: следующий блок начинается с нового листа | Да | Нет |

Перечень системных блоков закрыт продуктом — это ровно то, что документ умеет рассказать о попытке:

| Ключ | Блок |
| --- | --- |
| `header` | Шапка документа: название теста, вердикт, ФИО, дата, число попыток, логотип |
| `intro` | Вводный блок автора (`intro_json`, PRD-27) |
| `summary` | Сводка баллов: кольцо, три числа, плашка вердикта |
| `topics` | Темы и блоки разделов (PRD-50), с вложенными разрезами |
| `breakdown` | Сводный разрез по всему тесту (PRD-50 FR-28) |
| `scales` | Шкалы и диаграмма по шкалам |
| `indicators` | Показатели |
| `recommendations` | Рекомендации: тексты, ссылки, материалы, мероприятия |
| `courses` | Рекомендованные курсы по невзятым темам |
| `events` | Рекомендованные мероприятия |

Новых видов данных здесь нет: это сегодняшние секции `report.html`, названные и разъятые.

**Минимальный документ.** Пустой отчёт не выдаётся никогда: когда состав брать неоткуда —
шаблон его не объявил, — документ наполняется блоком `header`, то есть титулом с вердиктом.
Лист без имени и без исхода не годится ни на что: документ уносят с собой и показывают
специалисту.

Это граница УМОЛЧАНИЯ, а не запрет. Автор вправе выключить и титул: продукт решает, с чего
документ начинается, а не что автору разрешено. Обязательных блоков в модели нет вовсе.

### 3.2. Объявление в манифесте

Вариант вида `report` (и `report.adaptive`) перестаёт быть документом и становится ОБОЛОЧКОЙ:
корневой узел `.tb-report` с подложкой, брендингом и своими `settings[]`. Запрет `placeholders[]`
на этом виде ОСТАЁТСЯ в силе — у оболочки действительно нет авторского содержимого, оно живёт в
блоках.

Появляется вид `report.block`. Один вариант — одна раскладка одного блока:

```json
{
  "key": "report.block.topics.cards",
  "kind": "report.block",
  "block": "topics",
  "label": "Темы: карточки",
  "layoutFile": "layouts/report/topics.html",
  "isDefault": true
}
```

Для авторских страниц `block` равен `page`, и такой вариант объявляет `placeholders[]`:

```json
{
  "key": "report.block.page.text",
  "kind": "report.block",
  "block": "page",
  "label": "Страница: текст",
  "layoutFile": "layouts/report/page-text.html",
  "isDefault": true,
  "placeholders": [
    { "key": "title", "type": "text", "label": "Заголовок" },
    { "key": "body", "type": "richText", "label": "Текст" }
  ]
}
```

Правила объявления:

- на каждый ключ блока — минимум один вариант, ровно один помечен `isDefault`;
- вариантов на один блок может быть несколько: это и есть «Сменить вариант» в строке;
- разрыв листа варианта НЕ имеет: он не раскладка, а инструкция документу;
- ключи `placeholders[]` и `settings[]` уникальны в пределах варианта.

### 3.3. Документ по умолчанию

Манифест объявляет документ, который получает тест, ничего не настраивавший:

```json
"reportDocument": {
  "report": ["header", "intro", "summary", "topics", "breakdown", "scales",
             "indicators", "recommendations", "courses", "events"],
  "report.adaptive": ["header", "intro", "topics", "breakdown", "scales",
                      "indicators", "recommendations", "courses", "events"]
}
```

Умолчание обязано совпадать с сегодняшним порядком печати `report.html` — иначе уже собранные
тесты сменят вид документа без единой правки автора.

### 3.4. Оболочка и пагинация

Постраничная раскладка меряет ПРЯМЫХ детей корня документа (`shared/report/paginate-dom.ts`:
`[...root.children]`) и режет между ними. Поэтому оболочка обязана быть тонкой: она даёт корневой
узел `.tb-report` с фоном и темой и НЕ заворачивает блоки в промежуточный контейнер. Каждый блок —
прямой ребёнок корня.

Обёртка вокруг потока блоков превратила бы весь документ в один неделимый блок, и многостраничный
отчёт схлопнулся бы в один переросток, дорезаемый растром.

Правило держится НЕ проверкой, а устройством: вставку делает движок сборки, и он кладёт блок
прямым ребёнком корня. Шаблон не участвует в размещении блоков и потому не может их завернуть —
у него нет узла, в который они бы попали. Статическая проверка тут не нужна: она сторожила бы
ошибку, которую невозможно совершить.

Разрыв листа печатается узлом `<div data-page-break></div>` — существующий контракт (спецификация
формата §8.4.6), менять его не нужно.

## 4. Хранение

Новая таблица `report_blocks` — своя, а не зона в `content_pages`.

```text
report_blocks
  id            uuid    pk
  test_id       -> tests.id, on delete cascade
  mode          'standard' | 'adaptive'     -- документ на режим, как ветви report_settings_json
  block         text                        -- ключ блока: header|summary|…|page|page-break
  template_key  text null                   -- выбранный вариант; null = isDefault своего блока
  sort_order    integer
  enabled       boolean default true        -- системный блок гасится, но остаётся в списке
  values_json   jsonb default {}            -- содержимое: значения placeholders[] варианта
  settings_json jsonb default {}            -- свойства: значения settings[] варианта
  created_at, updated_at
  index (test_id, mode, sort_order)
```

Форма намеренно повторяет `content_pages`: те же понятия, тот же лайфцикл, те же компоненты
редактора. Отдельная таблица — потому, что страница отчёта НЕ участвует в выдаче, а каждый
потребитель `content_pages` (сборка выдачи, последовательности страниц, гард целостности,
книга Excel, снапшот публикации) обходит таблицу целиком. Один пропущенный фильтр там означал бы
страницу отчёта посреди прохождения теста — отказ, который увидит ученик. Отдельная таблица делает
эту ошибку невозможной, а не маловероятной.

Пустой набор строк = документ по умолчанию шаблона (§3.3). Строки материализуются при первой
правке документа — так же, как страницы теста.

Выбор оболочки и её поля остаются в `tests.report_settings_json` без изменений.

## 5. Сборка и рендер

### 5.1. Разрешение документа

Одна функция на весь продукт (`shared/report/report-document.ts`): манифест шаблона плюс строки
теста дают упорядоченный список блоков с раскладкой, значениями и признаком показа.

Правила разрешения:

- строк нет → документ по умолчанию, все блоки включены, варианты `isDefault`; состав, не
  объявленный шаблоном, вырождается в минимальный документ (§3.1), а не в пустоту;
- строки есть → берётся их порядок; блок, которого шаблон больше не объявляет, ПРОПУСКАЕТСЯ, но
  строка не удаляется (смена шаблона обратима);
- блок, появившийся в шаблоне после сборки документа, дописывается в КОНЕЦ выключенным: молча
  добавить в середину чужого документа новый блок нельзя, а потерять его — тоже;
- `template_key`, которого вариант больше не объявляет, деградирует к `isDefault` того же блока.

### 5.2. Отрисовка

Новая общая функция `renderReportInto(root, { shell, blocks, context })`:

1. рендерит оболочку через `renderScreenInto` — получается корневой узел документа;
2. для каждого включённого блока по порядку рендерит его раскладку тем же `renderScreenInto` с ТЕМ
   ЖЕ контекстом и с `content` этого блока (`placeholders[]` варианта + значения строки), после
   чего переносит результат ПРЯМЫМ ребёнком корня;
3. блок `page-break` печатает `<div data-page-break></div>`;
4. блок, не давший ни одного видимого узла, не оставляет после себя ничего.

Второй реализации сборки документа не появляется: её зовут все три выдачи.

### 5.3. Три выдачи

| Выдача | Шов |
| --- | --- |
| PDF (веб и LMS) | `shared/report/export-pdf.ts` — вместо `renderScreenInto` зовёт `renderReportInto` |
| SCORM-пакет | `resolveReportBake` отдаёт документ (оболочка + блоки + значения); сборщик кладёт раскладки всех использованных вариантов в пакет и очищает значения повторно, как уже делает для контентных страниц |
| Предпросмотр автора | `report-preview-modal.tsx` через `TemplateScreen` — тот же `renderReportInto`, значения ЧЕРНОВИКА |

### 5.4. Деградация

Шаблон, не объявивший ни `report.block`, ни `reportDocument`, печатает свою цельную раскладку
`report`/`report.adaptive` ровно как сегодня, а карточка редактора показывает сегодняшние поля без
списка блоков. Это тот же принцип, по которому PRD-27 деградирует шаблон без вида отчёта на макет
стандартного.

Механика блоков, таким образом, — opt-in ШАБЛОНА. Стандартный шаблон переводится на неё в рамках
этой работы (§9), поэтому основной путь продукта — блочный, а цельная раскладка остаётся только
дорогой совместимости для внешних шаблонов, которые ещё не перешли.

## 6. Безопасность

Разметка блоков-страниц проходит ровно тот же путь, что разметка контентной страницы: нормализация
в редакторе при вставке, очистка с диагностикой при сохранении на сервере, заключение авторского
CSS в область поля (`placeholderScope`), повторная очистка при сборке пакета
(`server/scorm/builders/test-json.ts`). Новых правил очистки эта работа не вводит.

## 7. Редактор

### 7.1. Где

Карточка «Отчёт о результатах» на вкладке «Настройки» (сторона `content`) показывает ДОКУМЕНТ.
Вкладка «Оформление» → «Оформление отчёта» сохраняет за собой выбор оболочки, подложку, логотип и
прочие поля `scope: appearance` — как сегодня.

### 7.2. Как

```text
Отчёт о результатах                                    [Предпросмотр]

  ┌ Титул ──────────────────────────────── системный ── 👁 ⋮ ┐
  ├──────────────── + Добавить блок ─────────────────────────┤
  ┌ ⠿ Ваш результат ────────────────────── системный ─ (•) ── ┐
  ┌ ⠿ Результаты по темам ──────────────── системный ─ (•) ── ┐
  ├──────────────── + Добавить блок ─────────────────────────┤
  ┌ ⠿ О тесте ─────────────────── авторская страница ── 👁 ⋮ ┐
  ┌ ⠿ Как читать отчёт ────────── авторская страница ── 👁 ⋮ ┐
  ┌ ⠿ ── разрыв листа ───────────────────────────────── ⋮ ── ┐
  ┌ ⠿ Рекомендации ─────────────────────── системный ─ (•) ── ┐
```

Правила строки — те же, что у строки страницы в «Структуре»:

- ручка перетаскивания слева, перетаскивание меняет порядок; клавиатурная альтернатива обязательна;
- название блока, тег природы («системный» / «авторская страница» / «разрыв листа»);
- меню строки: «Предпросмотр», «Сменить вариант» (отключено, когда вариант у блока один),
  «Удалить» (только у страницы и разрыва);
- системная строка вместо удаления несёт тумблер показа;
- строка авторской страницы раскрывается вниз в поля варианта — контролами PRD-22, с переключателем
  режима ввода;
- кнопка-вставка «+ Добавить блок» стоит МЕЖДУ строками и открывает палитру: авторская страница
  (список вариантов вида `page`), разрыв листа, а также системный блок, который автор ранее удалил
  из списка, если такой есть;
- опубликованный тест — только чтение.

Контрол полей один на весь продукт: `PlaceholderControl` и `ImagePlaceholderControl` выносятся из
`start-pages-section.tsx` в отдельный модуль, откуда их берут и структура теста, и отчёт. Вторая
копия означала бы расхождение режимов ввода и очистки.

### 7.3. Предпросмотр

Кнопка на месте и показывает СОБРАННЫЙ документ по черновику: порядок, выключенные блоки и
несохранённый текст страниц. Отдельная строка меню открывает предпросмотр одного блока — тем же
окном, что предпросмотр страницы теста.

## 8. Совместимость и контракт шаблонов

- Тест без строк `report_blocks`: документ по умолчанию шаблона, побайтово сегодняшний.
- Шаблон без блочных объявлений: цельная раскладка, карточка без списка блоков (§5.4).
- Смена шаблона: строки сохраняются, неизвестные блоки пропускаются, новые дописываются в конец
  выключенными (§5.1).
- `resultsBlockOrder` (PRD-49) для экрана `report` вытесняется списком блоков: два источника истины
  о порядке одного документа недопустимы. Для экранов итогов настройка остаётся как есть.
- Версия спецификации формата шаблонов поднимается до **2.0.0** — впервые за трек контракт меняется
  НЕ обратно совместимо по смыслу вида `report` (документ становится оболочкой), хотя старые
  шаблоны продолжают печататься по §5.4. Руководство разработчика — до 2.0.0, PDF в `docs/dist/`
  пересобираются.

## 9. Стандартный шаблон

Стандартный шаблон переводится на блоки в рамках этой работы: сегодняшний `report.html`
разбирается на десять раскладок блоков плюс оболочку, `reportDocument` объявляет их в сегодняшнем
порядке. То же для `report.adaptive`.

Проверка перевода — побайтовое сравнение PDF: тест, ничего не настраивавший, обязан дать документ,
неотличимый от собранного до правки. Это единственная гарантия, что разбор на блоки не изменил
вёрстку.

## 10. Отчёт шаблона «Сертификация»

### 10.1. Документ

| Лист | Блоки |
| --- | --- |
| 1 | `header` (логотип, `course.title`, тёмная карточка «вердикт / ФИО / дата» со знаком исхода), `intro` (обращение к слушателю), декоративная иллюстрация полем оболочки, затем `page-break` |
| 2 | `topics` — карточка на `result.topicGroups[]`: шапка с `label` и оранжевым бейджем `counterLabel`; строки тем с пилюлей `verdictLabel` и сеткой разрезов; затем `page-break` |
| 3 | Три авторские страницы: «О тесте», «Как читать отчёт», «Рекомендации» |

Далее — `scales`, `indicators`, `breakdown`, `recommendations`, `courses`, `events`: в референсе их
нет, но выбросить их значило бы потерять в документе то, что тест посчитал.

Заметьте: третий лист теперь собирает АВТОР, а не шаблон. Шаблон даёт варианты страницы (одна
колонка, две, три), автор ставит нужные и пишет текст.

### 10.4. Паритет с эталонным шаблоном

`tests/template-layout-parity.test.ts` требует, чтобы раскладки `certification` были побайтовыми

правила отдельным списком-исключением с обоснованием в самом тесте.

Гард продолжает стеречь 17 раскладок ученических экранов (все, кроме `report.html` и
`report.adaptive.html` из сегодняшних девятнадцати) — именно там он ловит расхождения контракта
рантайма, ради которых заводился. Правило исключения формулируется по КАТАЛОГУ (`layouts/report/`),
а не перечнем файлов: число раскладок блоков будет меняться, и перечень протух бы на первой же
правке шаблона.

## 13. Приёмка

1. Тест, ничего не настраивавший, даёт PDF, побайтово совпадающий с собранным до правки —
   на обоих шаблонах и в обоих режимах.
2. Автор переставляет «Рекомендации» выше «Тем», выключает «Сводку», добавляет две страницы и
   разрыв — и получает ровно такой документ, в вебе и из SCORM-пакета одинаково.
3. Незаполненная страница не даёт ни пустого листа, ни пустого отступа.
4. Вставка фрагмента с `<script>`, `onclick` и `body { … }` в поле страницы: скрипт и обработчик
   удалены, правило CSS заключено в область, и это видно И в вебе, И в пакете.
5. Предпросмотр показывает несохранённый документ: порядок, выключенные блоки, новый текст.
6. Смена шаблона на шаблон без блока `scales`: строка сохранена, блок пропущен, документ печатается;
   возврат прежнего шаблона возвращает блок на своё место.
7. Многостраничный документ режется по границам блоков; разрыв, поставленный автором, открывает
   новый лист; низ каждого листа непрозрачен (проверка по пикселям, не на глаз).
8. Отчёт «Сертификации» на реальной попытке сверен с референсом поэлементно по §10.3 — снимками
   рядом.
9. Перетаскивание строк работает с клавиатуры; опубликованный тест не редактируется.
10. `tests/template-layout-parity.test.ts` зелёный: 17 раскладок под гардом.

## 14. Вне охвата

- **Экран итогов.** Он остаётся на `resultsBlockOrder` и трёхпозиционных настройках показа.
  Расхождение двух механик признано сознательно: документ никто не проходит, сломать выдачу им
  нечем, а экран итогов видит каждый ученик. Перевод экрана на блоки — отдельная работа, и до неё
  расхождение живёт в техдолге `docs/ROADMAP.md`.
- Новые типы полей. Реестр `PLACEHOLDER_TYPES` не расширяется.
- Новые виды данных отчёта. §3.1 — это сегодняшние секции, названные и разъятые.
- Перенос вводного блока (`intro_json`) в поля страницы: у него своя колонка и своё место в
  редакторе, он приходит блоком `intro`.
- Загрузчик медиа для картинок блока: поле показывается адресом файла, как картинки оболочки
  сегодня.
- Условный показ блока по исходу попытки («страница только для непрошедших»).
- Библиотека готовых методических текстов и любой предзаполненный контент.
- Правка `report.verdictHeadline` через словарь надписей: расхождение §10.2 принято, отдельная
  работа при необходимости.
