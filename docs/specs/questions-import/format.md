## 1. Назначение

Документ фиксирует контракт файла Excel для массового экспорта и импорта банка вопросов:
набор колонок, форматы значений по типам вопросов, разделители, правила идентификации
и обновления, модель ошибок. Это единый источник истины для авторского формата.

Каждая колонка помечена статусом:

- **Текущий** — реализовано и работает в боевом коде.
- **PRD-14 Ф0** — нормализация поведения без изменения контракта (исправление дефектов);
  реализовано 2026-06-10.
- **PRD-14 Ф1** — расширение контракта (новые колонки/грамматики); реализовано 2026-06-10.

## 2. Общие правила

- Данные читаются из **первого листа** книги; заголовки — в строке 1, записи — со строки 2.
  Мультилистовой формат (вопросы + шкалы + показатели на разных вкладках) — следующий этап
  PRD-14, в текущем контракте не используется.
- Пустые строки пропускаются. Лишние колонки игнорируются.
- Значения ячеек приводятся к строке и обрезаются по краям; неразрывные пробелы и BOM
  (` `, `​`, `﻿`) нормализуются.
- **Пустая ячейка против отсутствия колонки** (правило обновления по `ID`):
  - колонка **отсутствует** в файле → поле НЕ изменяется (сохраняется текущее значение);
  - колонка **присутствует, но пустая** → поле сбрасывается к значению по умолчанию.
- Заголовки регистронезависимы по теме; для ряда колонок приняты алиасы (см. §4).

## 5. Форматы значений по типам

Разделитель вариантов — `#` (приоритетный) либо `|` (запасной при импорте). Нумерация
правильных ответов — **1-based** (с единицы).

### 5.1 `multiple_choice` (одиночный выбор, `single`)

- `Тексты вариантов ответа`: `A # B # C` (минимум 2 варианта).
- `Номера правильных ответов`: один номер, например `2`.

### 5.2 `multiple_response` (множественный выбор, `multiple`)

- `Тексты вариантов ответа`: `A # B # C # D`.
- `Номера правильных ответов`: список, например `1,3` (разделители `, . пробел`).

### 5.3 `matching` (сопоставление)

**Текущее поведение (дефект, исправляется в Ф0):** импорт игнорирует
`Номера правильных ответов`, требует равное число элементов слева и справа и навязывает
позиционное соответствие `i ↔ i`. Round-trip с экспортом не работает.

**Целевой формат (PRD-14 Ф0):**

- `Тексты вариантов ответа`: левый список, затем разделитель сторон `||`, затем правый
  список. Пример: `Кошка # Собака # Рыба || Мяу # Гав # Буль # Кваква`.
  Правый список может быть длиннее левого (дистракторы).
- `Номера правильных ответов`: пары `левый-правый` (1-based), например `1-1, 2-2, 3-3`.
- **Обратная совместимость:** если разделителя `||` нет — применяется старый разбор
  (чередование `лево # право # лево # право`, позиционное соответствие, без дистракторов).

### 5.4 `ranking` (ранжирование)

**Текущее поведение (дефект, исправляется в Ф0):** импорт игнорирует
`Номера правильных ответов` и всегда считает, что элементы перечислены в правильном порядке.

**Целевой формат (PRD-14 Ф0):**

- `Тексты вариантов ответа`: элементы в порядке отображения, например `Шаг А # Шаг Б # Шаг В`.
- `Номера правильных ответов`: правильный порядок как последовательность 1-based позиций
  элементов, например `3,1,2` (правильный порядок: 3-й, 1-й, 2-й элемент).
- **Обратная совместимость:** пустые `Номера правильных ответов` → элементы считаются уже
  перечисленными в правильном порядке.

## 6. Теги, обратная связь (PRD-14 Ф1)

### 6.1 `Теги`

- Разделители — `;` и `,` (любой из двух).
- Нормализация — общая функция `normalizeTags` ([shared/tags.ts](../../../shared/tags.ts)):
  trim, схлопывание пробелов, дедупликация без учёта регистра, длина ≤ `TAG_MAX_LENGTH`.
- Тег с запятой или точкой с запятой внутри не поддерживается (символы трактуются как
  разделители списка).

### 6.2 `Режим ОС` / `ОС при верном` / `ОС при неверном`

- `Режим ОС` = `общая` → используется `Обратная связь`; условные поля игнорируются.
- `Режим ОС` = `условная` → используются `ОС при верном` и `ОС при неверном`; общая
  обратная связь игнорируется.

### 6.4 `Варианты` (PRD-17, только в книге теста)

Фиксированные варианты выдачи (BR-12) — свойство РАЗДЕЛА теста, поэтому колонка `Варианты`
есть только в книге теста (`/workbook/export`/`import`), не в standalone-экспорте банка.

- Значение — **номера вариантов**, в которые входит вопрос (варианты авто-нумерованы по
  позиции, как в редакторе: «Вариант 1/2/3»). Разделители — `;` и `,`. Токен может быть голым
  числом (`1`) или вида `Вариант 1` (берётся первая группа цифр). Пусто = вопрос ни в одном
  варианте. Вопрос может входить в несколько (`1; 3`).
- На импорте по каждой теме раздела различные номера её вопросов образуют варианты секции
  (`form_set_json.forms`): форма N = вопросы, указавшие номер N; формы упорядочены по номеру,
  метка авто = «Вариант N» (неконтиг. номера 1,3 нормализуются в 1,2). Нужно **≥2** вариантов —
  один номер на тему = ошибка строки, секция сохраняется без вариантов.
- На экспорте номер = позиция формы (1-based), порядок возрастающий — round-trip контиг. наборов.
- Раздел в режиме вариантов: контролы выдачи из всей темы (`Вопросов в выборке`/квоты) не
  применяются — выпавший вариант выдаётся целиком (PRD-17 FR-03/FR-04).

## 7. Грамматика «Цена ответа» (PRD-14 Ф1)

Ячейка `Цена ответа` сериализует `questions.scoring_json` (PRD-10, scoring-model §11).
Пустая ячейка или `точное` → `null` (точное совпадение, `0/1`).

### 7.1 `weighted` (только `single`)

- Синтаксис: `веса: w1 # w2 # w3 ...` — по одному весу на вариант, в порядке вариантов.
- Весов меньше числа вариантов → недостающие добиваются нулями.
- Весов больше числа вариантов → ошибка строки.
- Опционально: `; sMax=<число>` (иначе `sMax` выводится как максимум весов).

### 7.2 `tiered` (`multiple` / `matching` / `ranking`)

- Синтаксис: `ступени: <условие>[& <условие>] => <балл>; ...`.
- Разделитель ступеней — `;` и `,` (любой из двух); условия внутри ступени — через `&`.
- Условие: `<correct|wrong> <оператор> <правая часть>`, где
  - `correct` — число верно выбранных единиц, `wrong` — число ошибочно выбранных;
  - оператор — `==`, `>=`, `<=`, `<`, `>`;
  - правая часть — число или ключевое слово `total` (всего верных в вопросе).
  - Пример: `ступени: correct == total & wrong == 0 => 2; correct >= 1 & wrong <= 1 => 1`.
  - Совместимость: старые односимвольные токены `c` (верных) / `x` (неверных) /
    `T`/`P`/`N` (всего) по-прежнему принимаются при импорте; экспорт пишет
    `correct`/`wrong`/`total`.
- Балл — неотрицательное число; **десятичный разделитель — точка** (`1.5`). Запятая
  зарезервирована как разделитель списка и десятичной не является.
- Первая сработавшая ступень определяет балл; иначе `0`.
- Опционально: `sMax=<число>` (иначе `sMax` выводится как максимум баллов ступеней).

Значение валидируется схемой `questionScoringSchema`; несоответствие режима типу вопроса
или невалидная грамматика → ошибка строки (запись пропускается).

## 8. Идентификация и дедупликация

- **Обновление по `ID`:** если `ID` задан и вопрос найден — выполняется обновление (включая
  смену темы и типа); если не найден — создаётся новый вопрос.
- **`contentHash`** = SHA-256 от `type + prompt + нормализованные данные ответа`;
  пересчитывается при каждой записи.
- **Дедупликация при создании (без `ID`):** если в той же теме уже есть вопрос с таким
  `contentHash` — запись пропускается (`skipped`). Дубликаты внутри одного файла также
  отсекаются.

---

## 9. Модель ошибок

- Импорт возвращает агрегат `{ created, updated, skipped, errors[] }`.
- Ошибки — построчные, в формате `Строка N: причина`; невалидная строка пропускается,
  обработка продолжается (best-effort).
- Типичные причины: не указана тема; неизвестный тип; пустой текст; меньше двух вариантов;
  некорректные номера правильных ответов; невалидная «Цена ответа».

---

## 10. Экспорт

- Колонки экспорта совпадают с контрактом; `ID` стоит первым столбцом.
- Сортировка строк — по имени темы (локаль `ru`).
- Фильтры выгрузки: все вопросы / выбранные темы (`topicIds`) / все темы теста (`testId`).
- Имя файла: `questions_<дата>.xlsx` или `questions_<тест>_<дата>.xlsx`.
- Экспорт и импорт должны быть **взаимно обратимы** (round-trip): файл, полученный
  экспортом, при импорте воспроизводит те же вопросы без потерь (целевое требование
  PRD-14; для `matching`/`ranking` достигается после Ф0, для тегов/ОС/цены ответа — после Ф1).

## 11. Инструменты (PRD-14 Ф2)

- **Шаблон:** `GET /api/questions/template` — книга с листом «Вопросы» (только
  канонические заголовки §3) и листом «Справка» (формат по каждой колонке/типу).

### 12.2 Лист `Шкалы`

`Ключ` (`^[a-z][a-z0-9_]{0,63}$`, уникум/тест) · `Название` · `Описание` · `Тип`
(`number`/`boolean`/`category`/`level`) · `Агрегация` (`sum`/`avg`/`weighted_avg`/`max`/`min`) ·
`Нормализация` (`none`/`percent`/`custom`) · `Направление` (`positive`/`inverse`) ·
`Диапазоны` · `Границы шкалы` · `Предел показа` · `Благоприятное направление` ·
`Показывать ученику` (`нет`/`уровень`/`уровень и значение`) ·
`SCORM` (`none`/`suspend_data`/`interaction`/`both`).

- `Диапазоны` (для `category`/`level`) — грамматика `min..max код «подпись»`; разделители
  диапазонов — `;` и `,`; подпись опциональна (по умолчанию = код); границы включительно
  `[min, max]`; применяются к сырому (агрегированному) значению, побеждает первый подходящий.
  Пример: `0..16 low «Низкий»; 17..26 mid «Средний»; 27..54 high «Высокий»`. Пусто — без диапазонов.
  Код уровня ОБЯЗАТЕЛЕН и не может содержать `«»`: он идентифицирует уровень (формулы, LMS,
  сохранение толкования при загрузке), и без запрета подпись занимала его место.
- `Границы шкалы` — домен парой в одной ячейке, `мин..макс`. Пусто — домен берётся из охвата
  уровней. Пара пишется целиком: ноль — законная граница, поэтому «не задано» нельзя выразить
  значением. `Предел показа` — число (PRD-46 §6), до которого тянется полный луч диаграммы;
  пусто — до максимума домена. `Благоприятное направление` — `Чем больше, тем лучше` /
  `Чем больше, тем хуже` / `Без оценки` (по умолчанию); значения не меняет, а задаёт его
  прочтение (НЕ путать с `Направление`, которое переворачивает значение при подсчёте).
- Колонки, которых в книге НЕТ, загрузка не трогает: толкование уровней (текст, тональность,
  вложения PRD-29/PRD-32) переживает круг «выгрузил → загрузил» и сшивается по коду уровня.
  Пустая ячейка ЕСТЬ значение — она очищает поле; отсутствующая колонка не значит ничего, и
  книги прежнего формата поэтому читаются без потерь.

### 12.3 Лист `Показатели`

`Имя` (`^[a-z][a-z0-9_]{0,63}$`, уникум/тест) · `Метка` · `Тип` (`boolean`/`number`/`string`) ·
`Формула` (DSL PRD-2) · `Показывать ученику` (`нет`/`уровень`/`уровень и значение`) · `SCORM`
(`interaction`/`suspend_data`/`both`/`none`) · `Управляет статусом` (`none`/`success`/`completion`;
не более одного `success` и одного `completion` на тест).

Формула валидируется серверным `validateResultVariableFormula`; невалидная → ошибка строки.

### 12.4 Лист `Вклады вопросов`

`Вопрос` (значение `ID` или `Ключ строки`) · `Шкала` (`Ключ` шкалы) · `Источник`
(`вопрос`/`вариант`/`пара`/`позиция` → `question`/`option`/`matching_pair`/`ranking_position`) ·
`Ключ источника` (**0-based** индекс варианта / `лево:право` для пары / `элемент:позиция` для
позиции, согласно движку шкал; для `вопрос` — пусто) ·
`Значение` (число; 0 и отрицательные валидны) · `Вес` (число, по умолчанию 1).

- `Ключ источника` валидируется против типа вопроса и числа вариантов/пар/позиций.
- `conditionJson` (условный вклад) в контракт НЕ входит (решение 2026-06-10): по PRD-5
  заморожен и движком шкал не используется. Добавим, когда PRD-5 разморозит условные вклады.

### 12.5 Локальный `Ключ строки` и порядок

- `Ключ строки` на листе `Вопросы` — алиас в пределах книги (не хранится в БД), позволяет
  `Вклады вопросовм` сослаться на вновь создаваемый вопрос.
- Порядок: `Вопросы` → `Шкалы` → `Вклады вопросов` + `Показатели` → `Структура` + `Квоты`
  → `Пороги вариантов`; ссылки (теги/темы/варианты) резолвятся после записи целей. Экспорт
  теста проставляет `Ключ строки` для round-trip и выгружает листы `Структура`/`Квоты`/
  `Пороги вариантов`.

### 12.6 Лист `Структура` (PRD-14 FR-16)

Описывает разделы теста (одна строка = один раздел). Импорт листа `Структура` **заменяет
разделы теста целиком**. Режим потока лист НЕ задаёт: сценарий прохождения приходит с листа
`Настройки` (PRD-48 FR-05, FR-06), а его отсутствие означает «Линейный». Когда сценарий —
«Через страницу-маршрутизатор», системную страницу-маршрутизатор материализует
`testSettingsService`.

`Раздел` (имя темы; должна существовать в банке или присутствовать на листе `Вопросы`) ·
`Порядок` (целое; пусто = порядок строк) · `Вопросов в выборке` (`draw_count`, целое ≥ 1) ·
`Тип порога` (`Сумма баллов` → `absolute` / `Процент` → `percent` / `Нет` → не проверять /
`Как у теста`/пусто → наследовать / `По вариантам` → порог на каждый вариант, §12.8) ·
`Порог` (число для `absolute`/`percent`; пусто для `По вариантам`) ·
`Обязательный` (да/нет, по умолчанию да) ·
`Обратная связь при непройденном уровне` (`adaptive_topic_settings.failure_feedback`; пусто =
оставить как есть, прочерк `-` = стереть).

- `Обратная связь при непройденном уровне` живёт ЗДЕСЬ, а не на листе `Адаптивные уровни`:
  значение одно на ТЕМУ, а `Структура` — единственный лист, у которого ровно одна строка на
  тему. Применяется только вместе со строками уровней темы на листе `Адаптивные уровни`:
  текст хранится строкой `adaptive_topic_settings`, а её пишет тот же payload, что и уровни
  (§12.13). Книга без листа уровней — и книга, не назвавшая уровней этой темы, — текст не
  применяет и предупреждает об этом.
- Пустая ячейка ОСТАВЛЯЕТ прежний текст темы, а не стирает его: `adaptiveSettings`
  переписывает настройки тем целиком, и без этого правила книга прежнего формата (колонки у
  неё нет вовсе) молча удаляла бы тексты. Чтобы стереть текст книгой, ставят в ячейке один
  прочерк — `-`, `–` или `—`. Это единственный «стиратель» листа `Структура`: остальные его
  колонки принадлежат самой строке раздела, а разделы книга переписывает целиком.
- Порог типа `Сумма баллов` сравнивается с **градуированной суммой баллов** раздела
  (`Цена ответа`, PRD-10), не с числом вопросов — точно по правилам начисления.
- Тема раздела резолвится по имени (нормализация регистра/пробелов).

### 12.7 Лист `Квоты` (PRD-11)

Квоты выдачи по тегам для разделов листа `Структура` (одна строка = одна страта
`DrawStratum`). Отсутствие квот у раздела = равномерная выдача.

`Раздел` (имя темы, как на листе `Структура`) · `Тег` (подтема; нормализация §3a PRD-11) ·
`Количество` (`count`, целое ≥ 1) · `Режим` (`Ровно` → `exact`, по умолчанию / `Не менее` → `min`).

- На каждый раздел `Σ Количество ≤ «Вопросов в выборке»` (иначе ошибка строки).
- Квота для раздела, отсутствующего на листе `Структура`, — ошибка.
- Семантика выдачи — `shared/draw/blueprint.ts` (PRD-11 §5): `exact` — ровно `count`,
  `min` — не менее; остаток выборки добирается случайно из вопросов без `exact`-тегов.

### 12.8 Лист `Пороги вариантов` (PRD-24)

Пороги прохождения на каждый вариант темы, для разделов листа `Структура` с типом порога
`По вариантам` (одна строка = один вариант раздела). Отсутствие листа = правил по
вариантам в книге нет.

`Раздел` (имя темы, как на листе `Структура`) · `Вариант` (НОМЕР варианта, 1-based — та же
нумерация, что в колонке `Варианты` листа `Вопросы`, §6.4) · `Тип порога` (`Процент` →
`percent` / `Сумма баллов` → `absolute`) · `Порог` (число).

- Типы у вариантов одного раздела могут различаться.
- Лист читается ПОСЛЕ сборки набора вариантов раздела (иначе номер не к чему привязать):
  порядок в книге — `Вопросы` → `Шкалы` → `Вклады вопросов` + `Показатели` →
  `Структура` + `Квоты` → `Пороги вариантов`.
- Номер варианта, отсутствующий среди объявленных для темы на листе `Вопросы`, — ошибка
  строки (остальные строки импортируются).
- Раздел с типом порога `По вариантам`, у которого покрыты не все варианты, — ошибка
  раздела: книга не должна обходить валидацию редактора.
- Порог типа `Сумма баллов` сравнивается с градуированной суммой баллов (PRD-10), как и на
  листе `Структура`; ограничение — достижимый максимум баллов ИМЕННО ЭТОГО варианта.

### 12.9 Лист `Обратная связь` (PRD-48 FR-12)

Обратная связь ВЛАДЕЛЬЦА — теста (`tests.feedback_json`) или раздела
(`test_sections.feedback_json`); у обоих она одной формы. Одна строка = один владелец.

`Кому` (`Тест` / `Раздел`) · `Раздел` (имя темы для `Кому` = `Раздел`; для `Кому` = `Тест`
ячейка ПУСТАЯ) · `Формат` (`Простой` → `plain` / `Форматированный` → `richText` / `HTML` →
`html`; словарь общий с вводными текстами листа `Настройки`) · `Текст`.

Правила применения:

- листа НЕТ в книге — обратная связь не меняется НИ У КОГО (ни у теста, ни у разделов);
- владелец, названный на листе, получает обратную связь ЦЕЛИКОМ из книги: текст и формат из
  своей строки, курсы/материалы/мероприятия — из строк листа `Рекомендации` с тем же
  владельцем. Названный без рекомендаций остаётся БЕЗ них: рекомендации — ветвь его обратной
  связи, и «нет строк» здесь означает «нет рекомендаций», а не «не трогать»;
- владелец, НЕ названный на листе, не меняется вовсе. Это же правило защищает книгу прежнего
  формата: книга со `Структурой` без листа `Обратная связь` переписывает разделы, но их
  обратную связь сохраняет — иначе перенос структуры молча стирал бы тексты;
- пустой `Текст` при отсутствии рекомендаций означает «обратной связи нет»: владельцу
  пишется `null`, а не пустая структура. Это единственный способ стереть текст книгой;
- владелец, названный дважды, применяется ПОСЛЕДНИМ вхождением; рекомендации при этом
  накапливаются по всем его строкам (они ключуются владельцем, а не строкой);
- имя темы нормализуется как на листе `Структура` (регистр, пробелы);
- раздел можно назвать только вместе с листом `Структура`: без него разделы теста не
  переписываются, и обратной связи некуда попасть — такая строка ошибка. Раздел, которого нет
  на листе `Структура`, — тоже ошибка строки (иначе текст ушёл бы в пустоту);
- заполненная ячейка `Раздел` при `Кому` = `Тест` — ошибка строки, а не молча отброшенное
  значение: скопированная и не очищенная ячейка — ровно та опечатка, ради которой колонки и
  разведены;
- колонка `Кому` до PRD-48 Э4 называлась `Уровень`. Старое имя принимается при загрузке
  наравне с новым (как `Тема` вместо `Раздел`), значения не менялись. Переименование
  понадобилось, когда владельцем стал и адаптивный УРОВЕНЬ: «Уровень = Уровень» не называет
  ничего.

Почему владелец и раздел — ДВЕ колонки, а не одна колонка «Владелец»: тема с названием
`Тест` в банке существует, и зарезервированное слово в общей колонке молча увело бы её
обратную связь на уровень всего теста.

Экспорт пишет лист ВСЕГДА — у теста без обратной связи одними заголовками; строка выгружается
только для владельца, у которого есть текст или рекомендации.

### 12.10 Лист `Рекомендации` (PRD-48 FR-13)

Курсы, материалы и мероприятия, приложенные к обратной связи (`links` / `assets` / `events`
внутри `feedback_json` владельца). Одна строка = одна рекомендация.

`Кому` (`Тест` / `Раздел` / `Уровень`; читается как на листе `Обратная связь`, включая старое
имя колонки `Уровень`) · `Раздел` (имя темы; для `Кому` = `Тест` пусто) · `Номер уровня`
(целое ≥ 1 для `Кому` = `Уровень`, для остальных владельцев ПУСТО) · `Тип` (`Курс` →
`links` / `Материал` → `assets` / `Мероприятие` → `events`) · `Заголовок` · `Ссылка`.

- **Третий владелец — адаптивный УРОВЕНЬ** (PRD-48 FR-16), и он несимметричен двум другим:
  адресуется парой `Раздел` + `Номер уровня`; подчинён листу `Адаптивные уровни`, а не листу
  `Обратная связь` (строка про уровень, которого нет на листе уровней, — ошибка строки); и
  принимает ТОЛЬКО тип `Курс` — материал уровня (`adaptive_level_links`) состоит из
  заголовка и ссылки, класть `Материал`/`Мероприятие` уровню некуда. Своей строки на листе
  `Обратная связь` уровень не имеет: его текст живёт на листе `Адаптивные уровни`, у которого
  нет колонки формата.
- Лист ПОДЧИНЁН листу `Обратная связь` так же, как `Квоты` подчинены `Структуре`:
  рекомендации физически лежат ВНУТРИ `feedback_json` владельца, поэтому владельца, которого
  нет на листе `Обратная связь`, у рекомендации быть не может. Строка с таким владельцем —
  ошибка строки; лист `Рекомендации` без листа `Обратная связь` отвергается целиком.
- Строгость `Ссылка` различается по типу и выравниванию не подлежит: у курса адрес обязателен
  и проверяется; у мероприятия может быть пустым (у встречи может не быть страницы записи); у
  материала необязателен и НЕ валидируется (техдолг PRD-42 §7: легаси-описатели хранят там
  относительный адрес медиатеки, и строгая проверка отвергла бы любой тест с таким).
- Строка без `Заголовок` отвергается: заголовок требует `feedbackContentSchema`, и выгрузка
  такую запись тоже не пишет.
- Файлы по ссылкам не переносятся: книга везёт адрес, а не файл (решение PRD-14, §5 PRD-48).
  Служебные поля старых описателей (`id`, `fileName`, `mimeType`, `scormHref`) книга тоже не
  несёт — как и редактор, который сбрасывает их при каждом сохранении.
- **Отсутствие листа `Рекомендации` НЕ равно «не трогать».** Владелец, названный на листе
  `Обратная связь`, берёт свою обратную связь ЦЕЛИКОМ из книги, поэтому книга с листом
  `Обратная связь` и без листа `Рекомендации` очищает курсы, материалы и мероприятия всех
  названных владельцев. Импорт предупреждает об этом (`warnings`), но не отказывает: это
  правило «названный — целиком», а не ошибка. Правя опечатку в тексте, оставляйте лист
  `Рекомендации` в файле.

### 12.11 Лист `Страницы` (PRD-48 FR-14)

Страницы теста (`content_pages`): стартовая, вопросная, маршрутизатор, вводные и итоговые
страницы разделов, экран итогов и авторские страницы. Одна строка = одна страница.

`Зона` (`До теста` → `before` / `После теста` → `after` / `До темы` → `before_topic` /
`После темы` → `after_topic`) · `Раздел` (имя темы для зон темы; для зон теста ячейка
ПУСТАЯ) · `Вид` (`Стартовая` → `start` / `Вопросы` → `questions` / `Маршрутизатор` →
`router` / `Введение раздела` → `intro` / `Обзор` → `review` / `Итоги раздела` →
`section-results` / `Итоги` → `results` / `Авторская` → `info`) · `Номер` (порядковый номер
внутри своей зоны, с 1) · `Вариант` (`template_key` — ключ варианта шаблона оформления) ·
`Режим` (`Шаблон` → `template` / `Стандартный` → `standard` / `HTML` → `html`) ·
`Автопереход` (да/нет) · `Задержка, мс` (целое; про пустую ячейку — в правилах ниже).

**Адрес страницы синтетический**, и другого у неё нет: `id` — uuid, локальный стенду;
`sort_order` по контракту НЕ уникален; `settings_json.sequenceId` (PRD-22) намеренно ОБЩИЙ
у группы страниц — это метка последовательности, а не идентификатор строки. Поэтому строку
адресует четвёрка «зона + раздел + вид + номер», а номер считается внутри ЗОНЫ, сразу по
всем видам: зона — единица, которую импорт заменяет для авторских страниц, значит внутри
неё нумерация и обязана быть устойчивой.

Зона и раздел разведены двумя колонками по той же причине, что владелец и раздел на листе
`Обратная связь`: тема с названием `До теста` в банке существует, и зарезервированное слово
в общей колонке молча увело бы её страницы на уровень всего теста.

Правила применения:

- листа НЕТ в книге — страницы не меняются вовсе (так читаются все книги, выгруженные до
  появления этих листов);
- **из девяти видов авторский ровно один — `Авторская`.** Остальные материализует
  `testSettingsService` по сценарию прохождения и составу тем, и книга может только НАЙТИ
  такую строку (по паре «вид + тема») и обновить её вариант, режим, автопереход и поля.
  Системная страница, которой в тесте нет, — ошибка строки: почти всегда это значит, что
  книга и приёмник разошлись сценарием или составом разделов, и выдуманная страница скрыла
  бы расхождение;
- **авторские страницы названной зоны заменяются набором из книги ЦЕЛИКОМ.** Ключа у них
  нет, поэтому единственная предсказуемая идемпотентность — «зона, названная в книге,
  выглядит как в книге». Набор может быть пустым: так книга очищает зону;
- зону называет ЛЮБАЯ строка с её адресом, включая строку СИСТЕМНОЙ страницы. Книга,
  подрезанная руками (строку `Итоги` оставили, свои страницы той же зоны убрали), тем самым
  удаляет авторские страницы приёмника. Импорт предупреждает об этом (`warnings`, зона и
  число удаляемых страниц), но не отказывает: очистка зоны книгой должна оставаться
  возможной;
- зона, не названная ни одной строкой, не трогается;
- пустая ячейка `Вариант`, `Режим`, `Автопереход` или `Задержка, мс` означает «оставить как
  есть» у страницы, которая в тесте УЖЕ есть. У авторской страницы, которую книга создаёт,
  оставлять нечего, поэтому пустая ячейка даёт значение по умолчанию: без варианта, режим
  `Шаблон`, без автоперехода и без задержки. Вариант, которого нет в шаблоне оформления
  приёмника, — ошибка строки: страница, привязанная к несуществующему варианту, не рисуется;
- шаблон оформления теста, который не разрешается вовсе, — ошибка листа: манифест варианта
  единственное, что типизирует и очищает значения полей, и без него не применяется ничего;
- лист читается ПОСЛЕДНИМ, после `Настроек` (сценарий) и `Структуры` (темы): набор
  системных строк зависит от обоих, а тему страницы иначе не к чему привязать;
- страница переносится без `id`, поэтому ссылки на страницу по идентификатору (например
  `retakePolicyJson.blockedPageId`) книга не везёт — это вне охвата PRD-48 (§5).

### 12.12 Лист `Поля страниц` (PRD-48 FR-15)

Содержимое (`values_json.values`) и настройки (`settings_json`) страницы. Одна строка = одно
поле.

`Зона` · `Раздел` · `Вид` · `Номер` (адрес страницы, теми же значениями, что на листе
`Страницы`) · `Куда` (`Содержание` → `values_json` / `Настройка` → `settings_json`) ·
`Ключ` (ключ поля из манифеста варианта) · `Значение`.

- Лист ПОДЧИНЁН листу `Страницы` так же, как `Квоты` подчинены `Структуре`: значение поля
  физически лежит НА странице, поэтому строка с адресом, которого нет на листе `Страницы`, —
  ошибка строки, а лист `Поля страниц` без листа `Страницы` отвергается целиком.
- Пустой `Номер` означает «страница этого вида в этой зоне». Если таких страниц несколько —
  ошибка строки с просьбой указать номер, а не догадка: первая попавшаяся страница почти
  наверняка не та.
- **Значения СЛИВАЮТСЯ поверх текущих:** ключ, которого книга не назвала, у страницы
  сохраняется. Сливает сам импорт — сохранение страницы заменяет `values_json` целиком.
- Значение проходит ТУ ЖЕ нормализацию и тот же санитайзер, что и сохранение из редактора
  страниц (`server/services/content-page-fields.ts`). Иначе книга была бы входом в обход
  санитайзера.
- Ключ, которого вариант не объявляет, не применяется, и импорт об этом предупреждает:
  незаявленный ключ не проходит санитайзер вообще, а книга приезжает с чужого стенда.
- Пустая ячейка `Значение` — это пустая строка, а не «оставить как есть»: строка существует
  только потому, что автор её написал. Чтобы оставить поле как есть, строку удаляют.
- Скаляр едет своим литералом (`5`, `true`), структурное значение (на практике — placeholder
  `resultField`) — компактным JSON и разбирается обратно в объект.
- `values_json.placeholderStyles` книга не везёт: авторский кегль выживает, только если
  вариант его разрешил (`textFit.allowAuthorFontSize`), то есть это свойство варианта, а не
  переносимое содержимое.
- **Круг по НАСТРОЙКАМ не замкнут между стендами с разными версиями шаблона:** ключ,
  которого вариант приёмника не объявляет, теряется, а значение `select` вне списка
  отбрасывается. Книга переносит настройки страницы ровно в объёме полей, ОБЩИХ у двух
  вариантов.

### 12.13 Лист `Адаптивные уровни` (PRD-48 FR-16)

Уровни адаптивных тем (`adaptive_levels`). Одна строка = один уровень.

`Раздел` (имя темы; принимается старое написание `Тема`) · `Номер` (`level_index` + 1, см.
ниже; пусто = следующий свободный номер внутри темы) · `Название` (`level_name`; пусто =
`Уровень N` по номеру) ·
`Сложность от` / `Сложность до` (`min_difficulty` / `max_difficulty`, целые 0..100, «от» ≤
«до») · `Вопросов` (`questions_count`, целое ≥ 1) · `Тип порога` (`Процент` → `percent` /
`Сумма баллов` → `absolute`; пусто = `percent`) · `Порог` (`pass_threshold`, целое ≥ 0) ·
`Обратная связь` (`feedback`, простой текст; пусто = нет обратной связи).

- **`Номер` считается с 1, а `level_index` — с 0.** Книга говорит нумерацией автора («первый
  уровень» — это №1), модель хранит индекс массива. Пересчёт живёт в одном модуле
  (`server/utils/workbook-adaptive.ts`): разбор вычитает единицу, выгрузка прибавляет. Ошибка
  на единицу, сделанная дважды, взаимно гасится на круге и проявляется только на стенде.
- **`Обратная связь` — простой текст, колонки формата нет:** `adaptive_levels.feedback` —
  колонка `text` без соседнего поля формата. Поэтому же обратная связь уровня описывается
  ЗДЕСЬ, а не на листе `Обратная связь`, где формат спрашивают: там уровню пришлось бы
  обещать выбор, который негде хранить.
- Уровень принадлежит ТЕМЕ, но действует только для тем, входящих в тест. Тема, которой нет
  на листе `Структура`, — ошибка строки (как у страниц, §12.11): уровень такой темы негде
  прочитать.
- Повторный `Номер` внутри одной темы — ошибка строки, а не молчаливая перезапись: номер —
  половина адреса уровня, и проигравший уровень исчез бы без единого слова.
- Пустое `Название` — не ошибка: уровень получает `Уровень N` по своему номеру, то же
  умолчание, что и уровень, добавленный кнопкой в редакторе. Редактор имя уровня не проверяет
  и сохраняет уровень без него, а книга не может быть строже редактора (PRD-48 §9); если бы
  такой уровень был у темы единственным, отказ строки отменял бы ВЕСЬ `save` — вместе с
  настройками, структурой, обратной связью и страницами.
- **Материалы уровня едут листом `Рекомендации`** (`Кому` = `Уровень`, §12.10), а
  `Обратная связь при непройденном уровне` темы — колонкой листа `Структура` (§12.6): это
  значение одно на тему, а `Структура` — лист с одной строкой на тему.
- **Уровни сохраняются ОДНИМ payload вместе с разделами.** `testSettingsService.save`
  принимает их как `adaptiveSettings` того же вызова, что и `sections` — отдельной записи
  уровней нет. Отсюда два следствия: применить уровни без листа `Структура` нельзя, и лист
  `Адаптивные уровни` без строк данных уровни НЕ стирает (как и пустая `Структура` не стирает
  разделы) — иначе шаблон и выгрузка теста без уровней очищали бы приёмник.
- **Запись темы делается, только если книга назвала её уровни.** `adaptiveSettings`
  переписывает настройки тем целиком, поэтому запись с пустым списком уровней означает не
  «у темы только текст», а «у темы уровней нет» — лестница темы была бы удалена. Тот же путь
  открывался бы для темы, все строки уровней которой отвалились ошибкой (например, опечаткой
  в `Тип порога`): проверка «адаптивный раздел без уровней» читает режим из ПРИСЛАННОГО
  payload, поэтому книга без листа `Настройки` её не включает и молча ничего бы не сказала.
  Тема без строк уровней, у которой заполнена `Обратная связь при непройденном уровне`, даёт
  предупреждение — текст ехать не с чем.
- Книга без листа `Адаптивные уровни` адаптивные настройки не трогает вовсе.
- Побочный, но важный итог: книга адаптивного теста заработала. Лист `Настройки` несёт
  «Режим теста = Адаптивный», а адаптивный режим требует уровня у КАЖДОГО раздела
  (`flow-policy-validator`, правило `adaptive_section_no_levels`). До появления этого листа
  такая книга упиралась в проверку; теперь уровни приезжают вместе со структурой.
