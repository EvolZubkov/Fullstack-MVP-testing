## 1. Назначение

Документ фиксирует контракт файла Excel для массового экспорта и импорта банка вопросов:
набор колонок, форматы значений по типам вопросов, разделители, правила идентификации
и обновления, модель ошибок. Это единый источник истины для авторского формата.

Каждая колонка помечена статусом:

- **Текущий** — реализовано и работает в боевом коде.
- **PRD-14 Ф0** — нормализация поведения без изменения контракта (исправление дефектов);
  реализовано 2026-06-10.
- **PRD-14 Ф1** — расширение контракта (новые колонки/грамматики); реализовано 2026-06-10.

---

## 2. Общие правила

- Данные читаются из **первого листа** книги; заголовки — в строке 1, записи — со строки 2.
  Мультилистовой формат (вопросы + шкалы + показатели на разных вкладках) — следующий этап
  PRD-14, в текущем контракте не используется.
- Пустые строки пропускаются. Лишние колонки игнорируются.
- Значения ячеек приводятся к строке и обрезаются по краям; неразрывные пробелы и BOM
  (` `, `​`, `﻿`) нормализуются.
- **Пустая ячейка против отсутствия колонки** (правило обновления по `ID`):
  - колонка **отсутствует** в файле → поле НЕ изменяется (сохраняется текущее значение);
  - колонка **присутствует, но пустая** → поле сбрасывается к значению по умолчанию.
- Заголовки регистронезависимы по теме; для ряда колонок приняты алиасы (см. §4).

## 5. Форматы значений по типам

Разделитель вариантов — `#` (приоритетный) либо `|` (запасной при импорте). Нумерация
правильных ответов — **1-based** (с единицы).

### 5.1 `multiple_choice` (одиночный выбор, `single`)

- `Тексты вариантов ответа`: `A # B # C` (минимум 2 варианта).
- `Номера правильных ответов`: один номер, например `2`.

### 5.2 `multiple_response` (множественный выбор, `multiple`)

- `Тексты вариантов ответа`: `A # B # C # D`.
- `Номера правильных ответов`: список, например `1,3` (разделители `, . пробел`).

### 5.3 `matching` (сопоставление)

**Текущее поведение (дефект, исправляется в Ф0):** импорт игнорирует
`Номера правильных ответов`, требует равное число элементов слева и справа и навязывает
позиционное соответствие `i ↔ i`. Round-trip с экспортом не работает.

**Целевой формат (PRD-14 Ф0):**

- `Тексты вариантов ответа`: левый список, затем разделитель сторон `||`, затем правый
  список. Пример: `Кошка # Собака # Рыба || Мяу # Гав # Буль # Кваква`.
  Правый список может быть длиннее левого (дистракторы).
- `Номера правильных ответов`: пары `левый-правый` (1-based), например `1-1, 2-2, 3-3`.
- **Обратная совместимость:** если разделителя `||` нет — применяется старый разбор
  (чередование `лево # право # лево # право`, позиционное соответствие, без дистракторов).

### 5.4 `ranking` (ранжирование)

**Текущее поведение (дефект, исправляется в Ф0):** импорт игнорирует
`Номера правильных ответов` и всегда считает, что элементы перечислены в правильном порядке.

**Целевой формат (PRD-14 Ф0):**

- `Тексты вариантов ответа`: элементы в порядке отображения, например `Шаг А # Шаг Б # Шаг В`.
- `Номера правильных ответов`: правильный порядок как последовательность 1-based позиций
  элементов, например `3,1,2` (правильный порядок: 3-й, 1-й, 2-й элемент).
- **Обратная совместимость:** пустые `Номера правильных ответов` → элементы считаются уже
  перечисленными в правильном порядке.

## 6. Теги, обратная связь (PRD-14 Ф1)

### 6.1 `Теги`

- Разделители — `;` и `,` (любой из двух).
- Нормализация — общая функция `normalizeTags` ([shared/tags.ts](../../../shared/tags.ts)):
  trim, схлопывание пробелов, дедупликация без учёта регистра, длина ≤ `TAG_MAX_LENGTH`.
- Тег с запятой или точкой с запятой внутри не поддерживается (символы трактуются как
  разделители списка).

### 6.2 `Режим ОС` / `ОС при верном` / `ОС при неверном`

- `Режим ОС` = `общая` → используется `Обратная связь`; условные поля игнорируются.
- `Режим ОС` = `условная` → используются `ОС при верном` и `ОС при неверном`; общая
  обратная связь игнорируется.

## 7. Грамматика «Цена ответа» (PRD-14 Ф1)

Ячейка `Цена ответа` сериализует `questions.scoring_json` (PRD-10, scoring-model §11).
Пустая ячейка или `точное` → `null` (точное совпадение, `0/1`).

### 7.1 `weighted` (только `single`)

- Синтаксис: `веса: w1 # w2 # w3 ...` — по одному весу на вариант, в порядке вариантов.
- Весов меньше числа вариантов → недостающие добиваются нулями.
- Весов больше числа вариантов → ошибка строки.
- Опционально: `; sMax=<число>` (иначе `sMax` выводится как максимум весов).

### 7.2 `tiered` (`multiple` / `matching` / `ranking`)

- Синтаксис: `ступени: <условие>[& <условие>] => <балл>; ...`.
- Разделитель ступеней — `;` и `,` (любой из двух); условия внутри ступени — через `&`.
- Условие: `<correct|wrong> <оператор> <правая часть>`, где
  - `correct` — число верно выбранных единиц, `wrong` — число ошибочно выбранных;
  - оператор — `==`, `>=`, `<=`, `<`, `>`;
  - правая часть — число или ключевое слово `total` (всего верных в вопросе).
  - Пример: `ступени: correct == total & wrong == 0 => 2; correct >= 1 & wrong <= 1 => 1`.
  - Совместимость: старые односимвольные токены `c` (верных) / `x` (неверных) /
    `T`/`P`/`N` (всего) по-прежнему принимаются при импорте; экспорт пишет
    `correct`/`wrong`/`total`.
- Балл — неотрицательное число; **десятичный разделитель — точка** (`1.5`). Запятая
  зарезервирована как разделитель списка и десятичной не является.
- Первая сработавшая ступень определяет балл; иначе `0`.
- Опционально: `sMax=<число>` (иначе `sMax` выводится как максимум баллов ступеней).

Значение валидируется схемой `questionScoringSchema`; несоответствие режима типу вопроса
или невалидная грамматика → ошибка строки (запись пропускается).

## 8. Идентификация и дедупликация

- **Обновление по `ID`:** если `ID` задан и вопрос найден — выполняется обновление (включая
  смену темы и типа); если не найден — создаётся новый вопрос.
- **`contentHash`** = SHA-256 от `type + prompt + нормализованные данные ответа`;
  пересчитывается при каждой записи.
- **Дедупликация при создании (без `ID`):** если в той же теме уже есть вопрос с таким
  `contentHash` — запись пропускается (`skipped`). Дубликаты внутри одного файла также
  отсекаются.

---

## 9. Модель ошибок

- Импорт возвращает агрегат `{ created, updated, skipped, errors[] }`.
- Ошибки — построчные, в формате `Строка N: причина`; невалидная строка пропускается,
  обработка продолжается (best-effort).
- Типичные причины: не указана тема; неизвестный тип; пустой текст; меньше двух вариантов;
  некорректные номера правильных ответов; невалидная «Цена ответа».

---

## 10. Экспорт

- Колонки экспорта совпадают с контрактом; `ID` стоит первым столбцом.
- Сортировка строк — по имени темы (локаль `ru`).
- Фильтры выгрузки: все вопросы / выбранные темы (`topicIds`) / все темы теста (`testId`).
- Имя файла: `questions_<дата>.xlsx` или `questions_<тест>_<дата>.xlsx`.
- Экспорт и импорт должны быть **взаимно обратимы** (round-trip): файл, полученный
  экспортом, при импорте воспроизводит те же вопросы без потерь (целевое требование
  PRD-14; для `matching`/`ranking` достигается после Ф0, для тегов/ОС/цены ответа — после Ф1).

## 11. Инструменты (PRD-14 Ф2)

- **Шаблон:** `GET /api/questions/template` — книга с листом «Вопросы» (только
  канонические заголовки §3) и листом «Справка» (формат по каждой колонке/типу).
- **Предпросмотр (dry-run):** `POST /api/questions/import?dryRun=true` — валидация и

  создаются, вопросы не пишутся). Запись — обычным `POST /api/questions/import`.

## 12. Мультилистовой формат (PRD-14 FR-15)

**Статус:** бэкенд реализован 2026-06-10 (эндпоинты `POST/GET /api/tests/:id/workbook/import|export`,
парсеры/сериализаторы листов, тесты зелёные); листы `Структура`/`Квоты` (FR-16: разделы +
квоты выдачи + порог в баллах + поток `router_by_topics`) добавлены 2026-06-11. Файл .xlsx
описывает ОДИН тест (выбирается при импорте); шкалы, показатели, измерения и структура —
test-scoped, лист `Вопросы` — глобальный.

### 12.1 Листы (распознавание по имени)

| Лист | Назначение | Идентификация (upsert) |
| --- | --- | --- |
| `Вопросы` | Банк вопросов (как §3, Ф0-2) + опц. колонка `Ключ строки` | `ID` (см. §8) |
| `Структура` | Разделы теста: тема, выборка, порог, обязательность (FR-16) | заменяет разделы теста целиком |
| `Квоты` | Квоты выдачи по тегам (PRD-11) для разделов листа `Структура` | по разделу + тегу |
| `Шкалы` | Шкалы теста (PRD-5) | (тест, `Ключ`) |
| `Показатели` | Показатели результата теста (PRD-2) | (тест, `Имя`) |
| `Вклады вопросов` | Вклады «вопрос × шкала» (PRD-5) | (тест, вопрос, шкала, `Источник`, `Ключ источника`) |

### 12.2 Лист `Шкалы`

`Ключ` (`^[a-z][a-z0-9_]{0,63}$`, уникум/тест) · `Название` · `Описание` · `Тип`
(`number`/`boolean`/`category`/`level`) · `Агрегация` (`sum`/`avg`/`weighted_avg`/`max`/`min`) ·
`Нормализация` (`none`/`percent`/`custom`) · `Направление` (`positive`/`inverse`) ·
`Диапазоны` · `Показывать ученику` (да/нет) · `SCORM` (`none`/`suspend_data`/`interaction`/`both`).

- `Диапазоны` (для `category`/`level`) — грамматика `min..max код «подпись»`; разделители
  диапазонов — `;` и `,`; подпись опциональна (по умолчанию = код); границы включительно
  `[min, max]`; применяются к сырому (агрегированному) значению, побеждает первый подходящий.
  Пример: `0..16 low «Низкий»; 17..26 mid «Средний»; 27..54 high «Высокий»`. Пусто — без диапазонов.

### 12.3 Лист `Показатели`

`Имя` (`^[a-z][a-z0-9_]{0,63}$`, уникум/тест) · `Метка` · `Тип` (`boolean`/`number`/`string`) ·
`Формула` (DSL PRD-2) · `Показывать ученику` (да/нет) · `SCORM`
(`interaction`/`suspend_data`/`both`/`none`) · `Управляет статусом` (`none`/`success`/`completion`;
не более одного `success` и одного `completion` на тест).

Формула валидируется серверным `validateResultVariableFormula`; невалидная → ошибка строки.

### 12.4 Лист `Вклады вопросов`

`Вопрос` (значение `ID` или `Ключ строки`) · `Шкала` (`Ключ` шкалы) · `Источник`
(`вопрос`/`вариант`/`пара`/`позиция` → `question`/`option`/`matching_pair`/`ranking_position`) ·
`Ключ источника` (**0-based** индекс варианта / `лево:право` для пары / `элемент:позиция` для
позиции, согласно движку шкал; для `вопрос` — пусто) ·
`Значение` (число; 0 и отрицательные валидны) · `Вес` (число, по умолчанию 1).

- `Ключ источника` валидируется против типа вопроса и числа вариантов/пар/позиций.
- `conditionJson` (условный вклад) в контракт НЕ входит (решение 2026-06-10): по PRD-5
  заморожен и движком шкал не используется. Добавим, когда PRD-5 разморозит условные вклады.

### 12.5 Локальный `Ключ строки` и порядок

- `Ключ строки` на листе `Вопросы` — алиас в пределах книги (не хранится в БД), позволяет
  `Вклады вопросовм` сослаться на вновь создаваемый вопрос.
- Порядок: `Вопросы` → `Шкалы` → `Вклады вопросов` + `Показатели` → `Структура` + `Квоты`;
  ссылки (теги/темы) резолвятся после записи целей. Экспорт теста проставляет `Ключ строки`
  для round-trip и выгружает листы `Структура`/`Квоты`.

### 12.6 Лист `Структура` (PRD-14 FR-16)

Описывает разделы теста (одна строка = один раздел). Импорт листа `Структура` **заменяет
разделы теста целиком** и фиксирует режим потока `router_by_topics` (со страницей-маршрутизатором);
системную страницу-маршрутизатор материализует `testSettingsService`.

`Раздел` (имя темы; должна существовать в банке или присутствовать на листе `Вопросы`) ·
`Порядок` (целое; пусто = порядок строк) · `Вопросов в выборке` (`draw_count`, целое ≥ 1) ·
`Тип порога` (`Сумма баллов` → `absolute` / `Процент` → `percent` / `Нет` → не проверять /
`Как у теста`/пусто → наследовать) · `Порог` (число для `absolute`/`percent`) ·
`Обязательный` (да/нет, по умолчанию да).

- Порог типа `Сумма баллов` сравнивается с **градуированной суммой баллов** раздела
  (`Цена ответа`, PRD-10), не с числом вопросов — точно по правилам начисления.
- Тема раздела резолвится по имени (нормализация регистра/пробелов).

### 12.7 Лист `Квоты` (PRD-11)

Квоты выдачи по тегам для разделов листа `Структура` (одна строка = одна страта
`DrawStratum`). Отсутствие квот у раздела = равномерная выдача.

`Раздел` (имя темы, как на листе `Структура`) · `Тег` (подтема; нормализация §3a PRD-11) ·
`Количество` (`count`, целое ≥ 1) · `Режим` (`Ровно` → `exact`, по умолчанию / `Не менее` → `min`).
