# PRD-39: Слияние карточек сопоставления вместо стрелки

**Версия:** 1.0

**Статус:** требования согласованы 2026-08-04, реализация не начата

**Связанные документы:** [PRD-12](../prd-12/web-runtime-parity.md),
[спецификация ревизии «Стандартного» шаблона](../spec-standard-template-uikit-revision.md)

**Зависимости:** PRD-12 (единый рендеринг вопроса на обоих хостах — правка меняет один общий
рендерер и автоматически действует в вебе и в SCORM-пакете)

## 1. Обзор

### 1.1 Контекст

Вопрос типа «сопоставление» (`ou-match`) сегодня соединяет пару карточек пунктирной стрелкой
в зазоре между колонками, которая становится сплошной и акцентной при соединении. Разметку
печатает один общий рендерер — `renderMatching` в
[`shared/template/question-interaction.ts`](../../../shared/template/question-interaction.ts) —
используемый и вебом, и SCORM-пакетом (`server/scorm/template/app/render/questions/matching.js`
лишь делегирует в него через `TBTemplate.renderMatching`).

Дизайн-система (`vendor/ui-kit/css/university-rt.css` → `client/src/styles/vendor/university-rt.css`)
уже полностью реализует альтернативный визуальный режим зазора — `ou-match--gap-narrow`: стрелка
скрыта, при соединении обе карточки и зазор между ними красятся одинаково и визуально сливаются
в одну панель, шов помечен волнистой SVG-линией (`ou-match__seam`). Эталонная разметка этого
режима уже есть в `vendor/ui-kit/src/components/Matching.tsx` — компоненте общего назначения,
который в самом приложении не используется (реальный рендер идёт через framework-free
`question-interaction.ts`). Общий рендерер этот режим не задействует — печатает только
`ou-match--gap-wide` и SVG стрелки.

При исследовании обнаружена смежная нестыковка: правила DS для акцентной заливки «залипшего»
(`is-connected`) состояния исключают строки проверки (review) по классам
`ou-match__row--correct` / `ou-match__row--incorrect` — эти классы существуют только в
неиспользуемом `Matching.tsx`. Реальная разметка приложения помечает такие строки классами
`correct-answer` / `incorrect-answer` (общая конвенция вида-вопроса, см. `theme.css`). Правило
исключения DS из-за этого никогда не срабатывает, и по специфичности акцентная заливка
перебивает зелёный/красный цвет вердикта. Для стрелочного режима это уже частично обойдено —
`server/scorm/templates/default/styles/theme.css` (строка ~585) вручную перекрашивает только
левую фиксированную карточку правильными классами. Режим слияния красит уже ОБЕ карточки и
зазор/шов — без такой же поправки итог проверки на слитой панели будет закрашен неверно.

### 1.2 Цель

Заменить визуальный режим соединения пары в вопросе-сопоставлении со стрелки на слияние в единую
панель — во всех шаблонах, использующих общий рендерер (встроенный «Стандартный», Certification,
любой загруженный внешний шаблон).

### 1.3 Метрики успеха

- В зазоре между колонками сопоставления нет стрелки ни в одном состоянии.
- При соединении пары обе карточки и зазор между ними визуально читаются как одна панель со
  швом-перфорацией; при разъединении — как две отдельные карточки с узким зазором.
- На экране проверки (review) слитая панель правильной пары зелёная, неправильной — красная;
  акцентная заливка «просто соединено» на review-строки не протекает.
- Эффект идентичен на вебе и в SCORM-пакете (общий рендерер, без ветвления по хосту).

## 2. Решение

### 2.1 Общий рендерер (`shared/template/question-interaction.ts`)

В `renderMatching`:

- класс корня меняется с `ou-match--gap-wide` на `ou-match--gap-narrow`;
- разметка `.ou-match__gap` вместо `<svg class="ou-match__gap-arrow">` печатает
  `<svg class="ou-match__seam" viewBox="0 0 6 48" preserveAspectRatio="none">` с той же геометрией
  волнистого пути, что уже в `Matching.tsx` (`M3 0 Q0 4 3 8 Q6 12 3 16 …`); стрелку эмитить не
  нужно — в narrow-режиме DS всегда прячет её (`display:none`), печатать мёртвую разметку смысла
  нет;
- комментарий над блоком, описывающий стрелочную логику, переписывается под новое поведение.

Это единственное место, определяющее визуальный режим — правка меняет поведение сразу на обоих
хостах.

### 2.2 Зазор между колонками (`theme.css` обоих встроенных шаблонов)

`server/scorm/templates/default/styles/theme.css` и `templates/certification/styles/theme.css`
переопределяют `--ou-match-gap-w: var(--ou-space-6)` (24px, подобрано под стрелку). Переопределение
убирается — действует встроенный узкий зазор DS для narrow-режима (8px): карточки вплотную, шов
между ними.

(`uploads/templates/certification/…` — рантайм-копия загруженного шаблона, не отслеживается git;
правка не касается этого пути.)

### 2.3 Цвет строки на экране проверки (theme.css обоих встроенных шаблонов)

Правило-образец уже существует (`theme.css`, «After a pair connects, the DS tints only the RIGHT
card + the arrow…», использует реальные классы `:not(.correct-answer):not(.incorrect-answer)`).
По той же схеме добавляются правила, которые для narrow-режима:

- исключают review-строки (`.correct-answer`, `.incorrect-answer`) из общего акцентного
  окрашивания обеих карточек панели (`.ou-match__card`) и зазора (`.ou-match__gap`) в
  «залипшем» состоянии — аналогично уже существующей поправке для фиксированной карточки;
- гарантируют, что зелёный/красный вердикт (уже задаваемый существующими правилами
  `.ou-match__row.correct-answer …` / `.ou-match__row.incorrect-answer …`) виден на всей слитой
  панели, включая сегмент зазора/шва, а не только на перетаскиваемой карточке.

## 3. Проверка

Приёмка через Playwright (dev-сборка, оба встроенных шаблона):

- прохождение вопроса-сопоставления: соединение и разъединение пары — стрелки нет, при
  соединении панель читается как единое целое со швом;
- экран проверки: правильная пара — зелёная слитая панель, неправильная — красная, без
  лилового акцента поверх вердикта;
- сверка в тёмной и светлой теме, если шаблон их поддерживает.

## 4. Вне рамок

- Изменение цвета/формы шва, иконки на карточке или логики самого drag-and-drop — не меняются.
- Режим `ou-match--gap-wide` в самой DS (`vendor/ui-kit`) не удаляется: это компонент общего
  назначения, стрелочный режим может понадобиться другому потребителю DS.
