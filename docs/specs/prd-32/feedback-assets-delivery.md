# PRD-32. Доставка вложений обратной связи

Статус: необходимость зафиксирована 2026-08-01, требования не собирались, форма решения не
согласована. Документ фиксирует ПРОБЛЕМУ и известные факты, чтобы работа не потерялась; к
проектированию не приступали.

## 1. Повод

Автор может приложить PDF к обратной связи — по теме, по уровню шкалы, по исходу показателя.
Редактор показывает файл в списке и позволяет его сохранить. **Ученик не увидит этот файл
никогда, а сам файл нигде не сохранится.**

Это не деградация и не регресс: загрузка вложений не была реализована с самого начала.
Редактор обратной связи говорит об этом прямо в собственной шапке
(`client/src/features/tests/editor/sections/feedback-editor-modal.tsx`): «список PDF-вложений
— только на клиенте, интеграция загрузки на сервер поставляется отдельно». При сохранении
файл выбрасывается: в модель уходит только дескриптор — название, имя файла, тип.

Вскрыто при реализации PRD-29: это первая работа, которая пытается показать вложения ученику,
и она упёрлась в то, что показывать нечего.

## 2. Что известно на сегодня

| Звено | Состояние |
| --- | --- |
| Выбор файла в редакторе | Работает, файл живёт в памяти вкладки |
| Сохранение | Дескриптор сохраняется, файл выбрасывается |
| Хранение файла | Отсутствует: ни на диске, ни в базе |
| Адрес для выдачи (`scormHref` в дескрипторе) | Поле объявлено в схеме, заполнять некому |
| Раздача на вебе | Маршрута нет |
| Упаковка в SCORM-пакет | Сборщик медиа (`server/scorm/builders/media-assets.ts`) про обратную связь не знает |
| Отрисовка ученику | Готова (PRD-29): вложение без адреса ОТБРАСЫВАЕТСЯ, мёртвая ссылка не рисуется |

Практическое следствие: подсекция «Материалы» сводного блока рекомендаций пуста и в вебе, и в
пакете. Паритет хостов не нарушен — пусто одинаково.

## 3. Почему это стоит закрыть

Сегодня интерфейс обещает автору то, чего не делает. Человек прикладывает памятку к уровню
выгорания, сохраняет тест и обоснованно считает, что ученик её получит. Молчаливая потеря
файла хуже отсутствия кнопки.

Ближайшая обходная дорога — класть материалы ССЫЛКОЙ в подсекцию «Пройти обучение»: ссылки
работают на обоих хостах. До закрытия этого PRD стоит либо убрать вложения из редактора,
либо явно пометить их как нерабочие.

## 4. Что предстоит решить

Требования не собирались; ниже — вопросы, с которых начинать.

| Вопрос | Почему важен |
| --- | --- |
| Где хранится файл: рядом с медиа вопросов (`uploads/media/`) или в своём хранилище | Определяет модель данных и права доступа |
| Кто имеет право скачать файл на вебе | Обратная связь видна ученику, но файл не должен раздаваться публично по угадываемому адресу |
| Как вложение попадает в ZIP и чем заполняется адрес при экспорте | Пакет автономен: файл обязан лежать внутри, а адрес быть относительным |
| Что происходит с вложением при публикации снимка (PRD-15) | Опубликованная версия неизменна, значит вложение нельзя подменить задним числом |
| Ограничения: размер, число файлов, только ли PDF | Сегодня проверка размера живёт только в редакторе и ни на что не влияет |
| Что с уже сохранёнными дескрипторами без файлов | В базе есть записи о файлах, которых никогда не было |

## 5. Связанные работы

- PRD-29 — потребитель: отрисовка вложений в сводном блоке рекомендаций готова и ждёт данных.
- PRD-15 — снимки публикации: вложение опубликованной версии обязано быть неизменным.
- Будущий PRD медиатеки — вынесен из PRD-14: реестр медиа, дедупликация по контрольной сумме,
  защита раздачи `/uploads`. Хранение вложений обратной связи логично решать вместе с ним, а
  не отдельным механизмом.
