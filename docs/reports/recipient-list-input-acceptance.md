## 5. Что найдено попутно и НЕ входило в охват

1. **Диалог рецензирования показывает поля назначения.** «Срок выполнения» и «Создать группу из списка»
   видны на вкладке «Списком», но прогон рецензирования их не отправляет вовсе (`review/invite` знает только
   срок жизни ссылки). Автор заполняет поля, которые ничего не делают. Расхождение существует с первой
   редакции общей вкладки. ИСПРАВЛЕНО 2026-09-11 — см. раздел 7.
2. **Утверждённый эскиз `prd52-invite-dialog.html` беднее реальной вкладки:** в его состоянии «списком» нет
   ни сроков, ни имени группы, ни кнопки «Проверить список» — они нарисованы только в эскизе PRD-28.
   ЗАКРЫТО 2026-09-11 приведением эскиза к реальному виду — см. раздел 7.
3. **Кнопки `Dark`/`Compact` в эскизе PRD-52 не работали** — `toggleTheme is not defined`. Починено в этой
   же ветке: без этого тёмную тему на эскизе было не посмотреть.
4. **Статус «уже назначен» в предпросмотре рецензирования** считается по назначениям теста, а не по грантам
   рецензирования (PRD-52 раздел 14.3). На приёмке не всплыл: все адреса были новыми.

## 7. Доделка 2026-09-11 по итогам разбора находок

Владелец решил: находку 1 (поля назначения в диалоге рецензирования) — исправить, находку 2 (эскиз беднее
реальности) — закрыть приведением эскиза к реальному виду.

### 7.1 Что исправлено в диалоге

Убраны из режима рецензирования — на вкладках «Пользователи», «Группы» и «Списком»:

- «Срок выполнения» — приглашение рецензента этого поля не отправляет;
- «Создать группу из списка» — группа создаётся вместе с назначением, которого здесь нет.

Переписаны подписи режима: «Приглашено» вместо «Назначено», «К приглашённым» вместо «К назначениям»,
«Все пользователи уже приглашены» вместо «…уже назначены», «Доступ выдан, ссылка выпущена…» вместо
«Назначение создано, …». Поле «Ссылка активна до» осталось: оно работает в обоих режимах.

Спека: PRD-52 раздел 14.4 (FR-36, FR-37). Тесты: три новых в
`client/src/features/tests/assign/__tests__/bulk-invite-tab.test.tsx` и два в
`client/src/components/__tests__/assign-test-dialog.test.tsx`; прогон — 43 теста трёх файлов зелёные.
Проверено в браузере: `real-review-bulk-fixed.png`, `real-review-report.png`.

### 7.2 Как пересобран эскиз

`docs/wireframes/approved/prd52-invite-dialog.html` собран из СНИМКОВ реального DOM работающего диалога:
шесть состояний (приглашены, пользователи, списком, списком с набранным списком, предпросмотр, отчёт).
Данные прогона заменены демонстрационными, идентификаторы разведены по состояниям, значение поля адресов
возвращено содержимым тега, а правила, которые ДС вставляет на лету (ширины колонок таблицы), внесены
отдельным блоком — иначе снимок потерял бы их вместе с рантаймом.

Скрипт сборки — `scripts/docs/build-prd52-wireframe.mjs`, порядок пересборки описан в его шапке: снять
снимки состояний (`document.querySelector('.ou-modal').outerHTML`) и правила динамического листа со
селекторами вида `.ou-tbl-cell-*`, затем запустить скрипт из корня репозитория.

Эскиз подключает таблицу стилей ДС оттуда же, откуда её берёт приложение
(`/client/src/styles/vendor/skillum-ds.css`). Копия в `docs/wireframes/ds/` отстала на ~42 КБ — в ней нет
раскладочных правил (`ou-stack--gap-*`, `ou-text--*`), и на ней снимок реального DOM разъезжается по
отступам и выравниванию. По этой же причине `npm run check:wireframes:ds` показывает на файле «unknown DS
class» для классов, которые в боевой таблице есть: словарь линтера собран по отставшей копии. Обновление
общей копии в охват не входило — её читают полсотни эскизов.

### 7.3 Вкладка «Группы» убрана из рецензирования

Решение владельца 2026-09-11: групп в рецензировании не нужно. Вкладка убрана из режима (PRD-52 раздел 14.5,
FR-38); у назначения теста она осталась без изменений. Два теста в
`client/src/components/__tests__/assign-test-dialog.test.tsx` держат обе стороны: в рецензировании вкладки
нет, в обычном режиме есть. Раздел 3.3 спеки приведён в соответствие — вкладок три.

### 7.4 Копия ДС для эскизов обновлена

`docs/wireframes/ds/skillum-ds.css` перезалит из боевой таблицы (`client/src/styles/vendor/skillum-ds.css`):
копия отставала на ~42 КБ и не имела раскладочных правил `ou-stack--gap-*`, `ou-text--*`. Находок «unknown DS
class» по эскизу PRD-52 стало 11 вместо 40; оставшиеся — артефакты снимка живого DOM: классы, которые ДС
генерирует на лету (`ou-tbl-cell-*`, они описаны прямо в файле эскиза, но линтер не читает его собственный
`<style>`), и модификаторы по умолчанию без собственных правил (`ou-field--default`, `ou-textarea--m`).

ВАЖНАЯ НАХОДКА при обновлении: в копии для эскизов жили стили компонента `ChoiceCard` (50 строк), которых в
боевой таблице ДС НЕТ вовсе, хотя сам компонент в ките есть (`vendor/ui-kit/src/components/ChoiceCard.tsx`).
В приложении он не используется, а в эскизе `prd7-tests-list.html` — используется, поэтому блок сохранён в
конце копии под комментарием «только для эскизов». Место этих правил — в самой ДС; пока их там нет, копия
перестала быть простым дублем.

Проверено: `prd7-tests-list.html` в состоянии «Удалить: с тестами» рисует карточки выбора как прежде
(`spot-choicecard.png`).
