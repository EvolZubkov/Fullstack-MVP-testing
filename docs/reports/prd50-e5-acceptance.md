# PRD-50: приёмка этапа Э5 в браузере

Дата: 2026-08-15. Ствол `main`, стенд `PORT=8098 npm run dev`, dev-БД с миграциями
`0019` — `0021`.

Э5 (FR-48) печатает сводный разрез по области теста на экране итогов адаптивного теста и в
его отчёте. Записи для адаптивной попытки считались и хранились ещё с «Э1-доделки»
(FR-17/FR-39) — до этого этапа их никто не читал обратно.

## Заодно перепроверены Э3 и Э4

Прогон теста «Сертификационный тест для руководителей» (`89e2a5e9`) через отладочный
проигрыватель повторён на коде с Э5: 43 вопроса отвечено, 5 пропущено, итог 33 %,
«Не пройден». Всё, что принято [протоколом Э3/Э4](prd50-e3-e4-acceptance.md), на месте:

- два блока разделов с заголовком `h4.tb-topic-group__title` и счётчиком в авторском
  формате — «зачтено 3 из 4» и «зачтено 0 из 4»;
- плашки тем печатают авторские «Зачтено» / «Не зачтено» с классами `is-pass` / `is-fail`;
- настройка «И там, и там» даёт оба места: вложенные полосы в четырёх карточках тем знаний
  (3 + 3 + 2 + 3 строки) и сводный блок «Разрез результата» из 11 строк — по одной на тег
  теста, значения 36 / 0 / 20 / 50 / 0 / 40 / 30 / 29 / 33 / 50 / 0 %;
- отчёт (PDF, 5 страниц) печатает то же: страница 2 — блок «Знания» со счётчиком и полосами
  внутри карточек, страница 3 — сводный блок с теми же одиннадцатью значениями.

Регрессии Э5 не внёс.

## Что проверено по Э5

Прогнать адаптивный тест до итогов на этом стенде НЕ УДАЛОСЬ — см. «Помеха» ниже. Поэтому
печать проверена прямым монтированием ОТГРУЖАЕМОЙ раскладки: в окне проигрывателя взяты
`state.templateLayouts['results.adaptive']` и `['report.adaptive']` — те самые файлы, что
лежат в собранном пакете, — и в них смонтирован контекст, построенный общим ядром
(`TBTemplate.buildAdaptiveResultContext` / `buildAdaptiveReportContext`).

Вход: адаптивный результат с одной темой (уровень «Базовый») и тремя записями области теста —
«Нормирование» 75 %, «Прогнозирование» 25 %, «Бенчмаркинг» 50 %.

### 1. Экран итогов, «Сводным блоком по тесту»

Подблоки экрана: `topics`, `breakdown` — разрез последним, как объявляет манифест.
Подзаголовки: «По темам», «Разрез результата». Один блок `.tb-breakdown`, три строки,
ширины полос `75%` / `25%` / `50%`, числа «75 %» / «25 %» / «50 %».

Вложенных полос в карточке уровня НЕТ (`.tb-topic__breakdown` — ноль). Это и есть решение
этапа: карточка адаптивной темы говорит подтверждённым уровнем.

### 2. Экран итогов, «В карточках тем»

Не печатается ничего: ни подблока, ни узла. Ровно то ограничение режима, о котором говорит
подсказка поля «Где показывать подытоги» — выбор автора не подменяется значением «блоком».

### 3. Экран итогов без настройки показа

Подблок один — `topics`. Контекст адаптивного экрана остаётся прежним, как у теста,
собранного до PRD-50.

### 4. Отчёт адаптивного теста

С включённым блоком: карточка `.tb-report__breakdown--block` одна, заголовки —
«Результаты по темам» и «Разрез результата», три строки с теми же числами. Без настройки —
карточки нет и заголовка нет. Документ показывает ровно то же, что экран (§5.2).

## Помеха: адаптивные тесты стенда непроходимы

Ни один адаптивный тест dev-БД не удалось довести до экрана итогов, и обе причины —
в данных стенда, а не в коде:

- «PRD-48 приёмка Э4 A» (`3542edef`): после первого же перехода уровень печатает
  «Вопрос 1 из 0» — под диапазон сложности уровня в теме нет ни одного вопроса, лестница
  встаёт;
- «Тест для HRBP Управление численностью» (`64b716d5`): прогон встаёт на «Вопрос 3 из 6»,
  таймер темы досчитывает до 0:00, экран не меняется.

Оба наблюдения — материал для отдельного разбора, к PRD-50 они отношения не имеют.

## Что НЕ проверено

- **Сквозной прогон адаптивного теста в браузере** — по причине выше. Проводка хостов
  закрыта модульными проверками на каждом шве: контекст ядра, веб-адаптер
  (`buildAdaptiveResultContext` / `buildAdaptiveReportInput`), исходники рантайма пакета
  (`adaptiveRender.js`, `pdfExport.js`, `app.js`), раскладки и манифесты обоих шаблонов.
- **PDF адаптивного отчёта** как файл — проверена сборка контекста и печать раскладки,
  но не растеризация.

## Следы, оставленные приёмкой

Настройка показа подытогов временно включалась у двух адаптивных тестов и снята обратно
в `NULL` прямым запросом: PUT `/api/tests/:id` очистить поле не может — маршрут переводит
`null` в «не трогать» (`breakdownDisplayJson ?? undefined`). Следы теста `89e2a5e9`
описаны в протоколе Э3/Э4 и не менялись.
