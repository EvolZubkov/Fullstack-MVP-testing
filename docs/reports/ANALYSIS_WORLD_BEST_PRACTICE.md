**Дата:** 2026-08-01

## 1. Оговорки, без которых документ вводит в заблуждение

1. **Записка составлена по публичным материалам стандартов и обзорным публикациям.** Полные тексты
   спецификаций (QTI 3.0, Standards for Educational and Psychological Testing, руководства ITC) не
   читались целиком. Всё ниже — карта территории, а не выписка из первоисточника.
2. **«Эталон» здесь — практика профессионального измерения**: сертификационные экзамены,
   лицензирование, вступительные испытания, психодиагностика. Это НЕ то же самое, что практика
   корпоративного электронного обучения, откуда взяты все шесть рассмотренных конкурентов.
   Планка отрасли заметно выше рыночной.
3. **Копировать эталон целиком нельзя и не нужно.** Значительная его часть предполагает штатного
   психометрика, нормативные выборки и бюджеты экзаменационных центров. Раздел
   [§10](#10-что-из-эталона-применимо-к-skillум) отделяет применимое от неприменимого.
4. Skill'Ум по своей нише (аттестация, сертификация, измерительные методики) ближе к этому
   эталону, чем к рынку квизов, — поэтому сравнение вообще имеет смысл.

## 3. Ось 1. Стандарты обмена и доставки

| Стандарт | Назначение | Skill'Ум |
| --- | --- | --- |
| **QTI 3.0** (2022) | Обмен САМИМИ заданиями и тестами между системами; вобрал APIP (доступность) | **Нет.** Наш обмен — книга Excel собственного формата |
| **SCORM 2004** | Упаковка учебного объекта для LMS, передача итога | + (4th Edition) |
| **SCORM 1.2** | Legacy, но всё ещё самый распространённый профиль в корпоративных LMS | Нет |
| **xAPI (Tin Can)** | Детальные события обучения в LRS, вне рамок «курс в LMS» | Нет |
| **cmi5** | Профиль xAPI, закрывающий разрыв «SCORM умеет запуск, xAPI умеет данные» — считается преемником SCORM | Нет |
| **LTI 1.3** | Встраивание внешнего инструмента в LMS как приложения, а не как пакета | Нет |
| **AICC** | Legacy, доживает | Нет |

**Что здесь считается хорошей практикой.** Разделять два разных обмена: *контент* (QTI — задания
переносимы между системами) и *данные о прохождении* (xAPI/cmi5 — результаты собираются в LRS
независимо от того, где играл контент). SCORM смешивает то и другое и ограничивает и первое,
и второе.

**Где мы.** Один формат доставки и ни одного формата обмена заданиями. Это самое узкое место
по этой оси: контент заказчика к нам можно только перепечатать, а от нас — только вручную.

Отраслевой перечень задаёт не вендор, а QTI. Ниже — взаимодействия по категориям (перечень

| Категория | Взаимодействие | Механика | Skill'Ум |

| Основные | Order | Упорядочение элементов | + |

| Основные | Match | Сопоставление пар | + |
| Основные | Hottext | Выделение фрагмента в тексте | - |
| Основные | Gap Match | Перетаскивание в пропуски текста | - |
| Основные | Slider | Выбор значения движком | +/- (шкала градациями, не непрерывный движок) |
| Основные | Extended Text | Развёрнутый текстовый ответ | - |
| Основные | File Upload | Загрузка файла как ответа | - |
| Встроенные | Inline Choice | Выпадающий список внутри текста | - |
| Встроенные | Text Entry | Ввод строки в текст | - |
| Графические | Hotspot | Клик по области изображения | - |

| Графические | Graphic Associate | Связывание объектов на изображении | - |
| Графические | Graphic Gap | Перетаскивание объектов в области изображения | - |
| Графические | Select Point | Указание точки на изображении | - |
| Расширяемые | **Portable Custom Interaction (PCI)** | Собственное взаимодействие, переносимое между системами | **Концептуально есть** |

**Главное наблюдение по этой оси, и оно не про количество.** Эталон не меряет продукт числом
типов. Он требует двух вещей: **покрытия классов взаимодействия** (выбор, порядок, связывание,
текстовый ввод, графика) и **расширяемости** — механизма PCI, позволяющего добавить своё
взаимодействие, не ломая переносимость.

Второе у нас в некотором виде есть: платформа шаблонов оформления (PRD-3/PRD-12/PRD-22) —
это ровно идея выносимого наружу представления. Первое покрыто на треть: класс «выбор»,
«порядок» и «связывание» закрыты, «текстовый ввод» и «графика» — пусты целиком.

Это уточняет вывод из [сравнения с iSpring](./ANALYSIS_WEBTUTOR_ISPRING.md): недостающие механики
там названы верно, но их следует читать не как «догнать вендора», а как **два незакрытых класса
взаимодействия из пяти**.

## 5. Ось 3. Банк заданий и сборка теста

| Практика | Что это | Skill'Ум |
| --- | --- | --- |
| Метаданные задания | Тема, подтема, уровень, когнитивный уровень, статистика, статус жизненного цикла | +/- (тема, теги, сложность; статистики и статуса нет) |
| Спецификация теста (blueprint) | Формальный план: сколько заданий из каждой области и какого уровня | + (квоты по тегам — это она и есть) |
| Автоматизированная сборка (ATA) | Сборка формы под спецификацию с ограничениями | +/- (квоты + фиксированные варианты) |
| Параллельные формы | Несколько эквивалентных вариантов теста | + (PRD-17), но **эквивалентность не доказывается** |
| Контроль экспозиции заданий | Ограничение частоты показа задания (randomesque, Sympson-Hetter и др.) | - |
| **LOFT** | Каждому — своя линейная форма, собранная на лету из банка | +/- (наша случайная выдача по квотам — это упрощённый LOFT) |
| **MST** | Многоступенчатый адаптивный тест: адаптация блоками, а не заданиями | - |
| **CAT** | Адаптация на уровне задания по модели IRT | +/- (наш адаптив уровневый, по диапазонам сложности, не по IRT) |
| Жизненный цикл задания | Черновик, обзор, пилот, боевое, изъято | - |

**Что считается хорошей практикой.** Выбирать дизайн под цель, а не по моде: для решения
«сдал/не сдал» фиксированная форма или LOFT эффективнее адаптивного теста; для отнесения к
нескольким категориям разумен MST; и только когда нужна надёжность по всему диапазону шкалы,
оправдан полноценный CAT.

**Где мы.** По этой оси мы неожиданно близко к эталону: квоты по тегам — это спецификация теста,
фиксированные варианты — параллельные формы, случайная выдача по квотам — упрощённый LOFT. Двух
вещей не хватает принципиально: **контроля экспозиции** (задание может выпадать всем подряд) и
**доказательства эквивалентности форм** — пороги по вариантам (PRD-24) обходят проблему
административно, но не измеряют её. Оба пробела разобраны ниже.

### 5.1 Экспозиция заданий: почему в пакете нельзя и что можно вместо

**Что теряется.** Экспозиция — доля испытуемых, увидевших задание. Чем она выше, тем вероятнее
утечка содержания, после которой задание измеряет не подготовку, а доступ к утечке. Величина
считается заранее и без всяких данных: доля примерно равна `drawCount / размер страты`. Банк 40 при
выдаче 20 — задание видит примерно каждый второй; банк 25 при той же выдаче — 80%, и банк выработан
с первого потока. Сегодня система это знает и молчит.

**Почему классические методы в пакете невозможны.** Контроль экспозиции по определению опирается
на ОБЩИЙ счётчик по всей популяции. Автономный SCORM-пакет не знает ничего за пределами текущего
запуска у текущего человека: межпользовательского хранилища в стандарте нет, `adl.data` даёт корзину
в пределах одной регистрации (и, по нашим наблюдениям, WebTutor её не хранит), а телеметрия
опциональна и по замыслу отключаема. Поэтому Sympson-Hetter и родственные вероятностные фильтры,
а также вывод «горячего» задания из оборота на лету неприменимы **по устройству модели**, а не по
сложности реализации.

**Куда переезжает рычаг.** На этап сборки пакета и на дисциплину его переиздания. Доступные меры,
по возрастанию усилий:

| Мера | Требует данных | Суть |
| --- | --- | --- |
| Предупреждение об ожидаемой экспозиции | Нет | Показать автору арифметику при настройке выдачи и на экспорте: «ожидаемая экспозиция 80%, банк выработается за один поток» |
| Равномерное распределение вариантов | Нет | Вместо случайного выбора — детерминированный по идентификатору обучающегося из LMS. Устраняет перекос случайности при малом числе вариантов и вырожденную ротацию в пакете, где история попыток недоступна |
| Запекание показателя экспозиции в пакет | Да | Накопленная экспозиция каждого задания уезжает в пакет, рантайм взвешивает ею выбор внутри страты: «горячие» задания выпадают реже. Не контроль в реальном времени, а перенос знания в статическую поправку |
| Окно банка вместо всего банка | Нет | В издание попадает подмножество банка; следующее издание берёт другое окно. Экспозиция размазывается по изданиям, у «остывших» заданий появляется пауза |
| Разные пакеты на потоки и подразделения | Нет | Один тест, разные подмножества банка — отраслевая норма для отдельных проведений |
| Мониторинг постфактум | Да | Там, где телеметрия включена или есть импорт выгрузок из LMS: сигнал «банк выработан, переиздавайте» |

**Оговорки, без которых меры вредны.** Равномерность распределения вариантов — не то же самое, что
снижение экспозиции: она гарантирует, что ни один вариант не выпадает чаще запланированного, но долю
показов не уменьшает. Взвешивание выдачи по экспозиции не должно систематически вымывать лёгкие или
трудные задания — иначе поправка чинит экспозицию и одновременно ломает сопоставимость форм.
И привязывать саму механику к телеметрии нельзя: автономность пакета — наше главное отличие, и
делать её условием корректной работы значит подрывать его же.

**Честная цена модели.** Здесь наше преимущество и наше ограничение — одно свойство. Пакет, живущий
без связи с издателем, не может участвовать в глобальном учёте; облачный конкурент с привязанным
пакетом теоретически может считать экспозицию централизованно. Вывод не «догонять», а называть
вслух: в нашей модели экспозиция управляется **на издании, а не в рантайме**. Так живут бумажные
экзамены и большинство сертификаций — но это требует процесса переиздания, которого у нас пока нет
как понятия.

Зафиксировано требованием BR-26 (Этап 31) в [главном BRD](../specs/brd-scorm-enhancements.md).

### 5.2 Эквивалентность форм: почему пороги по вариантам — обход

Параллельные формы в эталоне дают **сопоставимые баллы**: испытуемый с одной и той же подготовкой
получает один и тот же результат независимо от выпавшей формы. Свойство доказывается — сборкой из
откалиброванного банка по спецификации, статистическим эквивалентированием либо сравнением
распределений трудности.

У нас формы собирает автор вручную либо они получаются случайной выборкой по квотам, и проверки, что
вариант А не легче варианта Б, нет — её нечем сделать: единственная характеристика трудности
экспертная, и даже она между формами не сравнивается.

PRD-24 проблему признал (при разном достижимом максимуме абсолютный порог даёт неравные шансы) и дал
автору задавать свой порог на каждый вариант. Это выравнивает ФОРМАЛЬНОЕ условие сдачи, но не
трудность: пороги ставятся тем же способом, что и сложность заданий, — на глаз. Если вариант
содержательно труднее, снижение его порога есть компенсация вслепую, и проверить её нечем. Расхождение
не исчезает, а перестаёт быть заметным.

**Что значило бы измерять.** Взять пин `formId`, который в попытке уже сохраняется, и сравнить по
вариантам долю сдавших, среднее и разброс баллов при сопоставимом составе испытуемых. Систематически
более низкий результат означает, что вариант труднее, — дальше либо поправка порога по данным, либо
пересборка варианта.

### 5.3 Данные для обеих метрик уже накапливаются

Ни экспозиция, ни эквивалентность форм не требуют новой инфраструктуры сбора: всё нужное пишется
уже сегодня и лежит без употребления.

| Что нужно | Где лежит | Для какой метрики |
| --- | --- | --- |
| Какие задания были выданы в попытке | `attempts.variant_json` | Экспозиция |
| Какой вариант выпал | Пин `formId` в попытке (PRD-24) | Эквивалентность форм |
| Ответы и результаты прохождений в LMS | Телеметрия SCORM (`scorm_attempts`, `scorm_answers`) | Обе |
| То же там, где телеметрия выключена | Импорт обезличенных выгрузок из LMS (BR-26-02) | Обе |
| Неизменность состава, по которому считаем | Снимки публикации (PRD-15) | Обе |

**Не хватает не инфраструктуры, а вычисления и контура управления.** Считать метрику некому, а
показать её и превратить в действие (переиздать пакет, пересобрать вариант, поправить порог) —
негде. Это принципиально более дешёвая работа, чем завести сбор данных с нуля.

**И связка уже предусмотрена документами:** в шапке
[BRD психометрической аналитики](../specs/brd-psychometric-analytics.md) PRD-24 значится источником
данных для отчёта «проходимость по вариантам», а раздел 3.4 того же документа объявляет учёт
экспозиции вторым потребителем того же импорта. То есть оба пробела этой оси закрываются не отдельным
треком, а как СЛЕДСТВИЕ психометрики — что подпирает её приоритет: она даёт не только отчёт для
методиста, но и **обратную связь на уже принятые продуктовые решения** (пороги по вариантам, размер
банка, состав фиксированных вариантов).

## 6. Ось 4. Психометрика

| Практика | Что даёт | Skill'Ум |
| --- | --- | --- |
| Анализ заданий по CTT: трудность, дискриминативность, анализ дистракторов | Понять, какие задания не работают | - (BRD заведён, не начат) |
| Надёжность: альфа Кронбаха, KR-20, стандартная ошибка измерения | Насколько результату можно верить | - |
| IRT (Раш, 2PL, 3PL) | Параметры задания и способность испытуемого на одной шкале; основа CAT и эквивалентирования | - |
| DIF — дифференциальное функционирование задания | Выявить задания, работающие по-разному для групп при равной подготовке | - |
| Эквивалентирование форм (equating) | Сопоставимость баллов между версиями теста | - |
| Установление порога (standard setting): Ангофф, Хофсти, статистическое эквивалентирование | Обоснование проходного балла, а не «70% потому что круглое» | - |
| Валидность и её документирование | Доказательство, что тест измеряет заявленное | - |

**Что считается хорошей практикой.** Проходной балл, установленный волевым решением, —
основной дефект отраслевой практики; эталон требует процедуры. Есть данные, что переход от
гибридного Ангоффа к статистическому эквивалентированию повышает предсказательную валидность.

**Где мы.** Пусто целиком. Это одновременно самый большой разрыв с эталоном и самая большая
возможность: [BRD психометрической аналитики](../specs/brd-psychometric-analytics.md) заведён,
а у конкурентов по этой оси тоже пусто или близко к тому.

---

## 7. Ось 5. Нормирование и интерпретация результата

| Практика | Skill'Ум |
| --- | --- |
| Сырой балл → стандартизованная шкала: z-оценки, T-баллы, стены, стэнайны, процентили | - |
| Нормативная выборка, её описание и срок актуальности | - (понятия нет в модели) |
| Интерпретация уровня и зоны | + (PRD-29: интервалы, исходы, цветовые зоны) |
| Профиль по нескольким шкалам | + (шкалы и вклады), лепестковой диаграммы нет |

**Что считается хорошей практикой.** Для измерительной методики сырой балл не интерпретируем:
«34 балла по шкале эмоционального истощения» ничего не значит без нормы. Эталон требует
преобразования в нормированную шкалу с описанной выборкой норм.

**Где мы.** Это ровно позиция BR-21-05 в BRD, уже названная как требующая решения. Отраслевой
взгляд повышает её вес: без нормирования измерительный контур остаётся неполным, каким бы
удобным ни был экран итогов.

---

## 8. Ось 6. Безопасность и целостность

Руководство ITC различает **четыре режима доставки**, и требования к безопасности зависят от режима:
открытый (без контроля), контролируемый (в удобное время и месте), наблюдаемый (проктор),
управляемый (сертифицированный центр).

| Практика | Skill'Ум |
| --- | --- |
| Выбор режима доставки под ставки теста | - (модель режимов отсутствует) |
| Прокторинг для средних и высоких ставок | - |
| Подтверждающее тестирование после неконтролируемого прохождения | - |
| Рандомизация формы как мера против сговора | + |
| Контроль экспозиции задания | - |
| Аналитика аномалий (data forensics): сговор, подозрительные паттерны ответов и времени | - |
| Аутентификация участника | +/- (учётная запись, ссылка-приглашение; SSO — BR-22) |

**Что считается хорошей практикой.** Для средних и высоких ставок результат, полученный
без наблюдения, подтверждается контролируемым прохождением. Это дешевле сплошного прокторинга
и снимает главный аргумент против дистанционных экзаменов.

---

## 9. Ось 7. Доступность и Ось 8. Искусственный интеллект

### 9.1 Доступность

Отраслевой минимум — **WCAG 2.2 AA**. QTI 3.0 вобрал APIP: описание личных потребностей и
предпочтений участника (увеличенный шрифт, экранный диктор, расширенное время, альтернативный
текст) как часть самого задания, а не настройки платформы.

**Где мы.** Доступность нигде не заявлена как требование и не проверяется приёмкой. Для
образовательного и государственного заказчика это отсекающий критерий не мягче SSO. Судя по
известным особенностям кода (например, не объявленный `.sr-only`), реальное состояние ниже
декларируемого — а декларации и нет.

### 9.2 Искусственный интеллект

Текущее состояние практики, по публикациям 2025 года:

- **Генерация заданий и дистракторов** большими моделями работает и экономит время автора, но
  публикации сходятся на том, что генерации не хватает педагогической рамки, прозрачности и
  контроля качества. Практика — ИИ даёт черновик, человек утверждает.
- **Автоматическая оценка эссе** современными моделями достигает существенного согласия с
  человеком (QWK около 0.68 в исследовании 2025 года), но исследования надёжности фиксируют
  разброс и систематическую строгость моделей; внутренняя согласованность высокая только
  у людей-экспертов.

**Вывод для нас.** ИИ сегодня — не способ закрыть пробел с открытыми заданиями. Он снимает
часть стоимости ручной проверки, но не отменяет проверяющего, и в высоких ставках как
единственный оценщик не применяется.

## 10. Что из эталона применимо к Skill'Ум

Разделение по применимости, а не по привлекательности.

| Практика эталона | Применимость | Обоснование |
| --- | --- | --- |
| **Доступность (WCAG 2.2 AA)** | **Высокая, делать** | Отсекающий критерий для образовательного и государственного заказчика; не требует психометрика; полностью в нашей зоне контроля |
| **Обмен заданиями по QTI 3.0** | **Высокая, делать** | Закрывает вход (забрать банк заказчика) и выход (отсутствие замка); совпадает с найденным пробелом против WebTutor |
| **Психометрика на уровне CTT** (трудность, дискриминативность, дистракторы, надёжность) | **Высокая, делать** | BRD заведён; выполнимо на наших данных без нормативных выборок; у конкурентов пусто |
| **Нормирование результата** (стены, стэнайны, процентили) | **Средняя, решить** | Уже стоит как BR-21-05. Требует нормативной выборки, которой у заказчика может не быть — значит, механизм должен работать и без неё |
| **Контроль экспозиции заданий** | **Средняя** | Дёшево в простом виде (ограничить частоту показа), но без статистики использования смысла имеет мало — идёт после психометрики |
| **Классы взаимодействия: текстовый ввод** | **Средняя** | Один из двух незакрытых классов; автопроверяемо, работает в автономном пакете |
| **Классы взаимодействия: графика** (hotspot и родственные) | **Низкая** | Нужна в производственных и технических отраслях; вне их не востребована |
| **cmi5 и xAPI** | **Средняя** | Правильное направление отрасли, но ценность появляется у заказчика с LRS; SCORM пока покрывает спрос |
| **LTI 1.3** | **Низкая** | Другая модель поставки (инструмент, а не пакет); противоречит нашему главному отличию |
| **IRT, CAT, эквивалентирование форм** | **Низкая для реализации, высокая для понимания** | Требуют психометрика и объёмов данных, которых у корпоративного заказчика нет. Но знать надо: наш «адаптивный режим» — не CAT, и называть его так в материалах нельзя |
| **Установление порога процедурой** (Ангофф и др.) | **Низкая как функция, высокая как методическая позиция** | Реализовывать нечего, но это сильный аргумент в разговоре с методистом заказчика |
| **Режимы доставки ITC и подтверждающее тестирование** | **Средняя** | Дешёвая модель, снимающая часть претензий к отсутствию прокторинга: повторить результат под наблюдением вместо наблюдения за всеми |

## 11. Три вывода

1. **По оси сборки теста мы ближе к эталону, чем к рынку.** Квоты по тегам — это спецификация
   теста, фиксированные варианты — параллельные формы, случайная выдача — упрощённый LOFT.
   Никто из шести конкурентов такого набора не даёт. Это не осознано и никак не предъявлено:
   в наших материалах это «квоты», а в отраслевых терминах — узнаваемые практики.
2. **По оси доказательности мы вне эталона полностью.** Психометрики нет, нормирования нет,
   порог назначается волевым решением, эквивалентность параллельных форм не доказывается.
   Пока это так, продукт делает измерения, качество которых не может подтвердить.
3. **Два пробела — не «функции», а отсутствие языка.** Доступность и обмен по QTI не требуют
   ни психометрика, ни исследований: это работа, целиком лежащая в нашей зоне контроля, и обе
   позиции одновременно закрывают конкурентные разрывы, найденные ранее.
