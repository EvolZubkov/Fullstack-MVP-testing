# Разбор авторской аналитики: что она показывает и чего ей не хватает

Дата: 2026-09-12. Повод: оценка практической значимости инструмента для авторов тестов и
оценщиков. Проверено по коду на `main` (merge `1c86e2ca`).

Документ — вход в ФАЗУ 2 очерёдности работ по аналитике (решение владельца 2026-09-12):
сначала достраивается экспозиция (PRD-55 Э4-Э5), затем улучшение имеющейся аналитики по этому
разбору, и только потом психометрика отдельными PRD.

## 1. Что показывается сегодня

`GET /api/analytics/:testId` (`server/routes/analytics/test-details.ts`) отдаёт:

| Блок | Состав |
| --- | --- |
| `summary` | попытки, уникальные участники, средний балл, доля сдавших, среднее время, завершённые и брошенные |
| `topicStats` | те же величины в разрезе тем |
| `questionStats` | тема, авторская сложность, доля верных, число ответов |
| `levelStats` | статистика уровней, только для адаптивных тестов |
| `scoreDistribution` | гистограмма баллов по попыткам |
| `dailyTrends` | попытки, средний процент и доля сдавших по дням за 30 дней |

Вкладка «Попытки» показывает список прохождений с версией публикации и разбор одной попытки;
у телеметрической попытки в разборе считаются разрезы PRD-50.

## 2. Дефект, обесценивающий остальное

**Страница аналитики теста не видит прохождений из LMS.** `test-details.ts` строит ВСЕ блоки
раздела 1 из одного источника — `attempts`, то есть веб-попыток. Телеметрия SCORM и
импортированные выгрузки (PRD-54) в них не попадают вовсе.

Следствия:

- тест, выданный SCORM-пакетом (основной продуктовый сценарий), показывает на своей странице
  пустую либо частичную картину;
- выгрузки отчётов LMS, которые PRD-54 научился загружать ИМЕННО ради аналитики, на странице
  теста не видны — они видны только в общей аналитике (`/combined`, она читает оба источника);
- любая новая метрика или диаграмма, добавленная на эту страницу, будет считаться по неполным
  данным, поэтому чинить это нужно ПЕРВЫМ.

## 3. Данные, которые копятся и не используются

| Данные | Где лежат | На какой вопрос отвечают |
| --- | --- | --- |
| Время на задание | `scorm_answers.latency_ms`, с 2026-09-12, оба источника | Какое задание тормозит прогон; быстрый ответ на трудное задание — признак утечки ключа |
| Шкалы и показатели прохождения | `scorm_attempts.scales_json`, `variables_json` | Для измерительного теста это ВЕСЬ смысл прохождения. Сейчас опроснику аналитика показывает «средний балл —» и «0% верных», то есть бесполезна |
| Выданный вариант | `attempts.variant_json.formId` (PRD-17) | Равнотрудны ли варианты. `formId` в коде аналитики не встречается ни разу, хотя PRD-24 ввёл пороги по вариантам, а BRD психометрики называл отчёт «проходимость по вариантам» |
| Версия публикации | `attempts.snapshot_id` | Сейчас только в списке попыток. Ни один агрегат не разрезан по версиям: прохождения до и после правки теста смешаны в одном среднем |
| Разрезы по ключам (PRD-50) | считаются в разборе ОДНОЙ телеметрической попытки | Агрегата «по тесту в разрезе подтем» нет, хотя это прямой ответ на «где у группы провал» |
| Выбранные варианты ответа | `answers_json`, `scorm_answers.user_answer_json` | Мёртвый дистрактор (его не выбирает никто) и инвертированный (его выбирают чаще верного) |

## 4. Предложения, по порядку

### 4.1. Первая волна — данные есть, считать почти нечего

1. **Свести три источника на странице теста** с фильтром источника, как в общей аналитике.
   Это починка дефекта раздела 2, а не улучшение.
2. **Профиль по шкалам и показателям** для измерительных тестов: средние по шкале, распределение
   уровней, число прохождений. Закрывает бесполезность аналитики для опросников.
3. **Разрез по ГРУППАМ** (требование владельца 2026-09-12). Сегодня страница аналитики теста
   отвечает только на вопрос «как прошёл тест», а оценщику нужен второй разрез — «как прошла
   группа»: сводка и статистика по темам с фильтром по группе, сравнение групп между собой,
   переход к участникам группы. Данные есть: у веб-попытки группа выводится из `user_groups`, у
   импортированного прохождения она проставлена явно (`scorm_attempts.group_id`, PRD-54), а
   фильтр по группе уже реализован в общей аналитике — на странице теста его нет.
4. **Разрез по вариантам выдачи**: попытки, средний балл, доля сдавших по каждому варианту и
   пометка расхождения. Отвечает на вопрос о справедливости оценки.
5. **Медиана времени на задание** в карточке вопроса (PRD-55 FR-31a; реализовано в Э4 PRD-55).

### 4.1a. Фильтры страницы «Аналитика» — на компонент ДС

Требование владельца 2026-09-12: нынешняя панель фильтров — самодельная
(`FiltersBar` в `client/src/pages/author/analytics.tsx`, ряд из `Select` рядом с иконкой), и её
надо заменить компонентом `FilterBar` из ui-kit.

Что даёт замена, помимо единообразия: применённые условия становятся отдельными чипами и
снимаются по одному; число активных условий видно на кнопке; появляются сохранённые наборы
условий и признак «набор изменён»; строка поиска и действия встают в штатные слоты первой строки.
Для страницы, где разрезов станет больше (источник, группа, вариант, версия публикации),
самодельный ряд селектов не масштабируется — именно это и делает замену не косметикой.

### 4.2. Вторая волна — требует расчёта, но на имеющихся данных

1. **Разбор ответов задания**: частоты выбора вариантов с пометкой мёртвого и инвертированного
   дистрактора.
2. **Дискриминация в простом виде**: доля верных у сильной и слабой четверти участников;
   отрицательная разница означает ошибку в ключе или двусмысленность.
3. **Агрегат разрезов по подтемам** (PRD-50) на уровне теста.
4. **Разрез по версии публикации**, чтобы правка теста не смешивалась в одном среднем.

### 4.3. Диаграммы

Ложатся на пункты 4.1.4 и 4.2.1 - 4.2.2, отдельной работой не являются:

- карта «трудность × время» по заданиям теста — кластеры дают диагноз: лёгкое и долгое = запутанная
  формулировка, трудное и быстрое = утечка ключа;
- профиль экспозиции банка — столбики по заданиям, видно выработанную голову и мёртвый хвост;
- разбор вариантов ответа одного задания — горизонтальные столбики с пометкой верного.

Существующие «Распределение результатов» и «Тренды (30 дней)» не дублировать.

## 5. Что НЕ входит в фазу 2

Психометрический аппарат — трудность как доля балла, корреляция задание-остаток, альфа, SEM,
анализ дистракторов по корреляциям, согласованность шкал. Это фаза 3 и отдельные PRD поверх
[BRD психометрической аналитики](../specs/brd-psychometric-analytics.md); пункт 4.2.2 намеренно
даёт лишь грубый предшественник дискриминации, чтобы не начинать психометрику раньше срока.
