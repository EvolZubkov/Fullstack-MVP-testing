# PRD-51, этапы Э1-Э2: приёмка

Дата: 2026-08-16. Предмет: отчёт собирается из блоков, стандартный шаблон переведён.
Спецификация: `docs/specs/prd-51/report-document-blocks.md`.
План: `docs/plans/2026-08-15-report-document-blocks.md` (задача 11).

## Главный результат

Документ, собранный из блоков, и документ, напечатанный прежней цельной раскладкой,
**совпадают попиксельно** — на одной и той же попытке, через настоящий растеризатор и
настоящую постраничную раскладку.

Стенд: `.playwright-mcp/prd51-document-acceptance.html` — двойник существующего
`paged-acceptance.html`. Тот же конвейер, тот же `html2canvas`, подменён только писатель
PDF: каждый лист выводится картинкой. Ключ `?mono=1` печатает ту же попытку цельной
раскладкой — это эталон «до».

| Что снято | Блоки | Цельная раскладка |
| --- | --- | --- |
| Листов A4 | 3 | 3 |
| Формат листа | `[210, 297]` мм | `[210, 297]` мм |
| Ссылка-чип рекомендации | лист 3 @ 16,181 мм | лист 3 @ 16,181 мм |
| Растровое сравнение снимков | \-\- | `ImageChops.difference().getbbox() == None` |

Различий ноль: разбор эталона на двенадцать файлов был переносом, а не редизайном.

## Пакет SCORM

Собран `npm run scorm:sample`. Проверено по РАСПАКОВАННОМУ пакету, а не по намерению:

- `designSettings.report.layoutKey` = `layouts/report/shell.html` — вид отчёта стал
  оболочкой документа;
- `designSettings.report.document` несёт **10 блоков** — состав разрешён сборщиком, как и
  требует §5.3: манифеста шаблона в LMS нет;
- в пакете лежит **21 раскладка блоков** (12 обычного вида и 9 адаптивного) — рантайму
  есть что подставить каждому блоку;
- общий модуль сборки документа (`renderReportInto`) доехал в `app.js` вместе с
  `exportReportPdf`.

`TEST_DATA.reportBlocks` в этом пакете отсутствует, и это верно: генератор образца строит
данные выгрузки синтетически и строк документа не подаёт, поэтому документ разрешён из
умолчаний манифеста.

## Что НЕ проверено

Названо честно, чтобы не читалось как полная приёмка:

1. **Живое прохождение теста на dev-сервере** с последующим скачиванием PDF из веб-хоста.
   Растровое сравнение выше проверяет конвейер печати, но не проводку «база → сборка
   выгрузки → окно предпросмотра» на реальной попытке.
2. **Проигрывание пакета в плеере** (`npm run scorm:player`, `:5050`) со скачиванием
   отчёта из LMS-ветки. Данные для этой ветки проверены выше по распакованному пакету,
   но сам файл из плеера не снимался.
3. **Адаптивный отчёт на растре.** Его паритет доказан юнитом по DOM
   (`tests/report-document-parity.test.ts`), но через растеризатор он не прогонялся:
   стенд печатает обычный вид.
4. **Предпросмотр в редакторе** на живом тесте — переключён на общую сборку, но снят
   только юнитами.
