# PRD-51, этап Э3: приёмка редактора документа отчёта

Дата: 2026-08-16. Стенд: второй экземпляр dev-сервера на порту 8097, общая dev-база.
Учётная запись: `acceptance@local.test`. Браузер: Playwright (Chromium), пакет —
локальный плеер SCORM 2004 на порту 5050.

Тест приёмки: `PRD-51 приёмка Э3 · документ отчёта`, идентификатор
`608932a1-b0d0-4953-8484-ba45890ddd1f`. Два раздела по 3 вопроса, проходной балл 70 %.

## 1. Что проверено

### 1.1. Документ по умолчанию виден живьём

Карточка «Отчёт о результатах» вкладки «Настройки» показала 10 системных блоков в порядке,
объявленном манифестом стандартного шаблона: `header`, `intro`, `summary`, `topics`,
`breakdown`, `scales`, `indicators`, `recommendations`, `courses`, `events`. У каждой строки
бейдж варианта из манифеста, тег природы «системный», тумблер показа и меню.

### 1.2. Автор собрал документ

Проделано в браузере, реальными нажатиями:

## 2. Дефекты, найденные приёмкой

Оба нашлись живым прогоном и оба были невидимы юнит-тестам.

### 2.1. Схема манифеста не знала вида `report.block`

При старте сервера реестр шаблонов ОТБРАСЫВАЛ стандартный шаблон целиком:
`Skipping template "default": manifest validation failed — contentTemplates.23.kind: Invalid
option…` — и так на 19 вариантах блоков. Работа Э2 до приложения не доходила вовсе: в базе
оставался прежний манифест, и отчёт печатался цельной раскладкой.

Юниты этого не видели, потому что кормят манифест функциям напрямую, минуя проверку реестра.
Вид добавлен в `variantKindSchema`; после перезапуска реестр синхронизировал 19 вариантов
блоков и объявление `reportDocument` для обеих ветвей.

### 2.2. Текст авторских страниц молча терялся при сохранении

Сборка тела запроса звала `toRowInputs`, который готовит строку для РАЗРЕШЕНИЯ документа и
несёт `valuesJson`/`settingsJson`, тогда как маршрут принимает `values`/`settings`. Zod
выбрасывает незаявленные ключи без единого слова: документ сохранялся, а заголовок и текст
страницы приезжали в базу пустыми (`page values: {}`).

Тело собирается явным отображением, `TestSettingsPayload.reportBlocks` описывает контракт
маршрута, а тест проверяет имена полей буквально. Прежний тест сравнивал результат с формой
строки разрешения и потому пропустил дефект.

## 3. Расхождения с эскизом, принятые сознательно

Разметка строки сверена с утверждённым эскизом `docs/wireframes/prd51-report-document.html`
(состояния `s-default`, `s-readonly`) поэлементно, снимок рядом со снимком. Расхождений три,
все — следствие того, что копия CSS внутри эскиза неполна, а живой соседний экран
(«Структура») выглядит именно так:

1. Кнопок-вставки `n + 1`, а не `n − 1`: эскиз нарисовал только межстрочные. Живая
   «Структура» рисует вставку и перед первой строкой, и после последней — без них нельзя
   добавить блок в начало и в конец.
2. Строка с тегом несёт слева цветную полосу. Это существующее правило
   `tb-components.css` (`page-row:has(> .page-row__meta .ou-tag--info)`), которого в частичной
   копии CSS внутри эскиза нет. На «Структуре» тот же тег даёт ту же полосу.
3. Название блока — 16 px, 700, а не `body-s`: правило `.tb-tests-list .page-title` из
   `tb-tests-list.css` перебивает базовое для ВСЕХ строк внутри ящика редактора. Проверено
   на вкладке «Структура»: там названия страниц ровно такие же. Расхождение с эскизом, а не с
   продуктом.

Текст подсказки о числе вариантов оставлен в форме живого экрана — «Доступно вариантов: N»
вместо эскизного «Доступно 2 варианта»: она безопасна при любом числе.

## 4. Что НЕ проверено

**Растр адаптивного отчёта.** Документ адаптивной ветви проверен по испечённым данным
(§1.7), но на бумаге не сверялся: фикстура стенда `Тест для HRBP Управление численностью`
до конца не проходится — лимит 3 минуты истекает, а адаптивная выдача возвращает вопрос
«3 из 6» по кругу. Нужна отдельная адаптивная фикстура без лимита времени; это хвост
приёмки Э1-Э2, а не гейт Э3.

**Веб-выдача PDF.** Отчёт скачан из ПАКЕТА; веб-хост печатает его той же функцией
`renderReportInto` через тот же `export-pdf`, и совпадение двух выдач закреплено тестами
паритета, но живого скачивания из веба в этой приёмке не было.
