## 3. Аналитика: изъяны

### 3.1. Данные одного теста разбросаны по двум разделам (нарушает П1, П3)

- **Срезы.** Вкладка «Срезы» общего раздела целиком про один тест (`features/analytics/slices/slices-tab.tsx:122`).
  Внутри теста — своё «Сравнить срезы» на тех же слотах (`features/analytics/test/psychometrics-compare-panel.tsx`),
  но с другими таблицами. Один механизм в двух местах, каждое показывает половину.
- **Прохождения и разбор попытки.** В тесте их нет: кнопка уводит в общий реестр, теряется контекст и фильтр теста.
- **Два экспорта** («Экспорт Excel» в тесте и «Экспорт» в реестре) выгружают разное, разница нигде не объяснена.
- **«Обновить»** в общем разделе перезагружает страницу (`window.location.reload()`), в тесте — только данные.
- **Реестр** предлагает «Сохранить как срез» и «Сравнить со срезом» — с диалогом «По какому тесту сохранить срез»,
  который появился именно потому, что срез сохраняют не с того уровня (`features/analytics/registry/passage-registry.tsx:389-470`).

### 3.2. Распределение ответов нарисовано тремя способами

| Где | Вид | Верный вариант | Нет данных |
| --- | --- | --- | --- |
| Вопросы → колонка «Что отвечали» | строка `✓ A — 62 % · B — 21 % · ещё 2` + полоса | `✓` в тексте | `—` / `мало данных` / кнопка «Прочитать ответы» |
| Качество → разбор вопроса | таблица «Выбрали / Слабые / Сильные» с полосами | подпись «верный ответ» | абзац текста |
| Детали попытки | ответ строкой | цвет текста | «Нет ответа» |

Колонка «Что отвечали» (`features/analytics/test/question-table.tsx:324-378`):

- полоса показывает долю **самого популярного** варианта (`leader.share`), который может быть неверным; без подписи
  80 % читается как «80 % верных»;
- заголовок меняется в зависимости от типа теста («Разброс ответов» / «Что отвечали»);
- в одной колонке четыре разных «пустых» значения, прочерк означает «для этого типа не считается»;
- распределение подано предложением, а не графиком: сравнивать глазами нельзя;
- для сопоставления и ранжирования распределения нет вовсе — прочерк.

### 3.3. Два списка вопросов на одной странице

«Вопросы» и «Качество вопросов» перечисляют те же вопросы с теми же колонками «Трудность» и «Дискриминативность»
(`features/analytics/test/item-quality.tsx:667,692`). Непонятно, куда идти с вопросом «что не так с вопросом 7».

Разбор вопроса открывается неочевидно: клик по числу дискриминативности (ghost-кнопка, выглядящая как число) или
пункт в меню «⋯». Клик по строке ничего не делает. Разбор живёт внутри вкладки «Качество», «Ко всем вопросам» всегда
возвращает туда, даже если пришли из «Вопросов».

### 3.4. Одна величина в противоположных шкалах

«Трудность» — доля верных 0–1, больше значит легче. «Замысел» — 0–100, больше значит сложнее. Они стоят в соседних
колонках. В разборе наблюдение пересчитывается как `(1 − p)·100` («40 → 55»). Психометрические термины (r, D,
«корреляция с остатком», «экспозиция») вынесены на основной рабочий экран.

### 3.5. Несогласованности

- Проценты: «62 %» в тесте, «62%» и `toFixed(1)` в окне попытки и на вкладке уровней.
- «Вопрос» и «задание» вперемешку; в коде вкладка называется «Качество заданий», в интерфейсе — «Качество вопросов».
- Вкладки и открытый вопрос не записываются в адрес (`useState` на обеих страницах): ссылкой не поделиться, «Назад»
  браузера выкидывает со страницы.

### 3.6. Переходы между уровнями (нарушает П2)

| Переход | Сейчас | Проблема |
| --- | --- | --- |
| Общая → тест | только из строки среза | вниз почти не попасть |
| Тест → общая | «Все тесты» ведёт в список тестов | вверх — в другой раздел |
| Тест → вопрос | число дискриминативности или «⋯» | неочевидный вход, у вопроса нет своего места |
| Вопрос → тест | «Ко всем вопросам» | всегда на вкладку «Качество» |
| Ссылка на уровень | только память страницы | не поделиться, «Назад» не работает |

## 4. Аналитика: рекомендации

### 4.1. Три уровня с адресами

```text
/author/analytics                                   ← общая
/author/analytics/tests/:testId                     ← тест
/author/analytics/tests/:testId/questions/:qId      ← вопрос в тесте
```

- Вкладка и фильтр — параметры адреса (`?tab=questions&groupId=…`). Аналитика теста переезжает под `/author/analytics`.
- Одинаковая шапка на всех уровнях: хлебные крошки (каждая часть кликабельна), заголовок, подзаголовок «объём ·
  источники · фильтр», один компонент фильтра.
- **Вниз — клик по строке:** название теста в любой таблице → тест; строка вопроса → вопрос; строка прохождения → разбор.
- **Вверх — крошки,** фильтр переносится в обе стороны; условие, не имеющее смысла на уровне, становится снимаемым чипом.
- **В сторону:** на вопросе «Предыдущий / Следующий» в порядке сортировки и «Этот вопрос в других тестах»;
  на тесте — переключатель теста в крошке.
- Каждая цифра верхнего уровня ведёт вниз, туда, где она объясняется.

### 4.2. Что где живёт

| Уровень | Вопрос уровня | Содержимое | Чего здесь нет |
| --- | --- | --- | --- |
| Общая | Где по всем тестам нужно действие? | список тестов с показателями **каждого внутри себя**, реестр всех прохождений, сохранённые фильтры, «Требует внимания» | срезов, средних поверх тестов, вопросов |
| Тест | Как работает этот тест? | Обзор · Вопросы · Прохождения · Срезы · Выдача · Шкалы | детального разбора вопроса |
| Вопрос в тесте | Что не так с вопросом здесь? | трудность, дискриминативность, распределение ответов (с разрезом по срезу), время, прохождения с ошибкой на нём, действия | метрик теста целиком |

### 4.3. Срезы — только на уровне теста (П3)

- С общего уровня уходят вкладка «Срезы», «Сравнить со срезом» и «Сохранить как срез». Остаётся «Сохранить фильтр»
  (`kind = "filter"`): фильтр сужает список прохождений, срез — группа внутри теста для сравнения.
- В тесте одна вкладка «Срезы»: список и сравнение, в сравнении переключатель метрик «Результат и темы / Качество
  вопросов». Два текущих механизма сливаются.
- Строка среза ведёт во вкладку «Прохождения» теста, а не в общий реестр.
- Модель данных уже готова: `analytics_slices.test_id`. Нужно: расширить уникальность имени для срезов до
  `(created_by, test_id, name)` (сейчас `analytics_slices_owner_name_uq` по `created_by, name`) и проверить срезы с
  `kind = "slice"` и пустым `test_id` — перевести их в фильтры.

### 4.4. Один компонент распределения ответов

`AnswerDistribution` в двух размерах — компактный в таблице, полный в разборе вопроса и сравнении срезов:

- выбор и шкала: сегментная полоса по всем вариантам, верный отмечен цветом и иконкой, по наведению — полный перечень;
  в разборе — горизонтальная гистограмма, разрез «слабые / сильные» — слой того же графика;
- множественный выбор: подпись «доли отметивших, в сумме больше 100 %»;
- короткий ответ: топ написаний;
- свободный текст: объём и длина + «Прочитать ответы»;
- сопоставление и ранжирование: доля верно сопоставленных пар, средний сдвиг позиции.

### 4.5. Прочее

- Одна таблица вопросов с наборами колонок «Основное / Психометрика / Выдача» вместо двух вкладок.
- Три состояния пустоты с разным видом: «не применимо», «мало данных, нужно ещё N», «0».
- Трудность и замысел — в одной шкале и одном направлении; p-value — только в разборе.
- Один форматтер процентов («62 %»), одна глоссарная подсказка на термин во всём продукте.

## 5. Вторая ось: банк вопросов (П5)

Вся психометрика сейчас считается только внутри теста (`server/routes/analytics/psychometrics.ts`, все маршруты
`/psychometrics/:testId/...`). В «Темах и вопросах» из аналитики видна только авторская трудность. Связь односторонняя:
аналитика ведёт в тему (`features/content/content-tree.tsx`, «analytics diagnoses a question, but the fix happens in its
topic»), но в банке не видно, что с вопросом не так.

```text
Ось выдачи (тесты)                    Ось содержания (банк)
Общая аналитика                       Банк (папки)
   └ Тест                                └ Тема
        └ Вопрос в тесте  ⇄  Вопрос ┘
```

### 5.1. Что принадлежит вопросу, а что вопросу в тесте

| Показатель | Вопрос в банке | Вопрос в тесте |
| --- | --- | --- |
| Экспозиция: сколько раз и в скольких тестах | суммируется (износ) | доля в тесте |
| Версии содержания (`psycho_hash`) | **свойство вопроса** (сейчас ошибочно показано в тесте) | фильтр по версии |
| Пропуски, время, «мёртвые» варианты | по всем выдачам и по тестам рядом | да |
| Трудность | **по тестам рядом**, без общего среднего | да |
| Замысел против наблюдения | с каждым тестом | да |
| Дискриминативность, вклад в надёжность | только списком по тестам | **только здесь** |
| Цена, вклады в шкалы | нет | да |

Значения «по тестам рядом» — это один объект в разных контекстах, а не сравнение тестов.

### 5.2. Уровень темы — здоровье банка

Не «средний процент верных по теме», а: сколько вопросов на ревизии (с признаком в любом тесте); износ
(переэкспонированы / не выдавались); покрытие по трудности и расхождения замысла; вопросы с мёртвыми вариантами;
в каких тестах используется тема. Папка суммирует количества.

### 5.3. Где это живёт

Слой аналитики внутри «Темы и вопросы»: индикаторы у тем и папок, наборы колонок «Содержание / Качество», вкладка
«Статистика» в панели вопроса (`QuestionEditorDrawer`), фильтр «Требуют ревизии / Переэкспонированы / Не выдавались».
Общая аналитика получает только вход: дело «вопросы банка на ревизию» в очереди «Требует внимания».

Технически: срез `response-matrix` по вопросу через все тесты; трудность и дискриминативность по каждому тесту
отдельно; один расчёт признаков ревизии для таблицы теста, дерева банка и очереди.

## 6. Импорт (П4)

### 6.1. Где сейчас можно что-то загрузить

| Что | Формат | Где | В разделе «Импорт»? |

### 6.2. Изъяны

- Выгрузку LMS раздел «Импорт» уже принимает (`kind: "lmsExport"`, `pages/author/import.tsx:442`), но заголовок —
  «Импорт из Excel», описание — только про вопросы и шкалы (`lib/i18n.ts:632`). Возможность не обнаружить.
- Менеджер не видит раздел (дефект D4).
- Импорт устроен по формату файла, а не по задаче.
- История загрузок LMS видна только внутри формы и только по одному тесту (`/lms-import/batches/:testId`).
- Три точки загрузки LMS отличаются поведением: определение теста по файлу, фиксированный тест, третий вариант в Импорте;
  после загрузки в общей аналитике перезагружается вся страница.

### 6.3. Рекомендации

- Раздел «Импорт» — каталог задач: карточки «Вопросы и структура теста», «Прохождения из LMS», «Тест целиком (пакет)»,
  «Пользователи», «Шаблон оформления» — с назначением, форматом, шаблоном и инструкцией; плюс общая зона загрузки,
  определяющая вид файла.
- Раздел виден при любом праве на импорт, карточки — по правам.
- Одна форма задачи в двух оболочках: страница в разделе и окно короткого пути с заполненным контекстом. В окне —
  ссылка «Все виды импорта».
- Короткий путь оправдан, где задача возникает по ходу работы с объектом (тест, пользователи, назначение).
  В общей «Аналитике» он лишний — заменить подсказкой в пустом состоянии реестра.
- Единый журнал импорта (что, куда, кто, когда, итог, отмена); короткий путь показывает его с фильтром по контексту.
- Отчёт о загрузке ведёт в аналитику теста.

## 7. Экспорт (П6)

### 7.1. Где сейчас

**Содержимое теста** — меню «Действия» (`tests-list.tsx:1036-1070`): «Экспорт SCORM», «Экспорт в Excel», «Экспорт пакета
(.tbtest)». Ещё одна кнопка SCORM — на главной (`my-tests-section.tsx:135`).

**Данные:** «Экспорт Excel» в аналитике теста; «Психометрический отчёт» и «Матрица ответов» в подвале карточки
«Качество вопросов» (`item-quality.tsx:954-970`); «Экспорт» реестра; «Скачать детали» попытки (CSV).

### 7.2. Изъяны

- Три соседних «Экспорт …» без объяснения разницы; что Excel не переносит оформление и тексты результатов, сказано
  только в комментарии к коду (PRD-48).
- Телеметрия SCORM (дефект D2).
- Не сказано, какая версия выгружается: SCORM у опубликованного теста — из опубликованной версии, у черновика — из
  текущей правки.
- Выгрузка попытки — CSV с JSON (дефект D3), остальные — .xlsx.
- Кнопки выгрузки разного вида: иконка с текстом, ссылки в подвале, пункты меню.

### 7.3. Рекомендации

**«Сохранить как…» для содержимого теста** — один пункт меню вместо трёх:

```text
Сохранить тест «…» как…
Что выгрузить: ● Опубликованная версия от 12.09   ○ Текущий черновик (есть изменения)

◉ Пакет для LMS (SCORM, .zip) — для запуска в LMS
   ☑ Присылать телеметрию прохождений в аналитику (по умолчанию из настройки теста)
○ Книга Excel (.xlsx) — правка в Excel, загружается обратно через Импорт
   Не переносит: оформление, тексты результатов
○ Пакет теста (.tbtest) — перенос в другой экземпляр, резервная копия
                                              [Отмена] [Скачать]
```

Варианты по задаче, с «что не переносит» и «как загрузить обратно»; настройки внутри варианта; выбор версии; без права
вариант скрыт; последний выбор запоминается; короткие пути открывают это же окно.

**«Экспорт» данных — одно окно на каждом уровне аналитики**, текущий фильтр подставляется:

| Уровень | Варианты |
| --- | --- |
| Общая | прохождения по фильтру; лучшая попытка на участника |
| Тест | сводка · прохождения · психометрический отчёт · матрица ответов |
| Вопрос в тесте | ответы на вопрос |
| Попытка | протокол в .xlsx с ответами по-человечески |

сервер их принимает, CORS для домена LMS открыт.

| Что | Как стало |
| --- | --- |
| Включение | Решает настройка теста `telemetryEnabled`; у опубликованного теста — из снимка, из которого собирается пакет. Параметр `?telemetry=true` не читается |
| Адрес приёма | Настройка установки `scorm.telemetryBaseUrl` в `config/*.jsonc`; пусто — `server.appUrl`. Заданы явно для production и test. Если пусты оба — выгрузка с включённой телеметрией отклоняется (422), `localhost` в пакет не запекается |
| Выключенная телеметрия | В пакете нет ни настроек телеметрии в `TEST_DATA`, ни адреса, ни ключей, ни кода отправки. Остаётся пустая заглушка `Telemetry` без комментариев о телеметрии — имя нужно, чтобы вызовы в коде экранов не падали |
| Включённая телеметрия | Рантайм читается строго: отсутствие файла роняет сборку, а не выпускает пакет, который ничего не шлёт |
| «Webhook URL» | Убран из формы теста, книги Excel (старые книги загружаются, строка пропускается) и пакета — рантайм его никогда не читал. Столбец `tests.webhook_url` в базе остаётся, удалить его — отдельная миграция |
