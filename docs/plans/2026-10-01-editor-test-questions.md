# Вопросы теста в ящике теста — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** автор видит состав теста до вопроса и переходит к правке вопроса, не выходя из ящика
теста; недостающую тему создаёт тут же.

**Architecture:** новый пункт рейла вкладки «Состав и сценарий» — группа «Вопросы теста», её
дочерние пункты — темы теста. Форма показывает вопросы выбранной темы: текст и СВОДКУ свойств в
этом тесте. Сводка только читается: всё, что правится на других вкладках ящика (балл, цена
ответа, вклады в шкалы, варианты, квоты), здесь не правится. Правка содержания вопроса — в уже
встроенном `QuestionEditorDrawer` поверх ящика теста. Все данные уже есть в кэше редактора, новых
точек API нет.

**Tech Stack:** TypeScript, React 19, `@skillum/ui-kit`, lucide-react, Vitest.

**Эскиз:** [docs/wireframes/editor-settings-target.html](../wireframes/editor-settings-target.html),
состояния `s-composition-questions` (рейл и список) и `s-topic-picker` (кнопка «Создать тему»).

**Решения владельца (2026-10-01):**

- вопросы — отдельный пункт рейла со вторым уровнем «темы», а не блок под темами на «Составе»;
- поиск — по фрагменту текста вопроса;
- длинное название темы в рейле переносится, а не обрезается;
- в строке вопроса — только сводка, без правки того, что правится на других вкладках ящика;
- «Добавить вопрос» — нужен;
- тему можно создать из ящика теста, а не только выбрать существующую;
- в боковом меню «Тесты» стоят выше «Тем и вопросов»;
- аналитика в строке вопроса — следующая итерация.

**Границы.** Адаптивный режим: список показывает банк темы; уровень вопроса по сложности не
вычисляется. Порядок вопросов в списке — `orderIndex` темы, без учёта порядка выдачи.

## Следующая итерация: аналитика в строке вопроса

Не входит в эту итерацию, зафиксировано по решению владельца 2026-10-01.

- **Что показать:** фактическую экспозицию вопроса (сколько раз выдан), трудность и
  различающую способность из психометрики.
- **Источники:** `GET /api/analytics/tests/:testId/delivery`,
  `GET /api/analytics/psychometrics/:testId` (массив `items` по вопросам).
- **Ограничение:** оба требуют права `analytics.read` и доступа к тесту, поэтому показ
  условный, а при отсутствии права сводка остаётся без этих чисел.
- **Открытые вопросы:** формат в строке (числа в сводке или отметки только при отклонении),
  поведение на тесте без прохождений, ленивая загрузка при открытии пункта рейла.
