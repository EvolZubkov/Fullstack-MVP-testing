# План: участник выгрузки LMS как внешняя учётная запись

Дата: 2026-10-06. Статус: реализован 2026-10-06, приёмка в браузере пройдена на копии dev-базы.
Спека, которую меняет трек: [PRD-54](../specs/prd-54/lms-export-import.md). Смежная:
[PRD-28 «Внешний участник»](../specs/prd-28/external-participant.md).
Эскиз: [prd54-lms-external-participants.html](../wireframes/approved/prd54-lms-external-participants.html).

## 1. Повод

Группа, в которую загружали выгрузку LMS, показывает «0 чел.», хотя в аналитике её прохождения
видны. Причина в модели: участник выгрузки — только псевдоним на прохождении, в системе он не
заведён, а PRD-54 прямо запрещает импорту создавать учётные записи.

Решение владельца 2026-10-06: участник выгрузки — внешний пользователь. Он заводится в системе,
остаётся анонимным, но однозначно опознаётся, и с ним работают как с любым человеком: группы,
история прохождений, аналитика по людям. Местом хранения выбрана учётная запись вида «внешний»
(`users.is_external`), а не отдельный реестр.

## 2. Что меняется в решениях PRD-54

| Было | Становится |
| --- | --- |
| Импорт не создаёт учётных записей, связь только с уже заведённой по ключу | Импорт находит учётную запись или заводит внешнюю. Связано каждое прохождение |
| Флажок «Связать с пользователями по ключу» | Убран: связывание идёт всегда, ключ участника и есть его личность |
| Группа — метка на прохождении, `user_groups` не меняется | Метка остаётся, и участник становится членом выбранной группы |
| Откат удаляет прохождения партии | Ещё снимает членство, добавленное партией, и удаляет заведённые ею записи, если у них не осталось прохождений |

Остаются прежними: псевдоним из четырёх полей, порядок поиска (`learner_id`, затем ключ),
обезличивание как параметр конфигурации, запрет связывания по ФИО.

## 3. Внешняя запись из выгрузки

| Поле | Значение |
| --- | --- |
| `is_external` | `true` |
| `email` | `NULL`. Колонка становится необязательной: подставлять выдуманный адрес нельзя |
| `password_hash` | `NULL`, как у любого внешнего участника PRD-28 |
| `name` | ФИО из файла, если обезличивание выключено, иначе подпись «Участник» и первые восемь знаков ключа (раздел 3.1) |
| `external_key` | псевдоним (`participant_key`) |
| `lms_learner_id` | из колонки `learner_id`, если она в файле есть |
| `organization` | из файла, только если обезличивание выключено |
| `unit`, `position` | из файла всегда: они и сейчас хранятся у прохождения при обезличивании (BR-54-21) |
| роль | «Обычный пользователь» (`learner`), единственная роль внешнего участника по PRD-28 |
| `status` | «Активен» |

### 3.1. Подпись обезличенного участника

Решение владельца 2026-10-06. Личность участника — полный ключ (HMAC-SHA256, 256 бит), и его
совпадение у разных людей практически исключено. Подпись — только его начало, и короткая подпись
совпадает у разных людей уже на сотнях участников: шесть знаков (24 бита) дают совпадение с
вероятностью 2,9 % на тысяче внешних участников и 52 % на пяти тысячах.

- Подпись — «Участник» и первые **восемь** знаков ключа (32 бита: 0,01 % на тысяче, 1,2 % на десяти
  тысячах).
- При создании записи подпись проверяется: если её уже носит другая внешняя запись, подпись
  новой удлиняется на знак, пока не станет свободной. Ключ при этом один и тот же, меняется только
  то, сколько его знаков показано.
- Выданная подпись больше не меняется: она уже стоит в отчётах и выгрузках.
- Аналитика называет прохождение без связанной записи по тому же правилу — восемь знаков вместо
  шести (`attemptParticipant`). После переноса таких прохождений не остаётся, но правило одно.

Профиль уже существующей записи импорт по-прежнему не правит: решение «не его компетенция»
остаётся в силе. Поля заполняются только у записи, которую импорт сам завёл.

Записи без почты недоступны пути, который требует почту: приглашение, сброс пароля, ссылка на
назначенный тест. Сервер отклоняет их явно, интерфейс эти пункты гасит. Если позже записи
задают почту в карточке, она становится обычным внешним участником PRD-28.

## 4. Работы

1. **Спека.** PRD-54: решения выше (BR-54-38 и далее), §5.5, §8.5, §8.6, §11. PRD-28: внешний
   участник без почты. Руководство автора: раздел о загрузке выгрузки.
2. **Миграция.** `users.email` становится необязательной; новая таблица
   `lms_import_batch_users (batch_id, user_id, created_user, added_to_group)` — что партия
   завела и куда добавила, по ней работает откат. Миграция аддитивная: `predev` применит её сам.
3. **Перенос уже загруженного.** Та же миграция связывает прохождения без `user_id`: сначала с
   записью, у которой такой же `external_key`, иначе заводит внешнюю; проставляет членство по
   метке группы и пишет строки в `lms_import_batch_users`, чтобы откат старых партий работал так
   же. Затрагивает dev (20 строк), стенд и прод — при деплое, без ручных шагов.
4. **Импорт.** Поиск или создание записи (с проверкой подписи по разделу 3.1), членство в группе, учёт в
   `lms_import_batch_users`; сухой прогон считает «будет заведено участников». Убрать флажок
   связывания из формы и API. Откат — по разделу 2.
5. **Почта необязательна.** Пройти 14 мест расшифровки и остальной код, читающий `users.email`
   (31 файл): список и карточка пользователя, назначения, приглашения, сброс пароля, ссылки,
   выгрузки. Каждый путь, которому нужна почта, явно отказывает записи без неё.
6. **«Пользователи».** Строка внешней записи без почты: «—» вместо адреса, отметка «Внешний»,
   пункты меню, требующие почты, погашены. Фильтр «Вид учётной записи» уже есть (PRD-28).
7. **«Группы».** Колонка «Участников»: «37 чел.» и рядом «из них 37 внешних». Окно участников:
   внешние идут в общей таблице с отметкой «Внешний». Подтверждение удаления: число
   прохождений из LMS с меткой этой группы — после удаления они уходят в «Без группы», метка
   снимается и с прохождений, и с партий.
8. **Проверка.** Юнит- и интеграционные тесты (pglite) на создание, повторный импорт, откат и
   перенос; приёмка в браузере на dev: загрузка, группа, «Пользователи», откат.

## 5. Вне охвата

- Слияние внешней записи с настоящей учётной записью того же человека — отдельной задачей.
  Модель её допускает: перенести прохождения и членство на настоящую запись и удалить внешнюю.
- Назначение теста внешнему участнику без почты: доставить ссылку некуда.

## 6. Что нужно подтвердить

1. Статус новой записи «Активен» — или нужен другой.
2. Откат удаляет заведённую партией запись, только если у неё не осталось прохождений. Если
   владелец успел добавить её в другую группу или назначить ей тест, запись тоже остаётся.
3. Участник, которого вручную убрали из группы, при повторной загрузке того же файла снова
   станет её членом: членство ставит каждая загрузка с этой группой.
