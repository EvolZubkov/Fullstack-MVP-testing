# План: облик шкалы на диаграмме (PRD-46)

Дата: 2026-08-08. Ветка: `main` (PRD-45 и PRD-46 влиты). Статус: не начат.

Эскиз СОГЛАСОВАН: `docs/wireframes/approved/prd46-scale-visual.html`. Правило wireframes-first
выполнено — разметку контрола брать оттуда дословно.

## 1. Что есть и чего нет

Проверено по коду 2026-08-08.

Есть:

- ядро принимает облик: `color` в `shared/template/radar-view.ts:77`, чтение `source.color` в
  `shared/template/rose-view.ts:264`, `iconPaths` в `shared/template/chart-frame.ts:153` и их
  передача в `rose-view.ts:286`;
- поля варианта объявляются в манифесте как `contentTemplates[].settings` — список типизированных
  полей; `scalesChartKind` уже там (оба поставляемых шаблона);
- редактор рисует их через `SettingControl` (`client/src/features/tests/editor/sections/
  start-pages-section.tsx:1876`), причём реестр типов ЗАКРЫТ: неизвестный тип даёт видимую
  диагностику, а не молча превращается в однострочный ввод;
- конвертер hex/HSL готов: `client/src/features/tests/editor/sections/color-format.ts`.

Нет НИЧЕГО из проводки: грепом по `server`, `client`, `shared` ни один хост не задаёт ни `color`,
ни `iconPaths` на осях. Роза всегда рисуется выведенной категориальной палитрой — это видно и на
приёмке 2026-08-08, где цвета совпали с палитрой, а не с выбором автора.

ВАЖНО про историю: коммиты `01419a15`, `aa95f84a`, `a85fc9cc` («эскиз облика», «оформление
переехало в настройки итогов», «чипы облика в колонки») трогали ТОЛЬКО файл эскиза. Кода за ними
нет — по названиям легко решить обратное.

## 2. Решения, которые нельзя пересматривать

Приняты при проектировании PRD-46 и записаны в спеке и в эскизе.

1. Облик хранится НЕ в `config_json` шкалы, а картой в настройках варианта «Итоги», ключ — ключ
   шкалы. Шкала описывает суть, оформление приносит шаблон. Ключ стабилен, поэтому переименование
   шкалы ничего не ломает, а шаблон без розы поля не объявляет.
2. Одно поле настроек со значением-картой, не поле на шкалу: набор шкал заранее неизвестен.
3. Пиктограмма приходит в контекст КОНТУРАМИ, не именем: в пакете нет ни React, ни шрифта иконок.
   Каждый узел lucide нормализуется к пути, окружности — двумя полудугами.
4. Цвет по идентичности — всем шкалам или никому: одна шкала с объявленным направлением переводит
   всю розу на схему уровней. Смешивать два языка цвета на одной фигуре отвергнуто.
5. При объявленном направлении поле цвета ВЫКЛЮЧЕНО и объяснено, а не спрятано: цвет там
   высказывает вердикт и совпадает с линейкой в карточке, а исчезнувшее поле читается как дефект.
   Пиктограмма остаётся доступной — она несёт идентичность, а не оценку.
6. Строка на шкалу и превью НАБОРА рядом: соседние секторы смыкаются, и близкие оттенки видно
   только вместе.
7. Блок облика показывается только когда выбрана роза: при радаре настраивать нечего.
   **Уточнено владельцем 2026-08-08 при реализации:** к «розе» добавлено «авто». Обоснование
   пункта — «при радаре настраивать нечего» — разбирает два значения из четырёх; `авто` на
   ипсативной методике даёт розу, то есть ровно тот сценарий, ради которого написан PRD-46.
   При `нет` и `радар` блок по-прежнему не появляется, обоснование сохраняется целиком.

## 3. Порядок работ

Резать по сквозной пользе, а не по слоям: поле, которое никто не читает, хуже отсутствующего.

### Срез A — цвет, заданный автором

1. Тип поля-карты в контракте настроек варианта + валидация манифеста (закрытый реестр типов
   обязан о нём знать, иначе поле встретит диагностика).
2. Объявить поле в манифестах ОБОИХ поставляемых шаблонов рядом со `scalesChartKind`.
3. Контрол в редакторе по эскизу: строка на шкалу, `ColorPicker` в hex, хранение тройки HSL
   (`color-format.ts`), выключенное с объяснением поле при объявленном направлении, превью набора.
4. Проводка: карта → `MeasureInput`/оси → `source.color`. На ОБОИХ хостах, иначе расхождение
   (PRD-29 §9). Веб — `server/services/result-context.ts`, пакет — бейк и `viewResults.js`.
5. Тесты: разбор карты, приоритет «цвет автора → категориальная палитра», правило «всем или
   никому», отсутствие карты не меняет прежнюю картинку.

### Срез B — пиктограмма

1. Разрешитель lucide → контуры. Считать НА СБОРКЕ (веб — при отдаче контекста, пакет — в бейке):
   в пакете разрешать нечем.
2. Поле выбора пиктограммы в том же контроле.
3. Проводка `iconPaths` до `chart-frame`.
4. Тесты: нормализация окружности двумя полудугами, шкала без пиктограммы не ломает подпись.

### Срез C — приёмка

Браузер и пакет, ипсативная методика с четырьмя шкалами. Проверять и «всем или никому»: одной
шкале задать направление и убедиться, что вся роза ушла на схему уровней.

## 4. Грабли, известные заранее

- **Приёмка из worktree.** `templates.source_path` абсолютный; запуск dev из worktree
  переписывает его на своё дерево ГЛОБАЛЬНО (`syncBuiltinTemplates`, `server/index.ts:135`).
  Возвращать после приёмки.
- **DSL не поддерживает комментарии `{{! }}`** — разбор шаблона падает.
- **Предел палитры — шесть шкал**, не семь: серый слот выброшен как неразличимый.
- **Токены DS `--ou-cat-*` не годятся** как палитра диаграммы, палитра выведена пересчётом их
  тонов в OKLCH при L=0.62.
- **Манифест объявляет поле, но шаблон без розы его не объявляет** — контрол обязан переживать
  отсутствие поля, а сохранённая карта у такого шаблона не теряется.
