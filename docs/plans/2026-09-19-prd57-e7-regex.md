# Регулярное выражение (PRD-57, этап Э7): план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** дать текстовому правилу второй режим — регулярное выражение — вместе с бюджетом
времени, без которого его выпускать нельзя.

**Architecture:** сравнение выражением живёт в `shared/answer-check/regex.ts`; бюджет знает
общий модуль `budget.ts`, а убивает прогон каждый хост своим исполнителем. Движок оценки
остаётся СИНХРОННЫМ: сервер считает вердикты выражений предпроходом и передаёт их готовыми
в `checkRuleSet`.

**Tech Stack:** TypeScript, Node `worker_threads`, Web Worker, React 19, Vitest.

**Устройство согласовано:**
[docs/specs/2026-09-19-prd57-e7-regex-design.md](../specs/2026-09-19-prd57-e7-regex-design.md).
Требования: [PRD-57](../specs/prd-57/open-response-and-formatting.md) §6.2, §6.4.

**Порядок работ внутри этапа:** сначала бюджет и рантайм, потом переключатель в ящике.
Режим, выпущенный без бюджета, — это открытая дверь в обслуживание всех пользователей.

**Границы этапа.** Не делается: нечёткое сравнение, проба у пропусков (Э8), числовое
правило выражением (не делается никогда — FR-28f).

## Task 5: Защита пакета

**Решение принято по ходу и отличается от исходной постановки.** Рабочего потока в пакете
не будет: пакет оценивает СИНХРОННО из десятка мест рендера, и протащить туда асинхронный
вердикт значит перестроить ход прохождения ради защиты, которую половина LMS запретит
политикой безопасности. Вместо этого защитой становится сам замер: правило, вышедшее за
порог при сохранении, помечается признаком `slow` и в пакете НЕ ИСПОЛНЯЕТСЯ — ответ выходит
непроверенным (FR-28r), а не подвешивает вкладку участника. FR-28q такой откат допускает
прямо; бюджет как число в пакет не запекается, потому что читать его там некому.

- Modify: `shared/answer-check/rules.ts`, `server/scorm/template/app/scoring/engine.js`;
  Test: `tests/answer-check-rules.test.ts`, `tests/scoring-engine-port.test.ts`
- [x] **Step 1:** падающие тесты — с `skipSlow` медленное правило не исполняется и даёт
      «не проверено»; без признака считается как обычное; сработавшее соседнее правило
      важнее пропущенного.
- [x] **Step 2:** реализация плюс признак `slow` в схеме правила.
- [x] **Step 3:** оба набора.
