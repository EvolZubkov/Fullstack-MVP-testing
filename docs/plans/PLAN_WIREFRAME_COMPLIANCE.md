# PLAN: Приведение стандартного шаблона к эскизам

Источник истины: `docs/wireframes/prohozhdenie/*.html` (согласованные эскизы) и их
`*.dc.html` (data-context — с данными). Правки только к разметке/CSS шаблона через
DS-примитивы (`ou-*`), без отсебятины. Каждый экран после правок — рендер реализации
рядом с `.dc`-эскизом на реальном вьюпорте (>=900px), поэлементная сверка 1:1.

## A. Универсальные дефекты (затрагивают все экраны)

### A1. Сцена не заполняет окно (КРИТИЧНО, видно на скриншотах: футер уезжает вверх)

Контракт эскиза (одинаков во всех 36 файлах):
`html,body{margin:0;height:100%}`; корень сцены `height:100vh/100%; display:flex;
flex-direction:column; overflow:hidden`; `header` — `flex:none` (фикс сверху);
`main` — `flex:1; min-height:0; overflow:auto` (скролл ВНУТРИ тела); `footer` —
`flex:none` (фикс снизу).

Реализация: сама сцена в `theme.css` КОРРЕКТНА (`.tb-scene{height:100%;flex-col;
overflow:hidden}`, `.tb-scene__body{flex:1;overflow:auto}`, `.tb-scene__foot{flex:none}`,
колонка `.tb-scene__col{width:75%;height:100%}`). Сломана ОПОРА высоты родителей —
`html/body/.container/[data-hook="app"]` потеряли `height:100%` (были в удалённом
`base.css`). Из-за этого `height:100%` схлопывается в высоту контента: футер вверху,
пустота снизу, скролл на внешнем элементе.

Фикс:

- Пакет (`theme.css`, восстановить фундамент):
  `html,body{height:100%;margin:0}`;
  `.container{height:100%;display:flex;flex-direction:column;min-height:0}`;
  `.container>[data-hook="app"]{flex:1;min-height:0;display:flex;flex-direction:column}`;
  `#toast-root{flex:none}`.
- Веб-хост и превью (`client/src/components/template-screen.tsx`):
  `:host{min-height:100%}` -> `:host{height:100%}`; убедиться, что родитель хоста даёт
  высоту (страница take-test и стейдж превью 16:9).

### A2. Заголовок формы отличается от эскиза (все экраны с `header`)

Эскиз (`Прохождение теста - множественный выбор.html`, `Старт.html` и др.), с учётом
уточнений заказчика:

- Логотип — КАРТИНКА (`<img>`). Бейдж «РТ» в эскизе — плейсхолдер, НЕ воспроизводить.
- ПОДЗАГОЛОВОК под названием: «Обязательный курс · Попытка N из M»
  (`font:var(--ou-text-body-s);color:var(--ou-fg-muted)`).
- Таймеры — DS `ou-timer ou-timer--digital ou-timer--s` с подписями (`__lbl`/`__num`).
  НАЛИЧИЕ таймеров зависит от НАСТРОЕК теста: тест-таймер — если у теста задан лимит;
  таймер раздела — если у раздела задан лимит (при малом остатке — `is-critical`).
  Не всегда два; может быть 0/1/2.

Реализация (`question.html`, `start.html`, `review.html`): подзаголовка НЕТ; таймер —
один не-DS `.q-timer.q-timer--hidden` без подписи вместо DS `ou-timer`.

Фикс (общий header во всех сцен-макетах + рантайм-контекст):

- Логотип-картинка оставить как есть (`<img>` при `logoUrl`).
- Добавить подзаголовок (`course.subtitle` / «Попытка N из M`).
- Заменить `.q-timer` на DS `ou-timer--digital--s` (`__lbl`/`__num`); тест-таймер и
  таймер раздела — КАЖДЫЙ по своей настройке лимита; `is-critical` по порогу.

### A2a. Карта вопросов / легенда / счётчик / индикатор прогресса (экран вопроса)

Построчная сверка `question.html` с эскизом — отличается ВСЁ, кроме контейнера:

- РАСКЛАДКА (главное): в эскизе карта = ОДИН ряд `ou-quiz` с `flex-direction:row;
  align-items:center` — точки (индикатор прогресса) + ЛЕГЕНДА + счётчик в одну строку.
  В реализации они сложены в СТОЛБЕЦ (три строки). Легенда должна быть в одной строке
  с индикатором прогресса.
- Легенда, ПОРЯДОК: эскиз [пропущен, текущий, не отвечен, отвечен]; реализация
  [отвечен, пропущен, текущий, не выдан] — порядок и метки разные.
- Легенда, МЕТКА: эскиз «не отвечен»; реализация «не выдан».
- Легенда/точка «пропущен»: эскиз класс `is-flagged`; реализация `is-skipped`
  (и статусы точек карты должны идти теми же классами — `is-flagged` для пропущенного).
- СЧЁТЧИК: эскиз «отвечено N **из {total}** · пропущено K»; реализация
  «отвечено N · пропущено K» — потерян «из {total}».
- ИНДИКАТОР ПРОГРЕССА: эскиз — полоска `width:{answered/total%}` (напр. 67% при 8/12),
  скруглённый правый край. Проверить, что рантайм считает ширину = отвечено/всего, а не
  по индексу текущего.

Принцип (HARD, feedback «use provided markup verbatim»): header и карту вопросов брать
из эскиза ДОСЛОВНО (та же разметка/классы/порядок/тексты), параметризуя только данными —
не пересобирать своей упрощённой версией. Это же правило применить ко ВСЕМ экранам
таблицы B.
