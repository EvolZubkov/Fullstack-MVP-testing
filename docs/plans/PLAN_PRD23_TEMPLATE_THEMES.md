## 1. Что делаем

Шаблон может поставлять несколько палитр — «Сертификация» уже поставляет светлую и тёмную, но
платформа об этом не знает: автор теста не может ни выбрать вид теста, ни задать цвет для каждой
палитры. Задача закрывает четыре пункта таблицы «что требуется вне панели» из эскиза.

| Код | Что | Где сейчас пусто |
| --- | --- | --- |
| Т1 | Шаблон объявляет темы, которые умеет | Манифест: поля нет; платформа не знает про палитры |
| Т2 | Автор выбирает вид теста: «Светлая» / «Тёмная» / «Авто» | Хранения нет |
| Т3 | Цвет задаётся на каждую тему независимо | `designSettingsJson.params` — одно значение на ключ |
| Т4 | Выбранная тема доходит до отрисовки на обоих хостах | Переопределения печатаются инлайном, вне тем |
| Т5 | Цвета живут в собственном разделе рельсы | Лежат в «Брендировании» вперемешку со шрифтом и логотипом |

Отдельная задача, в объём НЕ входит: у «Стандартного» единственная палитра в `:root` — тёмная.
Пока у него нет светлых токенов, темы он не объявляет и остаётся плоским.

## 2. Контракт

### 2.1. Манифест

```json
"themes": [
  { "id": "light", "label": "Светлая" },
  { "id": "dark",  "label": "Тёмная" }
]
```

Поле необязательное. Нет поля или меньше двух тем — шаблон тем не поддерживает, раздел «Цвета»
плоский; уже загруженные шаблоны переиздавать не требуется.

`id` — из закрытого перечня платформы (`light`, `dark`), как реестр типов полей PRD-22. Смысл
идентификатора жёсткий: `light` — базовая палитра `:root`, `dark` — блок
`prefers-color-scheme: dark` либо `[data-theme="dark"]`. Валидация — при загрузке И при активации
(NFR PRD-3): перечень идентификаторов закрыт, а объявленная тема должна реально объявлять токены
в CSS шаблона.

### 2.2. Хранение

`tests.designSettingsJson` (колонка JSON, миграция не нужна):

```json
{
  "templateId": "certification",
  "theme": "auto",
  "params": { "fontFamily": "Rostelecom Basis" },
  "paramsByTheme": { "light": { "primaryColor": "…" }, "dark": { "primaryColor": "…" } }
}
```

- Отсутствие `theme` читается как `auto` — это сегодняшнее поведение «Сертификации».
- Смена выбора темы `paramsByTheme` не трогает: подобранная палитра не теряется.
- Обратная совместимость: у шаблона без тем всё остаётся в `params`. Если тест с плоскими цветами
  открыт под шаблоном С темами, плоское значение читается как значение ОБЕИХ тем и переезжает в
  `paramsByTheme` при первом сохранении — молча ничего не теряется.

### 2.3. Отрисовка

Веб-хост переписывает CSS шаблона `:root` → `:host`
([template-screen.tsx:101](../../client/src/components/template-screen.tsx)), поэтому приём общий
для обоих хостов:

- фиксированная тема — атрибут `data-theme` на корне сцены (SCORM — `<html>`, веб — shadow-host);
- «Авто» — атрибут не ставится, работает медиа-запрос шаблона;
- переопределения печатаются `<style>`-блоком той же структуры, что и `theme.css`, а не инлайн-стилем:
  инлайн нельзя ограничить медиа-запросом.

```css
:root { --primary: <светлое> }
@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { --primary: <тёмное> } }
:root[data-theme="dark"] { --primary: <тёмное> }
```

### 2.4. Раздел «Цвета»

Отбор параметров — по `type === "color"`, объявленный в манифесте `section` игнорируется: иначе
каждый уже загруженный шаблон пришлось бы переиздавать. Пустой раздел в рельсе не показывается.

## 4. Риски и как снимаем

| Риск | Чем опасен | Нейтрализация |
| --- | --- | --- |
| Браузер для приёмки Э4-Э7 | Правило приёмки фронтенда требует реального браузера; MCP-сервер Playwright в текущей сессии инструменты не отдаёт, хотя настроен | Приёмка не завязывается на MCP: сценарии кладутся в репозиторий (`scripts/acceptance/*.mjs` на `@playwright/test`), запускаются против `npm run dev`, скриншоты в `.playwright-mcp/`. Работает и через MCP, и без него; после установки пакета — `npm ci --dry-run` и сборка, чтобы лок не поехал |
| Плоские цвета уже сохранённых тестов | Автор молча теряет подобранную палитру при переходе на шаблон с темами | Правило переезда из 2.2 + три барьерных теста: чтение плоского значения как значения обеих тем, сохранение через `PUT /api/tests/:id/design` без потери ключа, смена шаблона с бестемного на темный |
| Печать `<style>` вместо инлайна меняет каскад | Переопределения теста перестают выигрывать у `theme.css` шаблона | Блок переопределений печатается ПОСЛЕДНИМ в тот же корень и повторяет селекторы шаблона: специфичность равна, выигрывает порядок. Тест на порядок вставки в обоих хостах + проверка вычисленного значения в браузере и на локальном плеере |
| Шаблон объявил тему, которой нет в CSS | Автор видит колонку, которая ничего не красит | Валидатор сверяет `themes[]` с токенами стилей и отказывает при загрузке И при активации (NFR PRD-3), сообщение называет тему |
| Шаблон объявил тему вне перечня | Неизвестный идентификатор доходит до отрисовки | Перечень закрыт и лежит в одном реестре `shared/template`, как реестр типов полей PRD-22; расширение — правка одного места |
| Смена версии «Сертификации» | Выпуск другого содержимого под номером, который уже импортирован в dev | Версия поднимается до 1.3.0, пакет переимпортируется, состояние сверяется запросом к `templates` (см. handoff, раздел 4.3) |
