# PRD-56, этап Э2. Реестр прохождений — план работ

> **Для исполнителя:** задачи выполняются по одной, сверху вниз, в режиме TDD: сначала падающий
> тест, потом минимальная реализация, потом прогон, потом коммит. Шаги отмечены чекбоксами
> (`- [ ]`).

**Цель:** сделать реестр прохождений рабочим местом оценщика: один список на все источники,
фильтр компонентом `FilterBar`, состояние фильтра в адресе, ленивая подгрузка при прокрутке и
экспорт ровно того, что отфильтровано.

**Спецификация:** [FR-01 - FR-05](../specs/prd-56/analytics-rework.md).
**Эскиз (согласован 2026-09-13):** [раздел «Аналитика»](../wireframes/prd56-analytics-section.html),
состояния `reg`, `reg-filtered`, `reg-empty`, `reg-export`, `filter-form`.
**Предыдущий этап:** [план Э1](2026-09-13-prd56-analytics-rework.md) — слой наблюдений, на
котором этот этап стоит.

## Что нужно знать до начала

- **Vitest запускается ТОЛЬКО через npm:** `npm test -- <путь>`; полный прогон — по явному
  разрешению владельца.
- **Дев-сервер не подхватывает серверные правки**: после них `npm run dev` перезапускается
  руками (tsx без watch). Первый снимок приёмки Э1 показал старые числа именно поэтому.
- **Приёмка в браузере:** `node scripts/check/acceptance-shot.mjs <путь> <файл.png> [селектор]`,
  в Git Bash — с `MSYS_NO_PATHCONV=1`. Учётка `acceptance@local.test`.
- **UI собирается только из компонентов ui-kit**; не хватает пропа — правится `vendor/ui-kit`.

## Состояние на начало работ

- Слой наблюдений готов: `loadObservations` умеет фильтры по тесту, группе, источнику, исходу и
  периоду, лимит со смещением и общее число ([observations.ts](../../server/services/analytics/observations.ts)).
  В реестре не используется ни разу — экран до сих пор ходит в `combined-full`.
- `GET /api/analytics/combined-full` отдаёт СПИСОК строк своей формы плюс сводку, читая обе
  таблицы целиком ([combined.ts:207](../../server/routes/analytics/combined.ts#L207)).
  Клиент фильтрует и сортирует полученное в памяти.
- Экран — [analytics.tsx](../../client/src/pages/author/analytics.tsx), 1845 строк: своя панель
  фильтров (источник, тест, даты, поиск), своя таблица `Table` с постраничностью, окно экспорта
  со своим набором условий.
- `FilterBar` в ui-kit уже умеет всё, что нужно по FR-02: счётчик условий, чипы с удалением по
  одному, общий сброс, сохранённые наборы. В продукте не используется.
- `DataGrid` умеет страницы, но не догрузку при прокрутке — по FR-01c её предстоит добавить.

Приёмка 2026-09-14 на дев-инсталляции (161 прохождение, три источника):

- реестр показывает веб, телеметрию и импорт одним списком; исход и источник подписаны
  словами, у прохождения без оценивания стоит прочерк, а не ноль;
- окно «Условия отбора» применяет условия разом, чип появляется в панели, счётчик растёт,
  выборка сужается (161 → 158 при `Источник: веб`), адрес страницы несёт условие;
- подвал говорит «Показано 25 из 161», следующая порция ждёт прокрутки.

Приёмка нашла дефект, которого тесты не видели: метка догрузки лежала СНАРУЖИ прокручиваемой
области таблицы, всегда попадала в видимую часть и вытягивала весь список сразу — на экране
было «Показано 158 из 158». Метка перенесена внутрь `ou-grid__scroll`, наблюдение ведётся
относительно него; поведение закреплено тестом.

Старая панель «Источник / Тест» уехала на вкладку «Обзор»: у реестра свои условия, и две
панели на одном экране давали два разных ответа на вопрос «что я сейчас вижу».

## Риски

- **`combined-full` остаётся до Э3 — РЕШЕНО по ходу.** Список прохождений из него ушёл
  полностью (вкладка «Прохождения» читает реестр), но обзор по-прежнему кормится этой ручкой:
  плитки, тренды и темы переезжают на срезы в Э3, и снимать её раньше значит переписывать
  обзор дважды.
- **Фильтр по группе у веб-попыток — РЕШЕНО в задаче 1.** «Группа» значит членство человека
  (`user_groups`), как во всём продукте; у импортированной строки к этому добавляется метка
  группы, которую проставил импорт (PRD-54) — там участник может быть не заведён вовсе. Оба
  пути проверены интеграционными тестами.
- **Объём экрана.** `analytics.tsx` — 1845 строк со срезами, экспортом и разбором попытки;
  реестр выносится в отдельную фичу постепенно, чтобы каждый коммит оставлял экран рабочим.
