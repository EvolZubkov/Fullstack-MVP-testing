# Диалог назначения и рецензирования: выбор двумя половинами — план реализации

> **Для исполнителя:** задачи выполняются по порядку, каждая по TDD (падающий тест, реализация,
> зелёный тест). Шаги отмечены флажками `- [ ]`. Коммит — только по явному разрешению владельца.

**Цель.** Вкладка «Пользователи» диалогов «Управление назначениями» и «Отправить на
рецензирование» выбирает людей двухпанельным списком с корзиной; действия вкладок стоят в подвале;
окно не меняет высоту между вкладками; раскладка формы подчиняется сетке 4 px.

**Контракт.** Эскиз [assign-dialog-user-picker.html](../wireframes/approved/assign-dialog-user-picker.html),
согласован владельцем 2026-10-20. [PRD-52](../specs/prd-52/test-review.md), раздел 14.7 (кандидаты
в рецензенты).

**Архитектура.** Двухпанельный список — готовый `TransferList` из `@skillum/ui-kit`. Чего у ui-kit
нет — режим заполнения высоты у `ModalDialog`, `Tabs` и `TransferList` и строка над половинами
`TransferList`, — добавляется в сам ui-kit, а не локальным CSS диалога. Правки сетки — в стилях
компонентов DS. Серверная часть не меняется: кандидаты и приглашение уже есть (коммиты `70359aba`,
`788d69da`).

**Стек.** React 19 + `@skillum/ui-kit` (vendored, `vendor/ui-kit`), Vitest + Testing Library.

**Прогоны.** Только целевые: `npm test -- <путь>`, `npm run check`. Полный прогон — лишь по явному
разрешению владельца.

## Задача 1. Расширения ui-kit

- [ ] `ModalDialog fill`: класс `ou-modal--fill`. Окно во всю доступную высоту (потолок тот же, что
  сейчас стоит как `max-height`), тело — колонка, занимает остаток, между блоками тела 16 px.
- [ ] `Tabs fill`: класс `ou-tabs--fill`. Активная панель занимает остаток и прокручивается сама.
- [ ] `TransferList fill`: класс `ou-transfer--fill`. Половины тянутся по высоте, списки листаются
  внутри половин.
- [ ] `TransferList above`: строка над половинами в той же сетке. `above={{ left, right }}` ставит
  содержимое над левой и правой половиной, `above={node}` — во всю ширину. Классы
  `ou-transfer--has-above`, `ou-transfer__above--left|right|span`.
- [ ] Истории в `*.stories.tsx` для каждого режима.
- [ ] Правила — в три копии CSS сразу; базовое правило компонента остаётся ВЫШЕ его модификаторов
  (урок восстановления бандла 2026-09-07).

## Задача 2. Сетка 4 px — только в этом диалоге

Решение владельца 2026-10-20: интервалы приводятся к сетке ТОЛЬКО в диалоге назначения и
рецензирования; глобальная правка компонентов DS — технический долг (ROADMAP §0.0.4, пункт 19).
Поэтому правила не меняют умолчаний DS, а привязаны к новым режимам, которые включает только этот
диалог (`ModalDialog fill`, `TransferList fill`). Остальные экраны не меняются.

- [ ] Под `ou-modal--fill`: панель вкладок — 16 px от вкладок; подпись → поле — 4 px; между
  кнопками подвала — 4 px.
- [ ] Под `ou-transfer--fill`: содержимое половины в 24 px от её краёв; внутри строки, у «Выбрать
  все» и в поиске 4 px; между «Выбрать все» и «N выбрано» 16 px.
- [ ] Проверка, что на других экранах ничего не сдвинулось: ящик теста (вкладки, поля), окно
  «Сохранить как…» (подвал), редактор вариантов (`TransferList` без `fill`). Снимки до и после.

## Задача 3. Вкладка «Пользователи»

- [ ] Падающий тест: в режиме назначения и рецензирования вкладка показывает `TransferList`;
  кандидаты слева, корзина справа пустая.
- [ ] Падающий тест: перенос стрелкой кладёт человека в корзину; новый поиск слева корзину не
  трогает; число на кнопке подвала равно размеру корзины.
- [ ] Падающий тест: «Назначить (N)» шлёт `assignments/bulk` с людьми из корзины, «Пригласить (N)» —
  `review/invite`; после успеха корзина пустеет.
- [ ] Реализация: `TransferItem` — имя (или адрес, если имени нет), подпись — адрес. Отбор слева
  прежний: в назначении — ученики с адресом без назначения, в рецензировании — ответ
  `review/candidates`. Сроки — в `above` (два поля — над половинами, одно — во всю ширину).
- [ ] Ошибка загрузки списка — прежнее «Не удалось загрузить список пользователей» вместо обеих
  половин.

## Задача 4. Подвал и высота окна

- [ ] Падающий тест: на «Пользователях» и «Группах» в подвале «Отмена» и «Назначить (N)» /
  «Пригласить (N)»; на «Назначено» / «Приглашены» — только «Отмена»; строки действия в панели нет.
- [ ] Реализация: подвал собирается по активной вкладке; `ModalDialog fill`, `Tabs fill`.
- [ ] Рецензирование: баннер и вкладки разделены 16 px (тело модала в режиме `fill`).

## Открытые вопросы

1. Шаги «Списком» после проверки: «Назад» и «Пригласить (N)» на предпросмотре, кнопки отчёта
   рассылки. Эскиз показывает в подвале только первый шаг. Переносить в подвал и остальные шаги —
   тогда эскиз дополняется этими состояниями до кода.
2. Зеркалирование правок ui-kit в исходники `ENGINERING_HANDBOOK` (`ui-kit/src`,
   `handbook/design-system/tokens/components/*.css`) — делать в этой же работе отдельным коммитом в
   том репозитории или позже.
3. Уведомление после приглашения в режиме рецензирования всё ещё говорит «Назначено» (FR-37).
   Исправить в этой же работе.
