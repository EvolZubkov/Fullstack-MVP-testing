## Что нужно знать до начала

- **Vitest только через npm:** `npm test -- <путь>`; полный прогон — по разрешению владельца.
- **`npm run check` НЕ видит тесты:** `tsconfig.json` включает только `client/src`, `shared`,
  `server` и вдобавок исключает `**/*.test.ts`. Смена экспортируемой сигнатуры ломает чужие
  тесты молча — это стоило полутора десятков падений в Э5.
- **Дев-сервер не подхватывает серверные правки** — после них перезапуск руками.
- **Приёмка в браузере:** `node scripts/check/acceptance-shot.mjs` и `acceptance-click.mjs`
  (в Git Bash с `MSYS_NO_PATHCONV=1`). Учётка `acceptance@local.test`.

## Состояние на начало работ: аудит против FR-28

FR-28 требует диаграмму только там, где данные суть РАСПРЕДЕЛЕНИЕ или СВЯЗЬ. Проверено по блокам
обоих экранов; правило соблюдено везде, и это не совпадение — форму выбирали поблочно в Э4 и Э5.

| Блок | Что за данные | Чем показан | Вердикт |
| --- | --- | --- | --- |
| Плитки теста | четыре отдельных числа | числа | верно: одно число — это число |
| Распределение результатов | распределение по корзинам | столбцы | верно |
| Темы и подтемы | ряд величин по темам | таблица | верно: читается сравнением строк |
| Динамика сдаваемости | ряд во времени | линия | верно: связь |
| Вопросы теста | список с сортировкой | таблица | верно |
| Варианты, версии | ряды величин | таблицы | верно |
| Профиль экспозиции | распределение по банку | список с полосами | верно (см. задачу 2) |
| Профиль по шкалам | средние по шкалам | полосы | верно |
| Распределение уровней | распределение по полосам | накопительная полоса | верно |
| Реестр прохождений | список | таблица | верно |
| Срезы | ряд величин по категориям | таблица | верно; разворота по темам нет — FR-06e |
| Требует внимания | четыре счётчика и списки | числа и списки | верно |

Отсюда объём Э6 (решение владельца 2026-09-14): диаграмм не добавляем и не убираем — остаются
уборка и FR-06e.

**Мёртвый слой страницы теста.** После Э4 (снятие списка попыток, окна разбора и карточек
заданий) и Э5 в `client/src/pages/author/test-analytics.tsx` остались: импорт `recharts`, который
ничего не рисует (страница целиком на `Charts` дизайн-системы); импорт `QuestionMetrics`, который
не собирается; семнадцать мёртвых объявлений — помощники снятого списка и окна
(`formatDate`, `percentTone`, `percentProgressTone`, `chartTooltipStyle`, `formatIndicatorValue`,
`renderReferenceValue`) и их типы (`AttemptDetail`, `AttemptListItem`, `AnswerRow`). Шапка модуля
обещает то, чего на экране больше нет: список попыток, окно разбора и диаграммы на `recharts`.

**FR-06e.** Разворот строки среза показывает долю верных ЭТОГО среза по темам и объём выборки у
каждой темы; ни с чем не сравнивает — за сравнением ведёт отдельный режим. Расчёт по темам уже
есть (`summariseTopics`, Э4), но собран он внутри маршрута теста вместе с разрешением оценивания:
чтобы им воспользовался и срез, сбор ответов теста нужно вынести в общее место.

## Риски

- **Рефактор сбора ответов трогает числа действующего экрана.** Задача 3 идёт отдельным
  коммитом и проверяется наборами страницы теста ДО того, как на неё обопрётся срез.
- **Разворот строки — новая механика `DataGrid`.** Если компонент её не умеет, правка уезжает в
  дизайн-систему и касается каждой таблицы продукта: держать её узкой, тесты ДС прогонять
  целиком.
- **Уборка выглядит безобидной и потому опаснее прочего.** Снимается только то, что не
  собирается; критерий — молчание компилятора с `--noUnusedLocals`, а не впечатление.
