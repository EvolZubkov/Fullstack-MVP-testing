# PRD-48 Э3: план реализации — страницы теста в книге

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Цель:** книга Excel обратимо переносит страницы теста и разделов вместе с содержимым их
полей и настройками.

**Решение:** два листа. «Страницы» — по строке на страницу (зона, раздел, вид, номер, вариант,
режим, автопереход). «Поля страниц» — по строке на значение поля или настройки, привязанное к
странице тем же адресом. Нормализация и санитайзинг значений выносятся из роута страниц в общий
сервис, чтобы книга не стала входом в обход санитайзера.

**Стек:** TypeScript, ExcelJS, Drizzle, Vitest. Миграций БД нет.

**Требования:** [спека PRD-48](../specs/prd-48/test-workbook-full-transfer.md), этап Э3 —
FR-14, FR-15.

**Ветка:** `prd-48-e1-test-settings` (продолжение; Э1 и Э2 приняты на dev-стенде).

## Ограничения модели, ради которых план такой

Разведка по коду (`content-pages-lifecycle.ts`, `routes/content-pages.ts`, `test-settings.ts`)
дала пять фактов, каждый из которых определяет решение:

1. **Из девяти видов страниц авторский ровно один — `info`.** Остальные семь
   (`start`, `results`, `router`, `questions`, `intro`, `review`, `section-results`)
   материализует сервер по сценарию и составу тем; `POST /content-pages` их создание не
   принимает (`type` ограничен четырьмя значениями, `kind` выводится из него). Книга может
   только НАЙТИ уже созданную системную строку и обновить её содержимое.
2. **Естественного ключа у страницы нет.** `id` — локальный uuid стенда, `sort_order`
   неуникален по контракту, `settings_json.sequenceId` намеренно ОБЩИЙ у группы страниц
   (это метка последовательности, не идентификатор строки). Адресовать страницу приходится
   синтетическим ключом.
3. **Сохранение заменяет `values_json` целиком, не сливая** (`PUT` роута страниц). Правило
   книги «пустая ячейка — оставить как есть» держится только если сливает САМ импортёр,
   прочитав текущее состояние страницы.
4. **`settings_json` теряет незаявленные ключи молча**, `select` вне списка и `number` с
   мусором отбрасываются без ошибки. Книга со стенда с другой версией шаблона потеряет часть
   настроек беззвучно.
5. **Порядок применения жёсткий:** страницы применимы только ПОСЛЕ «Настроек» (сценарий) и
   «Структуры» (темы) — набор системных строк зависит от обоих, а тему страницы иначе не к
   чему привязать.

## Что план НЕ делает

- Не создаёт системные страницы и не пытается обойти API: это сломало бы жизненный цикл.
- Не переносит `id` страницы, а значит и `retakePolicyJson.blockedPageId` (уже вне охвата,
  раздел 5 спеки).
- Не переносит файлы по ссылкам внутри значений — только адреса (решение PRD-14).
- Не чинит потерю авторского кегля (`placeholderStyles`) при варианте без
  `textFit.allowAuthorFontSize`: это свойство варианта, а не книги.

## Контракт листов

### «Страницы»

| Колонка | Смысл |
| --- | --- |
| `Зона` | `До теста` / `После теста` / `До темы` / `После темы` |
| `Раздел` | Имя темы для зон темы; пусто для зон теста |
| `Вид` | `Стартовая` / `Вопросы` / `Маршрутизатор` / `Введение раздела` / `Обзор` / `Итоги раздела` / `Итоги` / `Авторская` |
| `Номер` | Порядковый номер внутри своей зоны, с 1 |
| `Вариант` | `template_key` — ключ варианта шаблона |
| `Режим` | `Шаблон` / `Стандартный` / `HTML` |
| `Автопереход` | `Да` / `Нет` |
| `Задержка, мс` | Целое; пусто = без задержки |

Зона и раздел — отдельные колонки по той же причине, что уровень и раздел на листе
«Обратная связь»: значения зоны не могут совпасть с именем темы.

### «Поля страниц»

| Колонка | Смысл |
| --- | --- |
| `Зона`, `Раздел`, `Вид`, `Номер` | Адрес страницы, тот же что на листе «Страницы» |
| `Куда` | `Содержание` (`values_json`) / `Настройка` (`settings_json`) |
| `Ключ` | Ключ поля из манифеста варианта |
| `Значение` | Значение |

### Правила применения

- Лист «Страницы» отсутствует — страницы не меняются вовсе.
- Системная страница (любой `Вид`, кроме `Авторская`): импорт НАХОДИТ её по паре «вид + тема»
  и обновляет вариант, режим, автопереход и поля. Не находит — ошибка строки с внятным
  текстом: строка существует только тогда, когда её требует сценарий, и «нет такой страницы»
  почти всегда значит, что книга и приёмник разошлись сценарием.
- Авторские страницы зоны, названной на листе, ЗАМЕНЯЮТСЯ целиком набором из книги: у них нет
  ключа, и единственный предсказуемый способ идемпотентности — «зона, названная в книге,
  выглядит как в книге». Зона, не названная на листе, не трогается.
- «Поля страниц» подчинены «Страницам»: строка с адресом, которого нет на листе «Страницы», —
  ошибка строки (тот же порядок, что у «Квот» и «Рекомендаций»).
- Значения СЛИВАЮТСЯ поверх текущих: ключ, которого книга не назвала, сохраняется. Это
  требует чтения текущего состояния страницы импортёром — сохранение само не сливает.
- Значение проходит ту же нормализацию и тот же санитайзер, что и при сохранении из
  редактора. Иначе книга — вход в обход санитайзера.

## Задача 0. Вынести нормализацию полей страницы в сервис

Решение владельца 2026-08-11: правила нормализации и санитайзинга должны существовать в ОДНОМ
месте и вызываться и роутом, и импортом книги.

**Файлы:** создать `server/services/content-page-fields.ts`; изменить
`server/routes/content-pages.ts`; тест `tests/services.content-page-fields.test.ts`.

- [ ] **Шаг 1.** Прочитать `server/routes/content-pages.ts` и выписать ВСЁ, что делает
  нормализация: разрешение шаблона и варианта, санитайзинг `values` по типам placeholder
  (`text`/`textarea` → plain, `richText`/`html` → sanitize), проверку `resultField` по
  `allowedPaths`/`allowedRenderers` с 422, отбор `placeholderStyles` по
  `textFit.allowAuthorFontSize`, нормализацию `settings` по объявленным ключам с их типами
  (`number`/`boolean`/`select`/`text`/`image`/`sequence`), перенос `sequenceId` при смене
  варианта.
- [ ] **Шаг 2.** Написать характеризующие тесты на ТЕКУЩЕЕ поведение роута до правки: они —
  страховка рефакторинга, а не проверка новой функции. Прогнать, убедиться, что зелёные.
- [ ] **Шаг 3.** Перенести логику в сервис БЕЗ изменения поведения; роут зовёт сервис.
- [ ] **Шаг 4.** Те же тесты зелёные + существующие тесты страниц
  (`npm test -- tests/routes.content-pages*.test.ts`).
- [ ] **Шаг 5.** Коммит `refactor(content-pages): нормализация полей страницы вынесена в сервис`.

**Красный флаг:** если при переносе захочется «заодно поправить» поведение — не делай. Правка
поведения здесь ломает редактор страниц, а не книгу.

## Задача 1. Контракт листов

**Файлы:** создать `server/utils/workbook-pages.ts`, тест `tests/workbook-pages.test.ts`.

Экспортирует заголовки, ширины, словари значений (`PAGE_ZONE_CHOICES`, `PAGE_KIND_CHOICES`,
`PAGE_MODE_CHOICES`), `serializePageRows` / `serializePageFieldRows`, `parsePageSheets`.

Свойства, которые обязаны быть под тестом:
- круг «сериализовал — разобрал» для системной и авторской страницы;
- адрес страницы однозначен: две авторские страницы одной зоны различаются номером;
- поле с адресом, которого нет на листе «Страницы», — ошибка строки;
- неизвестные зона, вид, режим — ошибка своей строки;
- `Куда` разводит содержание и настройки в разные словари.

Коммит: `feat(workbook): контракт листов «Страницы» и «Поля страниц»`.

## Задача 2. Выгрузка

**Файлы:** `server/utils/workbook-sheets.ts`, `server/routes/tests-workbook.ts`,
`tests/routes.tests-workbook.test.ts`.

Страницы теста берутся через `storage.getContentPages(testId)`; номер внутри зоны
присваивается по `sort_order`. Оба листа встают ПОСЛЕ «Рекомендаций» и ПЕРЕД «Оценкой».

Тест: тест со стартовой страницей и двумя авторскими страницами в зоне «После теста»
выгружается так, что адреса различимы, а значения полей попадают на второй лист с правильным
`Куда`.

Коммит: `feat(workbook): выгрузка страниц теста и их полей`.

## Задача 3. Загрузка

**Файлы:** `server/services/workbook-import.ts`, `tests/routes.tests-workbook.test.ts`.

Проход применяется ПОСЛЕ сохранения настроек и разделов — системные страницы к этому моменту
уже материализованы службой. Порядок внутри прохода: найти системные строки по «вид + тема»,
обновить; заменить авторские страницы названных зон; применить поля через сервис из Задачи 0,
слив поверх текущих значений.

Тесты: обновление системной страницы; замена авторских страниц зоны; неназванная зона не
тронута; поле-сирота; системная страница, которой нет (расхождение сценария) — ошибка с
внятным текстом; значения сливаются, а не затирают неназванные ключи.

Коммит: `feat(workbook): загрузка страниц теста и их полей`.

## Задача 4. Шаблон, круг, документы

**Файлы:** `server/services/workbook-template.ts`, `tests/workbook-template.test.ts`,
`tests/routes.tests-workbook.test.ts`, `docs/specs/questions-import/format.md`,
`docs/specs/prd-48/test-workbook-full-transfer.md`.

Кроме обычной работы (листы в шаблоне, выпадающие списки, справка, круговой тест, контракт
формата) этап обязан ЗАПИСАТЬ В СПЕКУ ограничение, которое разведка вскрыла:

> Круг по НАСТРОЙКАМ страниц не замкнут, когда на стендах разные версии шаблона: ключ,
> которого вариант приёмника не объявляет, теряется молча, а значение `select` вне списка
> отбрасывается без ошибки. Книга переносит настройки страницы ровно в объёме полей, общих у
> двух вариантов.

Это не дефект реализации, а свойство модели настроек страницы, и обнаружить его на приёмке
дороже, чем прочитать в спеке.

Коммит: `feat(workbook): шаблон и контракт листов страниц` + `docs(prd-48): ограничение круга по настройкам страниц`.
