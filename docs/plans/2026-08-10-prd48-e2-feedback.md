# PRD-48 Э2: план реализации — обратная связь и рекомендации в книге

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Цель:** книга Excel обратимо переносит обратную связь теста и разделов вместе с приложенными к
ней курсами, материалами и мероприятиями.

**Решение:** два новых листа. «Обратная связь» — по строке на владельца (тест или раздел) с
форматом и текстом. «Рекомендации» — по строке на курс, материал или мероприятие, привязанной к
владельцу. Второй лист подчинён первому так же, как «Квоты» подчинены «Структуре»: рекомендации
физически лежат ВНУТРИ `feedback_json` владельца, поэтому владельца, которого нет на листе
«Обратная связь», у рекомендации быть не может.

**Стек:** TypeScript, ExcelJS, Drizzle, Vitest. Миграций БД нет.

**Требования:** [спека PRD-48](../specs/prd-48/test-workbook-full-transfer.md), этап Э2 —
FR-12, FR-13. Круговое требование FR-21 проверяется в объёме этапа.

**Ветка:** `prd-48-e1-test-settings` (продолжение; Э1 принят на dev-стенде 2026-08-10).

  Спека упоминает уровни в FR-12; их строки добавит Э4 тем же листом, когда владельцу будет на
  что ссылаться.
- Листы «Страницы», «Поля страниц», «Оформление» — Э3 и Э5.
- Медиафайлы: `url` материала переносится как адрес, файл остаётся на исходном стенде
  (решение PRD-14, раздел 5 спеки).

## Контракт листов

### «Обратная связь»

| Колонка | Смысл |
| --- | --- |
| `Уровень` | `Тест` или `Раздел` |
| `Раздел` | Имя темы для уровня `Раздел`; пусто для уровня `Тест` |
| `Формат` | `Простой` / `Форматированный` / `HTML` |
| `Текст` | Текст обратной связи |

Две колонки вместо одной «Владелец» не для красоты: тема с именем «Тест» в банке существует, и
зарезервированное слово в общей колонке молча увело бы её обратную связь на уровень теста.

### «Рекомендации»

| Колонка | Смысл |
| --- | --- |
| `Уровень` | `Тест` или `Раздел` |
| `Раздел` | Имя темы для уровня `Раздел`; пусто для уровня `Тест` |
| `Тип` | `Курс` / `Материал` / `Мероприятие` |
| `Заголовок` | Название ссылки, материала или мероприятия |
| `Ссылка` | Адрес; обязателен для курса, необязателен для материала и мероприятия |

### Правила применения

- Лист «Обратная связь» отсутствует — обратная связь не меняется ни у кого.
- Владелец, названный на листе, получает обратную связь ЦЕЛИКОМ из книги: текст и формат из
  своей строки, курсы/материалы/мероприятия — из строк «Рекомендаций» с тем же владельцем.
  Владелец, названный без рекомендаций, остаётся без них: рекомендации — ветвь его обратной
  связи, и «нет строк» здесь означает «нет рекомендаций», а не «не трогать».
- Владелец, не названный на листе «Обратная связь», не меняется вовсе.
- Строка «Рекомендаций» с владельцем, которого нет на «Обратной связи», — ошибка строки. Это тот
  же порядок подчинения, что у «Квот» и «Структуры».
- Пустой `Текст` при пустых рекомендациях означает «обратной связи нет» — владельцу пишется
  `null`, а не пустая структура.

## Задача 1. Контракт листов

**Файлы:** создать `server/utils/workbook-feedback.ts`, тест `tests/workbook-feedback.test.ts`

- [ ] **Шаг 1. Написать падающий тест**

Тест проверяет СВОЙСТВА контракта, а не список колонок:

```ts
/**
 * @module tests/workbook-feedback
 *
 * PRD-48 Э2: листы «Обратная связь» и «Рекомендации». Проверяются свойства контракта:
 * владелец опознаётся однозначно (тема с именем «Тест» не уводит строку на уровень теста),
 * рекомендации склеиваются со своим владельцем, а сирота даёт ошибку строки.
 */
import { describe, it, expect } from "vitest";
import {
  FEEDBACK_HEADERS,
  RECOMMENDATION_HEADERS,
  serializeFeedbackRows,
  serializeRecommendationRows,
  parseFeedbackSheets,
} from "../server/utils/workbook-feedback";

const PAYLOAD = {
  format: "richText" as const,
  text: "<b>Молодец</b>",
  links: [{ title: "Курс по финансам", url: "https://example.test/fin" }],
  assets: [{ title: "Памятка", url: "https://example.test/memo.pdf" }],
  events: [{ title: "Вебинар", url: "" }],
};

describe("листы «Обратная связь» и «Рекомендации»", () => {
  it("заголовки разводят уровень и раздел отдельными колонками", () => {
    expect(FEEDBACK_HEADERS).toEqual(["Уровень", "Раздел", "Формат", "Текст"]);
    expect(RECOMMENDATION_HEADERS).toEqual(["Уровень", "Раздел", "Тип", "Заголовок", "Ссылка"]);
  });

  it("обратная связь теста и раздела ходит по кругу", () => {
    const fb = serializeFeedbackRows(PAYLOAD, [{ topicName: "Финансы", feedback: PAYLOAD }]);
    const rec = serializeRecommendationRows(PAYLOAD, [{ topicName: "Финансы", feedback: PAYLOAD }]);
    const { test, byTopic, errors } = parseFeedbackSheets(fb, rec);

    expect(errors).toEqual([]);
    expect(test).toEqual(PAYLOAD);
    expect(byTopic.get("финансы")).toEqual(PAYLOAD);
  });

  it("тема с именем «Тест» не уводит строку на уровень теста", () => {
    const rows = [
      { "Уровень": "Раздел", "Раздел": "Тест", "Формат": "Простой", "Текст": "ОС темы" },
    ];
    const { test, byTopic, errors } = parseFeedbackSheets(rows, []);
    expect(errors).toEqual([]);
    expect(test).toBeUndefined();
    expect(byTopic.get("тест")?.text).toBe("ОС темы");
  });

  it("рекомендация без владельца на листе «Обратная связь» даёт ошибку строки", () => {
    const { errors } = parseFeedbackSheets(
      [{ "Уровень": "Тест", "Раздел": "", "Формат": "Простой", "Текст": "ОС" }],
      [{ "Уровень": "Раздел", "Раздел": "Право", "Тип": "Курс", "Заголовок": "К", "Ссылка": "https://a.test" }],
    );
    expect(errors).toHaveLength(1);
    expect(errors[0]).toContain("Право");
  });

  it("курс без ссылки — ошибка, мероприятие без ссылки — норма", () => {
    const owner = [{ "Уровень": "Тест", "Раздел": "", "Формат": "Простой", "Текст": "ОС" }];
    const bad = parseFeedbackSheets(owner, [
      { "Уровень": "Тест", "Раздел": "", "Тип": "Курс", "Заголовок": "К", "Ссылка": "" },
    ]);
    expect(bad.errors).toHaveLength(1);

    const ok = parseFeedbackSheets(owner, [
      { "Уровень": "Тест", "Раздел": "", "Тип": "Мероприятие", "Заголовок": "Вебинар", "Ссылка": "" },
    ]);
    expect(ok.errors).toEqual([]);
    expect(ok.test?.events).toEqual([{ title: "Вебинар", url: "" }]);
  });

  it("владелец с пустым текстом и без рекомендаций получает null", () => {
    const { test } = parseFeedbackSheets(
      [{ "Уровень": "Тест", "Раздел": "", "Формат": "Простой", "Текст": "" }],
      [],
    );
    expect(test).toBeNull();
  });

  it("неизвестный уровень и неизвестный тип дают ошибку своей строки", () => {
    const a = parseFeedbackSheets([{ "Уровень": "Глава", "Раздел": "", "Формат": "Простой", "Текст": "x" }], []);
    expect(a.errors).toHaveLength(1);
    const b = parseFeedbackSheets(
      [{ "Уровень": "Тест", "Раздел": "", "Формат": "Простой", "Текст": "ОС" }],
      [{ "Уровень": "Тест", "Раздел": "", "Тип": "Книга", "Заголовок": "К", "Ссылка": "https://a.test" }],
    );
    expect(b.errors).toHaveLength(1);
  });
});
```

- [ ] **Шаг 3. Написать модуль**

`server/utils/workbook-feedback.ts` должен экспортировать:

- `FEEDBACK_HEADERS`, `FEEDBACK_WIDTHS`, `RECOMMENDATION_HEADERS`, `RECOMMENDATION_WIDTHS`;
- `LEVEL_CHOICES` (`["Тест", "Раздел"]`) и `RECOMMENDATION_TYPE_CHOICES`
  (`["Курс", "Материал", "Мероприятие"]`) — их берёт шаблон книги;
- `serializeFeedbackRows(testFeedback, sections)` и `serializeRecommendationRows(testFeedback, sections)`,
  где `sections` — массив `{ topicName, feedback }`;
- `parseFeedbackSheets(feedbackRows, recommendationRows)` →
  `{ test?: FeedbackPayload | null; byTopic: Map<string, FeedbackPayload | null>; errors: string[] }`.

Требования к реализации, которые тесты не выражают, но нарушать нельзя:

- Формат читается теми же метками, что и вводные блоки листа «Настройки» («Простой» /
  «Форматированный» / «HTML»); словарь взять ОДИН на книгу, а не завести второй — иначе метки
  разойдутся. Если он лежит в `workbook-settings.ts` не экспортированным, экспортируй его
  оттуда, а не копируй.
- Имя темы нормализуется тем же способом, что и на листе «Структура» (пробелы, регистр).
- Владелец, названный дважды, применяется последним вхождением — опиши это в JSDoc.
- `url` мероприятия допускает пустую строку (`feedbackEventSchema`), `url` курса обязателен
  (`feedbackLinkSchema` требует настоящий URL), `url` материала необязателен
  (`feedbackAssetSchema`, поле намеренно нестрогое — техдолг PRD-42). Не ужесточай.

## Задача 3. Загрузка

**Файлы:** `server/services/workbook-import.ts`, `tests/routes.tests-workbook.test.ts`

- [ ] **Шаг 1. Падающие тесты**

Через роут импорта, на моках:

1. книга с обеими листами применяет обратную связь тесту (в патче `feedbackJson` с текстом,
   курсами, материалами и мероприятиями) и разделу (в `sections[].feedbackJson`);
2. книга БЕЗ листа «Обратная связь» не трогает обратную связь: в патче нет `feedbackJson`;
3. владелец с пустым текстом и без рекомендаций получает `null`;
4. рекомендация-сирота даёт ошибку в `result.errors`, а остальные строки применяются;
5. раздел, названный на «Обратной связи», но отсутствующий в «Структуре» (и в тесте), даёт
   ошибку строки — иначе обратная связь уходила бы в пустоту.

- [ ] **Шаг 2. Убедиться, что падают.**

- [ ] **Шаг 3. Реализовать проход**

Проход читается ДО прохода «Структура» (как «Настройки»), а применяется вместе с ним: обратная
связь раздела — поле `SectionPayload.feedbackJson`, и заполнить его надо там, где собираются
разделы. Обратная связь теста идёт в патч через тот же механизм, что и прочие колонки.

Требование, которое легко потерять: книга, несущая «Обратную связь» БЕЗ «Структуры», должна
применить обратную связь ТЕСТА (раздел без «Структуры» переписывать нечем — назвать раздел в
такой книге можно, но применить его обратную связь без переписывания разделов нельзя; такую
