# План: предпросмотр шаблона, сетка вариантов контентной страницы, выбор цвета

Дата: 2026-07-22. Статус: РЕАЛИЗОВАН (не закоммичен). Все этапы Э1-Э10 закрыты; приёмка на
локальном плеере и в предпросмотре реестра пройдена, полный прогон тестов зелёный (кроме девяти
предсуществующих падений аналитики, не относящихся к этой работе).

Повод: разбор четырёх дефектов, найденных при приёмке PRD-22, плюс два требования
заказчика — набор вариантов контентной страницы и понятные названия цветов.

## 1. Что чиним

| Код | Дефект | Место |
| --- | --- | --- |
| Д1 | Рельс предпросмотра строится от `preview.routes`, а не от вариантов: имя варианта из манифеста не выводится никогда, а несколько демо-экранов одного варианта читаются как несколько вариантов | `client/src/features/templates/preview-rail.ts`, `preview-check-modal.tsx` |
| Д2 | Текст предупреждений негде прочитать — есть только жёлтая точка и счётчик | `preview-check-modal.tsx` |

| Д4 | В шаблонах один вариант галереи; «с картинкой / без» существует только как разное наполнение демо | `server/scorm/templates/default/`, `templates/certification/` |
| Д5 | Выбор цвета: попап уезжает от кнопки и обрезается границами формы | `vendor/ui-kit/src/components/ColorPicker.tsx` |
| Д6 | Названия цветов шаблона не говорят, на какие элементы влияют | манифесты шаблонов, форма «Оформление» |

## 2. Этапы

### Э1. Убрать ложные предупреждения о слоте (Д3)

Ожидание слота `page-content` сохраняется только для экранов, которые рендерятся общей
обёрткой `layouts.content`. У варианта со своим `layoutFile` поля попадают на экран через
`data-placeholder`, поэтому слот не требуется. Формулировка «будет отрисован из
стандартного шаблона» остаётся только там, где макета действительно нет.

Взамен снятой проверки вводится содержательная: вариант объявил `placeholders[]`, а в
отрисованном экране нет ни одного соответствующего `data-placeholder` и нет непустого
слота — предупреждение «поля варианта не попадут на экран».

### Э2. Показать текст предупреждений (Д2)

Список сообщений выводится и для статуса `warn`, а не только для `fail`.

### Э3. Рельс от вариантов (Д1)

`ScreenSpec` получает `variantKey`. Уровни рельса: Раздел -> Вариант
(`contentTemplates[].label`) -> его демонстрации. Статус варианта — худший из статусов его
экранов. Демонстрации переключаются внутри стенда (`onAction`, `nav:next` / `nav:prev`),
под стендом подпись «Слайд i из n». Экраны без варианта группируются как сейчас.

### Э4. Сетка вариантов контентной страницы (Д4)

Шесть раскладок в двух семействах — обычная страница и галерейная (индикатор
последовательности и «Назад»):

| № | Ключи | Название | Поля |
| --- | --- | --- | --- |
| 1 | `info.text` / `gallery.text` | Текст | Заголовок (`text`) + Текст (`html`) |
| 2 | `info.text-lead` / `gallery.text-lead` | Текст с подзаголовком | + Подзаголовок (`text`) |
| 3 | `info.image-left` / `gallery.image-left` | Текст, изображение слева | № 1 + Изображение, 50% ширины |
| 4 | `info.image-left-lead` / `gallery.image-left-lead` | Текст с подзаголовком, изображение слева | № 2 + Изображение |
| 5 | `info.image-right` / `gallery.image-right` | Текст, изображение справа | № 1 + Изображение |
| 6 | `info.image-right-lead` / `gallery.image-right-lead` | Текст с подзаголовком, изображение справа | № 2 + Изображение |

Поле текста объявляется типом `html` — по контракту это ровно три режима ввода: обычный
текст, форматированный, HTML. Настройки: у обычных — `nextLabel`, `backgroundImage`;
у галерейных — плюс `sequenceId`.

Демо не раздувается: галерейные демо-страницы кладутся в одну последовательность с общим
`sequenceId` — группировка смотрит на идентификатор, а не на вариант, поэтому индикатор
виден и одной демонстрации на вариант достаточно.

Шаблон `certification` приводится к тому же принципу в объёме своих двух раскладок и
начинает использовать объявленную настройку `nextLabel`.

### Э5. Фоллбек не тихий

Решение остаётся за автором: `templateKey` в базе не переписывается, вариант меняется
только через модалку «Сменить вариант», которая показывает теряемые поля. Меняются два
момента: до сопоставления страница рисуется вариантом № 1 вместо заглушки, и в модалке
вариант № 1 предвыбран. При смене шаблона теста автор видит сводку «страниц требуют
сопоставления: N» с переходом к каждой.

### Э6. Подсветка проблемных тестов в списке

Жёлтый знак рядом со статусом теста, если в тесте есть страницы с недоступным вариантом;
в подсказке — количество, по клику — переход в «Структуру». Признак считается на сервере
в `GET /api/tests` одним запросом на все видимые тесты, без запроса на каждый.

### Э7. Выбор цвета (Д5)

`ColorPicker` переводится на общий `Popover` дизайн-системы: портал, привязка к кнопке,
переворот вверх при нехватке места, пересчёт при прокрутке и изменении размера. То же для
`GradientPicker`.

### Э8. Порядок в цветах шаблона (Д6)

В контракт параметра добавляется описание, форма выводит его под подписью. Названия
восьми цветов стандартного шаблона переименовываются по фактическому применению в
`base.css`, порядок — по значимости. В руководство разработчика добавляется таблица
«цвет — где виден». То же для `certification`.

### Э9. Документы

`spec-template-platform` (слоты против плейсхолдеров, назначение `preview.routes`,
эталонная сетка вариантов), руководство разработчика, PRD-22, PRD-1 §4.3, CHANGELOG.

### Э10. Приёмка

Предпросмотр обоих шаблонов без ложных предупреждений, имена вариантов в рельсе, листание
демонстраций. Каталог «Добавить страницу» показывает 12 вариантов. Список тестов
подсвечивает тест с недоступным вариантом. Отладчик и SCORM-пакет на локальном плеере.
Полный прогон тестов, проверка типов, markdownlint.

## 3. Порядок и риски

Порядок: Э1 -> Э2 -> Э3 -> Э4 -> Э5 -> Э6 -> Э7 -> Э8 -> Э9 -> Э10. Сначала снимаются
ложные предупреждения и делается видимым их текст, иначе приёмка последующих этапов идёт
вслепую.

Риски:

- смена идентичности экранов делает сохранённые отчёты проверки устаревшими — точки серые
  до нажатия «Перепроверить», гейт активации при этом работает;
- число экранов предпросмотра стандартного шаблона вырастет с 16;
- загруженные копии шаблонов на стенде перезаливаются вручную через раздел «Шаблоны»;
- Э6 требует аккуратности с запросами, чтобы список тестов не потерял в скорости.
