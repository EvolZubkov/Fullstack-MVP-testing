# План реализации раздела «Темы и вопросы»

## Метаданные

- Дата: 2026-06-15 (модель вопроса и выдачи вариантов — 2026-06-16)
- Статус: ЧАСТИЧНО РЕАЛИЗОВАН (2026-07-01). Реализовано: единое дерево «Темы и вопросы»,
  групповые операции с папками и темами (bulk перенос/доступ/видимость/владелец, двухрежимное
  удаление папки, partial-batch), сложность вопроса стала nullable (миграция 029). Остаток:
  валидация конструкторов, порядок и перемешивание вариантов ответа
- Источник дизайна: `docs/wireframes/approved/content-bank-explorer.html` (утверждён,
  включая модель сложности, медиа, валидации, конструкторов и порядка/перемешивания вариантов)
- Бизнес-требования: `docs/specs/brd-content-axis.md` (BRC-CA-01..44)
- PRD: `docs/specs/prd-16/content-axis-and-question-model.md` (FR-01..50; FR-90 отложен)
- Аудит-обоснование: `docs/AUDIT_UX_AUTHOR_CONTENT.md` (UX-01..13)
- Ключевая модель: тесты и иерархия `Тема ⊃ Вопрос` — ортогональные оси; данный раздел
  затрагивает только ось контента, ось тестов не трогает

## Цель

Объединить нынешние раздельные страницы «Темы» (`client/src/pages/author/topics.tsx`) и
«Вопросы» (`client/src/pages/author/questions.tsx`) в единый раздел «Темы и вопросы» —
table-tree `Папка (необязательная, вложенная) ⊃ Тема ⊃ Вопрос` в визуальном языке списка
«Тесты». Закрывает находки аудита UX-01 (нет сквозной навигации), UX-03 (рассогласование
оболочек/стилей), UX-06 (скрытые действия), UX-07 (фильтры не сохраняются).

## Границы

В охвате: новый раздел и его дерево, drawer'ы темы и вопроса, фильтр-панель, переносы
(вопрос -> тема, тема -> папка), массовые операции, FAB, навигация/маршрут, перевод
существующих действий на новый раздел.

Вне охвата (отдельные задачи): cross-axis «где используется тема» из редактора теста;
дашборд автора; серверные фильтры и bulk-эндпоинты (опционально, см. ниже); медиатека.

## Подход

Инкрементально, без «большого взрыва»:

1. Сначала извлекаем переиспользуемые куски из монолитов в отдельные компоненты/хуки
   (старые страницы продолжают работать на тех же извлечённых модулях — проверяем отсутствие
   регрессий).
2. Строим новый раздел на отдельном маршруте параллельно старым страницам.
3. Достигаем паритета функций, затем переключаем навигацию и ретайрим старые страницы.

Сервер: основной CRUD уже есть, дерево и фильтры реализуемы на клиенте из существующих
эндпоинтов. Серверные фильтры/bulk-эндпоинты — опциональная оптимизация, отложена.

## Статус серверных API

Готово: CRUD тем/вопросов/папок; bulk-delete тем и вопросов; дубль темы/вопроса; гранты/
видимость/владелец; `questionCount` в `GET /api/topics`; перенос вопроса в другую тему через
`PUT /api/questions/:id` (с проверкой доступа к обеим темам); перенос темы в папку через
`PUT /api/topics/:id` (folderId); перенос/вложение папки через `PUT /api/folders/:id`.

Опциональные гэпы (можно client-side на старте, серверная реализация — позже при росте банка):

- серверные фильтры списка вопросов (тип/сложность/теги/медиа/автор) — сейчас на клиенте;
- `GET /api/questions/distinct-tags` — список тегов берётся из загруженных данных;
- bulk-перенос (`PATCH .../move-to-topic`, `.../move-to-folder`) — на старте циклом одиночных
  PUT, при необходимости заменить на bulk-эндпоинт.

## Фазы

### Фаза 0. Извлечение переиспользуемого + каркас

- Извлечь из `questions.tsx`: `features/questions/builders/{single,multiple,matching,ranking}.tsx`,
  `features/questions/question-drawer.tsx` (Modal -> Drawer), хук `hooks/use-question-builder.ts`;
  старая страница «Вопросы» начинает использовать извлечённые модули (без изменения поведения).
- Извлечь `hooks/use-folder-mutations.ts`.
- Новый маршрут `/author/content` (ProtectedRoute `topics.manage`) -> пустой каркас страницы;
  в сайдбар добавить пункт «Темы и вопросы» (старые пункты пока остаются).
- Приёмка: старые страницы и тесты не сломаны (`npm run check`, `npm test` зелёные);
  новый маршрут открывается; редактор вопроса на старой странице работает из нового Drawer.

### Фаза 1. Table-tree (только чтение)

- Компонент дерева `features/content/content-tree.tsx` + CSS-конвенции table-tree
  (`tb-content-tree.css`, зеркало утверждённого эскиза): колонки НАЗВАНИЕ | СЛОЖНОСТЬ |
  ВОПРОСОВ | действия; шапка колонок; корневой ярлык «Все темы (N)»; папка «(N тем)»;
  тип вопроса — пиктограмма в ячейке названия; сложность — тег в колонке; счётчик вопросов
  темы — в колонке; indent-line у вопросов; раскрытие тем с ленивой подгрузкой вопросов.
- Дерево строится на клиенте из `GET /api/folders` + `GET /api/topics` + `getQuestionsByTopic`.
- Тулбар: поиск, «Развернуть/Свернуть всё», кнопка «Фильтры».
- Приёмка: дерево соответствует эскизу и стилю «Тестов» (светлая+тёмная); счётчики верны;
  раскрытие/сворачивание работает; большие темы подгружаются лениво.

### Фаза 2. Фильтр-панель и поиск

- Панель фасетов: Тип, Сложность, Теги, Медиа, Автор, Область; чипы активных условий +
  «Очистить всё»; клиентская фильтрация; состояние фильтров в URL; автораскрытие дерева к
  совпадениям; счётчик «найдено / всего».
- Приёмка: фильтры сужают дерево, чипы снимаются, состояние переживает навигацию (URL).

### Фаза 3. Редактирование (drawer'ы + создание)

- Drawer вопроса (создание/правка): открытие по строке вопроса и «Добавить вопрос»;
  предзаполнение темы; тип — сегмент; выбор темы — Combobox с группировкой по папкам.
- Drawer темы: переиспользовать TopicDrawer (Свойства/Доступ) из ⋯-меню темы.
- FAB speed-dial (Добавить папку/тему/вопрос); per-row ⋯-меню для папки/темы/вопроса.
- Приёмка: создание/правка темы и вопроса через drawer'ы; content-guard на правках.

### Фаза 4. Переносы, выбор, массовые операции

- Перенос вопроса в тему (Combobox-пикер, `PUT topicId`, заметка о выполнимости);

- Приёмка: переносы и массовые операции с защитой (dry-run/ContentImpactDialog).

### Фаза 5. Переключение навигации (cutover)

- Раздел «Импорт» сохранить; при необходимости перелинковать.
- Приёмка: навигация переключена, старые маршруты редиректят, мёртвых ссылок нет.

### Фаза 6. Тесты и приёмка

- Тесты на новый код (дерево, drawer'ы, фильтры, переносы); обновить тесты, ссылавшиеся на

## Модель вопроса и выдачи вариантов (по утверждённым эскизам)

Эти изменения уточняют Фазы 1-3 (дерево, фильтр, редактор вопроса) и добавляют отдельный блок
правок редактора тестов (ось сборки). Полные требования — `docs/specs/brd-content-axis.md`
(BRC-CA-10..44).

### Блок C1. Сложность вопроса (nullable + интервал)

- Миграция: `questions.difficulty` -> nullable (снять `NOT NULL`, default сохранить);
  zod/бэкенд принимают `null`. (BRC-CA-10)
- Редактор вопроса: слайдер 0–100 + поле ввода числа + переключатель «Не задано»
  (скрывает контролы установки). (BRC-CA-12)
- Дерево, колонка «Сложность»: показывать ЧИСЛО; «Не задано» для `null`; убрать выдуманные
  легко/средне/сложно и фикс-пороги тона. (BRC-CA-11)
- Фильтр: фасет «Сложность» = интервал 0–100 (слайдер) + свитч «Не задана» как гейт. (BRC-CA-13)
- Резолверы выдачи/аналитики учитывают `null` (без подстановки «середины»); метки/уровни —
  свойство теста (`adaptive_levels`), банк не трогаем. (BRC-CA-14)
- Приёмка: миграция применяется; редактор сохраняет и очищает значение; фильтр-интервал и
  «Не задана» сужают дерево; «Не задано» видно в колонке.

### Блок C2. Медиа (только загрузка файла)

- Редактор вопроса: убрать ввод URL и ручной выбор «Тип медиа»; медиа = вложение
  (превью + «Заменить»/«Удалить»); загрузка через DS `FileUploader` в модалке «Загрузка медиа»;
  тип авто из MIME. (BRC-CA-20..22)
- `client/src/components/questions/media-uploader.tsx` модернизировать на `FileUploader`/`FileItem`.
- Приёмка: загрузка файла даёт вложение; внешние URL не вводятся; SCORM-пакет содержит файл.

### Блок C3. Конструкторы вариантов и валидация

- Билдеры по типам с корректными контролами: Один ответ — radio; Несколько ответов — чекбоксы;
  Соответствие — пары; Ранжирование — список. (BRC-CA-30)
- Валидация до сохранения (тема, текст, ≥2 непустых варианта, правильный ответ по типу);
  ошибки — баннером `ou-banner--error` вверху формы; «Сохранить» заблокирована. (BRC-CA-31)
- Смена типа при введённых данных — подтверждение с предупреждением о потере конструктора. (BRC-CA-32)
- Приёмка: нельзя сохранить без правильного ответа или с <2 вариантами; баннер показывает причины;
  смена типа подтверждается.

### Блок C4. Порядок и «Случайный порядок» вариантов (уровень вопроса)

- Базовый порядок вариантов — ручной (drag за ручку) для Один ответ/Несколько ответов/Соответствие;
  хранится как порядок элементов в `questions.dataJson`. (BRC-CA-40)
- Переключатель «Случайный порядок вариантов» рядом с вариантами (= `questions.shuffle_answers`,
  по умолчанию включён); миграция не требуется. (BRC-CA-41)
- Ранжирование — без переключателя, перемешивание при выдаче обязательно. (BRC-CA-42)
- Приёмка: порядок меняется перетаскиванием; переключатель переживает сохранение; ранжирование
  всегда перемешано при выдаче.

### Блок C5 (ОТЛОЖЕНО — гипотеза). Редактор тестов: переопределение выдачи вариантов

ОТКЛАДЫВАЕТСЯ до подтверждения гипотезы необходимости (решение 2026-06-16). На старте редактор
тестов (PRD-7) и вкладка «Оценка» (PRD-15 блок D) НЕ меняются.

Поведение по умолчанию (старт): тест выдаёт варианты строго по настройкам ВОПРОСА из банка —
базовый порядок (`questions.dataJson`) + «Случайный порядок вариантов» (`questions.shuffle_answers`);
для Ранжирования перемешивание обязательно. Отдельного хранилища и резолвера переопределения не
вводим.

При подтверждении гипотезы (отдельная задача, расширение PRD-15 блока D): хранилище переопределения
на пару (тест, вопрос) — порядок + случайность (расширить `test_question_scoring` либо новая
`test_question_delivery`); резолвер «переопределение теста, иначе настройка вопроса»; UI в модале
«Оценка вопроса в тесте» + индикатор в таблице секции; фиксация снапшотом; SCORM-бейк/веб-выдача
из эффективных значений; Ранжирование игнорирует выключение перемешивания. Эскиз — ревизия
`prd15-test-scoring.html` (не начат). (BRC-CA-44)

### Блок C6. Терминология

- Везде (фасет фильтра, seg типа, тултипы пиктограмм, чипы условий): Один ответ / Несколько
  ответов / Соответствие / Ранжирование — из i18n (`t.questions.*`), без хардкода.
