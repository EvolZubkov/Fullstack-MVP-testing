# Область действия и срок жизни ссылки-приглашения

Дата согласования: 2026-07-30. Основание: обращение о том, что получатель ссылки обрезал у неё хвост
`learner/test/<id>` и оказался в кабинете пользователя. Предшествующий разбор и решения от 2026-07-29
зафиксированы в `docs/plans/PLAN_MAGIC_LINK_SCOPE.md`; настоящая спека уточняет и частично отменяет его этап 2.

## 1. Задача

Ссылка-приглашение, которая уходит учащемуся в письме о назначении теста (`/access/<token>`), должна:

1. оставаться действительной, пока не исчерпаны попытки; успешное прохождение теста её не гасит;
2. открывать только назначенный тест и ничего кроме него — переход в остальной интерфейс системы требует
   полноценной авторизации.

## 2. Исходное состояние

`server/routes/access.ts` проверяет только `revokedAt` и `expiresAt`, после чего ставит `req.session.userId` и
перенаправляет на `/learner/test/<testId>`. Сессия ничем не помечена и неотличима от входа по паролю, поэтому
ссылка даёт весь личный кабинет получателя — дефект D-1 плана.

Погашения ссылки по успешному прохождению в коде нет: оно было заложено в этапе 2 плана и не реализовано.
Единственные ограничения жизни токена сегодня — срок и отзыв.

## 3. Принятые решения

| Вопрос | Решение |
| --- | --- |
| Что показывать по ссылке при исчерпанных попытках | Штатный стартовый экран теста: кнопка старта неактивна, доступен «Мой результат» |
| Объём границы | Тест целиком, включая результаты всех своих попыток по этому тесту |
| Первый вход (GDPR-согласие, `mustChangePassword`) | По ссылке не спрашивается вообще; экран первого входа в границы не входит |
| Механизм ограничения | Флаг области в сессии плюс один guard-middleware с белым списком «метод плюс шаблон пути» |
| Что показывать при выходе за границы | Существующую форму входа `/login`. Отдельного экрана-заглушки нет (уточнено 2026-07-30) |

## 4. Жизнь ссылки

Токен остаётся тем, чем является сейчас: он действителен, пока не отозван (`revoked_at IS NULL`) и не истёк
срок (`expires_at`). Ни успешное прохождение, ни исчерпание попыток токен не гасят. Этап 2 плана отменяется
целиком — оба его условия («попытки не исчерпаны», «тест не пройден успешно») не вводятся.

Ограничение «до исчерпания попыток» обеспечивает механизм попыток, а не токен: старт новой попытки уже
отклоняется кодом `ATTEMPTS_EXHAUSTED` в `server/routes/attempts.ts`.

Срок берётся из `due_date` назначения либо составляет 30 дней по умолчанию (`resolveTokenExpiry` в
`server/routes/assignments.ts`) и не меняется. Следствие принято осознанно: ссылка может умереть раньше, чем
кончатся попытки, если наступил срок сдачи.

## 5. Серверная часть

### 5.1. Флаг области в сессии

Сессия получает необязательное поле `magic = { assignmentId, testId }`. Его ставит только обработчик
`/access/:token`. Успешный вход по паролю (`POST /api/auth/login`) поле удаляет — так полноценная авторизация
снимает ограничение и отдельный механизм повышения прав не нужен. Наличие поля есть признак ограниченной
сессии; обычный вход его никогда не ставит.

Тип `SessionData` объявлен дважды — в `server/routes.ts` и `server/middleware/auth.ts`. Поле добавляется в одно
место, дубликат объявления устраняется.

### 5.2. Guard

Новый модуль `server/middleware/magic-scope.ts` регистрируется в `registerRoutes` сразу после
session-middleware и до монтирования роутеров из `routerConfig`.

Guard действует только на `/api/*`. Всё вне `/api` проходит мимо: клиентский бандл и `/uploads/media/*` с
медиафайлами вопросов, без которых вопрос не отрисуется. Ограничение осознанное: медиафайл не привязан к тесту,
и сузить его границей теста нечем. Имена вида `timestamp_uuid.ext` не угадываются, но по ссылке можно скачать
любой медиафайл, зная точный адрес.

Принцип работы — «запрещено всё, что не разрешено явно». Разрешения перечислены таблицей пар «метод плюс
шаблон пути» в самом модуле, поэтому область видна целиком в одном файле, а новый роут по умолчанию закрыт.

Таблица разрешений:

| Метод | Путь | Примечание |
| --- | --- | --- |
| GET | `/api/auth/me` | Отдаёт признак ограниченной сессии |
| POST | `/api/auth/logout` | |
| GET | `/api/learner/tests` | Ответ урезается до одного `magic.testId` |
| GET | `/api/tests/:id/screen-template/:screen` | |
| POST | `/api/tests/:testId/attempts/start` | |
| POST | `/api/tests/:testId/attempts/start-adaptive` | |
| GET | `/api/tests/:testId/resume` | |
| POST | `/api/attempts/:attemptId/save-progress` | |
| POST | `/api/attempts/:attemptId/section-timer` | |

| POST | `/api/attempts/:attemptId/finish` | |
| POST | `/api/attempts/:attemptId/answer-adaptive` | |
| POST | `/api/attempts/:attemptId/expire-topic-adaptive` | |

Всё остальное под `/api` отклоняется с `403` и телом `{ error, code: "MAGIC_SCOPE" }`. В частности закрыты
`/api/auth/change-password`, `/api/auth/complete-first-login`, `/api/learner/attempts`, `/api/home` и вся
авторская часть.

### 5.3. Привязка к тесту

Привязку проверяет сам guard, а не обработчики, — это одна точка вместо правок в десятке файлов:

- для путей с параметром `:testId` или `:id` — равенство `magic.testId`;
- для путей с параметром `:attemptId` — загрузка попытки и сверка `attempt.userId` с `session.userId`, а
  `attempt.testId` — с `magic.testId`.

### 5.4. Гигиена ссылки

На ответ `/access/:token` добавляются заголовки `Referrer-Policy: no-referrer` и `Cache-Control: no-store`. Без
первого сырой токен уезжает в `Referer` при любом внешнем переходе со страницы.

## 6. Клиентская часть

`GET /api/auth/me` начинает отдавать `magicScope: { testId } | null`. Всё поведение клиента опирается на это поле.

`ProtectedRoute` в `client/src/App.tsx`:

- при наличии `magicScope` гейт первого входа (`!user.gdprConsent || user.mustChangePassword`) пропускается;
- разрешены ровно два маршрута: `/learner/test/<magicScope.testId>` и `/learner/result/:attemptId`;
- на любом другом маршруте происходит переход на `/login` — существующую форму входа.

Отдельного экрана-заглушки нет (уточнено 2026-07-30). Полноценная авторизация и есть способ выйти за пределы
теста, поэтому форма входа — прямой и достаточный ответ на такую попытку; промежуточный экран с кнопкой
«Войти по паролю» был бы лишним шагом. Форма входа (`client/src/pages/login.tsx`) не меняется.

Маршрут `/learner/result/:attemptId` клиент пропускает по любому идентификатору попытки: принадлежность
попытки этому тесту и этому пользователю решает guard, и на чужой попытке страница получит `403 MAGIC_SCOPE`.
Дублировать проверку на клиенте не нужно — второй источник правды был бы хуже.

Отказ `403 MAGIC_SCOPE` от API ведёт туда же, на `/login`. Обработка живёт в общей обёртке запросов и служит
страховкой от рассинхронизации клиента с guard.

`LearnerLayout` при ограниченной сессии скрывает навигационный кластер «Главная / Тесты / История», а логотип
перестаёт быть ссылкой на `/learner`. Остаются переключатель темы, имя пользователя и выход: шапка не
предлагает ни одного перехода, который упрётся в запрет.

Обработка `ATTEMPTS_EXHAUSTED` в `client/src/pages/learner/take-test.tsx` перестаёт показывать тост с
`navigate("/learner")` и разворачивается в состояние стартового экрана — неактивная кнопка старта и доступный
«Мой результат», по образцу кулдауна PRD-6. Правка касается обеих веток, обычной и адаптивной. Данные уже
приходят в `/api/learner/tests` (`completedAttempts`, `maxAttempts`), новый API не нужен.

Единственное новое в интерфейсе — шапка без навигации, она показана эскизом
`docs/wireframes/magic-scope-required.html`. Нового экрана не появляется, поэтому и рисовать его не нужно.

## 7. Проверка

Серверные тесты:

- запрос вне таблицы разрешений отдаёт `403` с кодом `MAGIC_SCOPE`;
- путь с чужим `testId` отклоняется;
- попытка другого теста или другого пользователя отклоняется;
- разрешённый путь проходит;
- `/api/learner/tests` в ограниченной сессии возвращает ровно один тест;
- успешный вход по паролю снимает `magic` и открывает кабинет полностью.

Клиентские тесты:

- при `magicScope` экран первого входа не показывается;
- маршрут вне области ведёт на форму входа;
- шапка рендерится без навигации;
- `ATTEMPTS_EXHAUSTED` разворачивается в состояние стартового экрана без редиректа.

Приёмка в реальном браузере обязательна, юнит-тестов недостаточно:

- полный проход теста по ссылке от старта до результата;
- обрезание адреса до `/` открывает форму входа, а не кабинет — исходный сценарий обращения;
- вход по паролю в том же браузере возвращает полный кабинет.

Порог покрытия 80 процентов держится на коде задачи; вне его покрытие не поднимается.

## 8. Вне объёма

- Этап 3 плана: не выдавать ссылку-вход владельцам привилегированных ролей (дефект D-3).
- Этап 4 плана в части наблюдаемости: IP и User-Agent в записи о погашении, кнопка отзыва ссылки в интерфейсе
  назначений (дефект D-4). Заголовки из того же этапа взяты в объём, см. раздел 5.4.
- Настоящий экран GDPR-согласия. Обнаружено попутно: `client/src/pages/first-login.tsx` отправляет
  `gdprConsent: true` жёстко зашитым, ни чекбокса, ни текста согласия в форме нет, строки `gdprConsent`,
  `gdprConsentText` и `gdprRequired` в `client/src/lib/i18n.ts` не используются. Согласие проставляется молча
  всем пользователям, а не только пришедшим по ссылке, поэтому это отдельная задача.
